# タスク画面（⌘⇧X）

[タスク](../platform/tasks.md)の一覧を人が眺め、足し、片付け、並べ替える画面。⌘⇧X で開く（タブが 0 枚の workspace でも開く）。打てば足せ、space で完了でき、⌘T でそのタスクのための ⌘T（worktree を選んで agent を開く）へ進め、覚える近道を増やさずに一覧の操作から作業の開始までが済む。agent が CLI や MCP で同じ一覧を変えると、開いている画面にもそのまま映る。

画面はタスクのストア（唯一の正）を直接読み書きする。画面が持つのは一覧ごとの入力と選択・範囲・タブ・絞り込み・焦点・編集中の下書き・GitHub タブの右の欄の値だけで、タスクの値を写さない——写しを持つと agent の変更と同期させる経路が要り、ずれる余地ができるため。値の検証もストアだけが持ち、画面独自の検証は作らない。結び付いた Issue・PR の GitHub の値も、GitHub タブの open な一覧も写さず、アプリで 1 つの置き場から引く（下記）。agent の状態も写さず、窓が持つ「worktree ごとの agent」の索引から引く（下記）。

## 器と構成

scrim ＋ガラスパネルのカード。上端アンカーで窓に収まり、窓が小さければカードごと縮む（一覧と詳細はそれぞれ内部スクロール）。詳細の欄は見本の比率でカードと一緒に縮むが、選択式の値が並びきる幅で止まる。

- **ヘッダー**: `❯`＋入力欄。右に「タスク N / GitHub N」のタブと、「すべて N / <開いた workspace の名前> N」の範囲の札。タスクの件数はどれも未完了の数で、入力の絞り込みには左右されない（タスクの件数は今の範囲、すべては全体、workspace は開いた workspace）。GitHub の件数は取れた open の Issue・PR の数（まだ何も取れていなければ出さない）。範囲の札は GitHub タブでも出ていてクリックで切り替わる（GitHub の一覧には効かない）。プレースホルダはタスクのタブで「タスクを追加・絞り込み」、GitHub のタブで「Issue・PR を絞り込み」。
- **本体**: タスクのタブは左に一覧、右に選んでいるタスクの詳細。GitHub のタブは左に open な Issue・PR、右に選んだ項目の欄（下記「GitHub タブ」）。選ぶ状態の間は、ヘッダーの下に何を選んでいるかの帯が出る（下記「選ぶ状態」）。
- **フッター**: 左は今の選択と焦点で主な操作が何をするかを 1 行で言い（例「space <タイトル> を完了にする」「↵ 『…』を追加」「←→ 優先度を変える」「↵ 確定」「↵ #221 をアサインしてタスクにする」）、失敗があれば赤でその理由に置き換える。右はその場所で効くキーのヒント（一覧・詳細・編集中・GitHub のタブ・右の欄・選ぶ状態で変わる）。

## 一覧

欄は「進行中 N」「未着手 N」「完了 N ⌄」の順。**どの欄でも列の順をそのまま使い、workspace や優先度で組み替えない**——並びはユーザー（と agent）が決めるもので、agent が足したタスクを強制的に上げることもしない。空の欄は見出しごと出さない。完了の欄は畳んだ見出しで始まり、↵ かクリックで開閉する。範囲に 1 件も無ければ「タスクはありません」の 1 行を出す。人の操作（選び直し・⌥↑↓・ドラッグで離す・範囲や完了の欄の切り替え・画面からの変更）で選んだ行が一覧の見えている範囲から外れたら、見える所まで最小の量だけ一覧を送る。agent の変更で選んだ行の位置がずれただけでは送らない——人が流して読んでいる一覧を引き戻さないため。

行の札:

- **取っ手**: 選んでいる未完了のタスクの行の左端に ⋮⋮ を出す。並べ替えられることを示す印で、掴む場所は行全体。
- **状態のアイコン**: 未着手は空の円、進行中は ◐、待ちは破線の円と時計、完了は塗りの円に ✓。待ちのアイコンが進行中・未着手より優先する。アイコンのクリックで完了 ⇄ 未着手。
- **主の結び付き**: 結び付きがあれば、状態のアイコンとタイトルの間に主の種別の印（Issue は中心に点のある円、PR は pull request の印）と「#番号」。保存した結び付きだけで決まり、GitHub の値の有無に依らず出る。
- **PR の札**: 主が Issue で PR も結び付いていれば、タイトルの後に最初の PR を「<PR の印> #213 レビュー待ち ✓」の札で出す。状態はマージ済み > 閉じた > 下書き > レビュー状態（レビュー待ち・承認済み・修正依頼。無ければ出さない）の順に強いものを 1 つ、CI は成功 ✓・失敗 ✗・進行中 ⋯（マージ済み・閉じた PR では出さない）。値が無い・実体が PR でなければ「#213」だけ。
- **レビュー**: 主が PR で、その作成者が gh で認証している自分と違えば、タイトルの後に「レビュー」。値か自分の login が無いときは出さない。
- **優先度**: 高は赤みの札、低は灰色の札で、低いタスクはタイトルも一段沈める。中は何も出さない。
- **期限**: 「10/6 月」。今年でなければ年も付ける。曜日は UI 言語に合わせる。
- **追加者**: agent が足したタスクに「claude が追加」。
- **agent**: タスクの worktree で agent が作業中なら「◌ claude 12分」（青）、入力待ちなら「▪ claude 入力待ち」（黄）を、右寄せの領域の先頭に出す（下記「agent の状態」）。
- **待ち**: 右寄せで「⏱ 理由 N日」。日数は待ち始めた日から今日までの暦日の差で、0 日は「今日」。
- **workspace**: 右端に、開いた workspace なら紫の札、ほかの workspace なら灰色の名前。解決できない参照（「なし」）は何も出さない。

完了のタスクの行は沈めて出し、並べ替えの対象にしない。

## 入力・追加・絞り込み

打つとタイトルの部分一致（大文字小文字・濁点などを区別しない）で一覧が絞られ、先頭に「＋『…』を追加」の行が選ばれた状態で出る。↵ で、**開いた時点の workspace** に付いた未着手のタスクが列の末尾に足され、入力が空に戻り、足したタスクが選ばれる。画面は開いたままなので続けて足せる。範囲に関わらず開いた workspace に付ける（詳細で「なし」や別の workspace に変えられる）。

**↵ はいつも選ばれている行の操作**: 追加の行なら追加、タスクの行なら完了 ⇄ 未着手、完了の見出しなら開閉。文字があるときに ↓ で一致したタスクを選んで ↵ を押せば、そのタスクが完了になる。↵ は入力欄の確定で受けるので、日本語入力の変換を確定する ↵ では発火しない。

## 一覧のキー

| キー | 動き |
|---|---|
| ↑↓ / ⌘↑↓ | 選択を動かす（端で巡回）/ 先頭・末尾へ |
| space | 入力欄が空のときだけ、選んだタスクを完了 ⇄ 未着手（完了の見出しなら開閉）。文字があるときは空白を打つ |
| ⌘⌫ | 入力欄が空のときだけ、選んだタスクを確認なしで消す（取り消しは無い）。文字があるときは行頭まで消す |
| ⌥↑↓ | 選んだタスクを、同じ欄の見えている隣のタスクと入れ替える。欄の端では何もしない。並びは保存され `orb task list` の順にも出る（落とし先は「ドラッグで並べ替え」と同じ規則） |
| → | タスクの行を選んでいれば詳細へ |
| ⌘T | 選んだタスクのための ⌘T を開く（下記） |
| ⇥ / ⇧⇥ | 範囲（すべて ⇄ 開いた workspace）/ タブ（タスク ⇄ GitHub）。タブを行き来しても、それぞれの入力・選んだ行は残る |
| esc | 閉じる |

- **空のときだけ効く単キー**は、文字入力と衝突させないため。日本語入力の変換中は、空の入力欄でも space を変換に使わせ、画面のキーとしては受けない。space と ⌘⌫ は押した瞬間だけを操作にし、押し続けたキーリピートは捨てる——space を押し続けて下の行が次々に完了にならないため、入力を消そうと ⌘⌫ を押し続けて空になった瞬間に、続くリピートでタスクが消えないため。
- 選んでいるタスクを完了にした・未着手に戻した・消した後は、同じ位置の行が選ばれる（完了の欄が開いていても、移った先へは追わない）。選んでいない行のアイコンのクリックで完了 ⇄ 未着手にしたときは、選択は動かない。
- マウス: 行のクリックで選ぶ（追加の行は追加、完了の見出しは開閉）。札のクリックでタブと範囲を切り替える。ホバーの選択追従は他のパレットと同じ入力モダリティの規約に従う（[workspace パレット](workspace.md)）。カード内のどこをクリックしても、焦点はモデルが決めた行き先へ当て直される。

## ドラッグで並べ替え

未完了のタスクの行を掴んで、**同じ欄（進行中 / 未着手）の中で**動かす。欄はまたがず、ステータスは変わらない。完了のタスク・追加の行・見出しは掴めない。

- 行のどこを掴んでもよく、わずかに動かして初めてドラッグになる。動かさずに離せば、これまでどおりのクリック（選ぶ・アイコンで完了切替）。
- 掴むと、その行が選ばれる（詳細の編集中なら、編集を確定してから一覧へ戻る）。掴んだ行は指に付いて上下に動き、欄の先頭・末尾の外へは出ない。ほかの行はずらさず、落ちる位置に accent の横線を出す（元の位置に落ちるときは出さない）。掴み中は、ほかの行の上を通ってもホバーで選択が動かない（掴み中のポインタの動きは実マウス移動として数えない）。
- 離した瞬間に 1 回だけ並びが変わって保存され、`orb task list` の順にも出る。選択は動かしたタスクのまま。元の位置で離せば何も変わらない（保存も起きない）。
- **落とし先の規則（⌥↑↓ と共通）**: 入力や範囲で絞り込んでいても掴め、見えている兄弟の中で動かす。下へ動かしたら直上の見えている行の直後、上へなら直下の見えている行の直前に入り、間に隠れたタスクは越えない。⌥↑↓ はこれの「隣へ 1 つ」にあたる。
- 自動スクロールは無い。見えている範囲で落とし、遠くへは ⌥↑↓ を使う。掴み中にホイールで一覧を流すと、落ちる位置は次にポインタを動かした時点で追従する。
- 掴み中の esc は、いつもどおり画面を閉じる（掴みも消える）。

## 詳細

選んでいるのがタスクの行のときだけ、そのタスクを出す。上から主の結び付き（「⊙ orbe#212」。owner は出さない。結び付きが無ければ出さない）・タイトル・agent の場所・「Issue・PR」の欄（結び付きが無くても出る）・ステータス・待ち・優先度・期限・workspace・追加（日付と追加者。日付は期限と同じく、今年でなければ年も付ける）・メモ、最後に「space 完了にする（完了なら未着手に戻す）」と「⌘⌫ 削除」のボタン。

**agent の場所**は、タスクの worktree に agent が居れば状態を問わず出す（完了・休止を含む）: 「claude が取り掛かっている」（入力待ちなら「claude が入力を待っている」、完了なら「claude が応答を終えた」、休止なら「claude が次の指示を待っている」）と、その下に「working 12分 · タブ <タブ名>」、右に「↗ タブへ」。↑↓ で止まる場所で、↵ かクリックでそのタブ（別の workspace ならそこへ切り替えて）へ移り、画面を閉じる。フッターは「↵ <タブ名> へ移る」。

**「Issue・PR」の欄**は各項目を 1 行ずつ並べ、末尾に「＋ 結び付ける」（右に「ブランチの PR は自動」）を置く。「＋ 結び付ける」は結び付きが 0 件でも出て、↑↓ で止まる場所で、↵ かクリックで GitHub タブの項目を選ぶ状態に入る（下記「選ぶ状態」。フッターは「↵ Issue・PR を選んで結び付ける」）。項目の行は、印（保存した種別）・番号（主とリポジトリが違う行は「<リポジトリ名>#番号」）・タイトル・右に状態（Issue は open / closed、PR は「✓ CI · レビュー待ち」「マージ済み」「閉じた」など）を出す。GitHub の値が無い・実体の種別が保存した種別と違うときは、タイトルと状態を出さず番号だけにする。行は ↑↓ で止まる場所で、↵ でその項目の GitHub のページをブラウザで開き、⌫ でその結び付きを外す（外すのは 1 件だけ——押し続けたキーリピートで、焦点が移った先の項目まで外さない）。クリックでも開け、ホバーか選択で出る「外す」のクリックでも外せる。フッターは「↵ #213 を GitHub で開く」と「⌫ 外す · ↑↓ 項目 · esc 一覧へ」。

→ で詳細に入るとステータスに居る。↑↓ で項目（タイトル → agent の場所 → 各結び付き → ＋ 結び付ける → ステータス → … → メモ）を移り、←→ で選択式の値を変える（ステータスは未着手 / 進行中、優先度は高 / 中 / 低、workspace は「なし」とサイドバーの順の各 workspace を巡回）。選択式でない項目の ← と esc、ヘッダーの入力欄のクリックは一覧へ戻り、焦点は入力欄へ移る（編集中なら確定してから戻る）。詳細でも space・⌘⌫ はそのタスクに効き、その後は一覧に戻って同じ位置の行を選ぶ。完了のタスクのステータスはどちらも選ばれていない見た目で、←→ で押した側の値へ戻せる。

**文字の項目**（タイトル・待ちの理由・期限・メモ）は ↵（かクリック）で編集を始め、↵ で確定、esc で取り消す。メモは複数行なので ↵ は改行で、⌘↵ で確定する。

- タイトルを空で確定すると、エラーにせず取り消しとして扱う。
- 待ちの理由と期限は、空で確定すると外れる。値がある間は「解除」のクリックでも外れる。完了のタスクには待ちを入れられない（[タスク](../platform/tasks.md)の不変条件）ので、待ちの項目は操作できない見た目になる。
- 期限は「10/6」（今日以降で最も近いその日）と「2026-10-06」を受ける。読めなければ理由をフッターに赤で出し、編集を続ける。
- ストアが値を受け付けないときは、何をしようとしたかに応じた文をフッターに赤で出す（ストアのエラーの文は読まない）。

**編集中の文字は、esc 以外では失わない。** 別の行や項目のクリック、タブ・範囲の切り替え、画面を閉じる、別の画面への差し替え（⌘⌘）、アプリの終了のどれでも、打った内容は確定して残る（確定できない期限は、編集を続ける場所が無いので捨て、理由だけを残す）。メモは 1 打鍵ごとには保存しない。

## agent の変更への追従と選択

選択は行の位置ではなく**同一性**（追加の行 / タスクの ID / 完了の見出し）で持つ。列が変わるたび（agent の変更を含む）に、同一性が今の行にあればそのまま、無ければ最後に居た位置の行（末尾で頭打ち）へ移す。範囲・タブ・完了の欄の開閉が変わったときも同じ規則で選び直す。だから agent が上の欄にタスクを足しても、選んでいるタスクは変わらず、直後の space や ⌘⌫ が別のタスクに当たらない。

- 選んでいたタスクが消えたら、同じ位置の行が選ばれる。
- 詳細に居る間に、そのタスクが消えた・一覧から外れたら一覧へ戻る。編集中のタスクが消えたら、編集は取り消される。
- 画面の操作がストアに届く前に agent がそのタスクを消していたら、エラーは出さずに上の規則で選択を移す。
- 詳細の結び付きの行に居る焦点も、位置ではなく項目の同一性で持つ。agent が結び付きを変えても別の項目へずれず、焦点の結び付きが外れたら同じ位置の止まる場所（末尾で頭打ち）へ移る。agent の場所に居る間に agent が去った（タブが閉じた・agent が終了した）ときも同じ。
- 掴み中に、掴んだタスクの欄の見えている並び（追加・削除・並べ替え・ステータス変更）か、掴んだ行の一覧の中の位置（上の欄の増減、入力で追加の行が出る など）が変わったら、掴みを捨てる。掴んだ行は元に戻り、離しても何も起きない（指と行がずれたまま、古い並びで確定しないため）。離す瞬間と agent の変更が重なっても、離した時点の並びを確かめてから確定する。掴んだ行の一覧の中の位置を動かさないほかの欄の変化（下の欄の増減、上の欄の中での並べ替え など）や、兄弟のメモの書き換えでは捨てない。

開いている間の workspace の名前と並びは、**開いた時点のもの**を使う。開いている間に（agent が制御 API で）workspace を改名・削除しても、閉じて開き直すまで画面には反映されない——workspace は観測できる値ではないので、描くたびに引くと反映が他の描き直しのついでに左右されるため。開いた workspace への結び付き（追加の既定・範囲・紫の札）も開いた時点で固定する。

## ⌘T — このタスクの worktree を開く

⌘T は、選んでいるタスクのための [⌘T](worktree.md)（worktree を選んで agent を開く画面）に差し替える。入力欄・詳細・編集欄のどこに焦点があっても効く。

- タスクの行（一覧・詳細）ならそのタスク、追加の行なら**足してから**そのタスク。完了の見出しと選ぶ状態では何もしない。完了したタスクでも開ける（↵ で進行中に戻る）。GitHub タブでは、結び付いていない行は**タスクにしてから**そのタスク、結び付いている行はそのタスク（「さらに」の行では何もしない）。
- 編集中なら、打った内容を確定してから開く（「編集中の文字は esc 以外では失わない」）。
- フッターの右のヒントの先頭に「⌘T 開く」を出す（一覧と詳細。GitHub タブの結び付いていない行では「⌘T タスクにして開く」）。

開いた ⌘T の札・先頭の欄・↵ でタスクに起きること（進行中にする・worktree を付ける）は [worktree パレット](worktree.md)が持つ。

## agent の状態

タスクの [worktree](../platform/tasks.md) で動く agent を、行の札と詳細の agent の場所に出す。タスクの worktree とタブの連は同じ場所のキーで揃っているので、「そのタスクの worktree のタブ」はキーの等値だけで決まる（⌘T を通さずに開いたタブも、再起動後のタブも拾う）。

- **行の札は作業中と入力待ちだけ、詳細の agent の場所と ↵ でタブへ移る先は状態を問わない**（完了・休止を含む）。札は今動いている作業を一覧で見分けるためのもので、終わった agent まで出すと一覧が札で埋まる。一方、詳細から ↵ でタブへ移るのは agent へ移る手段なので、1 ターン終わるごと（完了→休止）にそれが消えては、結果を見に行く・続きを頼む場面で使えない。
- 同じ worktree にタブが複数あれば 1 つにまとめる。入力待ち > 作業中 > 完了 > 休止の順に優先し（タブ行のグリフを畳む順と同じ）、同じ状態なら、その状態になったのが新しい方。
- **完了したタスクには出さない**——完了の行は沈めて出すもので、そこに今の作業の札が出ると、別の作業を誤って示す。
- 経過は、その状態になった時刻から 1 分ごとに描き直して出す（1 時間未満は分、1 日未満は時間、それ以上は日）。
- タブは観測できない値なので、窓が chrome の更新の合流点で全タブから「worktree ごとの agent」の索引を作り直し、値が変わったときだけ書く。画面はその索引を読むので、状態が変わるとすぐ追従する。
- codex・agy は終了を報告しないので、プロセスが終わった後も「作業中」が残ることがある（Attention と同じ）。

## PR の自動の結び付け

開いたときに 1 回、完了していないタスクの worktree のブランチに PR があれば、そのタスクの結び付きの末尾に足す（規則は [タスク](../platform/tasks.md)）。足した項目は出ている行の結び付きなので、その値は下の規則で取りに行く。人が詳細の ⌫ で外した PR は、開き直しても付け直さない。

## GitHub の値の取り方

結び付いた Issue・PR のタイトルや状態は、結び付きのリポジトリ名と番号で GitHub へ直接問い合わせて取る（gh の GraphQL。リポジトリをまたいで 1 回にまとめ、多ければ続けて分ける）。タスク画面は全 workspace をまたぎ、閉じた Issue やマージ済みの PR も出すので、開いた workspace の open な一覧からは引けないため。問い合わせ先が名前で決まるので、checkout も作業ディレクトリも要らない。

- **取りに行くのは出ている行の結び付きだけ**——今の範囲・入力で一覧に出るタスク（完了の欄は開いているときだけ）。完了したタスクは削除まで残り続けるので、保存されている結び付きを全部取ると使うほど重くなる。
- **開いたとき**に出ている行の結び付きを取り直す。**出ている行の結び付きが増えたとき**（agent が結び付けた・完了の欄を開いた・範囲や入力を変えた）は、この開いている間にまだ取りに行っていない項目だけを取る（前に答えのある項目も、開き直して初めて出たなら取り直す）。開いている間の定期的な取り直しはしない。
- 答えはメモリにだけ持ち、アプリで 1 つの置き場に置く。次に開いたときは前回の答えで先に描き、届いた分から描き直す。再起動直後は取れるまで番号だけが出る。
- **gh が無い・未認証・オフライン・時間切れのときは番号だけ**で、エラーも gh の可否も画面に出さない。取れなかった項目は次に開くまで取り直さない（打鍵のたびに gh を起こさないため）。

## GitHub タブ

開いた workspace のリポジトリの **open な Issue・PR を全部**（自分のものに限らない）出し、タスクにする・タスクに結び付ける入口にする。Issue・PR から作業を始めるのはここで、⌘T には Issue・PR の欄を持たせない。

**リポジトリは 1 つ**——開いた workspace の root で gh が既定とするリポジトリ（set-default、無ければ gh の規則で upstream → origin の順）。github.com のリポジトリに限り、GitHub Enterprise のリポジトリは「見つからない」として扱う（問い合わせと書き込みは github.com へ送るので、同じ owner/name の別のリポジトリを読み書きしないため）。origin が自分の fork で upstream が本体という形では本体の一覧が出て、`gh issue list` が出すリポジトリと一致する。結び付きとの突き合わせはこのリポジトリの正式名と番号で行う（リポジトリを改名する前に保存した結び付きは一致せず、結び付いていない側に出る）。

### 一覧

区分は「ISSUES · ORBE 24」「PULL REQUESTS · ORBE 7」（リポジトリ名は owner を除く。件数は絞り込みの札と入力を当てた後の数。当たる項目の無い区分は見出しごと出さない。両方 0 件なら「該当する Issue・PR はありません」）。

- **結び付いた行を区分の上にまとめる。** 地をうっすら塗り、右に結び付いたタスク（「🔗 #212 タスク機能の設計」。主の番号は、行のリポジトリと違えば `<リポジトリ名>#212`、主の無いタスクはタイトルだけ）を出す。結び付いた行は隠さない。
- **結び付いていない行は更新の新しい順に先頭 5 件**を出し、残りは「↓ さらに N 件」の行にまとめる。↵ かクリックでその区分の残りを全部出し、閉じるまで保つ。
- 行は印（Issue / PR）・「#番号」・タイトル・自分との関係の文。関係の文は PR なら「レビュー依頼 · あなた宛」（個人宛の依頼が自分）→「レビュー依頼 · @org/team 宛」（チーム宛だけで自分に頼まれている）→「作成者: あなた」→「@作成者」の順、Issue なら「担当: あなた」→「担当なし」→「@先頭の担当者」。
- 開いた直後は先頭の選べる行を選ぶ。

**絞り込みの札**は「すべて / 担当が自分 N / 作成者が自分 N / レビュー依頼 N」で、⇥ で巡回する（クリックでも選べる）。件数は一覧の全件で数え、入力に左右されない。「レビュー依頼」はチーム宛（自分の所属する入れ子のチームを含む）も入る——判定を GitHub の検索 `review-requested:@me` に任せ、チームの所属を手元で二重に持たない。自分の login がまだ分からない間は、札に件数を出さず、自分に関わる札では何も出さない。入力はタイトルの部分一致（タスクの絞り込みと同じ正規化）か番号（`#` の有無を問わず前方一致）で絞る。

### 右の欄

選んだ項目の見出し（「⊙ orbe#221 · 今日」。Issue は更新日、PR は CI とレビュー状態）・タイトル・関係の文に続けて:

- **結び付いていない行**: 「自分をアサインする — GitHub の担当者に自分を追加する」のチェック（既定オン）・優先度（既定は中）・期限（既定なし）、「⌘T で、タスクにしてから worktree を選んで開く」と「↵ タスクにする」「⌘T タスクにして開く」のボタン、「⌘L 既存のタスクに結び付ける」。チーム宛だけでレビューを頼まれている PR では、チェックは「自分をレビュアーにする」になる。自分が作成者・既に担当・個人宛にレビュー依頼済みの項目、自分の login がまだ分からないときは、チェックを出さない（足すものが無い・誰を足すか決まらない）。
- **結び付いている行**: 「結び付いているタスク」の箱（状態のアイコン・主の番号とタイトル・「進行中 · claude 作業中 12分」。agent の札はタスクのタブの行と同じく作業中・入力待ちだけ）と、「↵ #212 を開く」「⌘L 別のタスクに付け替える」「⌘⌫ 結び付けを外す」のボタン。

右の欄の値は画面の値で、ストアには「タスクにする」で初めて書く。**選択の同一性が変わると既定に戻る**（agent の変更で同じ行のままなら、打った値を保つ）。右の欄に居る間に選んだ項目が一覧から消えて選択が別の行へ移ったとき（取り直し・agent の変更）は、一覧へ戻る——別の項目の欄に既定の値で居続けると、↵ で見ていない項目をタスクにして自分を足してしまう。→（結び付いていない行で）で欄の先頭に入り、↑↓ で止まる場所（チェック → 優先度 → 期限）を移り、space でチェック、←→ で優先度、↵ で期限を打つ（「10/6」「2026-10-06」）。esc か優先度以外での ← で一覧へ戻る。欄の中でも ↵（期限以外）・⌘T・⌘L は、行の「タスクにする」「タスクにして開く」「結び付ける」と同じ。期限の打ちかけは詳細の編集と同じく esc 以外では失わず、読めない文字のまま「タスクにする」を押すと、作らずに理由を赤で出して編集を続ける。

### 操作

| キー | 結び付いていない行 | 結び付いている行 |
|---|---|---|
| ↵ | タスクにする | タスクのタブのそのタスクへ移る |
| ⌘T | タスクにしてから、そのタスクの ⌘T を開く | そのタスクの ⌘T を開く |
| ⌘L | 結び付けるタスクを選ぶ（選ぶ状態） | 付け替える先のタスクを選ぶ（選ぶ状態） |
| ⌘⌫ | — | 結び付けを外す（行は結び付いていない側へ戻る） |
| → | 右の欄へ | — |

↑↓ / ⌘↑↓ は選択（端で巡回 / 先頭・末尾）、⇥ は絞り込みの札、⇧⇥ はタブ、esc は閉じる。⌘L と ⌘⌫ は修飾付きのキーなので、入力欄の文字の有無を問わず効く（絞り込みの文字を打つ・消すのと衝突させない）。どちらも押した瞬間だけを操作にし、押し続けたキーリピートは捨てる（選択が移った先の行まで操作しない）。日本語入力の変換中は受けない。

- **タスクにする**: 開いた workspace に付いた未着手のタスクを列の末尾に足す。タイトルは項目のタイトル、優先度と期限は右の欄の値、主の結び付きがその項目。行は結び付いた行として区分の上へ移り、選択はその行を追う。GitHub タブに留まる。結び付きと一緒に 1 回で足すので、間に agent がその項目を結び付けていれば拒否され、「結び付けられませんでした」を出す。
- **自分を GitHub に足す**: チェックがオンなら、タスクを足した後に**裏で**、自分を担当者（レビュアー）に足す——ローカルの操作を GitHub の往復で待たせない。書き込む項目は押した瞬間の項目。成否は GitHub の応答に自分が入っているかで決める（push 権限が無いと、GitHub はアサインを黙って無視して成功を返す）。成功すれば応答の値でその 1 件だけを一覧に差し込み、関係の文が「担当: あなた」に変わる（一覧の全量の取り直しを待たない）。失敗してもタスクは残し（取り消さない）、フッターに赤で出し、その項目の右の欄にも赤で出す。失敗の記録は画面の寿命に依らず、次にその項目を選んだときにも見え（⌘T で閉じた後の失敗も、次に開いたときに見える）、次に試すか成功すれば消える。記録はメモリにだけ持ち、再起動で消える。
- **タスクへ移る**: タスクのタブへ移ってそのタスクを選ぶ。範囲・入力・完了の欄で隠れていれば、見えるように切り替える（範囲をすべてに、入力を空に、完了の欄を開く）。
- 開いている間に agent が結び付きを変えると、並びと右の欄がすぐ追従し、選んだ行は同一性（リポジトリと番号）で保たれる。

### 選ぶ状態

結び付ける相手を選ぶ一時的な状態。2 つの方向があり、**どちらも自分の入力と選択を持つ**——相手のタブの一覧を借りないので、抜けたときに元のタブの絞り込みと選んだ行がそのまま残る。入るときは空の入力・先頭の行から始まる。上に何を選んでいるかの帯が出る。

- **タスクを選ぶ**（GitHub タブの ⌘L から）: タスクのタブの行で選ぶ。帯は「#221 … を結び付けるタスクを選ぶ」。↵ でそのタスクの結び付きの末尾に付け（結び付いていた項目なら前のタスクから外す）、GitHub タブへ戻ってその行を選ぶ。追加の行は出さず、space・⌘⌫・⌥↑↓・ドラッグ・→・⇧⇥・⌘T・行のアイコンのクリック・詳細の操作は効かない。⇥ の範囲と完了の欄の開閉は効く（範囲と開閉はタスクのタブと共有する）。
- **項目を選ぶ**（詳細の「＋ 結び付ける」から）: GitHub タブの行で選ぶ。帯は「#212 … に結び付ける Issue・PR を選ぶ」。↵ でそのタスクの結び付きの末尾に付けて詳細へ戻り、焦点はその結び付きの行に居る。⌘T・⌘L・⌘⌫・→・⇧⇥ は効かず、右の欄は見出しと結び付いたタスクだけを出す。⇥ の絞り込みと「さらに」は効く（絞り込みと開いた区分は GitHub タブと共有する）。
- 選んだ相手が既にその項目を持っていれば、↵ は何もしない（フッターが「#221 は『…』に結び付いている」と言う）。別のタスクが持っていれば、フッターが付け替えを先に言う（「#221 を <前のタスク> から『…』へ付け替える」）。
- esc は何も変えずに、入る前の場所（GitHub タブ・詳細の「＋ 結び付ける」）へ戻る。対象の項目が一覧から消えた・対象のタスクが消えた（agent の削除）ときも、選ぶ状態を終えて戻る。
- **付け替えは 1 回の変更**——前のタスクから外し、選んだタスクの末尾に足し、1 回だけ保存する（[タスク](../platform/tasks.md)）。2 回に分けると、間に読んだ agent に「どこにも付いていない」状態が見え、後の 1 回が拒否されると外れただけで残る。

### 使えないとき

理由を GitHub タブの本体に 1 行で出し、タスクのタブは変えない（タスクのタブは今までどおり gh の可否を出さない）。

- gh が無い・gh が認証されていない・この workspace の GitHub のリポジトリが見つからない（オフラインを含む。区別しない）
- 前回の一覧が無いまま取得に失敗した（「Issue・PR を取得できませんでした」）
- 前回の一覧が無く、取得中なら「Issue・PR を読み込み中…」

**前回の一覧があれば、解決や取り直しが失敗していてもそれを描いたまま出す**（困るのは初回だけ）。

### 一覧の取り方

- 開くたびに（タスクのタブを開いていても。ヘッダーの「GitHub N」のため）root のリポジトリを解決し直し、Issue・PR の一覧と「自分の login・レビュー依頼」を取り直す。どれも前回の答えで先に描き、届いた分から描き直す。解決の答えは root ごとに覚え、新しい答えが前回と違えば新しい名前の一覧に切り替える。
- 一覧は作成の新しい順にページ送りで取り、Issue は 1000 件・PR は 500 件まで（上限を超える古い項目は出ず、札の件数も取れた範囲で数える）。表示は更新の新しい順に並べ直す——更新の順でページ送りすると、取っている間に更新された項目がページをまたいで動き、重複や取りこぼしが出る。レビュー依頼は検索の先頭 100 件まで。
- 一覧はアプリで 1 つの置き場にリポジトリ単位で持ち、画面は写さずに読む。同じリポジトリ・同じ種別の取得は常に 1 本で、開き直しても取得中なら合流する。取得は画面より長生きし、閉じても上限まで続く。取り直しの途中は、届いた範囲の後ろを前回の一覧の残りで埋め（一覧が縮んでまた伸びない）、取り終えたら今回の分に置き換え、途中で失敗したらそれまでの一覧を据え置く。自分を足した結果の差し込みは、取得中に届く古いページにも当てる（差し込んだ値が古いページで消えない）。
- 答えはメモリにだけ持つ。

## 開閉

開いている間の ⌘⇧X は、ほかのパレットと同じく何もしない（パレット表示中は window のコマンドが効かない。⌘T だけは例外として、このタスクのための ⌘T へ差し替える）。閉じるのは esc（一覧に居るとき。選ぶ状態ならやめる）・scrim のクリック。開くたびに状態は初めから（範囲は「すべて」、タブは「タスク」、完了の欄は畳む、絞り込みは「すべて」、右の欄は既定、先頭の行を選ぶ）。
