# タスク画面（⌘⇧X）

[タスク](../platform/tasks.md)の一覧を人が眺め、足し、片付ける画面。⌘⇧X で開く（タブが 0 枚の workspace でも開く）。打てば足せ、space で完了でき、⌘↵ でそのタスクのための ⌘T 画面（worktree を選んで agent を開く）へ進め、覚える近道を増やさずに一覧の操作から作業の開始までが済む。打った文は ⌘↵ で agent に任せられ、Home に起きた claude（[秘書](../agent/secretary.md)）がタスクにする。agent が CLI や MCP で同じ一覧を変えると、開いている画面にもそのまま映る。

画面はタスクのストア（唯一の正）を直接読み書きする。画面が持つのは一覧ごとの入力と選択（タスクの表は載せたタスクの並びも）・タスクの絞り込みと並び・開いている絞り込みのメニュー・タブ・GitHub の絞り込み・焦点・編集中の下書き・今足したタスク・GitHub タブの右の欄の値だけで、タスクの値を写さない——写しを持つと agent の変更と同期させる経路が要り、ずれる余地ができるため。値の検証もストアだけが持ち、画面独自の検証は作らない。結び付いた Issue・PR の GitHub の値も、GitHub タブの open な一覧も写さず、アプリで 1 つの置き場から引く（下記）。agent の状態も写さず、窓が持つ「worktree ごとの agent」の索引から引く（下記）。

## 器と構成

scrim ＋ガラスパネルのカード。上端アンカーで窓に収まり、窓が小さければカードごと縮む（一覧と右の欄はそれぞれ内部スクロール。右の欄は、キーで移った場所が見えるように送り、別のタスク・項目を選ぶと先頭から見せる）。右の欄はカードに対して一定の比率で一緒に縮むが、選択式の値が並びきる幅で止まる。

字と間隔は [workspace パレット](workspace.md)（⌘⇧S）と同じ尺度にそろえる——行・ヘッダーの入力欄・フッターのキーヒント・補足の小字を、ほかのパレットと同じ大きさで読ませるため。2 つの欄・タブ・編集欄を持つので器（カード）はほかのパレットと別だが、尺度は共有する。

- **ヘッダー**: `❯`＋入力欄。右に「タスク N / GitHub N / 提案 N」のタブ。タスクの件数は未完了の全件で、絞り込みにも入力にも左右されない。GitHub の件数は取れた open の Issue・PR の数（まだ何も取れていなければ出さない）。提案の件数は棚に出ている人の判断待ちの候補の数。タスクのタブで打っている間は、入力欄の背景に淡い地を敷き、欄の右端に「↵ タスクに追加」「⌘↵ agent に任せる」を出す（下記「入力・行き先・絞り込み」）。プレースホルダはタスクのタブで「タスクを追加・絞り込み」、GitHub のタブで「Issue・PR を絞り込み」、提案タブで「候補を絞り込み」。
- **本体**: タスクのタブは左に絞り込みの行と表、右の欄に選んでいるタスク（下記「右の欄」）。入力の行き先を選んでいる間は右の欄を出さず、一覧を広く使う（出すタスクが無い）。GitHub のタブは左に open な Issue・PR、右に選んだ項目の欄（下記「GitHub タブ」）。提案タブは棚・候補・詳細の 3 列（[提案タブ](automation.md)）。選ぶ状態の間は、ヘッダーの下に何を選んでいるかの帯が出る（下記「選ぶ状態」）。
- **フッター**: 左は今の選択と焦点で主な操作が何をするかを 1 行で言い（例「space「<タイトル>」を完了にする」「↵「<タイトル>」を orbe のタスクに足す」「←→ 優先度を変える」「↵ 確定」「↵ #221 をアサインしてタスクにする」）、失敗があれば赤でその理由に置き換える。右はその場所で効くキーのヒント（一覧・右の欄・編集中・GitHub のタブ・提案タブ・選ぶ状態で変わる）。ヒントはその場で効くキーだけを、行の操作 → 開く → 消す → ⇥ → esc の順に並べる。
  - タスクのタブでタスクの行（待ちを含む）を選んでいる: 「→ 詳細 · ⌘↵ agent を開く · ⌘⌫ 削除 · ⇥ タブ · esc 閉じる」。入力欄に文字がある間は ⌘⌫ を出さない（その間の ⌘⌫ は入力欄の文字を消す）。
  - タスクのタブで行を選んでいない（表が空など）: 「⇥ タブ · esc 閉じる」。
  - 打っている途中: 「⌘↵ agent に任せる · ↓ 一致する項目へ · ⇥ タブ · esc 閉じる」（一致するタスクが無ければ ↓ は出さない）。
  - タスクの右の欄: 「⌘↵ agent を開く · ↑↓ 項目 · ⇥ タブ · esc 一覧へ」（結び付きの行では ⌘↵ の後に「⌫ 外す」）。
  - GitHub の結び付いていない行: 「⌘↵ タスクにして開く · ⌘L 結び付ける · ⌘O ブラウザで開く · ⇥ タブ · esc 閉じる」。
  - GitHub の結び付いている行: 「⌘↵ agent を開く · ⌘L 付け替える · ⌘⌫ 外す · ⌘O ブラウザで開く · ⇥ タブ · esc 閉じる」。「さらに」の行・行が無いときは「⇥ タブ · esc 閉じる」。
  - GitHub の右の欄: 「↵ タスクにする · ⌘↵ タスクにして開く · ⌘O ブラウザで開く · ↑↓ 項目 · ⇥ タブ · esc 一覧へ」（期限の場所では ↵ を出さない）。

## 一覧

タスクのタブの左は、上に**絞り込みの行**、その下に**表**。表は、絞り込みと入力に合うタスクを今の並びで 1 つに並べる（下記「リストの更新」）。表に出す行（暗い行も数える）が 1 件も無く、入力も無ければ「該当するタスクはありません」の 1 行を出す。人の操作（選び直し・絞り込みや並びの切り替え・画面からの変更）で選んだ行が表の見えている範囲から外れたら、見える所まで最小の量だけ表をスクロールする。agent の変更で選んだ行の位置がずれただけではスクロールしない——人が流して読んでいる表を引き戻さないため。

### リストの更新

表は**リストの更新**——開く・絞り込みを変える（状態の札・ドロップダウンの値のオン・オフ）・並べ替える（列の見出し）・入力を変える——のときだけ、今の絞り込みと並びで組み直す。更新と更新の間は行の並びを保ち、絞り込みと入力に合わなくなった行（space や右の欄で完了にした・agent が値を変えた）は、完了の行と同じく暗くして次の更新まで同じ場所に残す。暗くなる・戻るときはフェードする（視差効果を減らす設定では一瞬）。行が人の知らない瞬間に消えたり動いたりすると、次のクリックや space が別のタスクに当たり、何をしたかを見返して取り消すこともできないため。

- 暗い行も普通の行と同じに選べ、操作できる。印や文字は足さない——外れた理由は行の札と列の値にそのまま見えている。
- 並びも次の更新まで保つ。状態・優先度・期限などで並べていて値が変わっても行は動かないので、並べている列の見出しの矢印と実際の並びは次の更新までずれうる。
- 新しく絞り込みと入力に合うようになったタスク（agent が足した・合うように変えた）は、並びの規則で入る位置に差し込む（既定の並びなら、足したタスクは先頭）。打って足したタスク・GitHub タブの「タスクへ移る」・メニューバーのピルで移ったタスクは、合わなくても同じ規則の位置に入れて選ぶ。消えたタスク（⌘⌫・agent の削除）は行ごと抜ける。
- タブの行き来・右の欄への出入り・メニューの開閉は更新に数えない。閉じて開き直すのは数える。
- 絞り込みと並びはタスクのタブと選ぶ状態（下記）で共有するので、選ぶ状態で札や見出しを押すと、抜けた後のタスクのタブの表も新しい絞り込みと並びで組み直されている。タスクのタブの選択は、選んでいた行が組み直した表に残ればそのまま、無ければ先頭の行——同じ位置に来た関係のない行を、気付かないまま space で完了にしないため。
- 件数（状態の札・タブの「タスク N」）は表に依らず全件で数えるので、すぐ変わる。

### 絞り込みの行

「状態」の小見出し・状態の札 4 つ（「未着手 N」「進行中 N」「待ち N」「完了 N」）・区切り・ドロップダウン 3 つ（「workspace」「優先度」「期限」）を並べ、幅に収まらなければ折り返す。札は押してオン・オフし、ドロップダウンは押してメニューを開く。どれも焦点は取らない。

- **種類の中は「または」、種類どうしは「かつ」、何もオンにしていない種類は全件**。開いた直後は、状態の札は完了だけ外れていて（完了のタスクは出ない）、ほかの種類は全件。
- **状態の札**の件数は、全タスクを表に出す状態で数える（ほかの絞り込みと入力には左右されない）。オンの札は accent の地と枠。
- **ドロップダウン**は、押すとその直下にメニューを開く。メニューは値ごとに 1 行で、チェックの印と名前を出し、行のクリックで値をオン・オフする（メニューは開いたまま。続けて複数をオンにできる）。開いている間、メニューは開いた時点の位置から動かない——オンにした値で表記が伸びてドロップダウンが次の行へ折り返しても、メニューは同じ場所に残り、続けて押す値の上にある。閉じて開き直すと、その時点のドロップダウンの直下に開く。メニューはカードの下端の手前までの高さに収め、収まらない値はメニューの中をスクロールして選ぶ（workspace が多いとき）。値は workspace が「なし」とサイドバーの順の各 workspace、優先度が高・中・低、期限が「期限切れ・今日・7 日以内・それより先・期限なし」（今日との暦日の差だけで決まる）。workspace の参照が解決できないタスク（削除された workspace）は「なし」に当たる。ドロップダウンの表記は、何もオンにしていなければ「workspace」、1 つなら「workspace: orbe」、複数なら「workspace: 2」。
- **メニューを閉じるのは**、メニューの外のクリック（下へは届かず、閉じるだけ）・esc（画面より先にメニューを閉じる）・右の欄へ入る・タブを替える・選ぶ状態に入る / 出るとき。↑↓・↵・space・打鍵では閉じず、キーは今までどおり表に効く——メニューはマウスで値を選ぶ場所で、焦点は入力欄に残る。
- **人が絞り込みを変えると、表を組み直して先頭の行を選ぶ**（入力を変えたときと同じ）。暗い行も消える——外したはずの行が残って見えると、絞り込みが効いていないように見えるため。

### 表

列は 状態・件名・優先度・期限・workspace・作成。件名だけが左揃えで残りの幅を取り、ほかの列は固定幅で見出しも中身も中央揃え。見出しは行の中身と同じ幅に揃える——スクロールバーが場所を取る設定で行があふれても、見出しと列がずれない。

- **並び**は既定で作成の新しい順（[タスク](../platform/tasks.md#一覧の並び)の並び）。列の見出しを押すとその列で並び、もう一度押すと逆になる。別の列へ移るとその列の既定の向き（期限は近い順、優先度は高 → 低、状態は進行中 → 待ち → 未着手 → 完了、件名と workspace は昇順）。並べている列は見出しの文字を濃くし、向きの矢印（既定の向きは ↓、逆は ↑）を添える。値の無いもの（期限なし・workspace なし）は向きに関係なく末尾。同じ値どうしは作成の新しい順。並びを変えても選択は同一性で保ち、その行を見える所へスクロールする。選んでいた行が組み直しで消えたら（暗かった行）、先頭の行を選ぶ——並びが変わった後の同じ位置は関係のない行で、次の space がそこに当たるため。見出しは焦点を取らない。
- **状態**: 同じ幅の札で「未着手」「進行中」「待ち」「完了」。札の幅は、今の UI 言語の状態の名前のうち最も長いものが省略されずに収まる幅で、UI 言語を切り替えると測り直す。表に出す状態は完了 → 待ち → 進行中 → 未着手 の順に決まる（待ちはステータスと独立した属性なので、完了以外で優先する）。状態の札・状態の絞り込み・札の件数・状態の列の並べ替えは、どれもこの 1 つの状態を使う。未着手と完了は中立の地、進行中は作業中の色、待ちは待ちの色。札のクリックで完了 ⇄ 未着手。
- **件名**: 主の結び付きがあれば「#番号」（保存した結び付きだけで決まり、GitHub の値の有無に依らず出る）、タイトル、「レビュー」（主が PR で、その作成者が gh で認証している自分と違えば。値か自分の login が無ければ出さない）、PR の札、補足の順。縮むのはタイトルが先だが、タイトルは日本語で 8 文字前後の最小幅を下回らない（件名の列そのものがそれより狭ければ列の幅まで）——件名で最も大事なのはタイトルで、札に押されて消えてはいけないため。それより狭くなるときは、続く札を「レビュー」→ PR の札 → 起きたことの札 → agent の補足の順にまるごと外す（途中で切った札は読めないため。今動いている agent を最後まで残す）。待ちの理由は外さず、残りの幅で末尾を省略する。主の番号は縮めない。タイトルは収まらなければ末尾を省略し、ほかの列を押し出さない。
  - **PR の札**: 主が Issue で PR も結び付いていれば、最初の PR を「<PR の印> #213 レビュー待ち ✓」で出す。状態はマージ済み > 閉じた > 下書き > レビュー状態（レビュー待ち・承認済み・修正依頼。無ければ出さない）の順に強いものを 1 つ、CI は成功 ✓・失敗 ✗・進行中 ⋯（マージ済み・閉じた PR では出さない）。値が無い・実体が PR でなければ「#213」だけ。
  - **補足**: 待ちなら「理由 · N日」（日数は待ち始めた日から今日までの暦日の差で、0 日は「今日」）。[待ちの条件](../platform/tasks.md)で待ちが解けたタスクは「<起きたこと> N分前」（期限なら「期限が来た N分前」）を強調色のカプセルで出し、経過は 1 分ごとに描き直す。起きたことは確認の出力の 1 行目（最大 4 KB）なので、1 行で、上限幅を超えれば末尾を省略する。タスクの worktree で agent が作業中なら「◌ claude 12分」（青）、入力待ちなら「▪ claude 入力待ち」（黄）（下記「agent の状態」）。
- **優先度**: 「高」「中」「低」。高は赤、低は沈め、低いタスクはタイトルも一段沈める。
- **期限**: 「10/6 月」。今年でなければ年も付ける。曜日は UI 言語に合わせる。列の幅は、年の付いた最も長い期限（どの UI 言語でも最も幅のある曜日名まで）が収まる幅。
- **workspace**: 名前だけ（どの workspace も同じ字）。なしは空。
- **作成**: 「10/10」（今年でなければ年も付ける）。補足の色。列の幅は、年の付いた日付が収まる幅。

完了のタスクの行と、絞り込みと入力に合わない行（上記「リストの更新」）は暗く出す。暗さは行の中身だけに掛け、選んでいる行でも選択の地は普段の濃さのまま——space で完了にした結果を、選んだまま確かめられるように。

## 入力・行き先・絞り込み

打つとタイトルの部分一致（大文字小文字・濁点などを区別しない）で表が絞られ（絞り込みの行の条件とも「かつ」）、入力欄の右端に「↵ タスクに追加」「⌘↵ agent に任せる」が出る。

打った文の行き先は、選択の同一性の 1 つ（**入力の行き先**）として持ち、表の行は持たない。打ち始めると入力の行き先が選ばれ、選ばれている間は「↵」の鍵が accent の枠で光る。↓ で一致するタスクへ移れる（光りは消える）。行き先を切り替える状態は持たない——キーが 2 つあるだけなので、開き直しても ↵ はいつもタスクに足す。入力の行き先を選んでいる間は右の欄を出さず、表を広く使う。フッターは左に「↵「<タイトル>」を <workspace> のタスクに足す」（足すタスクの workspace が決まらなければ「↵「<タイトル>」をタスクに足す」。タイトルは強調せず、地の語と同じ字で「」に囲む）、右に「⌘↵ agent に任せる」「↓ 一致する項目へ」（一致するタスクがあるとき）「⇥ タブ」「esc 閉じる」。

- **↵ でタスクに足す**: 中の優先度の未着手のタスクを足し、入力を空にして（リストの更新）、足したタスクを選ぶ（絞り込みに合わなければ暗い行として表に入れる。上記「リストの更新」）。画面は開いたままなので続けて足せる。足したタスクの workspace は絞り込みで決まる——絞り込みの workspace がちょうど 1 つ（「なし」以外）ならその workspace、そうでなければ workspace なし（右の欄で変えられる）。開いた直後は workspace を絞っていないので、workspace なしになる。
- **足した直後**: 右の欄の見出しが「タスク · 今 ⌘⇧X から足した」になる。そのタスクを選んでいる間、フッターの左は「→ 期限などを詰める」。
- **⌘↵ で agent に任せる**: 打った文を agent に任せる（下記「agent に任せる」）。タスクは増えない。

入力欄の中の 2 つはクリックでも効く（「タスクに追加」は ↵、「agent に任せる」は ⌘↵ と同じ）。

**↵ はいつも選ばれている行の操作**: 入力の行き先ならタスクに足す、タスクの行なら完了 ⇄ 未着手。文字があるときに ↓ で一致したタスクを選んで ↵ を押せば、そのタスクが完了になる。↵ は入力欄の確定で受けるので、日本語入力の変換を確定する ↵ では発火しない。

## 一覧のキー

| キー | 動き |
|---|---|
| ↑↓ / ⌘↑↓ | 選択を動かす（端で巡回）/ 先頭・末尾へ |
| space | 入力欄が空のときだけ、選んだタスクを完了 ⇄ 未着手。文字があるときは空白を打つ |
| ⌘⌫ | 入力欄が空のときだけ、選んだタスクを確認なしで消す（取り消しは無い）。文字があるときは行頭まで消す |
| → | タスクの行を選んでいれば右の欄へ |
| ⌘↵ | 入力の行き先なら agent に任せる、タスクの行なら agent を開く（下記） |
| ⇥ / ⇧⇥ | 次 / 前のタブ（タスク → GitHub → 提案 → タスクと巡る）。タブを行き来しても、それぞれの入力・選んだ行は残る |
| esc | 閉じる（絞り込みのメニューが開いていれば、まずメニューだけを閉じる） |

- **⇥ / ⇧⇥ は画面全体のキー**で、一覧だけでなく、右の欄・GitHub タブの右の欄・提案タブの棚と中身でも次 / 前のタブへ移る。効かないのは文字の編集中（焦点は編集欄に留まる）と選ぶ状態だけ。タブは画面全体のものなので、焦点の深さで効いたり効かなかったりすると、今どこに居るかを考えないとタブを替えられないため。右の欄から移ると、戻ってきたときは一覧に居る（選んだ行は残る）。
- **押し続けたキーリピートは、押し始めた場所でだけ効く**。キーで居場所が移ると（esc で一段戻る・→ で右の欄へ入る・↵ で編集を始める）、続くリピートは移った先の場所のキーにならず、焦点の持ち主へ流れる——esc を押し続けても一段戻るだけで画面は閉じず、→ を押し続けても入った先の値は動かない。編集を始めた欄では文字入力として届く（詳細の ↵ を押し続けると、編集を始めた後のリピートは改行）。⇥ / ⇧⇥ は画面全体のキーなので、押し続けるとタブを巡り続ける。

- **空のときだけ効く単キー**は、文字入力と衝突させないため。日本語入力の変換中は、空の入力欄でも space を変換に使わせ、画面のキーとしては受けない。space・⌘⌫・↵ は押した瞬間だけを操作にし、押し続けたキーリピートは捨てる——space や ↵ を押し続けて下の行が次々に完了にならないため、入力を消そうと ⌘⌫ を押し続けて空になった瞬間に、続くリピートでタスクが消えないため。
- space（↵・状態の札のクリックも同じ）で完了 ⇄ 未着手にしても、行は表の同じ場所に残り、選択もそのタスクに留まる——もう一度押せば取り消せる。続けて片付けるときは ↓ を挟む。⌘⌫ で消したときは行が抜けるので、同じ位置の行が選ばれる。選んでいない行の状態の札のクリックでは、選択は動かない。
- マウス: 行のクリックで選ぶ。札のクリックでタブ・絞り込みを切り替え、列の見出しのクリックで並べ替える。ホバーの選択追従は他のパレットと同じ入力モダリティの規約に従う（[workspace パレット](workspace.md)）。カード内のどこをクリックしても、焦点はモデルが決めた行き先へ当て直される。

## agent に任せる・agent を開く（⌘↵）

⌘↵ は、選んでいるものに合わせて agent へ渡す。押した瞬間だけを受け、キーリピートは捨てる。日本語入力の変換中は変換に渡す。

- **入力の行き先**を選んでいれば、打った文を [秘書](../agent/secretary.md)に頼む（agent に任せる）。Home に claude が 1 つ起き、画面は閉じて Home のそのタブへ移る。claude は打った文を依頼として受け、タスクを足す。受けたら入力欄を空にする。
- **タスクの行**を選んでいれば（一覧でも、右の欄で編集していないときでも）、そのタスクの agent を開く——そのタスクのための [⌘T 画面](worktree.md)（worktree を選んで agent を開く画面）に差し替える。解けた待ちで続きから始められるなら、⌘T 画面を開かずに続きから始める（下記「解けた待ちの ⌘↵」）。完了したタスクでも開ける（↵ で進行中に戻る）。
- GitHub タブの ⌘↵ は「タスクにして開く」——結び付いていない行はタスクにしてから、結び付いている行はそのタスクで、agent を開く（下記「GitHub タブ」）。
- 選ぶ状態では何もしない。
- 開いた ⌘T 画面の札・先頭の欄・↵ でタスクに起きること・Home のタスクの基点は [worktree パレット](worktree.md#タスクから開く)が持つ。

agent に任せられないときは、打った文を残してフッターに赤で理由を出す——claude が検出されていなければ「claude が見つからないので agent に任せられない」、Home にタブを起こせなければ「agent を起動できなかった」。空白・制御文字だけの文は黙って受けない。

## 右の欄

選んでいるのがタスクの行のときだけ、そのタスクを出す。上から見出し（主の結び付きがあれば「⊙ orbe#212」。owner は出さない。無ければ「タスク」、今足したタスクなら「タスク · 今 ⌘⇧X から足した」）・タイトル・会話の行 / 起きたことの箱 / agent の場所・「Issue・PR」の欄（結び付きが無くても出る）・ステータス・待ち（＋条件の箱）・優先度・期限・workspace・作成・詳細。

- **ステータス**は「未着手」「進行中」「完了」の 3 つの札。ストアのステータスを出すので、待ちのタスクでも元のステータスが選ばれている。
- **workspace** は、開いた workspace なら accent の札、ほかの workspace なら名前だけ、なしなら空。
- **作成**は「10/10 · あなた」（agent が足したなら「10/10 · claude」）。日付は期限と同じく、今年でなければ年も付ける。

**agent の場所**は、タスクの worktree に agent が居れば状態を問わず出す（完了・休止を含む）: 「claude が取り掛かっている」（入力待ちなら「claude が入力を待っている」、完了なら「claude が応答を終えた」、休止なら「claude が次の指示を待っている」）と、その下に「working 12分 · タブ <タブ名>」、右に「↗ タブへ」。↑↓ で止まる場所で、↵ かクリックでそのタブ（別の workspace ならそこへ切り替えて）へ移り、画面を閉じる。フッターは「↵ <タブ名> へ移る」。

**待ちの条件**（[タスク](../platform/tasks.md)）は右の欄の 3 か所に出る。値はどれも画面から変えられない——変えたいときは AI に頼み直し、人ができるのは待ちの「解除」（待ちと条件を外す。以後コマンドは走らない）だけ。

- **会話の行**（待っている間・条件に会話が付いているとき）: agent の場所の位置に 1 行で「claude 2日前の会話」と、その会話のタブが今あれば続けて「· タブ <タブ名>」、右に「↗ タブへ」（0 日は「今日の会話」）。タブがあるときだけ ↑↓ で止まる場所になり、↵ かクリックでそのタブへ移る（agent の場所と同じ。フッターは「↵ <タブ名> へ移る」）。同じタブを指す agent の場所は出さない（同じタブへの ↗ が 2 つ並ばないように）。会話のタブは、休眠のタブを含め、セッション ID でタブを引く窓の索引から決まる。同じ会話が生きたタブと休眠のタブの両方にあれば、生きたタブを取る（人が同じ会話を手で再開したとき、動いている方へ移る）。
- **条件の箱**（待っている間）: 待ちの項目の直下に「条件」（説明）・「確認」（「10 分ごと · 次は 7 分後」。次の時刻は番人と同じ関数で数え、過ぎていれば「まもなく」、期限までにもう確かめないなら「10 分ごと · 期限まで確認なし」。1 分ごとに描き直す）・「期限」（「10/6（月）9:00 には必ず解く」）と、開閉する「› 確認のコマンド」（開くと実際のコマンドの全文）・「› 実行の記録 N」（開くと新しい順に「時刻 · 結果 · 標準出力〔無ければ標準エラー〕の先頭」）。開閉する 2 つは ↑↓ で止まる場所で、↵ かクリックで開閉する（フッターは「↵ 確認のコマンドを開く／閉じる」「↵ 実行の記録を開く／閉じる」）。開閉の状態は画面が持ち、別のタスクを選ぶと閉じる。
- **起きたことの箱**（解けた後）: agent の場所の位置に「● <起きたこと> N分前 · 確認 N 回目」（期限なら「● 期限が来た …」）、満たしたときは確認の標準出力の 2 行目以降、会話があれば「⌘↵ claude で続きから」のボタン（クリックでも同じ）と「2日前の会話に、起きたことを添えて」。会話があっても続きから始められなければ、ボタンの代わりに「続きから始められない: <理由>」。欄が狭くて 1 行に収まらなければ「N分前 · 確認 N 回目」を折り返す。待ちの項目は空（「＋ 理由を入れる」）。

**「Issue・PR」の欄**は各項目を 1 行ずつ並べ、末尾に「＋ 結び付ける」（右に「ブランチの PR は自動」）を置く。「＋ 結び付ける」は結び付きが 0 件でも出て、↑↓ で止まる場所で、↵ かクリックで GitHub タブの項目を選ぶ状態に入る（下記「選ぶ状態」。フッターは「↵ Issue・PR を選んで結び付ける」）。項目の行は、印（保存した種別）・番号（主とリポジトリが違う行は「<リポジトリ名>#番号」）・タイトル・右に状態（Issue は open / closed、PR は「✓ CI · レビュー待ち」「マージ済み」「閉じた」など）を出す。GitHub の値が無い・実体の種別が保存した種別と違うときは、タイトルと状態を出さず番号だけにする。行は ↑↓ で止まる場所で、↵ でその項目の GitHub のページをブラウザで開き、⌫ でその結び付きを外す（外すのは 1 件だけ——押し続けたキーリピートで、焦点が移った先の項目まで外さない）。クリックでも開け、ホバーか選択で出る「外す」のクリックでも外せる。フッターは「↵ #213 を GitHub で開く」と「⌫ 外す · ↑↓ 項目 · ⇥ タブ · esc 一覧へ」。

→ で右の欄に入るとステータスに居る。↑↓ で項目（タイトル → 会話の行 → agent の場所 → 各結び付き → ＋ 結び付ける → ステータス → 待ち → 確認のコマンド → 実行の記録 → … → 詳細）を移り、←→ で選択式の値を変える（ステータスは未着手 / 進行中 / 完了、優先度は高 / 中 / 低で、どちらも端で止まる。workspace は「なし」とサイドバーの順の各 workspace を巡回）。完了にして絞り込みに合わなくなっても、行は暗くなって表の同じ場所に残り（上記「リストの更新」）、右の欄に居たまま次の ← で戻せる。完了にするとストアが待ちを外す（[タスク](../platform/tasks.md)の不変条件）ので、ステータスは一周させず（未着手の ← で完了に入らない）、←→ を押し続けたキーリピートでも動かさない。選択式でない項目の ← と esc、ヘッダーの入力欄のクリックは一覧へ戻り、焦点は入力欄へ移る（編集中なら確定してから戻る）。右の欄でも space・⌘⌫ はそのタスクに効く。space の後は右の欄に居たまま、⌘⌫ の後は一覧に戻って同じ位置の行を選ぶ。

**文字の項目**（タイトル・待ちの理由・期限・詳細）は ↵（かクリック）で編集を始める。1 行の項目（タイトル・待ちの理由・期限）は ↵ か ⌘↵ で確定、esc で取り消す。詳細は複数行なので ↵ は改行で、**esc で確定する**（⌘↵ では何も起きない）——↵ が改行に使われる複数行の欄では、編集を抜けるキーが esc しかないため。詳細には取り消しのキーが無く、打ち間違えたら打ち直して戻す。確定すると詳細の項目に居たまま編集が終わり、もう一度の esc で一覧へ戻る。編集中の ⇥ / ⇧⇥ は何もしない（タブは替わらず、焦点も編集中の文字も欄に残り、詳細にタブ文字は入らない）。フッターは編集中の欄に合わせて、1 行の項目なら左に「↵ 確定」・右に「esc 取り消し」、詳細なら左に「esc 確定」だけを出す。↵ を押し続けても、押した瞬間に編集を始めるだけで、続くキーリピートでは確定しない（編集のまま。詳細ではリピートも改行）——入力欄の確定はどれも、キーリピートを入口で捨てる。

- タイトルを空で確定すると、エラーにせず取り消しとして扱う。
- 待ちの理由と期限は、空で確定すると外れる。値がある間は「解除」のクリックでも外れる。完了のタスクには待ちを入れられない（[タスク](../platform/tasks.md)の不変条件）ので、待ちの項目は操作できない見た目になり、フッターにも ↵ の案内を出さない。
- 期限は「10/6」（今日以降で最も近いその日）と「2026-10-06」を受ける。読めなければ理由をフッターに赤で出し、編集を続ける。
- ストアが値を受け付けないときは、何をしようとしたかに応じた文をフッターに赤で出す（ストアのエラーの文は読まない）。

**編集中の文字は、1 行の項目の esc 以外では失わない。** 別の行や項目のクリック、タブ・絞り込み・並びの切り替え、画面を閉じる、別の画面への差し替え（⌘⌘）、アプリの終了のどれでも、打った内容は確定して残る（確定できない期限は、編集を続ける場所が無いので捨て、理由だけを残す）。詳細は 1 打鍵ごとには保存しない。

## agent の変更への追従と選択

選択は行の位置ではなく**同一性**（入力の行き先 / タスクの ID）で持つ。タスクが変わるたび（agent の変更を含む）に、同一性が今の行にあればそのまま、無ければ最後に居た位置の行（末尾で頭打ち）へ移す。タブが変わったときも同じ規則で選び直す（並べ替えたときは上記「表」）。だから agent が上にタスクを足しても、選んでいるタスクは変わらず、直後の space や ⌘⌫ が別のタスクに当たらない。

表の行はリストの更新のときだけ組み直す（上記「リストの更新」）ので、選択を動かしても表の行は変わらない。暗い行を ↓ で離れた直後の space・⌘⌫ も、離れた先の行に効く。

- 選んでいたタスクが消えたら、同じ位置の行が選ばれる。
- 右の欄に居る間に、そのタスクが消えたら一覧へ戻る。編集中のタスクが消えたら、編集は取り消される。
- 画面の操作がストアに届く前に agent がそのタスクを消していたら、エラーは出さずに上の規則で選択を移す。
- 右の欄の結び付きの行に居る焦点も、位置ではなく項目の同一性で持つ。agent が結び付きを変えても別の項目へずれず、焦点の結び付きが外れたら同じ位置の止まる場所（末尾で頭打ち）へ移る。agent の場所に居る間に agent が去った（タブが閉じた・agent が終了した）ときも同じ。

開いている間の workspace の名前と並びは、**開いた時点のもの**を使う。開いている間に（agent が制御 API で）workspace を改名・削除しても、閉じて開き直すまで画面には反映されない——workspace は観測できる値ではないので、描くたびに引くと反映が他の描き直しのついでに左右されるため。開いた workspace への結び付き（右の欄の workspace の札）も開いた時点で固定する。

## 解けた待ちの ⌘↵ — 会話を続きから

待ちの条件で解け、条件に会話が記録されていて、その CLI が再開できるタスクでは、⌘↵ は worktree パレットを開かず、その会話を続きから始める。会話は記録した作業ディレクトリに結び付いていて、worktree を選ぶ余地が無いため。フッターの左は「⌘↵ <タイトル> を claude で続きから」になる。会話の無い解けたタスク（タブの外から付けた条件など）の ⌘↵ は、そのタスクのための ⌘T 画面を開く。GitHub タブの ⌘↵ も同じ口を通り、結び付いたタスクを続きから始められるなら続きから始める。その行を選んでいる間は、フッターの左も「⌘↵ <タイトル> を claude で続きから」になる。

続きから始められないとき——会話のタブが無く、CLI が見つからない・記録した作業ディレクトリが無い——も ⌘↵ はそのタスクのための ⌘T 画面を開き、タスクのタブではフッターの左に「続きから始められない: <理由>」を出す。GitHub タブでは出さない——GitHub タブの行は起きたことの箱を見せないので、人は続きから始まると思って ⌘↵ を押しておらず、そのタスクのための ⌘T 画面が開いても食い違わない。続きからが詰まって agent を開けなくなることはない。起きたことは残り、新しい待ちを付けるか完了にすると消える。

会話には、起きたことを最初の入力として届ける。入力は Orbe が UI の言語で組む: 条件の説明・解けた時刻と確認の回数（期限なら期限）・満たしたときは確認の標準出力。届け方は、その会話を今持っているタブで決まる——同じ会話が 2 つのタブで同時に動いて割れないように。生きたタブと休眠のタブの両方が同じ会話を持っていれば、生きたタブとして扱う。

- **生きたタブ**: そのタブへ移る。会話へ今貼ってよいとき（[launch](../agent/launch.md#会話へ貼ってよいタブ)——agent が完了・休止を報告し、端末の前面で止まらずに動いている）だけ、起きたことを貼り付けて Enter を押す。作業中・確認待ち・agent が前面にいない（終わった・Ctrl+Z で止めた）タブでは移るだけで送らず、起きたことも残す——人が様子を見て、もう一度 ⌘↵ を押せる。agent が去った後のシェルに、外の人が書いた文面が貼り付けられて実行される事故を防ぐ。
- **休眠のタブ**: 起こすときの再開に最初の入力を 1 度だけ添えて、そのタブへ移る。
- **タブが無い**: 記録した workspace（無ければタスクの workspace、それも無ければ今の workspace）に、記録した作業ディレクトリで会話を最初の入力付きで再開する新しいタブを開いて前面にする（[再開の組み立て](../agent/launch.md#会話の再開の組み立て)。開いた時点で会話のタブの索引に載るので、続けて同じ会話の ⌘↵ を押しても 2 つ目は開かない）。

最初の入力の制御文字（改行・タブ以外）は空白にして届ける。

送らなかったとき以外は、届けた時点で起きたことは消える。

## agent の状態

タスクの [worktree](../platform/tasks.md) で動く agent を、行の札と右の欄の agent の場所に出す。タスクの worktree とタブの連は同じ場所のキーで揃っているので、「そのタスクの worktree のタブ」はキーの等値だけで決まる（⌘T を通さずに開いたタブも、再起動後のタブも拾う）。

- **行の札は作業中と入力待ちだけ、右の欄の agent の場所と ↵ でタブへ移る先は状態を問わない**（完了・休止を含む）。札は今動いている作業を一覧で見分けるためのもので、終わった agent まで出すと一覧が札で埋まる。一方、右の欄から ↵ でタブへ移るのは agent へ移る手段なので、1 ターン終わるごと（完了→休止）にそれが消えては、結果を見に行く・続きを頼む場面で使えない。
- 同じ worktree にタブが複数あれば 1 つにまとめる。入力待ち > 作業中 > 完了 > 休止の順に優先し（タブ行のグリフを畳む順と同じ）、同じ状態なら、その状態になったのが新しい方。
- **完了したタスクには出さない**——完了の行は暗く出すもので、そこに今の作業の札が出ると、別の作業を誤って示す。worktree が確定した作業のブランチと別のブランチにいる間も出さない（[タスク](../platform/tasks.md)。ブランチを切り替えて使い回す worktree の agent は、別の作業をしている）。worktree の今のブランチと既定ブランチはタブの索引を作り直すたびに `.git` から読む（git を起こさない。detached か読めなければ絞らない）。
- 経過は、その状態になった時刻から 1 分ごとに描き直して出す（1 時間未満は分、1 日未満は時間、それ以上は日）。
- タブは観測できない値なので、窓が chrome の更新の合流点で全タブから「worktree ごとの agent」の索引を作り直し、値が変わったときだけ書く。画面はその索引を読むので、状態が変わるとすぐ追従する。
- codex・agy は終了を報告しないので、作業中のままプロセスが終わると「作業中」が残ることがある（Attention と同じ。codex の turn の中断は休止として報告される）。

## PR の自動の結び付け

開いたときに 1 回、完了していないタスクの worktree のブランチに PR があれば、そのタスクの結び付きの末尾に足す（作業のブランチが確定していればそのブランチにいる間だけ、未確定なら今のブランチで引いて確定する。規則は [タスク](../platform/tasks.md)）。足した項目は出ている行の結び付きなので、その値は下の規則で取りに行く。人が右の欄の ⌫ で外した PR は、開き直しても付け直さない。

## GitHub の値の取り方

結び付いた Issue・PR のタイトルや状態は、結び付きのリポジトリ名と番号で GitHub へ直接問い合わせて取る（gh の GraphQL。リポジトリをまたいで 1 回にまとめ、多ければ続けて分ける）。タスク画面は全 workspace をまたぎ、閉じた Issue やマージ済みの PR も出すので、開いた workspace の open な一覧からは引けないため。問い合わせ先が名前で決まるので、checkout も作業ディレクトリも要らない。

- **取りに行くのは出ている行の結び付きだけ**——表に出ているタスク（暗い行を含む）。完了したタスクは削除まで残り続けるので、保存されている結び付きを全部取ると使うほど重くなる。
- **開いたとき**に出ている行の結び付きを取り直す。**出ている行の結び付きが増えたとき**（agent が結び付けた・絞り込みや入力を変えた）は、この開いている間にまだ取りに行っていない項目だけを取る（前に答えのある項目も、開き直して初めて出たなら取り直す）。開いている間の定期的な取り直しはしない。
- 答えはメモリにだけ持ち、アプリで 1 つの置き場に置く。次に開いたときは前回の答えで先に描き、届いた分から描き直す。再起動直後は取れるまで番号だけが出る。
- **gh が無い・未認証・オフライン・時間切れのときは番号だけ**で、エラーも gh の可否も画面に出さない。取れなかった項目は次に開くまで取り直さない（打鍵のたびに gh を起こさないため）。

## GitHub タブ

⌘T と同じ基点で決まるリポジトリ（下記）の **open な Issue・PR を全部**（自分のものに限らない）出し、タスクにする・タスクに結び付ける入口にする。Issue・PR から作業を始めるのはここで、⌘T には Issue・PR の欄を持たせない。

**リポジトリは 1 つ**——[⌘T](worktree.md) と同じ基点（開いた workspace のアクティブタブの cwd、タブが 0 枚かボード選択中なら workspace の root）で gh が既定とするリポジトリ（set-default、無ければ gh の規則で upstream → origin の順）。⌘T と揃えるのは、「タスクにして開く」が一覧と同じリポジトリの ⌘T 画面を開くため（workspace の root がリポジトリでない既定の workspace でも、タブの居るリポジトリが出る）。github.com のリポジトリに限り、GitHub Enterprise のリポジトリは「見つからない」として扱う（問い合わせと書き込みは github.com へ送るので、同じ owner/name の別のリポジトリを読み書きしないため）。origin が自分の fork で upstream が本体という形では本体の一覧が出て、`gh issue list` が出すリポジトリと一致する。結び付きとの突き合わせはこのリポジトリの正式名と番号で行う（リポジトリを改名する前に保存した結び付きは一致せず、結び付いていない側に出る）。

### 一覧

区分の見出しは「Issue 24」「PR 7」（種別は太字、件数は補足の色。件数は絞り込みの札と入力を当てた後の数。当たる項目の無い区分は見出しごと出さない。両方 0 件なら「該当する Issue・PR はありません」）。取得中の区分は末尾に選べない「読み込み中…」の行を出し、当たる項目が 0 件でも見出しと読み込み中の行を残す。取得中の区分がある間は「該当する Issue・PR はありません」を出さない——「無い」と「まだ届いていない」を取り違えさせないため。

- **結び付いた行を区分の上にまとめる。** 地をうっすら塗り、右に結び付いたタスク（「🔗 #212 タスク機能の設計」。主の番号は、行のリポジトリと違えば `<リポジトリ名>#212`、主の無いタスクはタイトルだけ）を出す。結び付いた行は隠さない。
- **結び付いていない行は更新の新しい順に先頭 5 件**を出し、残りは「↓ さらに N 件」の行にまとめる。↵ かクリックでその区分の残りを全部出し、閉じるまで保つ。
- 行は印（Issue / PR）・「#番号」・タイトル・自分との関係の文。関係の文は PR なら「レビュー依頼 · あなた宛」（個人宛の依頼が自分）→「レビュー依頼 · @org/team 宛」（チーム宛だけで自分に頼まれている）→「作成者: あなた」→「@作成者」の順、Issue なら「担当: あなた」→「担当なし」→「@先頭の担当者」。
- 開いた直後は先頭の選べる行を選ぶ。

**絞り込みの札**は「担当が自分 N」「作成者が自分 N」「レビュー依頼 N」で、クリックでオン・オフする。何もオンにしていなければ全件、オンにしていればオンの札のどれかに当たる項目を出す。札を変えると先頭の行を選ぶ。札の行の右端に、リポジトリの印とリポジトリ名（owner を除く）を 1 回だけ出す。件数は一覧の全件で数え、入力に左右されない。「レビュー依頼」はチーム宛（自分の所属する入れ子のチームを含む）も入る——判定を GitHub の検索 `review-requested:@me` に任せ、チームの所属を手元で二重に持たない。自分の login がまだ分からない間は、札に件数を出さず、自分に関わる札では何も出さない。入力はタイトルの部分一致（タスクの絞り込みと同じ正規化）か番号（`#` の有無を問わず前方一致）で絞る。

### 右の欄

選んだ項目の見出し（「⊙ orbe#221 · 今日」。Issue は更新日、PR は CI とレビュー状態）・タイトル・関係の文に続けて:

- **結び付いていない行**: 「自分をアサインする — GitHub の担当者に自分を追加する」のチェック（既定オン）・優先度（既定は中）・期限（既定なし）、「↵ タスクにする」「⌘↵ タスクにして開く」のボタン（欄が狭く横に並びきらなければ縦に積む）、「⌘L 既存のタスクに結び付ける」。チーム宛だけでレビューを頼まれている PR では、チェックは「自分をレビュアーにする」になる。自分が作成者・既に担当・個人宛にレビュー依頼済みの項目、自分の login がまだ分からないとき、チーム宛のレビュー依頼がある PR で自分へのレビュー依頼がまだ分からない（取得中・取得に失敗した）ときは、チェックを出さない（足すものが無い・誰を足すか決まらない）。
- **結び付いている行**: 「結び付いているタスク」の箱（状態のアイコン・主の番号とタイトル・「進行中 · claude 作業中 12分」。agent の札はタスクのタブの行と同じく作業中・入力待ちだけ）と、「↵ #212 を開く」「⌘L 別のタスクに付け替える」「⌘⌫ 結び付けを外す」のボタン。

右の欄の値は画面の値で、ストアには「タスクにする」で初めて書く。**選択の同一性が変わると既定に戻る**（agent の変更で同じ行のままなら、打った値を保つ）。右の欄に居る間に選んだ項目が一覧から消えて選択が別の行へ移ったとき（取り直し・agent の変更）は、一覧へ戻る——別の項目の欄に既定の値で居続けると、↵ で見ていない項目をタスクにして自分を足してしまう。→（結び付いていない行で）で欄の先頭に入り、↑↓ で止まる場所（チェック → 優先度 → 期限）を移り、space でチェック、←→ で優先度、↵ で期限を打つ（「10/6」「2026-10-06」）。esc か優先度以外での ← で一覧へ戻る。欄の中でも ↵（期限以外）・⌘↵・⌘L・⌘O は、行の「タスクにする」「タスクにして開く」「結び付ける」「ブラウザで開く」と同じ。期限を打っている間の ⌘↵ は打った期限の確定で、タスクは作らない。期限の打ちかけはタスクの 1 行の項目の編集と同じく esc 以外では失わず、読めない文字のまま「タスクにする」を押すと、作らずに理由を赤で出して編集を続ける。

### 操作

| キー | 結び付いていない行 | 結び付いている行 |
|---|---|---|
| ↵ | タスクにする | タスクのタブのそのタスクへ移る |
| ⌘↵ | タスクにしてから、そのタスクの agent を開く | そのタスクの agent を開く |
| ⌘L | 結び付けるタスクを選ぶ（選ぶ状態） | 付け替える先のタスクを選ぶ（選ぶ状態） |
| ⌘⌫ | — | 結び付けを外す（行は結び付いていない側へ戻り、選択はその行に残る） |
| ⌘O | GitHub のページをブラウザで開く | 同左 |
| → | 右の欄へ | — |

↑↓ / ⌘↑↓ は選択（端で巡回 / 先頭・末尾）、⇥ / ⇧⇥ は次 / 前のタブ、esc は閉じる。⌘L・⌘⌫・⌘↵・⌘O は修飾付きのキーなので、入力欄の文字の有無を問わず効く（絞り込みの文字を打つ・消すのと衝突させない）。↵・⌘L・⌘⌫・⌘↵・⌘O は押した瞬間だけを操作にし、押し続けたキーリピートは捨てる（選択が移った先の行まで操作しない。「さらに」で ↵ を押し続けて、開いた区分の見ていない項目をタスクにしない）。日本語入力の変換中は受けない。

- **タスクにする**: 開いた workspace に付いた未着手のタスクを足す。タイトルは項目のタイトル、優先度と期限は右の欄の値、主の結び付きがその項目。行は結び付いた行として区分の上へ移り、選択はその行を追う。GitHub タブに留まる。結び付きと一緒に 1 回で足すので、間に agent がその項目を結び付けていれば拒否され、「結び付けられませんでした」を出す。
- **自分を GitHub に足す**: チェックがオンなら、タスクを足した後に**裏で**、自分を担当者（レビュアー）に足す——ローカルの操作を GitHub の往復で待たせない。書き込む項目は押した瞬間の項目。成否は GitHub の応答に自分が入っているかで決める（push 権限が無いと、GitHub はアサインを黙って無視して成功を返す）。成功すれば応答の値でその 1 件だけを一覧に差し込み、関係の文が「担当: あなた」に変わる（一覧の全量の取り直しを待たない）。失敗してもタスクは残し（取り消さない）、フッターに赤で出し、その項目の右の欄にも赤で出す。失敗の記録は画面の寿命に依らず、次にその項目を選んだときにも見え（タスクにして開いて閉じた後の失敗も、次に開いたときに見える）、次に試すか成功すれば消える。記録はメモリにだけ持ち、再起動で消える。
- **タスクへ移る**: タスクのタブへ移ってそのタスクを選ぶ。絞り込みと入力は変えず、合わなくても表に入れて選ぶ（上記「リストの更新」）。
- 開いている間に agent が結び付きを変えると、並びと右の欄がすぐ追従し、選んだ行は同一性（リポジトリと番号）で保たれる。選んだ行が一覧に残ったまま「さらに」の内側に隠れたとき（⌘⌫ や agent が結び付きを外した・タスクを消した、一覧の後続のページで上位 5 件が入れ替わった）は、その区分を開いて選んだ行を見せる——隠れたままだと選択が同じ位置の別の項目へ移り、↵ で見ていない項目をタスクにしてしまう。

### 選ぶ状態

結び付ける相手を選ぶ一時的な状態。2 つの方向があり、**どちらも自分の入力と選択を持つ**——相手のタブの一覧を借りないので、抜けたときに元のタブの絞り込みと選んだ行がそのまま残る。入るときは空の入力・先頭の行から始まる。上に何を選んでいるかの帯が出る。

- **タスクを選ぶ**（GitHub タブの ⌘L から）: タスクのタブの行で選ぶ。帯は「#221 … を結び付けるタスクを選ぶ」。↵ でそのタスクの結び付きの末尾に付け（結び付いていた項目なら前のタスクから外す）、GitHub タブへ戻ってその行を選ぶ。入力欄のキーの案内は出さず（入力の行き先を持たない）、space（空の入力欄では何もせず、空白も入れない）・⌘⌫・⌘↵・→・⇥・⇧⇥・行の状態の札のクリック・右の欄の操作は効かない。絞り込みの行と並べ替えは効く（絞り込みと並びはタスクのタブと共有するので、抜けた後のタスクのタブの表も組み直されている）。選ぶ状態の表は空から自分で組み、抜けるとタスクのタブの表が戻る。
- **項目を選ぶ**（右の欄の「＋ 結び付ける」から）: GitHub タブの行で選ぶ。帯は「#212 … に結び付ける Issue・PR を選ぶ」。↵ でそのタスクの結び付きの末尾に付けて右の欄へ戻り、焦点はその結び付きの行に居る。⌘L・⌘⌫・⌘↵・⌘O・→・⇥・⇧⇥ は効かず、右の欄は見出しと結び付いたタスクだけを出す。絞り込みの札のクリックと「さらに」は効く（絞り込みと開いた区分は GitHub タブと共有する）。
- 選んだ相手が既にその項目を持っていれば、↵ は何もしない（フッターが「#221 は『…』に結び付いている」と言う）。別のタスクが持っていれば、フッターが付け替えを先に言う（「#221 を <前のタスク> から『…』へ付け替える」）。
- esc は何も変えずに、入る前の場所（GitHub タブ・右の欄の「＋ 結び付ける」）へ戻る。対象の項目が一覧から消えた・対象のタスクが消えた（agent の削除）ときも、選ぶ状態を終えて戻る。
- **付け替えは 1 回の変更**——前のタスクから外し、選んだタスクの末尾に足し、1 回だけ保存する（[タスク](../platform/tasks.md)）。2 回に分けると、間に読んだ agent に「どこにも付いていない」状態が見え、後の 1 回が拒否されると外れただけで残る。

### 使えないとき

理由を GitHub タブの本体に 1 行で出し、タスクのタブは変えない（タスクのタブは今までどおり gh の可否を出さない）。

- gh が無い・gh が認証されていない・GitHub のリポジトリが見つからない（オフラインを含む。区別しない）
- 前回の一覧が無いまま取得に失敗した（「Issue・PR を取得できませんでした」）
- 前回の一覧が無く、取得中なら「Issue・PR を読み込み中…」

**前回の一覧があれば、解決や取り直しが失敗していてもそれを描いたまま出す**（困るのは初回だけ）。

### 一覧の取り方

- 開くたびに（タスクのタブを開いていても。ヘッダーの「GitHub N」のため）root のリポジトリを解決し直し、Issue・PR の一覧と「自分の login・レビュー依頼」を取り直す。どれも前回の答えで先に描き、届いた分から描き直す。解決の答えは root ごとに覚え、新しい答えが前回と違えば新しい名前の一覧に切り替える。
- 一覧は作成の新しい順にページ送りで取り、Issue は 1000 件・PR は 500 件まで（上限を超える古い項目は出ず、札の件数も取れた範囲で数える）。1 ページは Issue 100 件・PR 50 件——PR はレビュー状態・CI・レビュー依頼の欄で重く、GitHub が問い合わせを打ち切る 10 秒に収めるため。表示は更新の新しい順に並べ直す——更新の順でページ送りすると、取っている間に更新された項目がページをまたいで動き、重複や取りこぼしが出る。レビュー依頼は検索の先頭 100 件まで。
- 一覧はアプリで 1 つの置き場にリポジトリ単位で持ち、画面は写さずに読む。同じリポジトリ・同じ種別の取得は常に 1 本で、開き直しても取得中なら合流する。取得は画面より長生きし、閉じても上限まで続く。取り直しの途中は、届いた範囲の後ろを前回の一覧の残りで埋め（一覧が縮んでまた伸びない）、取り終えたら今回の分に置き換え、途中で失敗したらそれまでの一覧を据え置く。自分を足した結果の差し込みは、取得中に届く古いページにも当てる（差し込んだ値が古いページで消えない）。
- 答えはメモリにだけ持つ。

## 開閉

待ちの条件が解けたときのメニューバーのピル（→ [menubar](../chrome/menubar.md)）のクリックでも開く。このときは Orbe を前に出し、そのタスクを選んだ状態で開く（開いていれば、そのまま選び直す。選ぶ状態ならやめる）。絞り込みや入力に合わなくても、GitHub タブの「タスクへ移る」と同じく表に入れて選ぶ。言語選択・オンボーディング・更新内容の画面が出ている間は開かない。

開いている間の ⌘⇧X は、ほかのパレットと同じく何もしない（パレット表示中は window のコマンドが効かない）。閉じるのは esc（一覧に居るとき。選ぶ状態ならやめる）・scrim のクリック。開くたびに状態は初めから（タブは「タスク」、タスクの絞り込みは完了だけを外した状態、並びは作成の新しい順、GitHub の絞り込みの札は何もオンにしない、右の欄は既定、先頭の行を選ぶ）。
