# Dispatch パレット（⌘⇧X）

worktree・ブランチ・GitHub Issue・PR から作業を開始するためのコマンドパレット。ディレクトリを準備してからエージェントを起動するのではなく、取り組む作業を選ぶと必要な worktree の用意からエージェント起動までがワンアクションで済む——Orbe の中心価値である「手順の簡略化」を最も濃く担う面。Cmd+Shift+X で開く（Cmd+X は奪わない）。

他パレット（[settings](settings.md)・[workspace](workspace.md)）と同じ提示経路だが、描画は共有パレット基盤を使わず専用の View／モデル／非同期データプロバイダが持つ。行の解剖と実データ供給が、共有基盤の 1 行リスト前提に載らないため。

## 器と構成

scrim ＋ ガラスパネル。上端アンカー・窓幅に追随する上限幅。カード高は窓高に束縛し、リスト部は実測内容高と上限の小さい方で定高化して超過分を内部スクロールへ回す（低窓・多件数でも末尾行・フッターに到達できる）。

カードは**一覧と [clean](#clean--worktree-の掃除) の 2 モード**を持ち、器（枠・焦点・高さの契約）は共通で中身だけが入れ替わる。掃除のために別のパレットを開かせない——同じ器の中の遷移なので、覚える近道が 1 本増えない。

一覧モードは上から:

- **ヘッダー**: `❯`＋実 `TextField`（フィルタ入力欄）＋右端に選択中の起動先チップ（`◐ <起動先> で開く`。起動先は検出 agent の raw command か素の shell）。chrome 入力欄のプレースホルダは共通モディファイアで描かれ、**フォーカス中に IME 変換がある間は非表示**になる——未確定文字は binding へ流れず空欄と区別できないため、field editor の marked text を監視して抑制する（確定・取消で空へ戻れば再表示。抑制はフォーカス欄のみ）。
- **リスト 5 セクション**: Worktrees / Local branches / Remote branches / Issues / Pull requests（見出しは選択対象外・空セクションは非表示）。Worktrees の末尾には掃除への入口となる `clean` 行が常在する（[clean](#clean--worktree-の掃除)）。行は先頭グリフ・名前・muted 補足・番号チップ（branch→open PR 相関のみ）・行末ノートで構成。issue/PR 行と、番号チップが付く（open PR に紐づく）worktree/branch 行の行末に「開く」ボタン。選択行のみ着色し、選択は移動時に可視域へスクロール追従する。裏のデータ到着でセクションが差し替わるときは、直前に選択していた行を実行ペイロードの同一性で探し直して選択を復元する——行数が変わっても選択が別の行を指さないため。この復元は入力モダリティを奪わない。
- **フッター**: `↵`＋選択行に連動する実行説明（対象名・前置/後置句・起動先名を色で描き分け）＋右端キーヒント `↑↓ 選択` `⇥ agent変更` `esc 閉じる`（⌘↵ が効く行の選択時は `⌘↵ 開く` を追加）。実行失敗時はこの行に失敗理由を赤で出す。worktree 作成待ち中は `↵` もキーヒントも出さず、スピナ＋「作成中…」のみを出す——操作が無効な間は効かない案内を残さない（優先度は 作成中 → エラー → 実行説明）。

## データ供給（プログレッシブ）

パレット提示と同時にデータロードが走る。git（worktree/branch 列挙・数十 ms）は即描画。初回ロードまでは候補行の形をしたスケルトン行を出し、開いた瞬間の空フレームを埋める。gh（issue/PR 取得・ネット）は前回結果を先に描いて裏で取り直す。git・gh とも子プロセス PATH（[shell-path](../platform/shell-path.md)）でサブプロセス実行し、completion をメインで受ける。

- **git 列挙**: worktree 一覧・local/remote branch 一覧（`refs/remotes/origin/HEAD` 等のノイズ除外。local branch は既存 worktree パスも取得して再利用判定に使う）・デフォルトブランチ。remote branch は即時読みに加え、裏で `git fetch --prune origin` を**独立レーン**で走らせ、成功時に読み直して当該セクションだけ差し替える（失敗時はキャッシュ据え置きで UI 非破壊）。独立レーンにするのは、共有 queue の barrier チェーンに載せると直後に Enter で来る worktree 作成がこの数秒の fetch を待たされるため。
- **GitHub 取得**: 可用性を `notGitHub`／`ghMissing`／`ghUnauthed`／`ready` に分類（origin URL が github.com か → ローカルの認証情報の有無）してから `gh issue list`／`gh pr list --json` で取得する。可用性の判定は**ネットに触らない**——疎通不能を「未認証」と誤分類すると、通信できないだけの状態で誘導情報行が出て前回結果が消えるため。ネット待ちはタイムアウトつき（stdout/stderr を並行排出しデッドロックを避ける）。
- **gh 結果のキャッシュ**: 取得結果はリポジトリ（`git-common-dir`）単位でプロセス内に保持し、次に開いたときは**前回結果を最初の描画フレームから描いた**うえで裏で取り直す（2 回目以降はローディング行を経由しない）。worktree 間で共有され、アプリ終了で消える。取得成功時はセクションをまるごと置換するので、閉じた issue／マージ済み PR は残らない。**取得失敗（オフライン・タイムアウト・非 0 終了・デコード失敗）は差し替えず前回結果を据え置く**（remote branch の裏 fetch と同じ規約）。失敗と「0 件」は取得層で区別され、0 件成功では行が消える。取得結果が前回と等値ならセクションを再構築しない。
- **フォールバック 3 分岐**: `notGitHub`→Issues/PR 両セクション非表示／`ghMissing`・`ghUnauthed`→Issues に誘導情報行 1 本／`ready`→実データ（0 件セクションは非表示）。
- **分類レーン**: [clean](#clean--worktree-の掃除) の 3 群判定に要る実測（worktree ごとの作業ツリーの汚れとその件数・停止中の git 操作・消してコミットが世界に残るか）を走らせる。一覧の `clean` 行が出す候補件数がこの結果を要求するので遅延できない。git を叩く部分は**独立レーン**（remote branch の裏 fetch と同じ理由——共有 queue の barrier チェーンに載せると直後の Enter で来る worktree 作成と、clean の削除実行を待たせる）。clean が読む PR の事実（レビュー中か・マージ済みか・マージ先）は、worktree にあるブランチ（main を除く。detached は対象外）を `--head` で名指しした取得（`--state all`・ブランチごとに 1 往復で open / closed の両方）から来る——直近 N 件の一覧窓では、窓落ちした PR のぶんだけ「マージ済みなのに merged チップが出ない」「レビュー中なのに安全確認を素通りする」が起きるため、窓は使わない（パレットの PR 一覧 UI は別で、bulk の open 一覧＝窓のまま）。1 往復では gh の上限まで（作成日時の降順に 100 件）取る——往復コストは件数に依らないので絞る動機が無い。cross-repo の PR は他人の同名ブランチの事実として突き合わせの前に除外し、残りの最新（open は最新の OPEN・closed は最新の非 OPEN）を採る。git レーン（worktree 一覧）と gh レーン（認証確認）の両方が揃ってから引く。取得の入口は両レーンの着地点から叩かれ、先に来た側は素通りし、**対象ブランチの顔ぶれが変わった回だけ**引き直す（worktree 削除後の引き直しがこれに当たる）。gh の主張のうち安全確認に効くのは open PR の有無だけで、マージ済みか・マージ先かは推定と表示に閉じる——**消してもコミットが世界に残ることの証明はローカル git の事実だけで閉じる**。ただし merged PR の base は取り込み判定の**比較先リストへの 1 本のヒント**にはなる: gh 着地で base が判明したら、**比較先の顔ぶれが変わった行だけ**判定を引き直す（PR 名指し取得の顔ぶれ dedup と同じ規約——発行時点で比較先を記録し、着地は発行時の比較先が現台帳と一致するときだけ反映する）。git の事実が動いた着地（fetch --prune・削除後）は従来どおり全行を引き直す。`fetch --prune` の完了後に git 列挙ごと打ち直すので、リモートで消えたブランチの `[gone]` は prune 済みの状態で読まれる——マージ直後という主用途で候補が空にならない。

## 操作

**フィルタ**: 打鍵で名前・番号・補足を大小無視部分一致で全セクション横断絞り込み。空になったセクションは消え、選択は可視行へクランプする。

**↑↓ / ⌘↑↓**: ↑↓ は可視の全行を平坦 index で巡回（wrap・見出しはスキップ）し、選択行へスクロール追従。⌘↑↓ は選択を最初/最後の対話行へジャンプ（見出し・ローディング・gh 誘導の非対話行は飛ばす。対話行ゼロなら no-op）。**行タップは決定**（↵ と同じ funnel を通り、非対話行・作成中・範囲外では不発。行内の「開く」ボタンは行の決定を巻き込まない）。**マウスホバーで選択がその行へ追従する**（着色行は常に 1 つ・非対話行へは追従しない・ホバーで決定は走らない）。追従の門は共有の入力モダリティ（[workspace パレット](workspace.md)）で、実ポインタ移動で pointer・キー移動や絞り込みで keyboard へ戻り、keyboard の間はスクロールで行がカーソル下へ来ても選択を奪われない。**カード内のクリックは焦点の宛先を確定させる**（共有 `PaletteCard` と同じ契約 → [workspace パレット](workspace.md)）——行タップ・行内の「開く」ボタン・行以外の余白のいずれの後も、↑↓ と絞り込みの打鍵がそのまま効く。

**⇥（起動先の巡回切替）**: 起動先は検出済み agent（表示は raw command）に素の shell を加えた列で、shell は default agent の直後に常在する。初期選択は default agent（agent 未検出時は shell）。agent 未検出でも shell を選べるため袋小路は無い。

### Enter（実行）

選択行の種別に応じて対象ディレクトリを解決し、選択中の起動先を**現 workspace の新しいタブ**でその cwd に起動する（agent は initialCommand で起動、shell は Cmd+T と同じ既定シェル）。起動後は次 runloop tick で新タブ surface にフォーカスを再確定する。

**対象ディレクトリの解決**:

- **Worktree 行**: 既存パスをそのまま使用（非破壊）。
- **Local branch**: 既存 worktree があれば再利用、無ければ `git worktree add`。
- **Remote branch**: ローカル追跡ブランチを作って add。
- **Issue**: 他行種別と対称で、`issue/<番号>` を既存 worktree／ローカルブランチと突合し 3 分岐（既存 worktree あれば再利用／同名ブランチだけ既存ならそこから追加／どちらも無ければデフォルトブランチから `-b issue/<番号>` で追加）。行末ノート／フッターも実解決に一致する（既存worktree／checkout → worktree／新規worktree）。
- **PR（same-repo）**: head ブランチの worktree を作成/再利用。fork（cross-repo）PR は worktree 化せず、⌘↵ でのブラウザ表示へ誘導する。

**worktree の作成場所**は実効設定 `worktree-dir`（[settings](settings.md)・[config](../platform/config.md)）のテンプレートから解決する。語彙は `{repo_path}`（main worktree の絶対パス）・`{parent}`（その親）・`{repo}`（その basename）・`{slug}`（branch 名の `/`→`-`）の 4 語＋先頭 `~` のみで、既定は `{parent}/{repo}-worktrees/{slug}`。4 語はすべて `{repo_path}` 1 つから導く——`{parent}/{repo}` は定義上つねに `{repo_path}` と同値であり、その同値を呼び手が整合した値を渡すことに委ねない。置換 → `~` 展開 → **純字句の**正規化（`.`・`..`・重複スラッシュを畳む。symlink は解決しない——実在する repo root と、これから作る作成先を同じ土俵で比べるため）で確定する。語彙に語を足すときは検証の既知トークン集合と置換の両方に入れる必要がある（検証だけ通って未置換のまま残ると、その名前のディレクトリが実際に作られる）。

**共有 exclude の自動追記**: `git worktree add` は隔離ディレクトリを追加するだけで現在の作業ツリーのファイルには触れない。ただし**作成先が作業ツリー内に落ちる場合だけ**、作成に成功した後で共有 exclude（`$GIT_COMMON_DIR/info/exclude`。git は `info/exclude` を常に common dir から読むので全チェックアウトに効く）へ除外を冪等に追記する——repo 内配置を設定で選べる以上、`git status` が worktree ぶんだけ汚れる（`git add .` が gitlink 化する）のを注意書きでなく自動化で塞ぐ。契約は「**Orbe が作ったものだけを除外する**」: 対象は worktree の親ディレクトリ、ただし親が root 自身か**作成前から実在していた**なら worktree 自身（既存ディレクトリを丸ごと除外して、そこへ後から置かれたユーザーの新規ファイルまで `git status` から消さない）。既に無視されている（ユーザーの `.gitignore` 由来を含む）なら触らず、`.gitignore` は書き換えない。判定は解決済みパスだけで行い、UI の行（プリセット／カスタム）には紐付けない。除外は補助なので、失敗しても worktree 作成は続行する。

**失敗時**（パス衝突・checkout 済・ネット不通）: palette を閉じずフッターに失敗理由を赤で表示し、agent を起動しない。作成が失敗したときは除外も書かない——何も起きなかった操作がユーザーの repo を書き換えない。失敗理由は git stderr から実質行（`fatal:`／`error:` 行・無ければ最終非空行）を抜く——成功時にも出る進捗風メッセージで本当の理由を覆い隠さないため（この整形は git ラッパー層に閉じる）。

**作成中の進捗表示・入力ロック**: 非同期作成の完了を待つ間 `isPreparing` を立て、フッターにスピナ＋「作成中…」を出す。この間は入力を受け付けない（Enter 再実行＝`git worktree add` 二重起動を弾く／↑↓・⇥・検索入力・Esc/scrim 閉じを握り潰す）。既存 worktree 再利用など同期に済むケースは同一 tick で palette が閉じるため進捗は描画されない。

**無応答の打ち切り**: `git worktree add` は独立レーンで走り、無出力が続けば打ち切られる（→ [git](../platform/git.md)）。打ち切られたとき **worktree の実体が出来ていれば成功として開く**——post-checkout hook は worktree が完成した後に走るので、hook が返らないだけの状態を失敗として扱うと、実在する worktree を指したまま再実行が「ブランチが既にある」で詰む。実体が無いまま打ち切られたときは失敗理由として専用の文言（応答が無いため中断した旨）をフッターに出す。git が自分で理由を言えた場合はそちらを出す。

### ⌘↵ / 開くボタン

issue/PR 行と、open PR に紐づく（番号チップが付く）worktree/branch 行で、`gh issue|pr view --web` により対象をブラウザで開く。worktree/branch 行は番号チップと同一番号のルックアップから紐づく PR を開く（一致を保証）。紐づかない行には出さない。

### 閉じる

Esc / scrim タップで閉じ、アクティブペインへフォーカスが返る。

## clean — worktree の掃除

作った worktree を消せる面。マージ済みの作業も、リモートで消えたブランチも、放っておけば worktree はディスクに残って Worktrees セクションに並び続ける。作る側だけがあって消す側が無いと、掃除のためだけにターミナルへ降りることになる。

**入口は Worktrees セクション末尾の `clean` 行 1 本**。Enter か行タップで clean モードへ入る。この行は**候補が 0 件でも残り**、行末の候補件数バッジだけが消える——同じ場所にいつでもある入口として、出たり消えたりしない。フィルタは `clean` のほか `rm` / `prune` / `掃除` でもこの行にヒットする。

### 3 群 — 「要らないの推定」と「消して安全か」は別のレイヤ

clean モードは**全 worktree を出す**。危険なものを選択肢から消すのではなく、理由を添えて出したうえで初期状態では選ばれないようにする。判断はユーザーに残しつつ、勢いでは消えない。

| 群 | 意味 | 条件 |
|---|---|---|
| 安全 | 掃除して問題なし | 推定が 1 つ以上立ち、かつ安全確認をすべて通った |
| 確認 | 消えるものがある | 残り全部（推定は立つが安全確認で落ちた／そもそも推定が立たない） |
| 使用中 | 削除できない | main worktree である、またはそのパスを開いているペインがある |

- **推定**（どれか 1 つ立てば足りる）: upstream が `[gone]` ／ 紐づく PR が MERGED ／ `prunable`（実体のディレクトリが手で消されている）。
- **安全確認**（1 つでも落ちれば安全に入らない）: main worktree でない ／ そのパスを開いているペインが無い ／ locked でない ／ **レビュー中の PR が紐づいていない** ／ 作業ツリーが clean ／ **停止中の git 操作が無い** ／ **消してもコミットが世界に残る**。

レビュー中の PR を持つ行が安全に入らないのは、**安全群がブランチ削除を無条件に行う群だから**。レビュー中のブランチは既定で残すべきもので、消すなら明示が要る——その明示ができるのは確認群だけ。

2 つを別レイヤにするのは、**「リモートで消えた＝要らない」が偽だから**。upstream が prune 済みでも、PR がマージされずクローズされていれば、どこにも無いコミットがその worktree にしか残っていないことがある。推定だけで消すとそれが消える。

判定できなかった事実は「安全」と読まない。コミットが世界に残るかを確かめられなかった worktree は安全に入らず、独自コミット件数も名乗らない。

**locked な worktree は「確認」に入る**。強制削除は locked を外さないので、安全に入れると「初期チェック済みなのに実行すれば必ず失敗する」罠になる。使用中に入れないのは、ユーザーが手で unlock して消せるから。

**ペインの占有**は全 workspace × 全タブ × 分割ツリーの全葉を走査して判定する（休眠 workspace のペインも含む）。パスは両辺を正規化して構成要素単位で前置一致を見る（macOS の `/tmp` `/var` は symlink で、素の文字列では一致しない）。子ディレクトリにいるペインも占有とみなし、worktree が入れ子なら最も長く一致したものへ帰属させる。

### 行の状態は 3 軸の直積

行が置かれた状況は独立した 3 つの軸の積で、単一のラベルの列挙では網羅できない。

| 軸 | 問い | 語彙 |
|---|---|---|
| A: worktree の中身 | 消すと何を失うか | 未コミットの変更／未追跡ファイル／停止中の git 操作／実体なし |
| B: ブランチの行き先 | 消すと世界に残るか | マージ済み PR（マージ先つき）／取り込み済み（merged → 実マージ先）／remote に保存済み／remote と同期済み／remote より進んでいる／未 push／レビュー中の PR／`[gone]`／独自コミット |
| C: 使用状況 | 誰かが使っているか | agent の稼働状態／タブで表示中／locked／main worktree |

軸A と軸B から**行末のラベルは最大 2 枚**まで。軸C はラベルではなく群の移動で表す（`locked` だけは確認群に置いたうえでラベルにも出す——強制削除でも外れないことが、その行が安全に入れない理由そのものだから）。**枠に載らなかった語は捨てず、展開したサブラインに同じ姿で並べる。** 片方の軸が黙っていれば、空いた枠はもう片方の 2 つ目で埋める。

**語が主張として偽になるなら、色を弱めるのではなく言わない。** コミットが世界に残ると確認済みのブランチは「未 push」「remote より進んでいる」を名乗らない——これらは「そのコミットがどこにも残らない」という主張であり、その行では嘘になる。失うものがある行では独自コミット件数がそれを名指す。

同じ原則が**取り込みの語を証明の種類で出し分ける**ことも決める。tip を含む比較先のある行と patch 等価の行は「merged → \<実マージ先\>」が真なので名乗る。到達性だけで安全が立った行は、単に完全 push 済みで未マージでも成立するため「merged」を名乗らせず、主張できる範囲だけを言う「remote に保存済み」を出す。

**merged PR チップが立つ行では「merged → \<X\>」はピル枠を争わずサブラインへ降りる**——同じ「merged」を 2 枚並べず、空いた枠は次の事実（`[gone]` 等）が埋める。PR チップは判定には使わないが、表示上の安全根拠としては真の主張なので右クラスタに立つ。降ろすのは重複するこの語だけで、「remote に保存済み」は残す——マージまでは主張しない別の根拠であり重複しないうえ、サブラインは確認群でしか開かないので safe 行で降ろせば消えてしまい、ローカルに証明した根拠が画面から無くなる。

**「remote に同期済み」が立つ行は「remote に保存済み」を名乗らない**（サブラインにも出さない）——同期済みが保存済みを含意し、強い方の主張が同じ事実を含んで立っている。「merged → \<X\>」はより強い別の主張なので抑制しない。

**安全確認に使う事実（作業ツリーの状態・停止中の git 操作・取り込み判定のどれか）を確かめられなかった確認行には判定不能チップ（「情報取得に失敗」・琥珀）が立つ**——基本起こらない異常系なので内訳は持たず、チップ 1 枚だけで語る。分類（群の振り分け）は変えない——判定不能を安全と読まない契約は分類側が持つ。prunable 行は作業ツリー側（status・停止中の操作）を意図的に問わないので、そこが取れなくても判定不能にはしない——失うものが無く、確認の対象ですらない。判定不能チップは損失の内訳（「〜も消えます」）には載せない——何が失われるかは不明で、消えると断定すれば嘘になる。

### 停止中の git 操作

rebase・merge・cherry-pick・bisect の途中で止まっている worktree は、**作業ツリーが clean に見えることがある**（コンフリクトの無い停止点）。status だけを見ていると安全確認を通ってしまい、初期チェック済みのまま消える。

判定は worktree の gitdir 直下に該当のファイルがあるかで行う。gitdir は worktree の `.git`（main worktree ではディレクトリ、リンク worktree では `gitdir:` 1 行のファイル）から解決するので、**git を新たに起動しない**。読めなければ「判定できなかった」として安全に入れない。

この確認は分類のときだけでなく、**削除を撃つ直前にも取り直す**。画面を開いた後に始まった操作を、強制削除が管理ディレクトリごと消さないため。

### 消してコミットが世界に残るかの判定

問うのは「既定ブランチに入っているか」ではなく「消してコミットが世界に残るか」。既定ブランチを比較先に固定すると、統合先が既定ブランチでないリポジトリ（git-flow の develop 統合など）で、統合先へマージ済みのブランチが「独自コミット +N 件」と誤表示され、この機能の主用途がそのまま外れる。

**3 段構えで判定する。**

**第0段（到達性）**: `git rev-list --count <tip> --not --remotes=origin --` が 0 なら、全コミットが `refs/remotes/origin/*` から到達可能で、worktree とローカルブランチを消してもコミットはそこに残る。比較先を推測せずに意味論を直接問えるので、統合先がどこであっても成立する。

信頼する ref を **origin に限る**のは、鮮度を保証できる範囲と揃えるため。prune するのは origin だけなので、fork や upstream の tracking ref は remote 側で消えた後もローカルに残り続ける。それを根拠にすると `[gone]` で安全群に入った行が stale な ref だけを頼りにブランチごと消え、後で全 remote を prune した時点でコミットが到達不能になる。origin に限れば「`[gone]` を作る prune」と「信頼する ref を掃除する prune」が同一操作になり、その組み合わせが構造的に消える。

`--` でオプションを終端するのは、`rev-list` が pathspec も取るため。終端しないとリポジトリ直下のエントリと同名のブランチ（`docs` 等）で `ambiguous argument` になり、その worktree だけ第0段が黙って失敗する。

判定に渡す名前は、ブランチのある行は `refs/heads/<branch>` の**完全 ref**・detached は oid（全段共通）。短縮名は refs/tags が refs/heads より先に解決されるため、同名タグ（`v1.0` をタグとブランチの両方に切る運用等）があるとタグの指すコミットを判定してしまう。

**第1段・第2段（比較先リストとの patch 等価）**: squash / rebase はマージで SHA が変わり到達性では見えないので、`git cherry` の patch-id 比較で拾う。比較先は**リスト**＝`[既定ブランチ] + 紐づく merged PR の base（origin/<base> がローカルに実在し既定と異なる場合）`。gh はリストへ 1 本足すヒントのみで**証明はローカル**——嘘の base は比較の不成立で確認群のままに倒れる（安全側）。これで squash 運用の git-flow（develop 統合・squash マージ・remote ブランチ削除）でも実マージ先との patch 等価が立つ。`git branch --merged` でも `git log <default>..<branch>` でも取れない——merge commit と squash が混在すると squash 済みブランチが未マージとして残るため。

ただし**素の `git cherry` 単独でも足りない**。cherry はコミット 1 個ずつの patch-id を比べるので、複数コミットを 1 つに畳んだ squash では畳んだコミットの patch-id が元のどれとも一致せず「未取り込み」と誤判定する。まず素の `git cherry` を見て未適用が 0 なら取り込み済み（fast-forward・merge commit・rebase・cherry-pick・単一コミットの squash がここで片付く）。残ったものについて、ブランチの累積差分を 1 個のダングリングコミットに合成してから再度 cherry にかけ、比較先側に同じパッチがあれば squash 取り込み済みと判定する。**2 段とも要る**——後段だけでは比較先の厳密な祖先であるブランチに対して偽陽性を返す（合成が空パッチになるため）。第1段は全比較先を先に回してから第2段へ移る（後続の比較先が 1 プロセスで立つとき 4 プロセスの後段を省くため。空パッチの偽陽性は同じ比較先の第1段が防ぐので、この順序でも防波堤は保たれる）。

合成は到達不可能なコミットオブジェクトを 1 つ書く（ref は触らず、いずれ gc で消える）。

**結論は 3 つ**: 到達性で立った（`remote に保存済み`、tip を含む比較先があるなら `merged → <実マージ先>`）／patch 等価で立った（`merged → <実マージ先>`）／どれも立たない（未取り込み）。名乗るのは**証明が立った比較先のローカル名**（先頭の `origin/` を落とした形）。複数立つときは**先に立った段**が勝ち、同じ段の中ではリスト順＝既定優先。到達性の行が名乗るのは tip を含む最初の比較先で、これはラベルの決定だけで安全事実そのものには関わらない。**判定できなかったときは 4 つ目の値**で、安全とは読まない——`.unmerged` は「どの比較先にも patch 等価でない」という主張なので、1 本でも確かめられなければ名乗らず判定不能に倒す。

未取り込みの行が「注意」の理由に出す独自コミット件数は、**到達不能数と、各比較先の patch 非等価数の最小との min**。どちらも「真に失われる数」の過大評価なので、min はより良い過大評価になる（既定ブランチが統合ブランチより遅れたリポジトリで「独自コミット +106」型の巨大数が実数へ縮む）。

### 選択と実行

安全群は**開いた瞬間に全チェック済み**、確認群は未選択、使用中は選べない。↑↓ は選べる行だけを群順に巡回し、使用中を飛ばす。space / Enter / 行タップでチェックを切り替え、`a` は安全群を選択に加える（トグルではない）。⌘Enter で実行し、0 件では何も起きない。Esc は一覧へ戻る（パレットは閉じない）。ハイライトはカーソル行だけが持ち、**チェックは 2 値**で、その状態はチェックボックスの塗りだけが示す。

**分類は clean モードへ入った瞬間の結果で凍結する。** 破壊的な複数選択の最中に、裏で届いたデータでカーソルの下のリストが組み替わったり初期チェックが変わったりしない。最新を取りたければ一覧へ戻って入り直す。

**ローカルブランチを消すかは、安全と確認で決まり方が違う。**

- **安全**: 実体があり、ブランチがあり、消してもコミットが世界に残ると確認済みの行だけがブランチも消す。実体が無い prunable 行は登録を消すだけでブランチに触らない。
- **確認**: チェックした行の下にサブラインが開き、そこで `残す`（既定）／`削除` を選ぶ。**`削除` を選ぶ行為そのものが安全確認の上書き**であり、どこにも残らないコミットを持つブランチはこの明示がなければ消えない。

**実行すると何が起きるかは、実行前に必ず読める——ただし語る場所はカテゴリで分かれる。** 行の右クラスタは状態（3 軸の事実）だけを語り、動作の予告は載らない。

- **安全群の見出し**が群の動作宣言を持つ（「安全 — worktree を削除（対象によってはローカルブランチも削除）」）。prunable 行がブランチに触らない例外は「対象によっては」の含みが吸収し、実態は行の `prunable · 実体なし` チップとフッタの内訳から読める。
- **フッタの実行ボタン**が実行の総量を語る。ブランチも消える行が選ばれているときは「worktree N 件とローカルブランチ M 件を削除」の内訳付き、0 件なら worktree 数だけ（0 件の内訳は出さない）。
- **確認群のサブライン**が行別の動作選択（`残す`／`削除`）を持つ。

**サブラインはその行の詳細であって、ブランチの選択欄ではない。** ブランチの `残す`／`削除` はそこに載る中身の 1 つで、失われるものの内訳と、ラベルの枠に載らなかった語も同じ場所に並ぶ。だから detached の行——rebase の停止中は必ずこの形になる——でも、書くことがあれば開く。書くことが何も無ければ開かない。

**立った事実は、その行の状態で必ず画面から到達できる。** ラベルに載るか、サブラインに載るか。どちらの経路も持たない語を作らないことが、削除を撃つ前に読める情報の下限を決めている。

ブランチの削除は**分類した時点の先端であるときだけ**実行する（凍結した判定のまま、その後に積まれたコミットを消さない）。worktree の削除は、直前に作業ツリーの汚れと停止中の git 操作を取り直して確かめてから実行する。

削除自体は強制削除で呼ぶ。submodule を持つ worktree は通常の削除が無条件に拒否されるためで、拒否を握り潰しているのではなく——強制が外す「汚れている」「submodule を持つ」の 2 つのうち、汚れは直前に Orbe 自身が確認済み、submodule は per-worktree のチェックアウトが消えるだけで実体は共有ディレクトリに残る。

### 削除の進行と失敗

削除は 1 件ずつ直列に進み、**選んだ行だけが実行順に並ぶ**（未選択の行は畳んで見えなくなる）。**行頭のチェックがそのまま進捗になる**——完了・実行中・待機が同じ位置で入れ替わり、行の meta 列には何が起きたかが出る。

**途中で失敗しても中断せず全件試みる。** 削除は取り消せないので、止めても部分実行済みの状態は残る——ユーザーが頼んだ残りを止める理由がない。

Esc は**まだ撃っていない残りを止める**。実行中の 1 件は完走させる（`git worktree remove` を途中で殺すと管理ディレクトリが半端に残り、「消えかけの worktree」という新しい状態が生まれる）。実行済みは戻らない。

**失敗しても成功した行を消さない。** 削除中と一部失敗は同じ行集合の別の時点であり、どの行が・なぜ落ちたのかを消えた行の跡地から推測させない。失敗した行はその場に赤で残り、理由（どの段階で落ちたか）と git の生の出力、そして再試行とタブで開く導線をその行の中に持つ。Enter は失敗した行だけを**凍結した依頼のまま**撃ち直す（分類し直さないので、ユーザーが見て承認した根拠と実行される内容が食い違わない。それでも危険にならないのは、ブランチ削除が先端の照合を、worktree 削除が直前の確認を毎回その場で通るから）。worktree が消えてブランチだけが残った行は、残りのブランチ削除だけを撃ち直す。

**終端は失敗の有無で分かれる。** 1 件も失敗しなければ一覧へ戻り、掃除の結果が Worktrees セクションと `clean` 行の候補件数に反映された姿で見える。1 件でも失敗すればその画面に留まり、Esc でパレットを閉じる。中断も同じ終端を通る。

**共有 exclude の後始末はしない。** worktree の作成が `$GIT_COMMON_DIR/info/exclude` へ除外を追記した場合（作成先が作業ツリー内に落ちる設定のときだけ）、その行は削除後も残る。1 本の除外行が親ディレクトリを指して複数の worktree をまとめて覆うことがあるため、消すには残った worktree との突き合わせが要る。存在しないパスの除外は無害で、同じ場所に作り直せばそのまま再利用される。
