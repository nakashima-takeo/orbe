# エージェント起動

エージェント CLI をワンアクションで「起動した状態のタブ」として開くための機構。一級サポートのエージェント CLI は claude / codex / agy（この並びがデフォルト未設定時の優先順）。

## 初回フロー（言語選択 → Onboarding）

初回起動時は、Onboarding（各 CLI へプラグイン導入・[plugin-package](plugin-package.md)）の**前段**に UI 言語だけを選ぶ画面を出す（ja/en 2 択・↑↓／↵ ないし行タップで確定・行はホバーで選択が追従・真のモーダル＝scrim では閉じない）。確定で現在言語を更新し永続化してから Onboarding へ進む。2 回目以降は言語画面をスキップする。起動フロー全体の文言は現在言語に追従する（[localization](../platform/localization.md)）。

## 検出

解決済みの子プロセス PATH（[shell-path](../platform/shell-path.md)）上の実行ファイルを絶対パスへ解決する。アプリ起動時に 1 回＋パレットを開くたびに裏で再走査する（in-flight 中はスキップ）。走査し直すのは実行ファイルの有無だけで、PATH 自体は取り直さない。解決できた CLI だけを覚える——見つからなかったことを覚えると、PATH が整う前の 1 回の走査がセッション全体を縛るため。

## 起動パレット（⌘⇧A）

検出済み CLI を列挙するオーバーレイ。↑↓＋Enter で起動、→ サブメニューに「デフォルトに設定」、← / Esc で 1 段戻る。ルート（一覧・検出中・空状態）はヘッダ行なしで行リストから始まり、サブメニューでは breadcrumb ヘッダが出る。検出ゼロは情報行のみの空状態。初回検出が未完了の間は「CLI を検出中…」の情報行を出し、完了で結果表示へ差し替える。● がデフォルト印。開いたまま再検出が届くと表示へ反映する（潜り先が消えたら一覧へ戻る）。

オーバーレイ UI は workspace パレットと共通のパレット基盤を共有する。ヘッダ行は入力欄か breadcrumb のあるときだけ描かれる（ヘッダのショートカットバッジは存在しない）。行リストの高さ上限・選択追従スクロール・⌘↑↓ での有効な先頭/末尾行ジャンプは共有基盤の挙動（→ [workspace パレット](../palette/workspace.md)）。

## デフォルト起動（⌘⇧C）

デフォルト（設定値が検出済みならそれ、それ以外〔未設定・未検出〕は検出順の先頭）を即起動する。検出ゼロならパレットの空状態を、初回検出未完了なら検出中パレットを開く。設定値は**アクティブ workspace の実効 `default-agent`** で workspace 上書きに追従する（⌘⇧C・worktree パレットの既定 agent・起動パレットの ● が同じ解決を読む・[workspace](../platform/workspace.md)）。

## 起動形態

アクティブタブの実効 cwd（0 タブ・ボード選択中は workspace の root path → [layout](../chrome/layout.md)）を引き継いだ新タブで、シェルの代わりに絶対パスのエージェント CLI を直接起動する（新規も再開も。この文書のコマンドの例は CLI の名前で書くが、先頭には絶対パスが入る）。環境変数 `PATH` には子プロセス PATH（[shell-path](../platform/shell-path.md)）を注入する——エージェントの子プロセスにも Orbe 自身と同じコマンド解決を保証するため。エージェント終了はシェル exit と同じ経路でタブが閉じる。永続スナップショットでは、hook 由来のエージェントセッションを持つペインは resume 起動、持たない／未対応 CLI のペインは保存 cwd の通常シェルタブで復元される。resume の解決はタブ起床（materialize 開始）時に行う（→ [persistence](../platform/persistence.md)）。

CLI によっては、Orbe が起動するとき必ず付ける引数がある。codex には共有のデーモンを使わない引数（`--no-daemon`）を付ける（`codex --no-daemon …`・`codex --no-daemon resume <id> …`）。Orbe のタブのモデルは「タブで動くプロセスが agent」で、hook と MCP サーバーもタブで動く agent の子として起動し、タブの環境（[notify](notify.md) の tab identity）を受け継ぐことを前提にしている。デーモン経由の codex では、hook と MCP サーバーを起動するのはデーモンで、その環境はデーモンを起動した時点の端末のもの——状態が別のタブに付き、MCP のツールが別のタブを名乗る。引数は CLI ごとの静的な知識として、新規と再開のコマンドを組む 1 か所が置く。GUI・worktree パレット・タスクの開始・制御 API・復元のどの経路から起動しても付き、経路ごとの付け忘れが起きない。この引数を持つ codex（0.156 以上）が前提で、それより古い codex は引数を知らず起動に失敗する。デーモンを既定で起動するのは 0.157 以上の codex。

agy には、コマンド実行などの 1 手ごとの確認を出させない引数（`--dangerously-skip-permissions`）を付ける（`agy --dangerously-skip-permissions …`・`agy --dangerously-skip-permissions --conversation <id> …`）。Orbe のタブのモデルは「タブの状態は agent の hook の報告で決まる」で、agy の hook は確認の待ちを知らせない（確認の前に呼ばれる hook は、確認の有無で変わらない）。確認を出す agy は、確認で止まっている間も作業中に見え、このモデルの中で正しく表せない。agy の設定で確認ありにしていても、引数が勝つ。引数を付けても、質問（[plugin-package](plugin-package.md) の event→state で待ちとして報告する）・[フォルダの信頼](#agy-のフォルダの信頼)の確認・agy の拒否の規則と禁止コマンドは残る。

付くのは Orbe が組む agy のコマンドすべてで、タブのシェルで手で始めた会話を Orbe が再開するとき（復元・⇧⌘T・制御 API の再開）にも付く。再開のコマンドを組む時点では、会話が確認ありで始まったかを知る材料が無い（hook の報告に無い）ため。タブのシェルで手で打つ `agy` には付かない。省くのは agent の 1 手ごとの確認だけで、「この中身を実行してよいか」を人が決める手続き——agy のフォルダの信頼、codex の hook の承認（[plugin-package](plugin-package.md#codex-の-hook-の承認)）——は飛ばさない。この引数を知らない agy は起動に失敗する（いつの版から在るかは確かめていない。1.4.0 には在る）。

## agy のフォルダの信頼

agy は信頼していないフォルダで起動すると、信頼するかの確認を出し、応えるまで会話を始めない（最初の入力を添えた起動も、確認に応えるまで入力が渡らない）。確認の間は hook が呼ばれないので、タブの状態は出ない。信頼はフォルダのパスの完全一致で、信頼済みのリポジトリの worktree も、信頼済みフォルダの子も、別のフォルダとして確認が出る——新しい worktree での起動は、毎回この確認に当たる。確認を出させない引数（`--dangerously-skip-permissions`）でも確認は消えない。Orbe は agy の設定に信頼を書き込まず、信頼を渡す引数も付けない。フォルダの信頼は、そのフォルダに置かれた hook などを実行してよいかを人が決める手続きで、Orbe は飛ばさない（[起動形態](#起動形態)）。

## 外部からの起動

制御 API と `orb agent spawn` / `orb agent resume`（[control/cli](../control/cli.md)）からも起こせる。**GUI と同じ経路**を通る——新しく起こすのは GUI と同じ 1 本の関数で、絶対パス・PATH 注入・cwd フォールバックの組成をそのまま共有し、再開は[会話の再開の組み立て](#会話の再開の組み立て)の 1 か所を通り、新規と同じく絶対パスで起動する。起動のされ方が入口ごとに割れると、その差は「GUI からは動くが CLI からは動かない」という遠い形で出る。

外部起動だけが持つのは対象 workspace の指定で、**指定しても前面化しない**（[control/api](../control/api.md) の mount 境界）。このとき解くデフォルトは**対象 workspace の**実効 `default-agent` で、⌘⇧C がアクティブ workspace のそれを読むのと同じ規則を、入力だけ変えて使う。

resume 起動は永続復元だけでなく `orb agent resume` からも走る。セッション ID は `orb tab list --json` の `agentSessionId`（hook 報告が入ってから値を持つ）から取る。

## 会話の最初の入力を添えた起動

起動（新規・再開）には、会話の最初の入力を添えられる（[タスク画面](../palette/tasks.md)の解けた待ちの ⌘↵ が起きたことを届ける・[`start_task`](../control/api.md) が頼みを渡す・[秘書](secretary.md)が依頼を渡すのに使う。休眠のタブを起こすときの再開には 1 度だけ添える）。席は CLI ごとに決まっていて、claude・codex は末尾の位置引数で、前にオプションの終わり（`--`）を置く（`claude --resume <id> -- <入力>`・`codex --no-daemon resume <id> -- <入力>`）——`-` で始まる入力をオプションと読ませないため（claude は commander、codex は clap で、どちらも `--` の後ろを位置引数として読む。配布物の中身で確かめた）。agy は `-i` の値（`agy --dangerously-skip-permissions --conversation <id> -i <入力>`）で、Go の標準の flag は `-` で始まる値もそのフラグの値として読むので `--` を置かない。入力はシェルの単語として引用して組むので、外の人が書いた文面を含んでも実行されない。改行・タブ以外の制御文字は、席に置く時点で空白にする——NUL はコマンドの文字列をそこで切って起動を壊すため。席で手当てするので、入力を作る側（続きから・`start_task`・秘書）のどれから来ても同じく守られる。起動の引数で渡すため、入力はプロセス一覧に見える。agy の形は agy 1.5.13 で確かめた——新規でも再開でも入力が渡り、再開は同じ会話 ID で続き、`--` で始まる入力も `-i` の値として渡る。

## 会話の再開の組み立て

会話の再開（復元・⇧⌘T・`restore_sessions`・`resume_agent`・解けた待ちの ⌘↵）は、どれも休眠のタブを足して起こす形で、再開のコマンドを組むのは休眠のタブの起床の 1 か所。新しいタブで再開した会話は、開いた時点で会話のタブの索引に載る（続けて同じ会話を開こうとしても、そのタブが見つかる）。

再開も新規と同じく、CLI を絶対パスで起動する。保存しているのは CLI の名前とセッション ID で、絶対パスは保存しない（版の更新で変わる）。起床の時点で、タブへ注入するのと同じ PATH に対して、[検出](#検出)と同じ解決で絶対パスを求める——タブのシェルが見つけるものと、起動するものが一致する。裏の検出の完了は待たない（起動直後の復元では、検出がまだ終わっていない）。その PATH に CLI が無ければ、タブは素のシェルで起き、会話の記録は再開できなかったものとして閉じる（[session-log](../platform/session-log.md) の `unresolved`）。裸の名前で起動しないのは、端末がタブのコマンドをログインの形で起動し、argv[0] が `-<名前>` になるため——argv[0] の名前で振り分ける shim（mise など）は、これを解けずに失敗する。絶対パスなら、argv[0] の末尾の名前が保たれる。

## 会話へ貼ってよいタブ

会話へ文字を貼って Enter を押すのは（解けた待ちの ⌘↵）、次のすべてを満たすタブだけ。

- agent が入力を受けられる状態（idle・done）を報告している。
- 報告を受けた時点の端末の前面のプロセスグループが報告者のグループで（＝報告した agent）、今も前面にいる。前面は libghostty が pty で読む（`tcgetpgrp`）。報告者のグループは、報告の接続の向こうのプロセス（`LOCAL_PEERPID`）から親へ辿って、最初に制御端末を持つプロセスのもの。報告者は応答まで接続を保つ（待ちには上限がある。[notify](notify.md) の `orbe-report` の契約）ので、上限の内に Orbe が接続を受け取れば報告者は生きている。
- そのプロセスグループに止まったプロセスが無い。

agent が終わった・Ctrl+Z で止めた後の前面は、シェルか止まった agent。前面の照合でシェルへのコマンドの実行を、止まりの照合で止まった agent の入力に溜まることを防ぐ。手で起こしたか、タブのコマンドとして起こしたか、終了を報告する CLI かを問わない。AI が判断して呼ぶ `prompt_agent` はこの判定を使わない。

報告者のグループで照合するので、次の報告は前面を覚えない（そのタブの会話へは貼らない）。

- tmux・screen の中の agent の報告。agent が属する端末はペインで、タブの前面（tmux のクライアント）は報告者のグループではない。tmux はタブの環境をペインへ配るので、報告はそのタブを名乗る。
- 前面が替わった後に届いた報告（報告が届く前に Ctrl+Z を押した）。辿るのを制御端末を持つ最初のプロセスで止めるので、agent を起こしたシェルは報告者のグループにならない。

hook を制御端末から切り離して（setsid で）起こす CLI でも、辿れば agent に当たる。

## デフォルトの永続

`default-agent` は他設定と同じ均一レイヤに載り、global は settings、workspace は当該 WS の上書き層に保存する。起動パレット ⌘⇧A・オンボーディングの「デフォルトに設定」は WS 文脈を持たないため、**global スコープの設定変更**へ一本化する。設定パレットの agent サブパレットは他項目と同じ経路で、workspace スコープなら上書きを書ける（→ [settings](../palette/settings.md)）。

## 裏で回す

タブを開かずに非対話で回せるのは claude だけで、codex・agy は理由付きで断る。引数の契約・使えるツールの絞り方・最終応答の取り出しは [裏で回す仕組み](../platform/background.md)。
