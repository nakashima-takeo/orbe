# 秘書

秘書は、[Home](../platform/workspace.md#home) に住む claude の会話 1 本。人は[タスク画面](../palette/tasks.md)（⌘⇧X）で打った文やタスクを ⌘↵ で頼み、秘書がそれを片付ける——タスクを書き、[`start_task`](../control/api.md) で agent を作業に取り掛からせ、進み具合を見る。人は頼むために秘書のタブへ移る必要も、秘書の手が今空いているかを気にする必要もない。Orbe が頼みを溜め、秘書を起こし、手が空くたびに 1 件ずつ届ける。

これを担うのは窓に 1 つの係。頼みを受けて溜め、秘書のタブを探し、無ければ起こし、手が空いていれば届ける。Home で人が手で起こした claude や、`start_task` が起こした agent は秘書ではない。

## 秘書の同一性

秘書は「Orbe が秘書として起こした claude のプロセス」（のタブ）。Orbe が起こすのは 2 つ——新しい claude を起こしたとき（係）と、秘書の会話を再開したとき。再開はどの経路でも（係の再開・休眠のタブの起床・[続きから](../palette/tasks.md#解けた待ちの-t--会話を続きから)・`resume_agent`）同じ組み立て（休眠のタブの起床）を通り、そこで秘書の役割の指示を添えて、そのタブを秘書として覚える。プロセスが終わればタブも閉じ、そのタブは秘書でなくなる（タブの ID は起動ごとに振り直すので、メモリにだけ持つ）。

人が Home のシェルで手で再開した秘書の会話のタブは、秘書と見なさない。会話 ID で見分けると、手で再開して終えた後のシェルや、同じタブで別に起こした claude を秘書と取り違え、頼みをそこへ貼るため。

会話 ID は、秘書のタブが報告するたびに書き直して保存する——/clear で同じプロセスの中で会話が替わっても秘書を見失わず、新しい会話がそのまま秘書の会話になる。会話 ID を使うのは、再起動の後に休眠している秘書のタブを見つける鍵（休眠のタブだけを全タブから探す。人が同じ会話を手で開いて動かしていても、休眠の秘書のタブを見つける）と、タブが無いときに再開する鍵だけ。見つけた休眠のタブは、起こすときに秘書として覚える。

`resume_agent` に、生きているタブで既に開いている会話（秘書の会話を含む）を渡すと、新しく起こさずそのタブを返す（[control/api](../control/api.md)）。秘書の座は移らない。

## 起こす

起こすのは、頼まれたときと、Orbe の起動時に届けていない頼みが溜まっているとき（agent の検出が済んだ後に 1 度）だけ。頼む前に秘書が起きていることはない。人が秘書のタブを閉じても勝手には起こし直さず、次に頼んだときに起こす。

起こし方は 3 通り。どれも Home のフォルダで、人が見ている workspace とタブを変えずに（選ばずに）起こす——Home が背景なら前面化せずに起こし、前面なら隠れタブとして起こす（前面の Home にタブがそれしか無いときだけは、選んで見せる）。

| 状態 | 起こし方 |
|---|---|
| 覚えた会話が無い | 新しいタブで claude を起こす |
| 覚えた会話はあるが、それを持つタブが無い | 新しいタブでその会話を再開する |
| 秘書のタブが休眠している | そのタブだけを起こす（起こす時点で再開が走る） |

秘書は claude 固定。claude が検出されていなければ頼みを受けない（タスク画面のフッターに赤で理由が出て、打った文は残る）。

### 再開できない会話

claude が会話の記録を消すと、覚えた会話は再開できなくなる。覚えた会話で起こしたタブ（新しいタブでの再開・休眠のタブの起床）が、会話を報告しないまま claude が終わって閉じたら、その会話はもう再開できないとみなして記録から外し、溜めがあれば新しい claude で 1 度だけ起こし直す。前の会話の文脈は失われるが、頼みが届かないまま止まり続けることはない。人や制御 API がタブを閉じたときは、報告の前でも会話を外さない（閉じたのは人の意思で、会話が壊れた証ではない）。

新しく起こしたタブが同じく会話を報告しないまま閉じても（claude が起きられない）、起こし直さない——起こし続けないため。溜めは残り、次に頼んだときにまた起こす。

## 秘書の役割の指示

秘書の役割は、秘書の会話を起こすときにだけ、claude の起動に追加の指示（`--append-system-prompt`）として添える。3 通りの起こし方のすべてと、秘書の会話をほかの経路で再開したとき（人が Home を開いて休眠の秘書のタブを起こした・続きから・`resume_agent`）に添える。

- **Home の rules に書かない**のは、rules は Home で動く全員が読むので、タスクの作業場で動く agent や人が手で起こした claude まで自分を秘書だと思うため（[Home](../platform/workspace.md#home)）。
- **会話の最初のメッセージで渡さない**のは、/clear で消えるため。起動の指示ならプロセスが続く限り効く。
- 再開した会話には、claude が最初に記録した指示が compact まで使われ続ける（再開時に添えた指示が効くのは compact の後か新しい会話から）。UI の言語の切り替えや指示の改版は、既存の秘書の会話には compact までは届かない。それでも再開のたびに添えるのは、compact の後に指示を組み直す元になるため。

指示は Orbe が UI の言語（日本語／英語）で持つ。骨子:

- あなたは Orbe の秘書。人の頼みを片付ける。頼まれていない間は何もしない。
- 頼みは Orbe が「⌘⇧X から · 時刻 — 本文」の 1 行で届ける。
- 自分が付けた待ちの条件が解けて人が続きを頼むと、「待ちの条件 · 時刻 — 起きたこと」の 1 行で届く。
- 「タスク N「…」を頼む」は、そのタスクを対象に動き、新しいタスクは作らない。補足があれば従い、無ければタスクの内容から判断し、迷えば人に聞く。
- 新しいタスク・並び・期限は、頼まれたときだけ書く。それ以外は提案にとどめる。
- タスクを足すとき、リポジトリの作業ならその workspace に付ける。リポジトリに属さないなら workspace を省く（Home に付く）。
- 作業に取り掛からせるときは `start_task` を使う。長い作業を自分で抱え込まず、agent に任せて進み具合を見る。

## 届ける

届けるのは、手が空いた秘書のタブへ 1 件を貼り付けて Enter を押す、この 1 通りだけ。

- **手が空いた**: 会話へ今貼ってよく（[会話へ貼ってよいタブ](launch.md#会話へ貼ってよいタブ)——idle か done で、報告した claude が端末の前面で止まらずに動いている）、前に送ったならその後に状態が変わっていること。送った頼みで claude は working を経て done を報告するので、done の状態変化が送った時刻を越えた時点で次の 1 件を送れる。作業中・入力待ち・まだ状態の報告が無い・Ctrl+Z で止めたタブには送らない。止めた claude が動き出したら、次の一巡（状態の報告・画面の更新）で届ける。
- **起こした直後も、最初の idle を待ってから貼る。** 届け方を 1 通りにすることで、「送った後のターンが終わるまで次を送らない」を 1 つの規則で守れる——最初の頼みを起動の引数で渡すと、起動直後の idle を「手が空いた」と取り違えて 2 件目を重ねる。
- **1 件ずつ・1 行で届ける。** 複数行を貼ると claude が「[Pasted text]」に畳み、出どころが見えなくなるため。
- **届いた確証は、貼った後の working（UserPromptSubmit）の報告。** 確証は報告が届いた直後に見る。確証が無いまま次の状態の変化（idle・done）が来たら、同じ頼みを送り直す——claude の対話（フォルダの信頼・要約から再開）が出ていると、貼った文字は入力欄に届かず、対話への入力になる。

1 行の形:

- 打った文: 「⌘⇧X から · 10:31 — 見積もりを山田さんに送る」
- タスク: 「⌘⇧X から · 10:31 — タスク 12「Dispatch: …」(owner/name#218) を頼む。補足: 直して PR まで出して」。主の結び付きが無ければ括弧を省き、補足が空なら「補足:」ごと省く。
- 秘書が付けた待ちの続きから: 「待ちの条件 · 10:31 — 」の後に、続きからの最初の入力（[タスク画面](../palette/tasks.md#解けた待ちの-t--会話を続きから)）を 1 行に畳んだもの。

本文は受けた時点に UI の言語で組んで固定する（タスクのタイトルと主の結び付きは、受けた時点の値）。改行や連続する空白は 1 つの空白に畳む。時刻は受けた時刻で、届ける日と違えば日付も付ける（「10/9 18:02」）。

## 溜める

頼みは受けた瞬間に溜めの列の末尾に足して、state フォルダの `secretary.json` に保存し（[persistence](../platform/persistence.md)）、届いた確証を見た瞬間に列から外して保存する。Orbe を終了しても、届いていない頼みは消えず、次の起動で秘書を起こして届ける（貼った直後に終了すると、届いていても次の起動でもう 1 度届きうる）。

頼んだ時点で秘書が作業中・入力待ちか、先に溜めがあれば、タスク画面のフッターは「秘書に頼んだ — 手が空いたら届く」と言う。

## 応えない秘書を知らせる

秘書のタブは選ばずに起こすので、claude がそこで人の答えを待っていても人には見えない。起こしてから最初の報告が、貼ってから届いた確証が、30 秒のうちに来なければ、秘書のタブを指す知らせを出す——メニューバーの滲み出しピル（印は入力待ちのグリフ、ワークスペース名は Home、本文「秘書が応答しない — タブで確かめる」）と入力待ちの音（[menubar](../chrome/menubar.md)・[sound](sound.md)）。ピルを押すと Orbe を前面にして秘書のタブへ移る。そのタブを見ているときは出さない。

## 限界

- **Home は claude の信頼が一度要る。** Home は Orbe が作る git の外のフォルダで、claude は未信頼のフォルダで最初に起きるとき、フォルダの信頼の対話を出して答えを待つ。Orbe は利用者の claude の設定（`~/.claude.json`）に触れないので、最初の頼みは秘書のタブで人が信頼に答えるまで届かない（応えない秘書の知らせが秘書のタブを指す）。Home を一度信頼すれば、その配下（タスクの作業場）も信頼済みになる。
- **長い会話を 1 時間ほど空けて再開すると、claude は「要約から再開」の対話を出す**（Pro / Max・10 万トークン超）。貼った頼みはその対話への入力になり、Enter で既定の選択肢が選ばれうる。頼みは溜めから消えず、確証が無いまま状態が変わるか、応えない秘書の知らせから人が答えた後に届く。対話で「Don't ask me again」を選べば以後は出ない。
- **人が秘書のターンを Esc で中断すると、溜めが止まる。** claude は中断で done を報告しないので、次に人が秘書へ何か送ってターンが終わるまで、溜めた頼みは出ない。API エラーで終わったターンは done になる（StopFailure）ので止まらない。
- **usage limit で止まったターンは終わりとみなさない。** claude はリセットを待って自分で続けるので、その間は溜めた頼みを貼らない（続きを打ち切らない）。待ちが続きなしに終わったら（`quota_auto_resume_disabled`）終わりとして次を届ける。自動の待ちが無い経路（API キーで使う claude・リセットが遠く待ちを始めない limit）では working が残り、Esc の中断と同じく溜めが止まる。
- **人が秘書の会話を手で別に開いていると、秘書の会話が 2 本になりうる。** 手で開いたタブは秘書と見なさないので、係はタブが無いときと同じく秘書の会話を別に再開する。
- **貼り付けた瞬間に人が秘書のタブで打っていると、文が混ざる**（`prompt_agent` と同じ）。
- **溜めた頼みの一覧や取り消しの画面は無い。** 見えるのは頼んだ直後のフッターだけ。
- **秘書の役割の指示がプロセス一覧に見える**（起動の引数のため）。中身は Orbe の定型文で、秘密を含まない。
