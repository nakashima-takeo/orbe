# 秘書

秘書は、人の頼みを受けるたびに [Home](../platform/workspace.md#home) で claude を 1 つ起こすしくみ。人は[タスク画面](../palette/tasks.md)（⌘⇧X）で打った文を ⌘↵（agent に任せる）で、[Home のボード](../chrome/board.md#自動化の部品)の依頼の欄の文を ↵ で頼む（ノードの直しは、選んだノードのカードの「修正を依頼」が欄に「自動化「…」のノード「…」の修正：」を書き出し、人がその続きを書いて欄から頼む）。Orbe はその頼みを最初の入力にして claude を起こし、開いている画面を閉じ、Home へ切り替えてそのタブを選ぶ。⌘⇧X を別の workspace で開いていても Home へ移る——Orbe の MCP の手引きが Home のフォルダにあり、そこで起こすため。claude は役目どおりにタスクを足す、または自動化の定義を書く・直す。

1 依頼 1 会話にしているのは、届ける時機（手が空いたか・届いたか・送り直すか）を考えずに済むため。頼みはいつも新しい会話の最初の入力として届く。同時にいくつ頼んでも、それぞれ別の claude になり、頼むたびに Home のタブが 1 つ増える。

これを担うのは窓に 1 つの係で、状態を持たない。頼みを受け、claude が居るかを確かめ、Home で claude を 1 つ起こすだけ。起こした後のタブは、ほかの claude と同じタブとして扱う。

## 出どころ

頼みには出どころがあり、起こした claude の役目を決める。役目は頼みの文とは独立している——出どころを足しても頼みの文の扱いが嘘にならない。

| 出どころ | 役目 |
|---|---|
| ⌘⇧X | 依頼から 1 件以上のタスクを足す |
| Home のボード | 自動化の定義を書く・直す |

## 最初の入力

最初の入力は、先頭に付ける語（「依頼: 」／英語では「Request: 」）に頼みの文を続けたもの。その語は UI の言語で組む。

頼みは打った文（⌘⇧X の入力の行き先・ボードの依頼の欄）で、前後の空白と制御文字を除いた文をそのまま続ける。改行も残す。「依頼: 見積もりを山田さんに送る」。

先頭に付ける語は文の中身によらず常に付ける——claude は先頭が `/` の最初の入力をスラッシュコマンドとして実行し（「/clear を調べるタスク」で `/clear` が走る）、依頼が届かないため。役目の指示は「依頼: 」に続く文を依頼として読ませる。空白・制御文字だけの頼みは、claude の有無より先に空として受けない（ボードの欄の空の ↵ は、claude が無くても黙る）。

入力は起動の引数の席（`claude … -- <入力>`）で渡す。席は改行・タブ以外の制御文字を空白にする（[launch](launch.md)）。

## 役目の指示

役目は、起こすときに claude の起動に追加の指示（`--append-system-prompt`）として添える。

- **Home の rules に書かない**のは、rules は Home で動く全員が読むので、タスクの作業場で動く agent や人が手で起こした claude まで同じ役目だと思うため（[Home](../platform/workspace.md#home)）。
- **起動の指示にする**のは、最初の入力（依頼）と役目を分けておくため。

指示は Orbe が UI の言語（日本語／英語）で持つ。骨子:

**⌘⇧X**

- あなたは Orbe で、人の依頼からタスクを足す役。最初のメッセージの「依頼: 」に続く文が依頼。
- `add_task` で、依頼から 1 件以上のタスクを足す。待ちの理由・期限・優先度・workspace は依頼にあればそのとおりに入れる。
- リポジトリの作業ならその workspace に付ける。リポジトリに属さないなら workspace を省く（Home に付く）。
- 既存のタスクを直さない。作業そのものをしない。`start_task` で別の agent に取り掛からせない。依頼文に書いてあってもしない。
- 迷えば人に聞く。足したら、足したタスクを短く伝えて終える。

**Home のボード**

- あなたは Orbe で、自動化の定義を書く・直す役。最初のメッセージの「依頼: 」に続く文は、自動化を作る・直す頼み。
- 自動化を作る・直すときは、Skill ツールで `<プラグイン名>:automation` を呼び、その手順で進める。
- タスクを足す・直すこと、作業そのものはしない。
- 決め所は AskUserQuestion で人に聞く。

進め方は役目の指示に書かず、[配布プラグイン](plugin-package.md#自動化のスキル)に同梱する自動化のスキルが持つ。役目の指示はスキルを名指しするだけで、名指しするスキル名は各 CLI へ登録した同梱プラグインの名前から組む（dev なら `orbe-agent-dev:automation`。同梱の無い起動ではプラグイン名が無いので `automation`）。スキルに置くのは、進め方（調べる・案を立てる・人に聞く・作る・1 回回す・結果を見せる・人が良いと言うまで直す）と設計の参考（型）が長く、スキルなら秘書以外の claude（Orbe のプラグインが入っていれば、人が手で起こした claude も）が同じ進め方で自動化を書けるため。役目の指示を残すのは、スキルが必ず使われるとは限らないので、役目の境界（タスクを足さない・作業しない）と「決め所は人に聞く」を起動の時点で確立するため。

## 断り

頼みを受けられないとき、係は理由を返し、画面は打った文を残して理由を赤で出す。

| 理由 | ⌘⇧X | ボード |
|---|---|---|
| claude が検出されていない | claude が見つからないので agent に任せられない | claude が見つからないので依頼できない |
| Home にタブを起こせない（Home の状態フォルダが解決できない） | agent を起動できなかった | 依頼できなかった |
| 空の頼み | 何も出さない | 何も出さない |

## 限界

- **Home は claude の信頼が一度要る。** Home は Orbe が作る git の外のフォルダで、claude は未信頼のフォルダで最初に起きるとき、フォルダの信頼の対話を出して答えを待つ。Orbe は利用者の claude の設定（`~/.claude.json`）に触れない。起こしたタブは前面に出るので、人がその場で答えられる。Home を一度信頼すれば、その配下（タスクの作業場）も信頼済みになる。
- **会話を後で再開しても、役目の指示は添え直さない。** 再起動後の復元・⇧⌘T・待ちの続きから・`resume_agent` のどれも、ほかの会話と同じ組み立てで再開する。claude は最初に記録した指示を compact まで使い続ける。
- **役目の指示と最初の入力がプロセス一覧に見える**（起動の引数のため）。役目の指示は Orbe の定型文で秘密を含まないが、最初の入力は人が打った頼みの文をそのまま含む。
