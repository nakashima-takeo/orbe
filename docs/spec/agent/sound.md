# エージェント通知音

エージェントの状態変化を音でも知らせる。画面を見ていなくても「終わった」「訊かれている」が分かるようにするための面で、状態の視覚表示（タブのグリフ・メニューバー投影・Attention パレット）と同じ単一情報源（[notify](notify.md)）から鳴る。

## 何をきっかけに鳴るか

報告が `waiting` / `done` への**実変化**を告げたときだけ。同じ状態の連続報告では鳴らない。`working` / `idle` では鳴らない。復元時の再設定や、`done` のペインを見たときのフォーカス消費でも鳴らない——**状態が動いた瞬間だけが音の契機**で、画面の再構成は契機ではない。

きっかけの条件はメニューバーの滲み出しピル（[menubar](../chrome/menubar.md)）と同一。

## どのペインで鳴るか

**見ているタブのペインでは鳴らない**。端末にその結果もプロンプトも出ている面で、注意を二重に奪わないため。粒度はタブなので、split で隣に見えているペインも鳴らない側に入る。ウィンドウが背面なら「見ているタブ」は無く、どのペインでも鳴る。

未activatedタブのペインでは鳴らない。Attention パレットとメニューバーも同じく、materializeを開始したタブのライブペインだけを対象にするため、**一覧のどこにも現れない音**は作らない。背景workspaceへ明示的に新規作成され、その場でmaterializeされたタブは対象に入り、workspaceを前面化していなくても鳴る。

「見ていないペインで起きた実変化」は 1 つの通知として一度だけ組まれ、音と滲み出しピルはその通知を映す 2 つの面——鳴る条件も読む設定（発信元 workspace の実効値）も面ごとに判断しない。「見ているか」の定義は `done` バッジのフォーカス消費とも同一で、目に映っているかの定義を 1 つに保つ。

## 何が鳴るか

音は 12 案（硝子 / 電紫 / 木肌 / 気配 / 紋章 / 返事 / 弾み / 遊技 / 鋼 / 洋琴 / 口笛 / 深層）＋**カスタム**（手持ちの音声ファイル）の 13 択。**案は音の性格を決め、`done` と `waiting` の 2 つの音を持つ**。同じ案の 2 つは音色を共有し、音形だけが違う——どの案を選んでも、2 つの音が同じ相棒の声として聞こえる。

12 案はアプリがその場で合成する。音量は合成の途中に掛かり、下げると同時に圧縮も浅くなって、単に小さくするのとは違う鳴り方になる。

全 24 音は聴感上の音量が揃うよう整合してある——案を切り替えても鳴りの強さは変わらず、選択は音の性格だけで決められる。

### カスタム音源（取り込み）

手持ちの音声ファイル（CoreAudio が読める形式）を音源にできる。ファイルは**選んだその場で取り込む**——デコードし、10 秒を超えていれば 10 秒で打ち切って末尾 200ms をフェードし、両端に数 ms のフェードを掛けてクリックを消し、12 案と同じラウドネス基準へ正規化して、アプリの領域（`sounds/` 配下・[persistence](../platform/persistence.md)）へ 48kHz モノラルの WAV として保存する。以後、元ファイルは一切見ない。

だからカスタム音源は 12 案と同じ性質を持つ。元ファイルを移動・改名・削除しても鳴り続け、音量は同じマスタ末尾（音量ゲイン → コンプレッサ）を通るので、案と切り替えても鳴りの強さも音量ノブの手応えも変わらない。差し替えたければ選び直す。読めないファイル・音が入っていないファイルは**選んだその場で理由を出して弾く**——鳴らす瞬間まで失敗が分からない状態を作らない。

`done` と `waiting` はそれぞれ別のファイルを指定できる。ただし既定では「入力待ちも完了と同じ音」のトグルがオンで、`waiting` は `done` の音源を鳴らす。トグルが左右するのは**どのファイルを引くか**だけ。

その event の音源が未設定なら、**紋章の同 event の音**で鳴る。トグルがオンでも `done` が未設定なら、`waiting` の報告は紋章の `waiting` 音になる（落ちても event は動かない）。手で書いた設定が実在しないファイルを指しているときも同じ規則。「鳴らない」状態の担体はオン/オフの 1 つだけ、という原則をカスタムでも崩さない。

取り込んだファイルの後始末は**参照集合の突き合わせ 1 本**。グローバル設定と全 workspace の上書きが指すファイル名を集め、`sounds/` の中でそこに無いものを消す。走るのは**参照集合が変わったとき**——カスタム音源の設定値が書き換わったときと workspace が消えたとき——で、順序は必ず「新しいファイルを書く → 設定値を差し替える → 突き合わせる」。突き合わせるのは**その時点の設定値**が指す集合で、**直前に書いた参照を必ず含む**（保存の完了は待たない）。手で編集した設定やクラッシュが残した孤児も、次に走ったときにまとめて回収される。

## 設定

設定パレット（[settings](../palette/settings.md)）に「通知音」「音量」「通知音のオン/オフ」の 3 行。いずれもグローバル / workspace 上書きの両スコープを持ち、**鳴らす音は発信元ペインの workspace の実効値**で決まる（どの workspace で起きたことかが音に出る）。既定はオンで、既定の案は紋章。root の「通知音」行はカスタム選択中なら「カスタム」を出す（オフのときは「なし」）。

カスタム音源の 3 項目（`done` の音源・`waiting` の音源・同一化トグル）も同じ設定機構に載り、両スコープ・制御 API・永続がそのまま効く（`orb config` は読み取りと解除まで——音源 2 項目は map なので、値を入れるのはパレットのファイル選択だけ）。ただし root には行を持たず、通知音サブのさらに奥（カスタム設定サブ）でだけ編集する——カスタムを選んでいない人の root に、効かないつまみを並べないため。

「鳴らない」状態の担体はオン/オフの 1 つだけ。音量は下限を持ち、絞り切っても無音にはならない——2 つの経路で「鳴らない」を表せると、どちらが効いているのか読めなくなるため。

音量の目盛りは **dB で等間隔**に刻む。1 つ動かせば、どの音量域にいても同じだけ変わる。％をそのまま倍率にすると、上端の 1 目盛りは聴き分けられないほど小さく、下端の 1 目盛りは音量が倍になるほど大きい——同じ操作の効きが場所で変わると、耳で合わせるのに何回押せばいいかが読めなくなる。macOS のシステム音量も同じ刻み方をしており、Orbe はその下でさらに狭い幅を細かく刻む。

音は聴いて選ぶ。通知音のサブパレットが試聴の面で、そこで `done` と `waiting` の両方を聴き分けられる（カスタムも案と同じように、確定後と同じ解決で鳴る → [settings](../palette/settings.md)）。**音量も耳で決める**——音量行で上げ下げすると、その音量で `done` が鳴る。音量は合成の途中に掛かって鳴り方そのものを変えるので、数字だけでは決められない。
