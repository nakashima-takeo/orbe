# エージェント通知音

エージェントの状態変化を音でも知らせる。画面を見ていなくても「終わった」「訊かれている」が分かるようにするための面で、状態の視覚表示（タブのグリフ・メニューバー投影・Attention パレット）と同じ単一情報源（[notify](notify.md)）から鳴る。

## 何をきっかけに鳴るか

報告が `waiting` / `done` への**実変化**を告げたときだけ。同じ状態の連続報告では鳴らない。`working` / `idle` では鳴らない。復元時の再設定や、`done` のペインを見たときのフォーカス消費でも鳴らない——**状態が動いた瞬間だけが音の契機**で、画面の再構成は契機ではない。

きっかけの条件はメニューバーの滲み出しピル（[menubar](../chrome/menubar.md)）と同一。

## どのペインで鳴るか

**見ているタブのペインでは鳴らない**。端末にその結果もプロンプトも出ている面で、注意を二重に奪わないため。粒度はタブなので、split で隣に見えているペインも鳴らない側に入る。ウィンドウが背面なら「見ているタブ」は無く、どのペインでも鳴る。

未activatedタブのペインでは鳴らない。Attention パレットとメニューバーも同じく、materializeを開始したタブのライブペインだけを対象にするため、**一覧のどこにも現れない音**は作らない。背景workspaceへ明示的に新規作成され、その場でmaterializeされたタブは対象に入り、workspaceを前面化していなくても鳴る。

「見ているか」の判定は、滲み出しピルの抑制と `done` バッジのフォーカス消費が共有するものと同一。目に映っているかの定義を 1 つに保つ。

## 何が鳴るか

音は 12 案（硝子 / 電紫 / 木肌 / 気配 / 紋章 / 返事 / 弾み / 遊技 / 鋼 / 洋琴 / 口笛 / 深層）。**案は音の性格を決め、`done` と `waiting` の 2 つの音を持つ**。同じ案の 2 つは音色を共有し、音形だけが違う——どの案を選んでも、2 つの音が同じ相棒の声として聞こえる。

音はアプリがその場で合成する。音声ファイルを持たないので、音量は合成の途中に掛かる。音量を下げると同時に圧縮も浅くなり、単に小さくするのとは違う鳴り方になる。

全 24 音は聴感上の音量が揃うよう整合してある——案を切り替えても鳴りの強さは変わらず、選択は音の性格だけで決められる。

## 設定

設定パレット（[settings](../palette/settings.md)）に「通知音」「音量」「通知音のオン/オフ」の 3 行。いずれもグローバル / workspace 上書きの両スコープを持ち、**鳴らす音は発信元ペインの workspace の実効値**で決まる（どの workspace で起きたことかが音に出る）。既定はオンで、既定の案は紋章。

「鳴らない」状態の担体はオン/オフの 1 つだけ。音量は下限を持ち、絞り切っても無音にはならない——2 つの経路で「鳴らない」を表せると、どちらが効いているのか読めなくなるため。

音量の目盛りは **dB で等間隔**に刻む。1 つ動かせば、どの音量域にいても同じだけ変わる。％をそのまま倍率にすると、上端の 1 目盛りは聴き分けられないほど小さく、下端の 1 目盛りは音量が倍になるほど大きい——同じ操作の効きが場所で変わると、耳で合わせるのに何回押せばいいかが読めなくなる。macOS のシステム音量も同じ刻み方をしており、Orbe はその下でさらに狭い幅を細かく刻む。

案は聴いて選ぶ。通知音のサブパレットが試聴の面で、そこで `done` と `waiting` の両方を聴き分けられる（→ [settings](../palette/settings.md)）。**音量も耳で決める**——音量行で上げ下げすると、その音量で `done` が鳴る。音量は合成の途中に掛かって鳴り方そのものを変えるので、数字だけでは決められない。
