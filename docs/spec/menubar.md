メニューバーに常駐アイテムを 1 個持つ。Attention の単一情報源（`AttentionStore`）をそのまま投影し、アプリ内の Attention パレットと同じ値を読む。目的は **Orbe を前面化せずに「今どのエージェントが待っているか」へ到達できること**。文言は現在言語に追従する（[localization](localization.md)）。

メニューバーはアプリのテーマ強制ではなく**システム外観**で描かれるため、アイテムの見えはシステムの Light/Dark に追従し、切替に即応する。静的な状態（①③④）のグリフ・数字は前景モノクロ（他の常駐メニューバーアイコンと同じ template 相当の見え）。アイテムの幅は常に content の内容幅そのもの——メニューバーは子ビューの制約を幅に読まないため、幅は content の intrinsic から明示反映する。

## 4 態

- **① 静か（要対応 0）**: 減光したブランドグリフのみ。`working` しかない間もここ（件数は `waiting`+`done` だけを数える）。
- **② 滲み出しピル（状態変化の瞬間）**: 行の中身が横へ滲み出るピル。出現時に波紋を 1 回。詳細は下節。
- **③ 収縮後（要対応 1 件以上）**: グリフ＋件数のピル。件数は `waiting`+`done` のみ。
- **④ ドロップダウン表示中**: ③のピル地を accent tint にして「開いている」ことを示す。

Reduce Motion では波紋と滲み出しのアニメーションを止める。②は静的表示で同じ時間出る（情報は落とさない）。

## ② 滲み出しピル

**立つ条件**: エージェント報告（[agent-notify](agent-notify.md)）が `waiting` / `done` への**実変化**のときだけ。同じ状態の連続報告では立たない。`working` は立てない。

加えて、そのペインが**見ているタブ**（→ [chrome](chrome.md)）にあるなら立てない——端末にその結果もプロンプトも出ている面で、注意だけを二重に奪わないため。粒度はタブなので、split で隣に見えているペインも立てない側に入る。抑制されるのはこのピルだけで、タブの状態グリフ・横断件数ストリップ・③の件数・④のドロップダウン・Attention パレットには従来どおり出る。

**中身**: ブランドグリフ・状態グリフ・ワークスペース名・hook 文言の先頭。文言を持たない報告ではタブタイトルを本文に据える。

**消える条件**: 表示時間 22 秒。ただしピルをホバーしている間は収縮せず、ホバーが外れてからの余韻ぶんだけ先送りする。②の間のアイテムクリックはピルを消して**該当ペインへ直行**する（Orbe 前面化＋そのペインへ focus。ドロップダウンは開かない）。表示中に別の変化が届けば行が差し替わり、波紋と滲み出しをやり直す（ただし立つ条件で抑制される変化は差し替えを起こさない）。

加えて、**ピルが指す行が一覧から外れた時点で取り下げる**——ピルは一覧の投影なので、そのペインが `working` へ戻った・`idle` へ落ちた・`clear` された・閉じられたときは 22 秒を待たずに消える。判定は行の再計算に相乗りする（→ 行の集合と更新）。行が残っている間の中身（ワークスペース名・本文）は更新しない——中身が変わるのは新しい変化の報告が立て直したときだけ。

**地とインク**: このピルだけは自前の不透明な暗地を持ち、その地に合わせてインクを解決する——メニューバーの実背景は壁紙由来の半透明で、地を透かす塗りでは文字も状態グリフも読めないため。

**幅の契約**: ピル全体に上限がある（メニューバーの他アイテムを圧迫しないため）。その内側予算を左から順に配り、

- ワークスペース名スロットは**自分の上限までの範囲で内容へハグ**する（上限いっぱいを占有しない。超えた分は省略）。
- 本文スロットは上限を宣言せず**残り予算を吸う**（超えた分は省略）。

つまり **ワークスペース名が短いほど本文が長く出る**。どちらのスロットも提案幅では膨らまない＝短い本文ならピルはそのぶん縮む（内容ハグ）。

## ④ ドロップダウン

**開く**: アイテムのクリック（②の間を除く）、または**背面からの ⌘⌘**（Accessibility / Input Monitoring のどちらかの権限があるときだけ。権限の付与・剥奪は前面化のたびに再評価する）。メニューバーが出ていない状況（フルスクリーン等）では no-op。前面時の ⌘⌘ はドロップダウンではなくアプリ内の Attention パレットを開く（本ページの範囲外）。

アプリを前面化せずに開き、パネル自身がキーになるので Esc / ⌘O を受ける。アイテム直下・右揃えに出し、画面端では可視領域へクランプする。**閉じる**: 外クリック・キー喪失・Esc・行クリック。

**中身**（上から）:

- `waiting` / `done` の行リスト。行の形は Attention パレットと共用（状態グリフ・ワークスペース名・タブタイトル・右端に経過時間、文言があれば下段に折り返し）。0 件なら「対応するものはありません」の 1 行。
- 区切り線の下に `working` の減光集約 1 行（件数とワークスペース名の列挙）。クリック不可。0 件なら出ない——**進行中はここに畳み、要対応だけを一覧に立てる**のがこの面の分け方。
- フッター: 「クリックでそのペインへ」＋「orbe を開く ⌘O」。
- 権限未付与のときだけ、その下に控えめなヒント 1 行。

**操作**: 行クリック＝Orbe を前面化してそのペインへ移動（workspace の activate ＋タブ選択＋ペイン focus）。⌘O とフッター右＝前面化のみ。権限ヒントのクリック＝前面化して設定パレットを開く（権限状態の行はそこにある → [settings-palette](settings-palette.md)）。

## 行の集合と更新

投影する行は **activate 済み workspace のライブペインのみ**（休眠 workspace は対象外）で、エージェント状態が `waiting` / `done` / `working` のペインを状態変化時刻の降順に並べる。`idle` と未報告は出さない。件数と一覧は `waiting`+`done` のみで、`working` は集約 1 行が受ける。

snapshot は chrome と同じ coalesce 契機で更新する（[chrome](chrome.md)）——メニューバー専用の走査タイミングは作らない。ドロップダウンの経過時間だけは表示中に自走する。
