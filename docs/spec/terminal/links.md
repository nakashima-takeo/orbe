# リンクを開く

端末上のリンクを ⌘クリックすると、libghostty が `OPEN_URL` アクションで host に URL 文字列を渡し、host（Orbe）が macOS の作法で開く。この action は常に処理済みを返し、libghostty のフォールバックオープナーは使わない。

リンクには由来が 2 種ある。`OPEN_URL` の `kind` がそれを区別し、Orbe はこの区別で開き方を分ける。

- **正規表現で検出したリンク**（`kind` が `unknown`／`text`／`html`）: libghostty が画面の文字列から http URL やファイルパスとして検出したもの。**見えている文字列そのものが対象**なので、隠された対象は存在しない。
- **OSC 8 ハイパーリンク**（`kind` が `osc8`。`printf '\e]8;;URL\e\\text\e]8;;\e\\'`）: 端末出力が表示文字列と別に URL を指定する。**見えている文字列と無関係な対象を仕込める**ので、端末出力を信頼しない経路に通す。

## 正規表現で検出したリンク

見えている文字列を対象として、判定を挟まず開く。画面に見えている文字がそのままリンク先なので、見た目と別の対象を仕込む偽装ができない。

- 解決は純関数: scheme 付きはそのまま URL、scheme 無しは `~` を展開してファイル URL とみなす。
- `kind==text` は既定エディタ（拡張子の既定アプリ → プレーンテキストの既定アプリの順）で開き、それ以外は URL の既定アプリで開く。

## OSC 8 ハイパーリンク

入力は URL 文字列だけ。判定は文字列・ローカル host 名の集合・ファイルシステムの状態だけから決まり、結果は 3 値。

| 判定 | 意味 |
|---|---|
| **allow** | Orbe が決めた開き先で開く。開き先は判定に含まれる。 |
| **confirm** | 対象と開き先アプリ名を見せて人が決める。任意のアプリを起動できる対象。 |
| **block** | 開かず、理由を示す。 |

### 規則（上から順に最初に当たったもの）

1. 不可視・制御・行分割文字を含む → **block（不可視文字）**。列挙ではなく Unicode の性質で断つ: 一般カテゴリが Other（制御・書式・私用・未割当・サロゲート）か Separator（U+0020 を除く空白・行・段落区切り）、または Default_Ignorable（ソフトハイフン・関数適用・異体字セレクタ・結合書記素接合子・タグ文字等）の文字。表示と実体が食い違う手口をパースの前に断つ。
2. scheme 無し・解釈不能 → **block（不正形式）**。相対参照を後段が勝手に解決しない。
3. `http`／`https`: host があれば **allow（URL の既定アプリ）**、無ければ **block（host 無しの web）**。
4. `mailto`: 宛先があれば **allow（URL の既定アプリ）**、無ければ **block（不正形式）**。
5. `file`:
   - query／fragment 付き → **block（不正形式）**。ファイルシステム上の対象を指さない。
   - host が空・`localhost`・**このマシンのホスト名**（`gethostname` の値。大文字小文字を区別しない）のどれでもない → **block（別ホストのファイル）**。coreutils `ls --hyperlink`・ripgrep `--hyperlink-format=default`・fd・cargo は同じ取り方で得たホスト名を host に置いた `file://` を出すので、ローカルと認める——ここが上流 Ghostty（空か `localhost` のみ）との差で、日常のファイルリンクを壊さないため。
   - `..` と symlink をすべて畳んだ実体が存在する通常ファイルかディレクトリでない（デバイス・ソケット等） → **block（存在しない／特殊ファイル）**。
   - 実体は次の「家族」の順で判定する（[ローカルファイルの開き先](#ローカルファイルの開き先)）。
6. それ以外の scheme（`vscode://`・`cursor://`・`man:` 等） → **confirm**。

### ローカルファイルの開き先

**危険はファイルの型ではなく、Launch Services がその型に選ぶ handler にある。** 拡張子の無い実行ファイルや `.command` は Terminal に、`.py` は IDLE に、`.jnlp` は Java に、`.configprofile` はプロファイル導入に、`.fileloc` は中で参照した先に渡る。だから Orbe はローカルファイルを Launch Services の型→handler 解決に渡さず、内容の家族ごとに開き先を自分で決める。判定は上から順。

1. **転送ファイル → block（転送／実行ファイル）**: 中身が別の対象を指すもの（`.webloc`・`.inetloc`・`.fileloc`・`.afploc`・`.url` 等、macOS が「保存された URL」と解する型と、Finder エイリアス）。
2. **VS Code 系のワークスペース（`.code-workspace`）→ confirm**: 中身はテキストだが、エディタはワークスペースとして開き、Cursor 等は信頼の確認なしにその中のタスクを自動実行する。テキストとしてエディタに渡さず、中身の判定より前で確認に回す。
3. **画像・PDF → allow（その型の既定アプリ）**: 既定アプリは型で引く（ファイルで引くと実行ビットで handler が化ける）。`.svg` は画像。
4. **テキスト → allow（GUI コードエディタ）**: macOS がテキストと解する型の通常ファイル（ソース・設定・ログ・`.html`・`.command`・`.py`・`.sh`・`.scpt`・`.jnlp`・`.configprofile`・`.js` を含む。実行ビットは見ない）。開き先は ⌘⇧E と**同じ解決**の GUI コードエディタ（→ [chrome/layout](../chrome/layout.md#gui-エディタ起動cmdshifte)）にファイルパスを渡す。エディタは実行しない。GUI エディタが見つからなければ plain text の既定アプリ（TextEdit 等）に明示的に渡す——テキストには安全な閲覧先が必ずあるので、確認や警告で止めない。
5. **型が無い・実行形式・音声/動画の通常ファイル → 中身で判定**: macOS に型が無い通常ファイル（`.zig`・`.rs`・`.go`・`.lock`・`.env`・`.conf`・Dockerfile 等）、実行形式と解される通常ファイル（拡張子が無く実行ビットが付いたシェルスクリプト等）、音声/動画と解される通常ファイル（`.ts` は TypeScript でも MPEG-2 TS と解される）は、ファイルの冒頭の中身が NUL を含まない UTF-8 ならテキスト（4 と同じ開き先）。そうでなければ型が無いものは confirm、音声/動画はその型の既定アプリ、実行形式は 6 へ。
6. **アプリ・実行形式 → block（転送／実行ファイル）**: `.app`・unix 実行形式（`/bin/ls` 等のバイナリ）・`.dylib`・`.o`・`.jar`・`.class`・`.exe` 等、macOS がアプリか実行可能と解する型で中身がテキストでないもの。ディレクトリ/バンドル（`.app`）は中身判定の対象外で常に block。
7. **フォルダ（package でないディレクトリ）→ allow（Finder でフォルダ自身を開く）**。
8. **それ以外 → confirm**: `.zip`・`.dmg`・`.pkg`・`.docx`・`.plist`・`.shortcut`・`.terminal`・`.prefPane`・`.saver`・`.scptd`・`.xcodeproj`・型の無いバイナリ等。**列挙の抜けは allow でなく confirm に落ちる**——新しい危険な型が現れても黙って開かない。confirm で開くときは Launch Services の handler に渡す（そのアプリ名を見せた上で人が決めている）。

### 確認・ブロックの見せ方

標準の警告ダイアログ（終了確認・エディタ未検出と同じ作法）。文言は surface の窓の現在言語で引き、窓が無ければ OS 追従。surface の窓があればシートで出し、無ければアプリモーダル。表示は libghostty からの通知の中では行わず、通知が返ってから改めて出す。

- **confirm**: 「端末出力のリンクを開きますか？」と開き先アプリ名（Launch Services の登録アプリ。無ければ「既定のアプリ」）、ボタンは「キャンセル（既定）」「開く」。
- **block**: 「Orbe はこのリンクを開きませんでした」と理由（不正形式・不可視文字・host 無しの web・別ホストのファイル・存在しない／特殊ファイル・転送／実行ファイルの 6 種）、ボタンは「OK」「リンクをコピー」。コピーするのは、`file` ならこのマシンで開けるローカルのパス、それ以外は表示と同じ元の文字列で、開く近道は作らない（ホスト名が変わった直後に自分のファイルが「別ホスト」と判定されたときの逃げ道もこれ）。

どちらも対象文字列を等幅・選択可の欄に出す。confirm の `file` は開く実体のパス、それ以外（block はすべて）は元の文字列——block では理由（別ホスト・query 等）が見えるように。不可視文字は `\u{XXXX}` に可視化する。Orbe はリンクのホバー表示を持たないので、このダイアログが真の対象を人に見せる唯一の場所。

### 境界

- 判定は ⌘クリック時に 1 回、同期に行う（存在確認・型取得・中身判定のファイル読みを伴う。ネットワークボリュームで待たされ得るが、判定を省く方が危険）。
- OSC 8 の `.html` はテキストとしてエディタで開く（ブラウザで描画しない）。判定を家族で閉じる単純さを取る。
- OSC 8 の検出自体は libghostty の `link-osc8`（既定 true）が持つ。無効化したいユーザーは `~/.config/ghostty` で切る。
- 正規表現で検出したリンクの挙動は OSC 8 の規則の影響を受けない。
