# レビューの送信

PR の diff で積んだ未送信のコメント（返信・新しいスレッド → [pull-request-comments](pull-request-comments.md)）と全体へのコメントを、1 つのレビューとして GitHub へ送る場所。PR の画面の上のバーの右端の「レビュー」のボタンから、バーの右下にポップアップを開く（置き場の共通の決まり → [shell](shell.md#バーの右下の置き場)）。左の列を閉じていても、本文を読みながらでも、マウスなしでも送れるようにするため。送る規則（選べる種類・送れるか・送れない理由・送信）は PR ごとの状態が持ち（→ [pull-request](pull-request.md)）、同じ PR を出すどの面でも同じ答えになる。寸法と色は [design-system](../../design/design-system.md) §5 の PR review popup。

## ボタン

「レビュー」のボタンは、PR の画面で、open の PR があって中身が読めている間だけ、バーの右端に出る。未送信のコメントがあれば、名前の後ろに吹き出しの印と数（注意の黄）を付ける——数は GitHub の数で、書き込みの後の読み直しで変わる。幅が足りなくても、ボタンも数も譲らない（→ [shell](shell.md#上のバー)）。押すとポップアップを開き、開いている間に押すと閉じる。開いている間は開いている姿になる。

レビューのやりとり（スレッドと、自分が作者か）を読めるまでは押せない姿にする——自分の PR かどうかが分からないと、種類を出すかを決められない。押せない間にレビューのやりとりの読みが失敗していれば、ツールチップにその文（「レビューのコメントを読み込めません（理由）」）を出す。ボタンの VoiceOver の名前は「レビュー」、未送信のコメントがあれば「レビュー、未送信のコメント N」。

PR の一覧（左の列）に焦点がある間の ⌘↑ も、ボタンを押したのと同じに開く——どの行を選んでいても、何も選んでいなくても。ボタンが押せない姿の間・既に開いている間は何もしない。左の列を閉じている間と、本文に焦点がある間は、キーでは開かない（ボタンを押す）。一覧でファイルを見る・⌘↑・書く・⌘↵（か esc）・↑↓ が、マウスなしで回る——閉じると焦点は開く前に在った一覧へ戻り、選択は開く前のまま。

## ポップアップの中身

上から次を並べる。

- **全体へのコメント**: 見出しと、枠つきの欄。↵ は改行で、10 行まで伸び、その先はスクロールする。取り消しの履歴は欄ごと。開くと欄に焦点が入る。
- **未送信のコメント N**: 数が 1 以上のときだけ。最後に読めたレビューのやりとりから、未送信のコメントを 1 件 1 行で並べる——`ファイル名:行` の札（行を持たないスレッドなら `ファイル名`）と、本文の先頭の 1 行（収まらなければ末尾を省く）。並びはパスの順 → 行の順（行を持たないものはそのファイルの最後）→ 書いた順。6 行まで見せ、越える分はこの区分の中でスクロールする。見出しの数は GitHub の数で、行は読めたスレッドから組む——1 スレッドのコメントは 100 件までしか読まないので、それを越えるスレッドに未送信のコメントがあると、数と行が食い違う（→ [GitHub の読み書き](../platform/github.md#レビューのやりとり)）。
- **現在の diff に表示できない未解決のスレッド N 件**: 今の diff に置けない未解決のスレッド（古い版の行に付いた・ファイル単位・rename の判定が GitHub と手元で食い違うファイルの古い側の行に付いた）があるときだけ。押すと GitHub の PR を開く——未解決の議論に気づかないまま承認しないため。解決済みは数えない。
- **下端**: 右寄せで、種類（コメント／承認／変更を依頼。既定はコメント）と「レビューを送信」とキーの札 ⌘↵。
- **下端の帯**: 送れない理由（弱い色）か、送信の失敗（赤）があるときだけ。

## 未送信のコメントの行から移る

今の diff に置ける行を押すと、ポップアップが閉じ、そのファイルの PR の diff が本体に出て（左の列の行を Enter で開くのと同じ——PR の一覧でその行を選び、焦点を本文へ移す）、その行とスレッドが見える位置に来る（行を中央に、収まらなければ行を上端に。古い側の行も、並びの中の位置へ送る）。畳んでいたスレッドは開く。diff が初めての位置を決める前なら、最初の変更区間の代わりにその行へ送り、同じファイルの diff が既に出ていれば、その場で送る（→ [diff](diff.md)）。

今の diff に置けない行（積んだ後に push があって行が古くなった・ファイル単位など）は、弱い色で出し、押すと GitHub の PR を開く——その場所へは移れない。diff の両端が分からない間は、置けるとみなす。

## 種類と色

種類は、選べる種類が 2 つ以上のときだけ出す。自分の PR では「コメント」しか選べない（GitHub が承認と変更の依頼をエラーで返す）ので、種類を出さず、返信をまとめて送るだけになる。レビューのやりとりを読めていない間は、ポップアップを開けない（前述）。

承認を選ぶと緑、変更を依頼を選ぶと黄で、ポップアップの縁・上側の色づけ・外の光と、送信のボタンの地を塗る。コメントは色を付けない（送信のボタンはアクセントの色）。

## 送れる条件と理由

送れるのは、PR が open で、「承認」か、全体へのコメントか未送信のコメントがあるときだけ（どちらも無ければ「コメント」と「変更を依頼」は送れない）。全体へのコメントは欄に見えている字（変換中の字を含む）で数え、空白と改行だけなら空とみなす（送るときも本文を付けない）。

送れるのは、PR の diff の両端を求め終え、その先頭のコミットで中身とレビューのやりとりも読んでいる間だけ——ファイルの列・diff・スレッドと、送るレビューの版を揃えるため（両方が新しい先頭へ一緒に読み直された直後の承認は、利用者がその版の diff を見たかに依らず通る）。揃っていない間は送信のボタンを押せない姿にし、下端の帯に理由を出す: 読み込んでいる・両端を求めている間は「PR の最新の内容を読み込むまで送信できません」、中身とレビューのやりとりの先頭が食い違ったまま揃える読みをやめた間は「PR の最新の内容を揃えて読めませんでした。再読込してください」、diff の両端を求められない間は「PR の diff を表示できないため、送信できません。再読込するか、GitHub で送信してください」（diff で確かめられない版へのレビューを Orbe から送らない。再読込で両端を求め直す → [pull-request](pull-request.md#diff-の両端)）。送るものが無いだけの間は、文を出さずに押せない姿にする。未送信のレビューが前の先頭に結ばれているときの承認の付き先は確かめていない（→ [pull-request-comments](pull-request-comments.md#限界)）。判定は PR ごとで、開いている diff の有無と数に依らない。

## 送信と結果

ボタンか ⌘↵ で送る。どちらも、変換中なら確定してから送る。⌘↵ は、焦点がポップアップの中にある間だけ送信になり、送れなければエラー音を鳴らし、押し続けたキーリピートは何もしない。diff の返信欄の ⌘↵ は「レビューに追加」で、送信にはならない。2 回押しても送信は 1 回。

- **送信中**: 欄（打てない）・種類・送信のボタンが押せない姿になる。ポップアップは開いたままで、閉じることはできる（送信は続く）。
- **通った**: ポップアップが閉じる（開いたときの PR のまま開いていれば）。書きかけを空にし、種類をコメントに戻す。未送信は 0 になり、ボタンの数が消える。
- **通らなかった**: 書きかけと種類を残し、開いていれば下端の赤い帯に失敗の文を出す（時間切れは、GitHub で反映されたかを確かめるよう告げる）。閉じていれば、バーの右下の札「レビューを送信できませんでした（理由）」に出す（→ [pull-request-panel](pull-request-panel.md#出せない理由と失敗)）。ポップアップを開くと札からは消えて帯で読め、閉じると札に戻る。失敗が消えるのは、札の × と次の送信のときだけ——時間切れの後に GitHub を確かめに行ってポップアップが閉じても、警告は残る。

## 書きかけの残り方

全体へのコメントの書きかけと選んだ種類は PR ごとの状態が持つ——ポップアップを閉じても、ほかの画面へ切り替えて戻っても、別の PR へ移って戻っても残り、アプリを終えると消える。変換中の字は、閉じるときに確定して書きかけに入る。

## PR が替わったとき・open でなくなったとき

ブランチの切り替えなどで worktree の今の PR が替わったとき、中身の読み直しで PR が open でなくなった（マージ・クローズ。ボタンを出さなくなった）ときは、ポップアップは閉じる——open でない PR へは送らない（diff のコメントが、open でない PR へ未送信のレビューに積む書き込みを断るのと同じ規則）。変換中の字は、開いていた PR（前の PR）の書きかけへ確定する——前の PR の字を次の PR の書きかけに入れない。中身は PR ごとに作り直す。
