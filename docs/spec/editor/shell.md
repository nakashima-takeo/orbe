# 面の骨

エディター面の中身の構造。端末の隣でファイルを選び、複数開いて切り替え、閉じ、作るための器で、文書のコードビュー（→ [code](code.md)）はこの骨の本体に載る。左からレール・サイドバー（エクスプローラーか[プロジェクト検索](search.md)のパネル）・列——列は上からファイルタブ行、パンくず、本体（焦点の文書のテキスト面。俯瞰（ミニマップ・スクロールバー）も面の中に描く。無ければ[面の機構](faces.md)の空状態）。骨は SwiftUI の部品で、幾何は面（AppKit）が解く——テキスト面は view の同一性と焦点の取り方に依存し、SwiftUI の再親化に晒せないため。

## サイドバーの幅と開閉とパネル

サイドバーの幅はドラッグで変えられる——サイドバーと本体の境（縁の線）に細い当たりがあり、掴むと連続で追従する。下限があり、上限は本体に最低幅（サイドバーの下限と同じ）が残るまで。開閉と、どのパネルを出すかはレールで決める（後述）。幅・開閉・パネルの記憶は**アプリ全体で 1 つ**（タブ・workspace をまたいで同じ。面の配置のようなタブ単位ではない）で、再起動でも戻る（→ [persistence](../platform/persistence.md) の app-state）。

サイドバーが見えるかは開閉だけで決まり、列幅は関係ない。列が狭いときは**表示幅を「列幅 − レール − 本体の最低幅」まで切り詰める**——記憶している幅は変えず、列が広がれば記憶の幅に戻る。それでも足りない極端な幅では残りをそのまま分け、サイドバーの表示幅は 0 まで縮む。当たりは境を動かせるときだけ出る——列が狭くてサイドバーを下限まで出せない間は境が動かないので、当たりも出ない。文書が無いときもファイルタブ行の帯は残り、本体に空状態が出る。寸法と色は [design-system](../../design/design-system.md) §5 の Rail / Explorer / Search panel / File tabs / Breadcrumb。

## レール

左端のアイコン列。項目は「ファイル」（エクスプローラー）と「検索」（→ [search](search.md)）で、サイドバーのパネルと 1 対 1。別の項目を押すとそのパネルへ切り替わり（閉じていれば開く）、出しているパネルの項目を押すと閉じる。検索を押して検索パネルが出たら入力欄に焦点が入る。エクスプローラーから離れると行内入力は終わる。選択は左縁の細い accent 線と淡い地で示し、サイドバーを閉じている間は選択印が無い——design-system §5 が「選択を左バーで示すのはエディター面のレールだけ。chrome ではどこでもしない」と定める、その 1 か所。

## エクスプローラー

タブの根（cwd が属する git worktree ルート。管理外は cwd → [files](files.md)）の実ファイルを描く。展示データは持たない。

- **ルート行**は根の basename を大文字で出し、クリックで根の開閉。ヘッダー右端に 新規ファイル／新規フォルダ／すべて折りたたむ の 3 ボタン。
- **ツリー**はディレクトリを先に、あとは名前順——大小とアクセントを無視し、数を数として比べる（Finder と同じ。`file2` が `file10` より前）。この比べ方は検索結果の並びと 1 つを共有する。ディレクトリはシェブロン（クリックで開閉）、ファイルは種別チップ（種別 → 見た目の決定点は 1 か所で、15 言語は色相付き、未知は拡張子の頭文字の無彩、拡張子が無ければ `·`）。ファイル行の右端に git バッジ——M（変更）・A（追加）・U（未追跡）・C（競合）——を出し、**名前もバッジの色**で描く。色は A・U が git の追加の青、M が git の変更の黄で、赤と緑に頼らない（→ [design-system](../../design/design-system.md) §3）。ディレクトリ行はバッジを持たず、配下の集約もしない。
- **展開は面の状態**で永続しない。一覧は展開したディレクトリだけ遅延で取り、監視の通知（→ [files](files.md)）で変わったパスの親のうち展開中のものを取り直す。展開中のディレクトリが消えれば畳む。読めないディレクトリは空として畳む。
- **根のサービスは面が画面に見えている間だけ握る**（窓に付き、隠れていない）。隠れているタブや幅 0 の面は握らないので、全タブの根を常時監視しない。離すと監視は止まるが一覧と status の見え方は保ち、次に見えたときに握り直して展開中を取り直す。**status は最後に成功したもの**を保つ——握り直した直後（git が返るまで）も、git の一時失敗でも、バッジは消えない。根が変われば（cd）ツリーを作り直す。
- **ファイル行を押す**と仮のタブ（後述）で開き、2 回目の押下（ダブルクリック）で普通のタブにする。1 回目はダブルクリックの判定を待たずにすぐ開く——見て回るクリックに遅れを足さない。ダブルクリックの 1 回目は仮のタブを入れ替える（仮のタブがあれば、それは閉じる）。焦点は押すたびに本文へ移る（→ 焦点）。
- **文書をアクティブにしたとき**（ツリーのクリック・ファイルタブ・制御 API `open_file`・復元）、根の下ならツリーは祖先を開いてその行を選択表示し、可視位置へ送る。根の外の文書では選択を外す。パンくずのディレクトリを押しても同じく開いて選択する。
- **新規作成**はツリーの行内入力。挿す先は、選択がディレクトリならそこ、ファイルならその親、無ければ根で、その親の子の先頭に入力行が現れ、可視位置へ送る。続けて押せば前の入力は消えて新しい入力だけが出る。Enter で作り、ファイルならそのまま開く。空・`/` 入り・既に在る・作れない名前は音で断って入力に留まる。Esc と、焦点が別の view へ移ることで取り消す（変換中の Esc は変換だけを取り消す）。入力の終わりは入力の状態が落ちることで、理由を問わない（Enter・取り消しのほか、すべて折りたたむ・根を畳む・サイドバーを閉じる・cd など）。打ちかけの名前は入力の状態が持つ。中間ディレクトリは作らない。

## ファイルタブ行

セッションの文書の列（→ [code](code.md)）を自然幅のタブで並べ、溢れは横スクロール（スクローラーは出さず、アクティブが変われば可視位置へ）。タブはチップ・名前・右端の枠。枠には × か未保存のドット（外部変更と衝突中は注意の黄）を出す——VS Code のタブと同じく、アクティブのタブは × を常に、それ以外はタブにポインタがあるときだけ出し、未保存のタブは × 自体にポインタがあるときのほかは × の代わりにドットを出す（タブに乗っただけではドットのまま。未保存の印は閉じる直前まで見えている）。閉じられるタブと未保存のタブが一目で分かり、未保存の印と × が並んで幅を食わない。枠の幅は常に確保し、ポインタでレイアウトが動かない。クリックで切替（undo・選択・スクロールは文書ごとに残る）。× にポインタを乗せると枠に地が付いて × が明るくなり——押せる範囲に乗ったことが見える——枠のどこを押しても閉じる。アクティブは淡い地と上縁の accent 線で示す——レールと同じくエディター面の中だけの例外。右端に分割・その他の印は持たない。

### 仮のタブ

見るだけのファイルを開くたびにタブが積もらないよう、列の中に**仮のタブを高々 1 枚**持つ。仮のタブは名前を斜体にし、地にうっすらした斜線を敷く（アクティブなら淡い地の上。上縁の accent・× と未保存の枠・チップは普通のタブと同じ）。仮で開くと、仮のタブがあればその位置で新しいファイルに入れ替わり（前のファイルは閉じる）、無ければ末尾に足す。開いているファイルを仮で開き直しても焦点が移るだけで、普通のタブは普通のまま。仮で開けないファイル（読めない・UTF-8 でない）は音で断り、今の仮のタブは残る。

仮で開く入口は、エクスプローラーのファイル行のシングルクリックと、検索結果のシングルクリック・キーで一致へ動く・F4 / ⇧F4（→ [search](search.md)）。それ以外——検索結果のダブルクリックと Enter、エクスプローラーのダブルクリック、新規作成、Finder からのドロップ、制御 API `open_file`——は普通のタブで開き、そのファイルが仮のタブなら普通に変える。エージェントが `open_file` で見せたファイルを、人の次のクリックが黙って入れ替えないため。

仮のタブが普通のタブになるのは、本文を編集して未保存になった瞬間（打鍵・貼り付け・ドロップ・複数カーソルの編集など入口を問わない）、タブのダブルクリック、上の普通に開く入口で開き直したとき。未保存になった仮のタブはその場で普通に戻るので、入れ替えで編集が消えることは無く、未保存の確認に仮のタブは出てこない。普通のタブは仮に戻らない——保存しても、元に戻しても。未編集の仮のタブを ⌘S しても仮のまま。

## パンくず

焦点の文書の、根からのディレクトリ ›…› チップとファイル名。ディレクトリはホバーで文字が上がり、押すとツリーのそのフォルダが開く。根の外の文書は絶対パスの構成要素で、押せない。診断件数は持たない。文書が無ければパンくずの段は無い。

## 焦点

骨の操作で文書を開く・切り替える・新規作成を確定したら、焦点を面の焦点 view（テキスト面）へ移す——制御 API `open_file` と同じ結果で、分割中は面の記憶もエディターへ移る。× は焦点を動かさない（面の中に焦点があれば新しい行き先へ移るのは[コード](code.md)の規則。ただしサイドバー——検索結果・行内入力——にある焦点は、文書が切り替わっても動かない）。行内入力を出すときは先に面自身が first responder になる（入力欄は焦点を面が持っているときだけ取る）。入力欄は面の配下なので chrome キー（→ [layout](../chrome/layout.md)）は効いたまま、通常の打鍵は入力欄に入る。入力行が画面外に出て入力欄が消えている間は面が焦点を預かり（打ちかけは残る）、行が戻れば入力欄が取り直す——預かっている間に焦点が面の外へ移れば取り消す。入力が終わったとき焦点がまだ入力欄か面か窓に居れば面の焦点 view へ移す（端末をクリックして抜けて終わったなら端末のまま）。検索パネル（→ [search](search.md)）が隠れたときも、焦点がパネルにあれば同じ規則で面の焦点 view へ移す。

## 未保存を捨てる前の確認

未保存の文書を捨てる人の操作は 1 種類の確認——保存／保存しない／キャンセル——を挟む。入口は 3 つ: ファイルタブの ×（その文書 1 件）、人の操作でタブを閉じる（⌘W・タブ行の中クリック・workspace パレットの削除。そのタブ、または workspace の全タブの未保存を合計して 1 回）、アプリの終了（全 workspace の全タブの合計）。保存を選んで 1 つでも失敗すれば閉じない／終了しない——失敗はいずれも音で断り、外部変更（→ [files](files.md)）なら印が立ったまま残って ⌘S の上書きへ、書けない先（親ディレクトリの消失・読み取り専用・容量）ならそのまま。シェルの終了と制御 API による閉鎖（`close_tab`・`remove_workspace`）は確認せず黙って捨てる——プロセスは既に無く、無人の操作に確認は出せない。× とタブを閉じる確認は sheet で非同期に確定し（閉じる要求は main-queue のブロックから届くので、その中のモーダルは端末描画と制御 API を止める）、応答までにタブが消えていれば何もしない。終了の確認は実行中プロセスの確認と同じくモーダル。文言は現在言語。

## 外部変更の上書き

印の立った文書（→ [files](files.md)）の ⌘S は「ディスク上で変更されています」の確認を出し、上書きを選べば force で保存する。キャンセルなら何もしない。上書きは戻せないので Return では確定しない（クリックだけ。Esc はキャンセル）。上書きされるのは確認を出した文書——応答までに焦点が別の文書へ移っていても（エージェントの `open_file`）変わらず、その文書が閉じられていれば何もしない。上書きも通常の保存も書けない先（親ディレクトリの消失・読み取り専用・容量）で失敗すれば音で断り、印は立ったまま残る（エラー面は持たない）。

## 開いていた文書の復元

タブは開いている文書の実体パスの列とアクティブの実体パスと仮のタブの実体パスを永続する（→ [persistence](../platform/persistence.md)）。復元はタブが materialize されるときに起き、読めなくなったファイルは黙って落ちる（アクティブが落ちていれば先頭、仮のタブが落ちていれば仮のタブ無し）。仮のタブは仮のまま同じ位置に戻る——再起動のたびに見ていただけのタブが普通のタブとして積もらない。復元より先に開いていた文書があれば（制御 API の `open_file`）その焦点と開き方を保つ——復元は既に居るものを壊さず、普通に開いていた文書を仮に下げない。未保存の内容は戻らない。一度も見なかったタブは未消費の状態をそのまま書き戻すので、再起動を重ねても文書の列は失われない。

## VS Code との差

仮のタブは VS Code の preview editor を土台にし、次の点で違う。

- **エクスプローラーのシングルクリックは本文へ焦点を移す**（VS Code はエクスプローラーに残す）。エクスプローラーはキー操作を持たず、焦点を残すと打鍵が前に居た所（分割中なら端末）へ行くため。
- **入れ替えは仮のタブの位置で、無ければ末尾**（VS Code はアクティブなタブの右）。結果をたどる間タブが動かず、新しく開いた文書は末尾という列の規則とも食い違わない。
- **仮のタブを切る設定と、固定のキー（VS Code の ⌘K Enter）は持たない**。固定はダブルクリックか編集で足り、覚える近道を増やさない。
- **押し続けた ↑↓ は離すまで開かない**（VS Code は時間だけで間引くので、初期遅延の間やリピートの間隔が窓より長いときに窓が切れて開く）。→ [search](search.md)
- **斜体に斜線の地を足す**（VS Code は斜体だけ）。斜体だけでは普通のタブと見分けにくく、日本語名・絵文字では斜体が効かない字もあるため。
