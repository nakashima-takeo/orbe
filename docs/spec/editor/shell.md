# 面の骨

エディター面の中身の構造。端末の上に重ねた面で、作業ツリーの変更・今のブランチの PR・ファイルを、3 つの画面に分けて読み、直し、作るための器で、文書のコードビュー（→ [code](code.md)）と diff（→ [diff](diff.md)）はこの骨の本体に載る。上に全幅の**上のバー**（下端に線）、その下に**左の列**（開いているとき。エクスプローラー・[プロジェクト検索](search.md)・[ソース管理](source-control.md)・[PR](pull-request-panel.md)のパネル）と**本体**（画面の中身——文書のテキスト面か diff の面。俯瞰（ミニマップ・スクロールバー）も面の中に描く。出すものが無い・表示できなければ見出しと案内の一文 → [面の機構](faces.md)の面の中身と空状態）が並ぶ。骨は SwiftUI の部品で、幾何は面（AppKit）が解く——テキスト面は view の同一性と焦点の取り方に依存し、SwiftUI の再親化に晒せないため。上のバーより下（左の列・本体・境の当たり・ファイル内検索のバー）は 1 枚にまとまっていて、⌥ の透かしはそこだけを見えなくする（→ [faces](faces.md) の ⌥ で端末を透かす）。

## 画面と本体

連は**画面**——Changes（作業ツリーの変更）・PR（今のブランチの PR）・Files（開いている文書）——を 1 つ選んで持ち、本体と左の列の中身は画面で決まる。本体は Files なら今の文書、Changes なら Changes の diff（作業ツリー diff かステージ済み diff。→ [diff](diff.md)）、PR なら PR の diff で、どれも無ければ空。diff の本体は、上端にそのファイルの見出しの帯を持つ（→ [diff](diff.md#見出し)）。画面を切り替えて戻ると、元の画面の本体（開いていた diff・今の文書）と、その位置・選択・左の列の一覧の選択とスクロール位置が残っている。

画面を選ぶまでは、連の根が git の worktree の根なら Changes、そうでなければ Files で開く（連のキーを決めるのと同じ規則で、開いた瞬間に分かる）。根が cd で付け替わったときも、選ぶまでの画面を新しい根で決め直す。画面を選んだことになるのは、人と制御 API の入口だけ——上のバーの切り替えを押す・ツリーや検索結果や一覧の行から開く・新規作成・Finder からのドロップ・ソース管理の行の「ファイルを開く」・diff の見出しの「ファイルを開く」・⌘⇧F・F4 / ⇧F4・制御 API `open_file` / `open_diff`。開けなかったとき（読めない・テキスト面を作れない）は画面を選ばない。Changes を出したときに diff が自動で開く（→ [source-control](source-control.md)）・復元・cd での連の吸収は、選んだことにならない——⌘E を押しただけの連は、その連の最後のタブが git 管理外のフォルダへ cd すれば Files で開く。選んだ画面は連ごとに覚え、再起動で戻る（後述の復元）。

## 上のバー

面の上端に全幅で置く 1 段。左から次を並べる。寸法と色は [design-system](../../design/design-system.md) §5 の Editor bar。

- **左の列の開閉**: 押すと左の列を開閉する（後述の左の列の開閉）。開いている間は押された姿で、ツールチップは開いていれば「サイドバーを閉じる」、閉じていれば「サイドバーを開く」（どの画面でも同じ名前）。
- **画面の切り替え** `Changes`・`PR`・`Files`: 押すとその画面を選ぶ。選んでいる画面の項目は選択の姿。`Changes` にはソース管理の件数（→ [source-control](source-control.md#件数)）を、`PR` には今のブランチの open の PR の番号（`#N`。→ [pull-request](pull-request.md) の worktree の今の PR）を添える。件数は変更が無い・git 管理外なら出さず、番号は PR があるときだけ出す。どちらも、ほかの画面に居ても・左の列を閉じていても、面が見えている間は追従する——番号は、PR の画面を一度も出していなくてもエディターを開けば出る。
- **今のファイルのボタン**（区切り線の後）: Files の画面で今の文書があるとき、その文書の種別チップ・親のパス・名前を出す。親のパスは、根の下なら根からの相対のディレクトリをすべて、根の外なら `~` で縮めた絶対のディレクトリ。文書が未保存なら白い丸、「ディスクが変わった」（→ [files](files.md)）が立っていれば黄の丸を名前の後ろに出す——後者は未保存かどうかに依らない。押すと開いているファイルの一覧を開閉する（後述）。左の列を閉じていても出る。文書が 1 つも無いときは出ない。Changes と PR の画面では、左の列を閉じていて本体が diff のときだけ出て、その diff のファイルの状態の字（左の列の行と同じ字と色）と名前を出す——ディレクトリと印の丸（未保存・ディスクが変わった）は、すぐ下の diff の見出しに出ているので出さない。押すと変更ファイルの一覧を開閉する（後述）。左の列を開く・Files へ切り替える・diff が無くなる、のどれかで消える。
- **「プレビュー」の札と「開いたままにする」**: 今の文書が仮の文書（後述）のとき、ボタンの名前を斜体にし、ボタンの右に出す。「開いたままにする」を押すと普通の文書になり、札とボタンが消える。焦点は動かない。このボタンには、検索結果の列（→ [search](search.md)）に焦点がある間だけキーの札 ↵ が付く——そこでは ↵ が一致を普通の文書として開くので、札の示す操作と ↵ の操作が一致する。本文・検索の入力欄・ファイル内検索の欄・開いている一覧にある間の ↵ は別の操作（改行・検索し直す・次の一致・切り替え）なので、札を出さない。本文の ↵ は、仮の文書でも改行のまま。
- **Changes の部品**（git 管理下と分かっている間だけ）: 今の項目の後ろに、ブランチ名の札（前に区切り線）と同期のボタン、右端に「コミット」（押すとバーの右下にコミットのポップアップを開閉する）。中身は → [source-control](source-control.md#上のバーの部品)。
- **「⌥ 端末を表示」**（右寄せ）: ⌥ を押し続けると下の端末が見えることの案内（→ [faces](faces.md) の ⌥ で端末を透かす）。押せない。透かしている間だけ、押している間の姿になる。

バーが狭くて全部が収まらなければ、部品は決まった順に譲る（まるごと出さないか、狭い姿に替わる）。ある部品が収まらなくても、ほかの部品は幅が余れば出る——今のファイルの親のパスが長くて収まらなくても、右が空いていれば「⌥ 端末を表示」は出る。広げれば、逆の順に戻る。先に譲るものから:

- 「⌥ 端末を表示」を出さない。
- Changes の「コミット」の添え書き（ステージ済みの行数）を出さない。
- Changes のブランチ名を省略する。名前は先頭の 4 字と「…」より縮めない。
- 今の項目のボタンの親のパスを出さず、それでも足りなければ名前を省略する。名前は先頭の 1 字と「…」より縮めない——今の項目の名前が 1 字も読めない姿を作らないため。
- Changes のブランチ名の札を出さない。

ブランチ名の札を出さなくなると、札が使っていた幅は、先に譲っていた部品へ回る。今の項目のボタンの親のパスと名前・「コミット」の添え書き・「⌥ 端末を表示」は、回った幅に入れば広い姿に戻る（狭めていく途中で、札が消えた幅でだけ、一度消えた部品がまた出る）。

開閉・切り替え・今の項目のボタン・「プレビュー」の札・「開いたままにする」・Changes の同期のボタンと「コミット」は落とさない。それでも収まらなければ、バーの右端が切れる。

バーのボタンは押しても焦点を取らない——焦点はバーの操作が決める（後述の焦点）。透かしている間、バーは見えるが押せない（器がクリックを受ける → [faces](faces.md)）。

### 開いているファイルの一覧

今のファイルのボタンを押すか ⌘P で、ボタンの下に開いている文書の一覧が浮かぶ。⌘P はエディターのキー（→ [layout](../chrome/layout.md)）で、ボタンを押すのと同じ——ボタンが出ていない画面では何もしない。開いた一覧はもう一度押すか ⌘P で閉じる。

- **並び**: 見出し（「開いているファイル」と数・⌘P）の下に、開いている文書の列をそのまま最近使った順（後述）に並べる。1 行目が今の文書で「現在」の札が付く。開いたときの選択は 2 行目（1 つ前に使った文書。文書が 1 つなら 1 行目）——ボタンか ⌘P と ↵ の 2 打で、直前のファイルと行き来できる。
- **行**: 種別チップ・名前・親のパス（根からの相対。収まらなければ頭から省く）・札（「現在」「プレビュー」）。仮の文書は名前が斜体。右に、未保存の白い丸か「ディスクが変わった」の黄の丸、どちらも無ければ ×。丸の上にポインタがある間は × に替わる。右端に、その文書の属するリポジトリの git の状態の字（M・A・U・C。→ [files](files.md)）。Orbe の外で `git add` などをすると、開いたままの一覧でも字が替わる。
- **キー**: ↑↓ で選択が動き（見出しは飛ばし、端で止まる）、↵ か行のクリックで、その文書が本体に出て一覧が閉じ、焦点が本文へ移る（仮の文書は仮のまま）。→ で選んでいる行の詳細に入り、← で一覧へ戻る。esc で閉じる。
- **閉じる**: 行の × で、その文書を閉じる。未保存なら未保存の確認（後述）が出て、キャンセルなら閉じない。閉じた後も一覧は開いたままで、焦点も一覧に残る——続けて × で閉じられる。今の文書を閉じると、1 つ前に使った文書が本体に出る。最後の 1 つを閉じると、一覧とボタンが消える。
- **詳細**: 先頭にその文書の行、続けて「開いたままにする」（仮の文書だけ）と「ファイルを閉じる」。↑↓ と ↵ で実行し、実行の後は一覧へ戻る。
- **閉じ方**: esc・ボタン・⌘P・行を決めたとき・最後の文書を閉じたとき・画面を切り替えたとき・一覧とボタンの外を押したときは閉じて、焦点を本体の行き先へ戻す（外の押下は、その後そのまま押した先へ届く）。焦点が一覧の外へ移ったとき（端末やタブを選んだ）と、⌘E で面を閉じたときも閉じ、焦点はそのまま。⌥ で透かしている間の押下では閉じない。⌥ を押している間は、一覧も上のバーより下と一緒に見えなくなる。
- **大きさ**: 幅は一定で、名前とディレクトリの長さでは広がらない。高さは行の数に合わせ、面の下端に届くなら一覧の中でスクロールする。行が数万でも、開く操作と ↑↓ で行の中身を問うのは見えている行だけ——変更ファイルの一覧（後述）も同じ器に載る。開閉は保存しない。

### 変更ファイルの一覧

Changes と PR の画面で、今のファイルのボタンを押すか ⌘P で、ボタンの下に変更ファイルの一覧が浮かぶ。位置・大きさ・↑↓・↵ と行のクリック・esc・閉じ方は、開いているファイルの一覧と同じ。ボタンが出ていない間（左の列を開いている）は、⌘P は何もしない。

- **並び**: Changes は、ソース管理パネルの 2 区分（→ [source-control](source-control.md)）を、見出し（「ステージされている変更」「変更」と数）で区切って並べる。0 件の区分は見出しごと出さない。PR は、見出し（「変更ファイル」と数）の下に、変更ファイルを PR のパネルの今の表示と同じ順に並べる——ツリー表示なら、ツリーを全部開いたときにファイルの行が上から並ぶ順、リスト表示ならパスの順（→ [pull-request-panel](pull-request-panel.md)）。表示を替えれば、開いている一覧も並び替わる。どちらも、左の列で畳んだ区分やフォルダも開いた形で全部並ぶ。開いたときの選択は、本体の diff の行。
- **行**: 種別チップ・名前・ディレクトリ（根からの相対。収まらなければ頭から省く）・右端に状態の字（左の列の行と同じ字と色）。× と丸は出さない。PR で確認済みのファイルは名前を弱い色にする。開いている間に status が変わる・確認済みを付け外しすると、一覧の行も替わる。
- **選ぶ**: ↵ か行のクリックで、その行の diff が本体に出て一覧が閉じ、焦点が本文へ移る。左の列の一覧でも、その行が選ばれる（その行を含む区分やフォルダを畳んでいれば開く。左の列の行を開いたときと同じ）。→ の詳細は無い。

## 左の列

左の列の中身は画面で決まる——Files はエクスプローラーか検索パネル（→ [search](search.md)）、Changes はソース管理パネル（→ [source-control](source-control.md)）、PR は PR のパネル（→ [pull-request-panel](pull-request-panel.md)）。どのパネルも上端にパネルの題の行を持ち、出すものが無い・表示できないときは、題の行の下に短い一言を出す（→ [faces](faces.md) の面の中身と空状態）。Files の左の列は、⌘⇧F・F4 / ⇧F4 で検索パネルになり、検索パネルの「ツリーに戻る」か Esc でエクスプローラーに戻る（→ [search](search.md)）。どちらを出しているかは連の面が持ち、保存しない（起動し直すとエクスプローラーで始まり、検索語は残る）。画面を切り替えて戻っても、左の列を閉じて開いても、どの一覧も選択とスクロール位置が残る。

### 開閉

左の列は、上のバーの左端のボタンと ⌘B で開閉する。⌘B はエディターのキー（→ [layout](../chrome/layout.md)）で、エディターに焦点がある間だけ効き、端末に焦点がある間は Orbe が取らず端末へ届く。閉じると本体が面の全幅に広がり、開けば閉じる前の幅で戻る。閉じるとき、焦点が左の列のパネル（検索パネルの欄と列・ソース管理パネルの列・PR のパネルの欄と列、行内入力）にあれば本体の焦点の行き先へ移す（→ 焦点）。⌘⇧F・F4 / ⇧F4 は、閉じていれば開く。左の列を閉じていても、Changes・PR の画面の一覧は行を組み続ける——本体に自動で開く行を決めるのに一覧が要る（→ [source-control](source-control.md)・[pull-request-panel](pull-request-panel.md)）。

### 幅

左の列の幅はドラッグで変えられる——左の列と本体の境（縁の線）の、上のバーより下に細い当たりがあり、掴むと連続で追従する。下限があり、上限は本体に最低幅（左の列の下限と同じ）が残るまで。幅・開閉の記憶と、ソース管理パネルのグラフの枠の高さ（→ [source-control](source-control.md)）は**アプリ全体で 1 つ**（連・workspace をまたいで同じ）で、再起動でも戻る（→ [persistence](../platform/persistence.md) の app-state）。中身は連の画面で決まるので記憶しない。

左の列が見えるかは開閉だけで決まり、面の幅は関係ない。面が狭いときは**表示幅を「面の幅 − 本体の最低幅」まで切り詰める**——記憶している幅は変えず、面が広がれば記憶の幅に戻る。切り詰めた表示幅は左の列の下限を下回ってもよく、面の幅が本体の最低幅以下なら 0 になる。当たりは境を動かせるときだけ出る——面が狭くて左の列を下限まで出せない間は境が動かないので、当たりも出ない。寸法と色は [design-system](../../design/design-system.md) §5 の Editor bar / Explorer / Search panel / Source control panel / PR panel / Diff body。

## エクスプローラー

連の根（連のタブの cwd が属する git worktree ルート。管理外は cwd → [files](files.md)）の実ファイルを描く。展示データは持たない。

- **ルート行**は根の basename を大文字で出し、クリックで根の開閉。ヘッダー右端に 新規ファイル／新規フォルダ／すべて折りたたむ の 3 ボタン。
- **ツリー**はディレクトリを先に、あとは名前順——大小とアクセントを無視し、数を数として比べる（Finder と同じ。`file2` が `file10` より前）。この比べ方は検索結果の並びと 1 つを共有する。ディレクトリはシェブロン（クリックで開閉）、ファイルは種別チップ（種別 → 見た目の決定点は 1 か所で、15 言語は色相付き、未知は拡張子の頭文字の無彩、拡張子が無ければ `·`）。ファイル行の右端に git バッジ——M（変更）・A（追加）・U（未追跡）・C（競合）——を出し、**名前もバッジの色**で描く。色は A・U が git の追加の青、M が git の変更の黄で、赤と緑に頼らない（→ [design-system](../../design/design-system.md) §3）。ディレクトリ行はバッジを持たず、配下の集約もしない。
- **展開は面の状態**で永続しない。一覧は展開したディレクトリだけ遅延で取り、監視の通知（→ [files](files.md)）で変わったパスの親のうち展開中のものを取り直す。展開中のディレクトリが消えれば畳む。読めないディレクトリは空として畳む。ツリーのスクロール位置は、画面を切り替えても・左の列を閉じて開いても・検索パネルから戻っても戻る。ただし、ツリーが隠れている間に選択が替わっていれば（検索の結果から別のファイルを開いた等）、位置を戻す代わりに、選択の行を一覧の中ほどへ送る。ツリーを初めて出すときは、選択（今の文書の行）が在ればその行を一覧の中ほどへ送り、無ければ先頭から出す。
- **根のサービスは面が画面に見えている間だけ握る**（窓に付き、隠れていない）。隠れている連や幅 0 の面は握らないので、全連の根を常時監視しない。離すと監視は止まるが一覧と status の見え方は保ち、次に見えたときに握り直して展開中を取り直す。**status は最後に成功したもの**を保つ——握り直した直後（git が返るまで）も、git の一時失敗でも、バッジは消えない。連の根が変われば（cd）ツリーを作り直す。
- **ファイル行を押す**と Files の画面で仮の文書（後述）として開き、2 回目の押下（ダブルクリック）で普通の文書にする。1 回目はダブルクリックの判定を待たずにすぐ開く——見て回るクリックに遅れを足さない。ダブルクリックの 1 回目は仮の文書を入れ替える（仮の文書があれば、それは閉じる）。焦点は押すたびに本文へ移る（→ 焦点）。
- **Files の今の文書が替わったとき**（ツリーのクリック・検索結果・ソース管理パネルの「ファイルを開く」・diff の見出しの「ファイルを開く」・制御 API `open_file`・復元・diff の中で未保存になった文書が今の文書になったとき）、そのファイルが根の下ならツリーは祖先を開いてその行を選択表示し、可視位置へ送る。根の外のファイルでは選択を外す。diff を開いてもツリーは追従しない。
- **新規作成**はツリーの行内入力。挿す先は、選択がディレクトリならそこ、ファイルならその親、無ければ根で、その親の子の先頭に入力行が現れ、可視位置へ送る。続けて押せば前の入力は消えて新しい入力だけが出る。Enter で作り、ファイルならそのまま開く。空・`/` 入り・既に在る・作れない名前は音で断って入力に留まる。Esc と、焦点が別の view へ移ることで取り消す（変換中の Esc は変換だけを取り消す）。入力の終わりは入力の状態が落ちることで、理由を問わない（Enter・取り消しのほか、すべて折りたたむ・根を畳む・左の列を閉じる・Files の画面でなくなる・左の列が検索パネルになる・cd など）。打ちかけの名前は入力の状態が持つ。中間ディレクトリは作らない。

## 左の列の一覧のスクロールバー

エクスプローラーのツリー・検索結果の列・ソース管理の列（変更・グラフ）・PR のパネルの列は、OS のスクロールバーを出さず、細いつまみだけを描く。トラックの地も枠も描かない。見本は VS Code の一覧のスクロールバー。macOS の「スクロールバーを常に表示」設定やマウス接続にも左右されず、操作していない一覧の右端には何も出ない。

- **出方**: つまみは、一覧の上にポインタがある間と、つまみのドラッグ中に見える。スクロールの位置が変わっても現れ、止まってしばらくすると消え始める。ポインタが一覧から出たとき、ドラッグを一覧の外で離したときは、すぐ消え始める。現れ方・消え方・色はコード面のスクロールバーと同じで（→ [code](code.md)）、「視差効果を減らす」設定では時間をかけない。パネルを出しただけでは点かない。中身が収まっている一覧には出ない。
- **大きさの変化だけでは出ない**: 全体の長さや見えている長さが変わっても、位置が動かなければつまみは現れない。検索結果が流れ込む間やフォルダを開いたときに、つまみが点滅し続けないため（コード面は大きさの変化でも現れる）。
- **掴めるのはつまみだけ**: つまみを掴んで引くと、引いた距離だけ一覧が送られる。ポインタが一覧の外へ出ても追従する。帯のつまみ以外の所は当たりを持たず、押せばその行のクリックになる——行の右端の git バッジ辺りも押せる。つまみを押しても下の行は選ばれない。
- **ホイールはどこでも効く**: つまみの上を含め、一覧のどこでホイール・トラックパッドを使っても一覧が送られる。
- **末尾に 1 行分の空き**: 一番下まで送ると、最後の行の下に行 1 つ分の空きが残る（VS Code の一覧と同じ）。最後の行が下端に貼り付かず、終わりだと分かる。空きは一覧の中身の一部なので、ホイール・つまみのドラッグ・End のどれでも届き、つまみの長さと位置も空き込みの高さで決まる。収まっているかも空き込みで判定する——行だけなら収まる一覧でも、空きを足して溢れれば 1 行未満だけ送れて、つまみが出る。空きを押しても何も選ばれない。
- どの一覧も、見せる規則・つまみの長さと位置の式・色と時間を共有する。描く層は一覧の作りに合わせる。検索結果の列・ソース管理の列・PR のパネルの列は自前の列の中につまみを持つ。ツリーは SwiftUI のつまみを重ね、つまみ自体には当たりを持たせず、ポインタの位置で「つまみの上か」を判定する。重ねた部品に当たりを持たせると、その上のホイールが一覧に届かないため。

VS Code の一覧とは次の点で違う。全体や見えている長さが変わっただけでは現れない（VS Code は現れる。理由は上の「大きさの変化だけでは出ない」）。帯のつまみ以外を押しても、その位置へは飛ばない（行のクリックを優先する）。先頭の行が上へ隠れている間の上端の影は描かない。

## 開いている文書と仮の文書

Files の画面の本体に出るのは、連の開いている文書の列（→ [code](code.md)）の今の文書。列は**最近使った順**で、先頭が今の文書——開いた・切り替えた文書が先頭へ移り、今の文書を閉じると 1 つ前に使った文書が今の文書になる。列の順は、開いているファイルの一覧の並びそのもので、一覧のために別の順を持たない（同じ文書の集まりに順序が 2 つあると、片方は誰にも見えなくなる）。diff は開いている文書の列に入らない（→ [diff](diff.md)）。未保存の文書は必ず列に居る——Changes の diff の中で編集して未保存になった文書も、列の 2 番目（今の文書のすぐ次）に入る（列が空なら今の文書になる）。今の文書を替えても、undo・選択・スクロールは文書ごとに残る。

### 仮の文書

見るだけのファイルを開くたびに開いている文書が積もらないよう、列の中に**仮の文書を高々 1 つ**持つ。仮で新しく開くと、仮の文書があれば列から外し（その仮の文書は閉じる）、新しいファイルを列の先頭に入れる。開いているファイルを仮で開き直しても今の文書になるだけで、普通の文書は普通のまま。仮で開けないファイル（読めない・UTF-8 でない）は音で断り、今の仮の文書は残る。

仮で開く入口は、エクスプローラーのファイル行のシングルクリックと、検索結果のシングルクリック・キーで一致へ動く・F4 / ⇧F4（→ [search](search.md)）。それ以外——検索結果のダブルクリックと Enter、エクスプローラーのダブルクリック、ソース管理パネルの行の「ファイルを開く」、diff の見出しの「ファイルを開く」、新規作成、Finder からのドロップ、制御 API `open_file`——は普通の文書として開き、そのファイルが仮の文書なら普通に変える。エージェントが `open_file` で見せたファイルを、人の次のクリックが黙って入れ替えないため。diff は仮・普通を持たない（行を開くと入れ替わる → [diff](diff.md)）。

仮の文書が普通の文書になるのは、本文を編集して未保存になった瞬間（打鍵・貼り付け・ドロップ・複数カーソルの編集など入口を問わない。Changes の diff の中で打ったときも）と、上の普通に開く入口で開き直したときと、上のバーか開いているファイルの一覧の詳細で「開いたままにする」を選んだとき。すでに未保存の文書を仮で開けば、はじめから普通の文書として開く。未保存になった仮の文書はその場で普通に戻るので、入れ替えで編集が消えることは無く、未保存の確認に仮の文書は出てこない。普通の文書は仮に戻らない——保存しても、元に戻しても。未編集の仮の文書を ⌘S しても仮のまま。

## 焦点

骨の操作で文書を開く・切り替える・新規作成を確定したら、焦点を面の焦点 view（テキスト面）へ移す——制御 API `open_file` と同じ結果。面の中に焦点があれば、本体が替わると新しい行き先へ移る（[コード](code.md)の規則）。ただし左の列——検索結果・ソース管理の列・PR のパネルの列と全体へのコメント欄・行内入力——と、開いているファイルの一覧にある焦点は、本体が替わっても動かない（一覧の × で今の文書を閉じても、焦点は一覧に残る）。開いているファイルの一覧は、開いている間焦点を持ち、閉じたときに焦点をどこへ置くかは閉じ方で決まる（前述）。

上のバーで画面を切り替えたときは、Changes・PR で左の列を開いていれば、その一覧の状態で決める。一覧の状態は 3 つ——行がある・これから来る（今読んでいる・行を作っている）・無い。Changes は、git 管理外か親「ソース管理」を畳んでいれば無い。変更の列に行があればある。git 管理下かの判定の前か、今の status から行がまだ出来ていなければこれから来る。それ以外（変更なし）は無い。PR は、列に行があればある。worktree の今の PR の答えを読んでいるか、PR の中身を読んでいればこれから来る。それ以外（PR が無い・表示できない・中身を読めなかった）は無い。

- 行がある・これから来る: 面が焦点を預かり、一覧に行があり次第、一覧へ焦点を入れる（そのタブで初めて画面を出した直後で、行がまだ出来ていなくても、出来た時点で一覧に入る）。預かっている焦点は左の列のそのパネルの焦点として数える——行を待つ間に diff が自動で開いても焦点は diff の本文へ移らず、左の列を閉じる・別の画面へ切り替える・親「ソース管理」を畳む・根が替わると本体の焦点の行き先へ戻る。待つ間に打ったキーはどこにも届かない。
- 預かりは、焦点が面から離れたとき（一覧が受け取った・端末のタブを選んだ・左の列の欄を押した・⌘E で閉じた）と、本体へ焦点を求めたとき（本体を押した・文書や diff を本文へ開いた・`open_file` / `open_diff`）に終わる。そのとき一覧への焦点の要求が残っていれば取り消す——後で一覧が現れても、人が移した焦点を奪わない。一覧の状態が無いと決まれば、本体の焦点の行き先へ移す。
- それ以外——Files・左の列を閉じている・一覧の状態が無い——は本体の焦点の行き先（テキスト面。面が無ければ面自身）へ移す。切り替えた先の一覧が既に焦点を持っていれば触らない。

ソース管理のメッセージ欄は、上のバーの右下に開くコミットのポップアップの中に在る。上のバーの右端の「コミット」を押すか、変更の列に焦点がある間に ⌘↑ を押す（どの行を選んでいても・何も選んでいなくても）と、ポップアップが開いて欄に焦点が入る。閉じた後の焦点は、開く前に在った所へ戻る（→ [source-control](source-control.md#コミットのポップアップ)・[キーと焦点](source-control.md#キーと焦点)）。

行内入力を出すときは先に面自身が first responder になる（入力欄は焦点を面が持っているときだけ取る）。入力欄は面の配下なので chrome キー（→ [layout](../chrome/layout.md)）は効いたまま、通常の打鍵は入力欄に入る。入力行が画面外に出て入力欄が消えている間は面が焦点を預かり（打ちかけは残る）、行が戻れば入力欄が取り直す——預かっている間に焦点が面の外へ移れば取り消す。入力が終わったとき焦点がまだ入力欄か面か窓に居れば面の焦点 view へ移す（端末をクリックして抜けて終わったなら端末のまま）。検索パネル（→ [search](search.md)）・ソース管理パネル（→ [source-control](source-control.md)）・PR のパネル（→ [pull-request-panel](pull-request-panel.md)）が隠れたとき（画面を切り替えた・左の列を閉じた・検索パネルからエクスプローラーへ戻った）も、焦点がそのパネルにあれば同じ規則で面の焦点 view へ移す。パネルを出したまま中の列が消えるとき（PR のパネルの答えが替わって行が無くなった）も同じ。

## 面の中の確認とフォーカス

戻せない操作の確認の一部（ソース管理の破棄 → [source-control](source-control.md#ステージ解除破棄)）は、窓のシートではなく、エディター面の中に出す。面の全体（上のバーを含む）を幕で暗くし、上端から少し下・左右の中央にダイアログ（題・本文・「キャンセル esc」と確定のボタン）を出す。確認が属するのはこの面の操作なので、ほかのタブや窓の操作まで止めない。寸法と色は [design-system](../../design/design-system.md) §5 の Editor confirm。

- **確定はクリックだけ**。↵ では確定しない。esc と「キャンセル」はキャンセル。連打の 2 回目以降の押下（OS がダブルクリック・トリプルクリックと数える押下）は、どのボタンにも届けない——行の「破棄」を続けて押したとき、2 回目以降が出たばかりの確認の「破棄」に当たらないように。間を置いた 1 回の押下で確定する。
- **後ろへは届かない**: 出ている間は確認が焦点を持ち、幕の押下・スクロールは何もしない（上のバー・左の列・本体のどれも押せない）。キーは、窓のキー（⌘E・タブの切り替えなど）だけが今までどおり働き、エディターのキー（⌘S・⌘B・⌘P）・端末とエディターの両方が使うキー（⌘F・⌘↑↓）・F4 / ⇧F4・PR の画面の v・通常の打鍵は、何もせずに消える。本体が替わっても（エージェントが diff を開く・status の変化で diff が閉じる）、焦点は確認から動かない。
- **迷ったらキャンセル**: 出ている間に焦点が確認の外へ移った（パレットを開いた・制御 API が焦点を求めた・別のタブへ移った）・画面が替わった・面が隠れた・窓から外れた・cd で根が替わったときは、確定せずにキャンセルとして閉じる。
- **閉じた後の焦点**: 出す前に在った所——左の列の一覧（一覧のために面が預かっていた焦点を含む。コミットのポップアップが開いていたなら、それを開く前の所）か、本体——へ戻る。焦点が外へ移って閉じた・面が隠れて閉じたときは、焦点に触れない。出すときに、開いている一覧とポップアップは閉じる。
- ⌥ で透かしている間は、幕とダイアログも見えなくなる（閉じない。焦点も動かない）。

未保存を捨てる前の確認と外部変更の上書きの確認は、窓のシートで出す（後述）。

## 未保存を捨てる前の確認

未保存の文書を捨てる人の操作は 1 種類の確認——保存／保存しない／キャンセル——を挟む。入口は 4 つ: 開いているファイルの一覧の行の × と詳細の「ファイルを閉じる」（その文書 1 件。「保存しない」なら、その文書を使う Changes の diff は編集前の中身で開き直す → [diff](diff.md)）、人の操作で連の最後のタブを閉じる（⌘W・chrome のタブ行の中クリック。その連の未保存）、workspace を閉じる（workspace パレットの削除。workspace の全連の未保存を合計して 1 回）、アプリの終了（全 workspace の全連の合計）。連の未保存は連の開いている文書の未保存を、実体の単位で数える——同じ文書を本体の文書と Changes の diff が使っていても 1 回。連の途中のタブを閉じても問わない——連のエディターは残るので、何も失われない。保存を選んで 1 つでも失敗すれば閉じない／終了しない——失敗はいずれも音で断り、外部変更（→ [files](files.md)）なら印が立ったまま残って ⌘S の上書きへ、書けない先（親ディレクトリの消失・読み取り専用・容量）ならそのまま。シェルの終了・agent の終了と制御 API による閉鎖（`close_tab`・`remove_workspace`）で連の最後のタブが閉じたときは、確認せず黙って捨てる——プロセスは既に無く、無人の操作に確認は出せない。人が自分のタブを閉じたあと、残った agent のタブが後で終われば、その連の未保存はそこで消える。タブを閉じる確認は sheet で非同期に確定し（閉じる要求は main-queue のブロックから届くので、その中のモーダルは端末描画と制御 API を止める）、応答までにタブが消えていれば何もしない。終了の確認は実行中プロセスの確認と同じくモーダル。文言は現在言語。

## 外部変更の上書き

印の立った文書（→ [files](files.md)）の ⌘S——本体が Files の文書でも、その文書を新しい側に使う Changes の作業ツリー diff でも——は「ディスク上で変更されています」の確認を出し、上書きを選べば force で保存する。キャンセルなら何もしない。上書きは戻せないので Return では確定しない（クリックだけ。Esc はキャンセル）。上書きされるのは確認を出した文書——応答までに本体が別の文書へ替わっていても（エージェントの `open_file`）変わらず、その文書が閉じられていれば何もしない。上書きも通常の保存も書けない先（親ディレクトリの消失・読み取り専用・容量）で失敗すれば音で断り、印は立ったまま残る（エラー面は持たない）。

## 開いていた文書と画面の復元

連は開いている文書の実体パスの列と今の文書の実体パスと仮の文書の実体パス、選んだ画面を永続する（→ [persistence](../platform/persistence.md)。画面を選んでいなければ書かない）。diff は永続せず再起動で戻らない。復元は連の器が初めて content に載るとき（前面で mount される・背景で起こされる → [layout](../chrome/layout.md)）に起き、タブの起床には結ばない——起きているタブが cd でまだ一度も載っていない連へ入っても、その連の器が初めて載る時点で戻る。選んだ画面は連を作った時点で戻る。文書の列は最近使った順のまま書き、その順で戻る。保存した今の文書が列の先頭でなければ（復元より先に開いていた文書が無いとき）、戻すときに今の文書を先頭へ移す。読めなくなったファイルは黙って落ちる（今の文書が落ちていれば先頭、仮の文書が落ちていれば仮の文書無し）。仮の文書は仮のまま同じ位置に戻る——再起動のたびに見ていただけの文書が普通の文書として積もらない。ただし、仮の文書のファイルの文書が既に未保存なら（cd で連が畳まれて移ってきた未保存の文書）、普通の文書として戻る（すでに未保存の文書を仮で開くときと同じ）。復元より先に開いていた文書があれば（制御 API の `open_file`）その今の文書と開き方を保つ——復元は既に居るものを壊さず、普通に開いていた文書を仮に下げない。未保存の内容は戻らない。一度も載らなかった連は未消費の状態をそのまま書き戻すので、再起動を重ねても文書の列は失われない（まだ載っていない連へ cd で文書が移ってきても、未消費の文書は開いている文書の後ろに合わせて書く）。

## VS Code との差

仮の文書は VS Code の preview editor を土台にし、次の点で違う。

- **エクスプローラーのシングルクリックは本文へ焦点を移す**（VS Code はエクスプローラーに残す）。エクスプローラーはキー操作を持たず、焦点を残すと打鍵が前に居た所へ行くため。
- **仮で新しく開いた文書は列の先頭に入る**（VS Code はアクティブなタブの右）。列は最近使った順という規則と食い違わない。
- **仮の文書を切る設定と、固定のキー（VS Code の ⌘K Enter）は持たない**。固定はダブルクリック・編集・上のバーの「開いたままにする」で足り、覚える近道を増やさない。
- **押し続けた ↑↓ は離すまで開かない**（VS Code は時間だけで間引くので、初期遅延の間やリピートの間隔が窓より長いときに窓が切れて開く）。→ [search](search.md)
