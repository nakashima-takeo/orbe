# 面の骨

エディター面の中身の構造。端末の隣でファイルを選び、複数開いて切り替え、閉じ、作るための器で、文書のコードビュー（→ [code](code.md)）と diff（→ [diff](diff.md)）はこの骨の本体に載る。左からレール・サイドバー（エクスプローラー・[プロジェクト検索](search.md)・[ソース管理](source-control.md)のパネル）・列——列は上からタブ行、パンくず、本体（焦点のタブの本体——文書のテキスト面か diff の面。俯瞰（ミニマップ・スクロールバー）も面の中に描く。タブが無ければ[面の機構](faces.md)の空状態）。骨は SwiftUI の部品で、幾何は面（AppKit）が解く——テキスト面は view の同一性と焦点の取り方に依存し、SwiftUI の再親化に晒せないため。

## サイドバーの幅と開閉とパネル

サイドバーの幅はドラッグで変えられる——サイドバーと本体の境（縁の線）に細い当たりがあり、掴むと連続で追従する。下限があり、上限は本体に最低幅（サイドバーの下限と同じ）が残るまで。開閉と、どのパネルを出すかはレールで決める（後述）。幅・開閉・パネルの記憶と、ソース管理パネルのグラフの枠の高さ（→ [source-control](source-control.md)）は**アプリ全体で 1 つ**（連・workspace をまたいで同じ。面の配置のような連単位ではない）で、再起動でも戻る（→ [persistence](../platform/persistence.md) の app-state）。

サイドバーが見えるかは開閉だけで決まり、列幅は関係ない。列が狭いときは**表示幅を「列幅 − レール − 本体の最低幅」まで切り詰める**——記憶している幅は変えず、列が広がれば記憶の幅に戻る。それでも足りない極端な幅では残りをそのまま分け、サイドバーの表示幅は 0 まで縮む。当たりは境を動かせるときだけ出る——列が狭くてサイドバーを下限まで出せない間は境が動かないので、当たりも出ない。タブが無いときもタブ行の帯は残り、本体に空状態が出る。寸法と色は [design-system](../../design/design-system.md) §5 の Rail / Explorer / Search panel / Source control panel / File tabs / Diff tabs / Diff body / Breadcrumb。

## レール

左端のアイコン列。項目は「ファイル」（エクスプローラー）・「検索」（→ [search](search.md)）・「ソース管理」（→ [source-control](source-control.md)）の順で、サイドバーのパネルと 1 対 1。別の項目を押すとそのパネルへ切り替わり（閉じていれば開く）、出しているパネルの項目を押すと閉じる。検索を押して検索パネルが出たら入力欄に、ソース管理を押せばメッセージ欄に焦点が入る（親「ソース管理」を畳んでいれば入れない）。「ソース管理」の項目は、変更があれば右下に件数のバッジを出す（パネルを閉じていても、面が見えていれば追従する）。エクスプローラーから離れると行内入力は終わる。選択は左縁の細い accent 線と淡い地で示し、サイドバーを閉じている間は選択印が無い——design-system §5 が「選択を左バーで示すのはエディター面のレールだけ。chrome ではどこでもしない」と定める、その 1 か所。

## エクスプローラー

連の根（連のタブの cwd が属する git worktree ルート。管理外は cwd → [files](files.md)）の実ファイルを描く。展示データは持たない。

- **ルート行**は根の basename を大文字で出し、クリックで根の開閉。ヘッダー右端に 新規ファイル／新規フォルダ／すべて折りたたむ の 3 ボタン。
- **ツリー**はディレクトリを先に、あとは名前順——大小とアクセントを無視し、数を数として比べる（Finder と同じ。`file2` が `file10` より前）。この比べ方は検索結果の並びと 1 つを共有する。ディレクトリはシェブロン（クリックで開閉）、ファイルは種別チップ（種別 → 見た目の決定点は 1 か所で、15 言語は色相付き、未知は拡張子の頭文字の無彩、拡張子が無ければ `·`）。ファイル行の右端に git バッジ——M（変更）・A（追加）・U（未追跡）・C（競合）——を出し、**名前もバッジの色**で描く。色は A・U が git の追加の青、M が git の変更の黄で、赤と緑に頼らない（→ [design-system](../../design/design-system.md) §3）。ディレクトリ行はバッジを持たず、配下の集約もしない。
- **展開は面の状態**で永続しない。一覧は展開したディレクトリだけ遅延で取り、監視の通知（→ [files](files.md)）で変わったパスの親のうち展開中のものを取り直す。展開中のディレクトリが消えれば畳む。読めないディレクトリは空として畳む。
- **根のサービスは面が画面に見えている間だけ握る**（窓に付き、隠れていない）。隠れている連や幅 0 の面は握らないので、全連の根を常時監視しない。離すと監視は止まるが一覧と status の見え方は保ち、次に見えたときに握り直して展開中を取り直す。**status は最後に成功したもの**を保つ——握り直した直後（git が返るまで）も、git の一時失敗でも、バッジは消えない。連の根が変われば（cd）ツリーを作り直す。
- **ファイル行を押す**と仮のタブ（後述）で開き、2 回目の押下（ダブルクリック）で普通のタブにする。1 回目はダブルクリックの判定を待たずにすぐ開く——見て回るクリックに遅れを足さない。ダブルクリックの 1 回目は仮のタブを入れ替える（仮のタブがあれば、それは閉じる）。焦点は押すたびに本文へ移る（→ 焦点）。
- **タブをアクティブにしたとき**（ツリーのクリック・タブ行・ソース管理パネルの行と「ファイルを開く」・制御 API `open_file` / `open_diff`・復元）、そのファイルが根の下ならツリーは祖先を開いてその行を選択表示し、可視位置へ送る（diff タブはそのファイルの行）。根の外のファイルでは選択を外す。パンくずのディレクトリを押しても同じく開いて選択する。
- **新規作成**はツリーの行内入力。挿す先は、選択がディレクトリならそこ、ファイルならその親、無ければ根で、その親の子の先頭に入力行が現れ、可視位置へ送る。続けて押せば前の入力は消えて新しい入力だけが出る。Enter で作り、ファイルならそのまま開く。空・`/` 入り・既に在る・作れない名前は音で断って入力に留まる。Esc と、焦点が別の view へ移ることで取り消す（変換中の Esc は変換だけを取り消す）。入力の終わりは入力の状態が落ちることで、理由を問わない（Enter・取り消しのほか、すべて折りたたむ・根を畳む・サイドバーを閉じる・cd など）。打ちかけの名前は入力の状態が持つ。中間ディレクトリは作らない。

## サイドバーの一覧のスクロールバー

エクスプローラーのツリー・検索結果の列・ソース管理の列（変更・グラフ）は、OS のスクロールバーを出さず、細いつまみだけを描く。トラックの地も枠も描かない。見本は VS Code の一覧のスクロールバー。macOS の「スクロールバーを常に表示」設定やマウス接続にも左右されず、操作していない一覧の右端には何も出ない。

- **出方**: つまみは、一覧の上にポインタがある間と、つまみのドラッグ中に見える。スクロールの位置が変わっても現れ、止まってしばらくすると消え始める。ポインタが一覧から出たとき、ドラッグを一覧の外で離したときは、すぐ消え始める。現れ方・消え方・色はコード面のスクロールバーと同じで（→ [code](code.md)）、「視差効果を減らす」設定では時間をかけない。パネルを出しただけでは点かない。中身が収まっている一覧には出ない。
- **大きさの変化だけでは出ない**: 全体の長さや見えている長さが変わっても、位置が動かなければつまみは現れない。検索結果が流れ込む間やフォルダを開いたときに、つまみが点滅し続けないため（コード面は大きさの変化でも現れる）。
- **掴めるのはつまみだけ**: つまみを掴んで引くと、引いた距離だけ一覧が送られる。ポインタが一覧の外へ出ても追従する。帯のつまみ以外の所は当たりを持たず、押せばその行のクリックになる——行の右端の git バッジ辺りも押せる。つまみを押しても下の行は選ばれない。
- **ホイールはどこでも効く**: つまみの上を含め、一覧のどこでホイール・トラックパッドを使っても一覧が送られる。
- **末尾に 1 行分の空き**: 一番下まで送ると、最後の行の下に行 1 つ分の空きが残る（VS Code の一覧と同じ）。最後の行が下端に貼り付かず、終わりだと分かる。空きは一覧の中身の一部なので、ホイール・つまみのドラッグ・End のどれでも届き、つまみの長さと位置も空き込みの高さで決まる。収まっているかも空き込みで判定する——行だけなら収まる一覧でも、空きを足して溢れれば 1 行未満だけ送れて、つまみが出る。空きを押しても何も選ばれない。
- どの一覧も、見せる規則・つまみの長さと位置の式・色と時間を共有する。描く層は一覧の作りに合わせる。検索結果の列とソース管理の列は自前の列の中につまみを持つ。ツリーは SwiftUI のつまみを重ね、つまみ自体には当たりを持たせず、ポインタの位置で「つまみの上か」を判定する。重ねた部品に当たりを持たせると、その上のホイールが一覧に届かないため。

VS Code の一覧とは次の点で違う。全体や見えている長さが変わっただけでは現れない（VS Code は現れる。理由は上の「大きさの変化だけでは出ない」）。帯のつまみ以外を押しても、その位置へは飛ばない（行のクリックを優先する）。先頭の行が上へ隠れている間の上端の影は描かない。

## タブ行

セッションのタブの列——文書のタブ（ファイルタブ）と diff のタブ（→ [code](code.md)・[diff](diff.md)）——を自然幅のタブで並べ、溢れは横スクロール（スクローラーは出さず、アクティブが変われば可視位置へ）。タブはチップ・名前・右端の枠。枠には × か未保存のドット（外部変更と衝突中は注意の黄）を出す——VS Code のタブと同じく、アクティブのタブは × を常に、それ以外はタブにポインタがあるときだけ出し、未保存のタブは × 自体にポインタがあるときのほかは × の代わりにドットを出す（タブに乗っただけではドットのまま。未保存の印は閉じる直前まで見えている）。閉じられるタブと未保存のタブが一目で分かり、未保存の印と × が並んで幅を食わない。枠の幅は常に確保し、ポインタでレイアウトが動かない。クリックで切替（undo・選択・スクロールは文書ごとに残る）。× にポインタを乗せると枠に地が付いて × が明るくなり——押せる範囲に乗ったことが見える——枠のどこを押しても閉じる。アクティブは淡い地と上縁の accent 線で示す——レールと同じくエディター面の中だけの例外。右端に分割・その他の印は持たない。

diff タブはファイルタブと同じ形・同じ高さで、名前の後に種類の注記（「（作業ツリー）」/「（ステージ済み）」。注意の黄）を出し、アクティブの上縁は accent ではなく注意の黄。未保存の印は、その diff が新しい側に使う文書が未保存のときに出る。焦点が diff タブのときだけ、タブ行の右端に見せ方の切り替え「インライン / 並列」が出る（→ [diff](diff.md)）。タブ行の高さは文書のタブだけのときと同じで、ファイルタブ ⇄ diff タブを切り替えても本体の上端は動かない。

### 仮のタブ

見るだけのファイルを開くたびにタブが積もらないよう、列の中に**仮のタブを高々 1 枚**持つ——文書のタブと diff のタブで枠は 1 つで、仮で開いた diff は次に仮で開いたもの（文書でも diff でも）に同じ位置で入れ替わる。仮のタブは名前を斜体にし、地にうっすらした斜線を敷く（アクティブなら淡い地の上。上縁の accent・× と未保存の枠・チップは普通のタブと同じ）。仮で開くと、仮のタブがあればその位置で新しいファイルに入れ替わり（前のファイルは閉じる）、無ければ末尾に足す。開いているファイルを仮で開き直しても焦点が移るだけで、普通のタブは普通のまま。仮で開けないファイル（読めない・UTF-8 でない）は音で断り、今の仮のタブは残る。

仮で開く入口は、エクスプローラーのファイル行のシングルクリックと、検索結果のシングルクリック・キーで一致へ動く・F4 / ⇧F4（→ [search](search.md)）、ソース管理パネルの行のシングルクリック・↑↓（diff を仮のタブで開き、焦点は列に残る → [source-control](source-control.md)）。それ以外——検索結果のダブルクリックと Enter、エクスプローラーのダブルクリック、ソース管理パネルの行のダブルクリック・Enter と「ファイルを開く」、新規作成、Finder からのドロップ、制御 API `open_file`——は普通のタブで開き、そのファイルが仮のタブなら普通に変える。エージェントが `open_file` で見せたファイルを、人の次のクリックが黙って入れ替えないため。

仮の diff タブは、それが使う文書が未保存になれば普通のタブになる。

仮のタブが普通のタブになるのは、本文を編集して未保存になった瞬間（打鍵・貼り付け・ドロップ・複数カーソルの編集など入口を問わない）、タブのダブルクリック、上の普通に開く入口で開き直したとき。すでに未保存の文書（diff ならそれが使う文書）を仮で開けば、はじめから普通のタブで開く。未保存になった仮のタブはその場で普通に戻るので、入れ替えで編集が消えることは無く、未保存の確認に仮のタブは出てこない。普通のタブは仮に戻らない——保存しても、元に戻しても。未編集の仮のタブを ⌘S しても仮のまま。

## パンくず

焦点のタブのファイルの、根からのディレクトリ ›…› チップとファイル名。ディレクトリはホバーで文字が上がり、押すとツリーのそのフォルダが開く。根の外の文書は絶対パスの構成要素で、押せない。diff タブのパンくずはその diff の根からのディレクトリで（diff は根の中のパスだけ）、diff の根が連の根と同じときだけ押せる。診断件数は持たない。パンくずの段は文書のタブと diff のタブの両方にあり、タブが無いときだけ無い——列の頭の高さと SwiftUI 側の出し分けは、同じ 1 つの事実（本体の種類）から決まる。

## 焦点

骨の操作で文書を開く・切り替える・新規作成を確定したら、焦点を面の焦点 view（テキスト面）へ移す——制御 API `open_file` と同じ結果で、分割中は面の記憶もエディターへ移る。× は焦点を動かさない（面の中に焦点があれば新しい行き先へ移るのは[コード](code.md)の規則。ただしサイドバー——検索結果・ソース管理の列と欄・行内入力——にある焦点は、文書が切り替わっても動かない）。行内入力を出すときは先に面自身が first responder になる（入力欄は焦点を面が持っているときだけ取る）。入力欄は面の配下なので chrome キー（→ [layout](../chrome/layout.md)）は効いたまま、通常の打鍵は入力欄に入る。入力行が画面外に出て入力欄が消えている間は面が焦点を預かり（打ちかけは残る）、行が戻れば入力欄が取り直す——預かっている間に焦点が面の外へ移れば取り消す。入力が終わったとき焦点がまだ入力欄か面か窓に居れば面の焦点 view へ移す（端末をクリックして抜けて終わったなら端末のまま）。検索パネル（→ [search](search.md)）・ソース管理パネル（→ [source-control](source-control.md)）が隠れたときも、焦点がそのパネルにあれば同じ規則で面の焦点 view へ移す。

## 未保存を捨てる前の確認

未保存の文書を捨てる人の操作は 1 種類の確認——保存／保存しない／キャンセル——を挟む。入口は 4 つ: タブの ×（その文書を使う最後のタブのときだけ、その文書 1 件。同じ文書をほかのタブ——同じファイルの作業ツリー diff・ファイルタブ——が使っていれば確認せずに閉じ、未保存の印は残ったタブに出る）、人の操作で連の最後のタブを閉じる（⌘W・chrome のタブ行の中クリック。その連の未保存）、workspace を閉じる（workspace パレットの削除。workspace の全連の未保存を合計して 1 回）、アプリの終了（全 workspace の全連の合計）。連の未保存は連の文書の単位で数える——diff タブだけが使う文書も 1 件で、同じ文書をファイルタブと diff タブが使っていても 1 回。連の途中のタブを閉じても問わない——連のエディターは残るので、何も失われない。保存を選んで 1 つでも失敗すれば閉じない／終了しない——失敗はいずれも音で断り、外部変更（→ [files](files.md)）なら印が立ったまま残って ⌘S の上書きへ、書けない先（親ディレクトリの消失・読み取り専用・容量）ならそのまま。シェルの終了・agent の終了と制御 API による閉鎖（`close_tab`・`remove_workspace`）で連の最後のタブが閉じたときは、確認せず黙って捨てる——プロセスは既に無く、無人の操作に確認は出せない。人が自分のタブを閉じたあと、残った agent のタブが後で終われば、その連の未保存はそこで消える。× とタブを閉じる確認は sheet で非同期に確定し（閉じる要求は main-queue のブロックから届くので、その中のモーダルは端末描画と制御 API を止める）、応答までにタブが消えていれば何もしない。終了の確認は実行中プロセスの確認と同じくモーダル。文言は現在言語。

## 外部変更の上書き

印の立った文書（→ [files](files.md)）の ⌘S は「ディスク上で変更されています」の確認を出し、上書きを選べば force で保存する。キャンセルなら何もしない。上書きは戻せないので Return では確定しない（クリックだけ。Esc はキャンセル）。上書きされるのは確認を出した文書——応答までに焦点が別の文書へ移っていても（エージェントの `open_file`）変わらず、その文書が閉じられていれば何もしない。上書きも通常の保存も書けない先（親ディレクトリの消失・読み取り専用・容量）で失敗すれば音で断り、印は立ったまま残る（エラー面は持たない）。

## 開いていた文書の復元

連は開いている文書のタブの実体パスの列とアクティブの実体パスと仮のタブの実体パスを永続する（→ [persistence](../platform/persistence.md)）。diff のタブは永続せず再起動で戻らない——アクティブが diff のタブなら、diff のタブを除いた列でその位置にある文書のタブ——右隣、無ければ左隣（焦点のタブを閉じたときに焦点が移る規則と同じ）をアクティブとして書き、仮のタブが diff のタブなら仮は書かない。復元は連の器が初めて content に載るとき（前面で mount される・背景で起こされる → [layout](../chrome/layout.md)）に起き、タブの起床には結ばない——起きているタブが cd でまだ一度も載っていない連へ入っても、その連の器が初めて載る時点で戻る。読めなくなったファイルは黙って落ちる（アクティブが落ちていれば先頭、仮のタブが落ちていれば仮のタブ無し）。仮のタブは仮のまま同じ位置に戻る——再起動のたびに見ていただけのタブが普通のタブとして積もらない。復元より先に開いていた文書があれば（制御 API の `open_file`）その焦点と開き方を保つ——復元は既に居るものを壊さず、普通に開いていた文書を仮に下げない。未保存の内容は戻らない。一度も載らなかった連は未消費の状態をそのまま書き戻すので、再起動を重ねても文書の列は失われない（まだ載っていない連へ cd で文書が移ってきても、未消費の文書は開いている文書の後ろに合わせて書く）。

## VS Code との差

仮のタブは VS Code の preview editor を土台にし、次の点で違う。

- **エクスプローラーのシングルクリックは本文へ焦点を移す**（VS Code はエクスプローラーに残す）。エクスプローラーはキー操作を持たず、焦点を残すと打鍵が前に居た所（分割中なら端末）へ行くため。
- **入れ替えは仮のタブの位置で、無ければ末尾**（VS Code はアクティブなタブの右）。結果をたどる間タブが動かず、新しく開いた文書は末尾という列の規則とも食い違わない。
- **仮のタブを切る設定と、固定のキー（VS Code の ⌘K Enter）は持たない**。固定はダブルクリックか編集で足り、覚える近道を増やさない。
- **押し続けた ↑↓ は離すまで開かない**（VS Code は時間だけで間引くので、初期遅延の間やリピートの間隔が窓より長いときに窓が切れて開く）。→ [search](search.md)
- **斜体に斜線の地を足す**（VS Code は斜体だけ）。斜体だけでは普通のタブと見分けにくく、日本語名・絵文字では斜体が効かない字もあるため。
