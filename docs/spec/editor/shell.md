# 面の骨

エディター面の中身の構造。端末の隣でファイルを選び、複数開いて切り替え、閉じ、作るための器で、文書のコードビュー（→ [code](code.md)）はこの骨の本体に載る。左からレール・サイドバー（エクスプローラー）・列——列は上からファイルタブ行、パンくず、本体（焦点の文書のテキスト面。無ければ[面の機構](faces.md)の空状態）。骨は SwiftUI の部品で、幾何は面（AppKit）が解く——テキスト面は view の同一性と焦点の取り方に依存し、SwiftUI の再親化に晒せないため。

## サイドバーの幅と開閉

サイドバーの幅はドラッグで変えられる——サイドバーと本体の境（縁の線）に細い当たりがあり、掴むと連続で追従する。下限があり、上限は本体に最低幅（サイドバーの下限と同じ）が残るまで。開閉はレールで行う（後述）。幅と開閉の記憶は**アプリ全体で 1 つ**（タブ・workspace をまたいで同じ。面の配置のようなタブ単位ではない）で、再起動でも戻る（→ [persistence](../platform/persistence.md) の app-state）。

サイドバーが見えるかは開閉だけで決まり、列幅は関係ない。列が狭いときは**表示幅を「列幅 − レール − 本体の最低幅」まで切り詰める**——記憶している幅は変えず、列が広がれば記憶の幅に戻る。それでも足りない極端な幅では残りをそのまま分け、サイドバーの表示幅は 0 まで縮む。当たりは境を動かせるときだけ出る——列が狭くてサイドバーを下限まで出せない間は境が動かないので、当たりも出ない。文書が無いときもファイルタブ行の帯は残り、本体に空状態が出る。寸法と色は [design-system](../../design/design-system.md) §5 の Rail / Explorer / File tabs / Breadcrumb。

## レール

左端のアイコン列。項目は「ファイル」1 つ。選択中の項目を押すとサイドバーが閉じ、もう一度押すと開く（項目が増えれば、別の項目を押すとそのパネルへ切り替わり、同じ項目を押すと閉じる）。選択は左縁の細い accent 線と淡い地で示し、サイドバーを閉じている間は選択印が無い——design-system §5 が「選択を左バーで示すのはエディター面のレールだけ。chrome ではどこでもしない」と定める、その 1 か所。

## エクスプローラー

タブの根（cwd が属する git worktree ルート。管理外は cwd → [files](files.md)）の実ファイルを描く。展示データは持たない。

- **ルート行**は根の basename を大文字で出し、クリックで根の開閉。ヘッダー右端に 新規ファイル／新規フォルダ／すべて折りたたむ の 3 ボタン。
- **ツリー**はディレクトリを先に、あとは名前順（大小無視）。ディレクトリはシェブロン（クリックで開閉）、ファイルは種別チップ（種別 → 見た目の決定点は 1 か所で、15 言語は色相付き、未知は拡張子の頭文字の無彩、拡張子が無ければ `·`）。ファイル行の右端に git バッジ——M（変更）・A（追加）・U（未追跡）・C（競合）——を出し、**名前もバッジの色**で描く。ディレクトリ行はバッジを持たず、配下の集約もしない。
- **展開は面の状態**で永続しない。一覧は展開したディレクトリだけ遅延で取り、監視の通知（→ [files](files.md)）で変わったパスの親のうち展開中のものを取り直す。展開中のディレクトリが消えれば畳む。読めないディレクトリは空として畳む。
- **根のサービスは面が画面に見えている間だけ握る**（窓に付き、隠れていない）。隠れているタブや幅 0 の面は握らないので、全タブの根を常時監視しない。離すと監視は止まるが一覧と status の見え方は保ち、次に見えたときに握り直して展開中を取り直す。**status は最後に成功したもの**を保つ——握り直した直後（git が返るまで）も、git の一時失敗でも、バッジは消えない。根が変われば（cd）ツリーを作り直す。
- **文書をアクティブにしたとき**（ツリーのクリック・ファイルタブ・制御 API `open_file`・復元）、根の下ならツリーは祖先を開いてその行を選択表示し、可視位置へ送る。根の外の文書では選択を外す。パンくずのディレクトリを押しても同じく開いて選択する。
- **新規作成**はツリーの行内入力。挿す先は、選択がディレクトリならそこ、ファイルならその親、無ければ根で、その親の子の先頭に入力行が現れ、可視位置へ送る。続けて押せば前の入力は消えて新しい入力だけが出る。Enter で作り、ファイルならそのまま開く。空・`/` 入り・既に在る・作れない名前は音で断って入力に留まる。Esc と、焦点が別の view へ移ることで取り消す。入力の終わりは入力の状態が落ちることで、理由を問わない（Enter・取り消しのほか、すべて折りたたむ・根を畳む・サイドバーを閉じる・cd など）。打ちかけの名前は入力の状態が持つ。中間ディレクトリは作らない。

## ファイルタブ行

セッションの文書の列（→ [code](code.md)）を自然幅のタブで並べ、溢れは横スクロール（スクローラーは出さず、アクティブが変われば可視位置へ）。タブはチップ・名前・未保存ならドット（外部変更と衝突中はドットが変更の黄になる）・×。クリックで切替（undo・選択・スクロールは文書ごとに残る）、× はホバーで見え、押すと閉じる（幅は常に確保し、ホバーでレイアウトが動かない）。アクティブは淡い地と上縁の accent 線で示す——レールと同じくエディター面の中だけの例外。右端に分割・その他の印は持たない。

## パンくず

焦点の文書の、根からのディレクトリ ›…› チップとファイル名。ディレクトリはホバーで文字が上がり、押すとツリーのそのフォルダが開く。根の外の文書は絶対パスの構成要素で、押せない。診断件数は持たない。文書が無ければパンくずの段は無い。

## 焦点

骨の操作で文書を開く・切り替える・新規作成を確定したら、焦点を面の焦点 view（テキスト面）へ移す——制御 API `open_file` と同じ結果で、分割中は面の記憶もエディターへ移る。× は焦点を動かさない（面の中に焦点があれば新しい行き先へ移るのは[コード](code.md)の規則）。行内入力を出すときは先に面自身が first responder になる——面の記憶がエディターへ移る経路は面とテキスト面の 2 つしか無く、入力欄が直接焦点を取ると分割中の焦点帯と位置ドットが端末を指したままになる。入力欄は面の配下なので chrome キー（→ [layout](../chrome/layout.md)）は効いたまま、通常の打鍵は入力欄に入る。入力行が画面外に出て入力欄が消えている間は面が焦点を預かり（打ちかけは残る）、行が戻れば入力欄が取り直す——預かっている間に焦点が面の外へ移れば取り消す。入力が終わったとき焦点がまだ入力欄か面か窓に居れば面の焦点 view へ移す（端末をクリックして抜けて終わったなら端末のまま）。

## 未保存を捨てる前の確認

未保存の文書を捨てる人の操作は 1 種類の確認——保存／保存しない／キャンセル——を挟む。入口は 3 つ: ファイルタブの ×（その文書 1 件）、人の操作でタブを閉じる（⌘W・タブ行の中クリック・workspace パレットの削除。そのタブ、または workspace の全タブの未保存を合計して 1 回）、アプリの終了（全 workspace の全タブの合計）。保存を選んで 1 つでも失敗すれば閉じない／終了しない——失敗はいずれも音で断り、外部変更（→ [files](files.md)）なら印が立ったまま残って ⌘S の上書きへ、書けない先（親ディレクトリの消失・読み取り専用・容量）ならそのまま。シェルの終了と制御 API による閉鎖（`close_tab`・`remove_workspace`）は確認せず黙って捨てる——プロセスは既に無く、無人の操作に確認は出せない。× とタブを閉じる確認は sheet で非同期に確定し（閉じる要求は main-queue のブロックから届くので、その中のモーダルは端末描画と制御 API を止める）、応答までにタブが消えていれば何もしない。終了の確認は実行中プロセスの確認と同じくモーダル。文言は現在言語。

## 外部変更の上書き

印の立った文書（→ [files](files.md)）の ⌘S は「ディスク上で変更されています」の確認を出し、上書きを選べば force で保存する。キャンセルなら何もしない。上書きは戻せないので Return では確定しない（クリックだけ。Esc はキャンセル）。上書きされるのは確認を出した文書——応答までに焦点が別の文書へ移っていても（エージェントの `open_file`）変わらず、その文書が閉じられていれば何もしない。上書きも通常の保存も書けない先（親ディレクトリの消失・読み取り専用・容量）で失敗すれば音で断り、印は立ったまま残る（エラー面は持たない）。

## 開いていた文書の復元

タブは開いている文書の実体パスの列とアクティブの実体パスを永続する（→ [persistence](../platform/persistence.md)）。復元はタブが materialize されるときに起き、読めなくなったファイルは黙って落ちる（アクティブが落ちていれば先頭）。復元より先に開いていた文書があれば（制御 API の `open_file`）その焦点を保つ——復元は既に居るものを壊さない。未保存の内容は戻らない。一度も見なかったタブは未消費の状態をそのまま書き戻すので、再起動を重ねても文書の列は失われない。
