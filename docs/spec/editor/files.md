# ファイルと git

エディター面が乗る、UI を持たない土台。開いている文書のファイルが外で書き換わったら追いつく、外で `git add` すれば印が変わる、index の版と本文の差が引ける——端末の隣でエージェントがファイルを書き換え続ける前提で、面に見えるものを実物に追従させるための機構。ツリー・バッジ・ガターの見え方は各面の spec が持ち、ここは「何を、いつ、どう知るか」だけを持つ。

## 根

エディターの根は、タブの cwd が属する git worktree ルート。git 管理外なら cwd 自身。タブ行の連（→ [chrome](../chrome/chrome.md)）と同じ規則・同じ値で、規則の置き場は 1 か所。symlink 経由の綴りや `/private` の有無が違っても同じ場所は同じ根になる。

根が git 管理下かどうかは根のサービスが決める。根に `.git` があれば git に toplevel を訊き、その綴りを正準形に揃えて根と一致したときだけ管理下——`.git` はあるが git が別の toplevel を返す（壊れた `.git`）か失敗すれば管理外として扱う。git の返す綴りと根の綴りの突き合わせはここ 1 か所に閉じ、git の綴り自体は書き換えない（Dispatch は `git worktree list` の生パスと等値比較するため）。

根が git 管理下になる／外れる変化は cwd の変化まで追わない。

## 根のサービスと寿命

根 1 つにつき 1 つのサービスが、監視・git 状態・開いている文書の baseline・一覧・新規作成を担う。同じ根を見る者は同じサービスを共有し、握る者がいる間だけ生きる——文書を全部閉じ、面も隠れれば監視も止まる。全タブの根を常時監視しない。

握る者は観測者として登録し、baseline を追いたいファイルへの**関心**を申告できる。追う集合は生きている観測者の関心の和集合で、観測者が消えれば関心も消える。同じファイルを 2 つのタブで開いて片方を閉じても、残った方の baseline は追従し続ける。

握る者は 2 種。開いている文書ごとの**結線**（文書と同寿命）と、エディター面の**ツリー**（→ [shell](shell.md)。面が画面に見えている間だけ握り、タブの根を見る）。結線が握るのは文書の実体が属する根であって、タブの根ではない——制御 API で外のファイルを開いても、その文書の baseline と外部変更は自分のリポジトリで見る。

## 監視

根の下と、git 管理下なら git dir（linked worktree では本体側にある index・HEAD の在処と共有の refs）を FSEvents で監視する。届いた変化は 3 本の通知に分かれる。

- **ファイルが変わった** — 変わったパスの集合（根の綴りの絶対パス）。取りこぼしがあれば「全部見直せ」。git dir の中は含まない。
- **status が変わった** — git 管理下のみ。取り直しの結果が前と違うとき。git の一時失敗では変えない——status は「最後に成功した取り直しの結果」で、失敗のたびに印が消えて戻ることはない。
- **baseline が変わった** — 関心のあるファイルについて。初回の取得も、index から消えて無くなったときも含む。

git dir の中は、objects・reflog・他の worktree の私有状態・submodule の内部・`.lock` の出入りと、git 自身の読み取りが生む副産物（fsmonitor デーモンの cookie——拾うと自分の status が自分を呼び戻す）を除いて拾う（index・HEAD・refs・packed-refs・merge / rebase の進行状態——拾う側を列挙せず、git が足す状態ファイルは拾う側に倒す）。監視は連続する変化の間は待つが、最初の保留から 1 秒経てば続いていても出す——ビルドのように変わり続ける間も通知は 1 秒に 1 回は出る。根が管理下と分かったときに根の監視を張り替えない（張り替えの隙間に届いた変化が落ちる）。

自分の保存も監視には映る（clean → M）。除くのは「文書の外部変更」だけで、それはダイジェストの比較が担う（後述）。

## 取り直しジョブ

git 管理下の根は、監視の 1 バッチごとに取り直す: status → 関心のあるパスの index の OID → OID が変わったものだけ blob の本文。「status が変わった」の通知は status が返った時点で出し、baseline はその後に続く——blob の取得は smudge filter（git-lfs のネットワーク等）で遅くなりうるので、その後ろにバッジを並べない。根ごとに 1 本に直列化し、実行中に要求が来たら「終わったらもう 1 回」に畳んで積まない。古い結果が後から乗らず、index が動けば監視が取り直すので最終的に最新へ収束する（status と baseline が同一時点である保証は持たない——別々の git 起動で読む）。世代を数えて捨てる仕組みは持たない——直列化で足りる。

観測は独立レーンで走る（→ [git](../platform/git.md)）。巨大リポジトリの status が worktree の削除や ref の更新を待たせない。

## status とバッジ

status はユーザーの設定に左右されない——未追跡の表示・submodule の無視は引数で封じ、パスは NUL 区切りで verbatim に受け、観測で index を書き換えない。ファイルは根からの相対パスで引け、印は 4 つ: 変更（M）・index に追加（A）・未追跡（U）・競合。競合が最優先、次に unstaged の変化（index に追加した後の編集は M）、それ以外の変化（削除・rename・種類の変化を含む）は M。未追跡ディレクトリの中のファイルは status に個別に出ないので、ディレクトリの前方一致で U と引ける。ディレクトリ行の集約は持たず、面も集約しない（ディレクトリ行は無印 → [shell](shell.md)）。

## baseline

開いている文書の baseline は、index の版を**作業ツリーに出したときの中身**——そのパスの属性で smudge filter と eol 変換を掛けた後の本文（textconv・外部 diff は通らない）。ガターは git の見方を映すものなので、底も git が clean と言う姿に揃える。`git add` / `git checkout` 等で index の blob が変われば追従し、変わらなければ取り直さない（OID で判定）。取り直しの鍵が OID なので、`.gitattributes` や filter 設定の変更は index の blob が変わるまで baseline に映らない。作業ツリーの編集では変わらない。未追跡・非 git・index に無い・競合中（stage 0 が無い）・UTF-8 でないファイルは baseline 無し。smudge の実行コマンドは config 側にしか書けず、信頼できないリポジトリがコードを走らせる面は checkout と同じ。

文書は baseline と本文の行差分（ハンク）を持つ（→ [code](code.md)）。

## 一覧と新規作成

ディレクトリの一覧は `.git` を出さず、ドットファイルは出す。名前順（大小無視。ディレクトリを先に並べるのは面の側）で、symlink は辿らない（リンク自体の種類）。空ファイルとフォルダを作れ、既に在れば失敗し（在るかも symlink を辿らない——壊れた symlink の位置には作らない）、中間ディレクトリは作らない。作った変化は監視が拾い、通知は通常の経路で出る。

## 外部変更

文書は**ディスクの姿**——最後に読んだ／書いたファイルのバイト列（BOM を含む）のダイジェスト——を持つ。監視で自分のパスが変わった（または全部見直せ）とき、および ⌘S の直前に、実ファイルを読み直して比べる。監視が届く前の ⌘S でも同じ判定になる。

- 未保存でない文書は本文を新しい内容に差し替える。⌘Z で戻せる区切りで、未保存にならない。
- 未保存の文書は本文を保って「ディスクが変わった」印を立てる。印の立った文書の ⌘S は失敗し、ディスクに触れない。force の保存だけが上書きする（印はファイルタブのドットの色に出て、force は ⌘S が出す上書きの確認で選ぶ → [shell](shell.md)）。
- 外のツールが UTF-8 として読めない内容（別の符号化・バイナリ）を書いたときも、一致を証明できないので差し替えず印を立てる。存在するが読めない（権限等）ファイルは消えたものと同じに扱う（印は立たず、⌘S は書く）。
- 「ディスクが変わった」は照合のたびに導出する。同じバイト列の書き直し（mtime だけの変化。BOM の有無の変化は変化として拾う）・自分の保存・消えたファイルでは印は立たず、外のツールが元の内容に戻せば消える。消えたファイルは ⌘S で作り直す。

印の変化はタブの通知に載る（未保存と同じ 1 本）。
