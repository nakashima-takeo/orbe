# ファイルと git

エディター面が乗る、UI を持たない土台。開いている文書のファイルが外で書き換わったら追いつく、外で `git add` すれば印が変わる、index の版と本文の差が引ける——端末の隣でエージェントがファイルを書き換え続ける前提で、面に見えるものを実物に追従させるための機構。ツリー・バッジ・ガターの見え方は各面の spec が持ち、ここは「何を、いつ、どう知るか」だけを持つ。

## 根

エディターの根は、タブの cwd が属する git worktree ルート。git 管理外なら cwd 自身。タブ行の連（→ [chrome](../chrome/chrome.md)）と同じ規則・同じ値で、規則の置き場は 1 か所。symlink 経由の綴りや `/private` の有無が違っても同じ場所は同じ根になる。

根が git 管理下かどうかは根のサービスが決める。根に `.git` があれば git に toplevel を訊き、その綴りを正準形に揃えて根と一致したときだけ管理下——`.git` はあるが git が別の toplevel を返す（壊れた `.git`）か失敗すれば管理外として扱う。git の返す綴りと根の綴りの突き合わせはここ 1 か所に閉じ、git の綴り自体は書き換えない。

管理下かはサービスができるときに 1 度だけ決め、管理下になる／外れる変化はサービスが生きている間は追わない。開いている根で `git init` しても、その根を握る者が誰もいなくなる（文書を全部閉じ、面も隠れる）までは管理外のまま——cd で離れて戻っても、同じ根を握る者がいる間はサービスが同じなので決め直さない。

## 根のサービスと寿命

根 1 つにつき 1 つのサービスが、監視・git 状態・開いている文書の baseline・git の書き込み・一覧・新規作成を担う。同じ根を見る者は同じサービスを共有し、握る者がいる間だけ生きる——文書を全部閉じ、面も隠れれば監視も止まる。全タブの根を常時監視しない。例外は書き込みで、完了をまだ返していない書き込みがある間はサービスが自分を生かしておく（握る者が離れても完了は返り、「根ごとに 1 つ」が崩れない）。

握る者は観測者として登録し、baseline を追いたいファイルへの**関心**を申告できる。追う集合は生きている観測者の関心の和集合で、観測者が消えれば関心も消える。同じファイルを 2 つのタブで開いて片方を閉じても、残った方の baseline は追従し続ける。

握る者は 3 種。開いている文書ごとの**結線**（文書と同寿命）と、エディター面の**ツリー**（→ [shell](shell.md)。面が画面に見えている間だけ握り、タブの根を見る）と、**プロジェクト検索**（→ [search](search.md)。ツリーと同じく面が画面に見えている間だけ握り、タブの根を見る。関心は申告しない）。結線が握るのは文書の実体が属する根であって、タブの根ではない——制御 API で外のファイルを開いても、その文書の baseline と外部変更は自分のリポジトリで見る。

## 監視

根の下と、git 管理下なら git dir（linked worktree では本体側にある index・HEAD の在処と共有の refs）を FSEvents で監視する。届いた変化は 3 本の通知に分かれる。

- **ファイルが変わった** — 変わったパスの集合（根の綴りの絶対パス）。取りこぼしがあれば「全部見直せ」。git dir の中は含まない。
- **status が変わった** — git 管理下のみ。取り直しの結果が前と違うとき。status はブランチ・HEAD・upstream を含むので、作業ツリーが変わらなくても HEAD や upstream が動けば届く（コミット・fetch・push）。git の一時失敗では変えない——status は「最後に成功した取り直しの結果」で、失敗のたびに印が消えて戻ることはない。
- **baseline が変わった** — 関心のあるファイルについて。初回の取得も、index から消えて無くなったときも含む。

git dir の中は、objects・reflog・他の worktree の私有状態・submodule の内部・`.lock` の出入りと、git 自身の読み取りが生む副産物（fsmonitor デーモンの cookie——拾うと自分の status が自分を呼び戻す）を除いて拾う（index・HEAD・refs・packed-refs・merge / rebase の進行状態——拾う側を列挙せず、git が足す状態ファイルは拾う側に倒す）。監視は連続する変化の間は待つが、最初の保留から 1 秒経てば続いていても出す——ビルドのように変わり続ける間も通知は 1 秒に 1 回は出る。根が管理下と分かったときに根の監視を張り替えない（張り替えの隙間に届いた変化が落ちる）。

自分の保存も監視には映る（clean → M）。除くのは「文書の外部変更」だけで、それはダイジェストの比較が担う（後述）。

## 取り直し

git 管理下の根の取り直しは 2 本で、データの依存が無いので別々に走る。

- **status** — status だけ。監視の 1 バッチと、書き込みの完了が求める。
- **baseline** — 関心のあるパスの index の OID → OID が変わったものだけ blob の本文。監視の 1 バッチと、関心の追加が求める。

どちらも根ごとに直列化し、実行中に要求が来たら「終わったらもう 1 回」に畳んで積まない。status は数万エントリになりうるので、前の値との比較と、置き換えた値の解放は main の外で済ませる——main に載るのは、変わったときの受け取りと通知だけ。古い結果が後から乗らず、index が動けば監視が取り直すので最終的に最新へ収束する（status と baseline が同一時点である保証は持たない——別々の git 起動で読む）。世代を数えて捨てる仕組みは持たない——直列化で足りる。2 本に分けるのは、blob の取得が smudge filter（git-lfs のネットワーク等）で遅くなりうるから——その後ろにバッジと書き込みの完了を並べない。

観測の git は他の git を待たない（→ [git](../platform/git.md)）。hook で止まったコミットの間もバッジは追従する。

## status とバッジ

status はユーザーの設定に左右されない——未追跡の表示・submodule の無視・先行/遅れの計数・rename の検出は引数で封じ、パスは NUL 区切りで verbatim に受け、観測で index を書き換えない（→ [git](../platform/git.md)）。中身は、ファイルごとの変化（index 側と作業ツリー側。rename・copy は元パスも）と、ブランチ——今のブランチ（名前 / detached）・HEAD（コミット / 初回コミット前）・upstream（名前と、先行/遅れの数または「不明」）。

未追跡はファイル 1 件ずつ（新しいフォルダの中も。ステージ・破棄の行になる）。index から外して作業ツリーに残したファイル（`git rm --cached`）は、index 側の削除と未追跡を 1 つの行に併せ持つ——ステージ済みの削除として見え、解除できる（印は U）。ディレクトリの形で残るのは未追跡の入れ子のリポジトリだけで、その中のファイルはディレクトリの前方一致で U と引ける。

ファイルは根からの相対パスで引け、印は 4 つ: 変更（M）・index に追加（A）・未追跡（U）・競合。競合が最優先、次に unstaged の変化（index に追加した後の編集は M）、それ以外の変化（削除・rename・種類の変化を含む）は M。ディレクトリ行の集約は持たず、面も集約しない（ディレクトリ行は無印 → [shell](shell.md)）。

## baseline

開いている文書の baseline は、index の版を**作業ツリーに出したときの中身**——そのパスの属性で smudge filter と eol 変換を掛けた後の本文（textconv・外部 diff は通らない）。ガターは git の見方を映すものなので、底も git が clean と言う姿に揃える。`git add` / `git checkout` 等で index の blob が変われば追従し、変わらなければ取り直さない（OID で判定）。例外は取得が git の失敗で落ちたとき——前の baseline（古い index 版）を保ったまま、次の取り直しで同じ版をもう一度取りに行く（LFS のネットワークのような一時失敗を回復させる）。同じ版で 3 回失敗すれば baseline 無しとして諦め、index が別の版へ動くまで取り直さない（必須 filter の欠落のような恒久失敗で git を回し続けない）。取り直しの鍵が OID なので、`.gitattributes` や filter 設定の変更は index の blob が変わるまで baseline に映らない。作業ツリーの編集では変わらない。未追跡・非 git・index に無い・競合中（stage 0 が無い）・UTF-8 でないファイルは baseline 無し。smudge の実行コマンドは config 側にしか書けず、信頼できないリポジトリのコードが実行される面は checkout と同じ——きっかけがファイルを開くことである点だけが違う。

文書は baseline と本文の行差分（ハンク）を持つ（→ [code](code.md)）。

## git の書き込み

根のサービスが git の書き込みの入口になる——ステージ・解除・破棄・コミット・amend・最後のコミットの取り消し・pull・push・fetch（それぞれの意味と失敗の分類 → [git](../platform/git.md)）。git 管理外の根では書き込めない（失敗で返る）。

**順番**: index を書くのはその worktree の根のサービスだけで、根は worktree ごとに 1 つに決まるので、同じ worktree の index への書き込みの順番はここで作れば足りる（git は index.lock を待たずに落ちる）。index を書く操作（ステージ・解除・破棄・コミット・amend・取り消し・pull）は投げた順に 1 つずつ走る。pull はネット待ちごと順番に入り、その間の同じ worktree へのステージ等は待つ（他の worktree・他のリポジトリは待たない）。fetch・push は並ばない。破棄の git とゴミ箱への移動は 1 枠で走り、後から投げた書き込みと入れ替わらない。ステージ・解除・破棄の対象は status の行。rename の行の元パスは、解除には常に含め（rename の行を解除すると、元パスの削除の側も解除される）、ステージ・破棄には呼んだ時点の index に在るときだけ含める（→ [git](../platform/git.md)）。

**止める**: どの書き込みも無出力で打ち切らず、止める手を返す。順番待ちの書き込みを止めると、その場で行列から外れ、前の書き込みの終わりを待たずに git を起こさないまま「止めた」で返る。走っている書き込みは git を止めて「止めた」で返る。

**完了の時点**: 完了は「書き込みの後に始まった status の取り直し」が済んでから返る（結果が前と同じでも、git が失敗しても）。完了が届いた時点で status はもう書き込み後の姿になっている——監視の到着（最大 1 秒）を待たない。書き込みより前に始まっていた取り直しには付けない（書き込み前の状態を読んでいるかもしれない）。baseline の取り直しは待たない。pull・push の前提（upstream・detached）の判定も、取り直した status で行う。

## 一覧と新規作成

ディレクトリの一覧は `.git` を出さず、ドットファイルは出す。名前順（大小とアクセントを無視し、数を数として比べる——`file2` が `file10` より前。ディレクトリを先に並べるのは面の側）で、symlink は辿らない（リンク自体の種類）。空ファイルとフォルダを作れ、既に在れば失敗し（在るかも symlink を辿らない——壊れた symlink の位置には作らない）、中間ディレクトリは作らない。作った変化は監視が拾い、通知は通常の経路で出る。

## 外部変更

文書は**ディスクと揃えた姿**——最後に開いた・保存した・取り込んだときのファイルのバイト列（BOM を含む）のダイジェストと、そのときの本文（未保存の判定の底 → [code](code.md)）——を持つ。監視で自分のパスが変わった（または全部見直せ）とき、および ⌘S の直前に、実ファイルを読み直して比べる。監視が届く前の ⌘S でも同じ判定になる。

- ディスクの内容が今の本文と同じなら（外のツールが同じ修正をした・BOM だけを足した）、本文にも undo にも触れず、それを取り込んだ内容として受け入れる。未保存も印も消える。衝突でも失うものも無いので、上書きの確認を出さない。
- 未保存でない文書は本文を新しい内容に差し替える。⌘Z で戻せる区切りで、未保存にならない。編集しても保存時の内容に戻した文書も同じ。
- 未保存の文書は本文を保って「ディスクが変わった」印を立てる。印の立った文書の ⌘S は失敗し、ディスクに触れない。force の保存だけが上書きする（印はファイルタブのドットの色に出て、force は ⌘S が出す上書きの確認で選ぶ → [shell](shell.md)）。印の立った文書を保存時の内容まで戻して未保存が解けると、その時点で照合し直して外の内容に差し替える（⌘Z で戻せ、戻せば未保存。差し替えた後は redo が消える——redo の編集は差し替えた本文に当てられない）——印が立っていれば、失うと困る未保存があるか、読めない内容が書かれている。
- 外のツールが UTF-8 として読めない内容（別の符号化・バイナリ）を書いたときも、一致を証明できないので差し替えず印を立てる。存在するが読めない（権限等）ファイルは消えたものと同じに扱う（印は立たず、⌘S は書く）。
- 「ディスクが変わった」は照合のたびに導出する。同じバイト列の書き直し（mtime だけの変化。BOM の有無の変化は変化として拾う）・自分の保存・消えたファイルでは印は立たず、外のツールが元の内容に戻せば消える。消えたファイルは ⌘S で作り直す。

印の変化はタブの通知に載る（未保存と同じ 1 本）。
