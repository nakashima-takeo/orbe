# ソース管理

エディター面のレールの「ソース管理」で出すサイドバーのパネル。端末へ戻らずに、変更を見る → ステージする → コミットする → push / pull / fetch するまでをエディターの中で済ませる——エージェントが書き換えた変更を 1 件ずつ diff で確かめ、選んで積む作業を、端末の `git` を打つ手間なしに回すため。git の操作はすべて根のサービスの書き込みの口を呼び（→ [files](files.md)）、走らせ方・順番・前提の判定・失敗の分類はそちら（→ [git](../platform/git.md)）が持つ。ここが持つのは見せ方と、worktree ごとの状態だけ。

## パネルの構成

上から次の順に並ぶ。寸法と色は [design-system](../../design/design-system.md) §5 の Source control panel。

- **見出し**「ソース管理」。
- **実行中の帯**（後述）。走っている操作があるときだけ出る。
- **区分「ソース管理」**: 畳むと下の欄・ボタン・失敗の文が隠れる。右端に ✓（コミット。⌘↵ と同じ条件）・再読込（status を取り直し、グラフを読み直す）・…（メニュー: プル / プッシュ / フェッチ）。
- **メッセージ欄**: 1 行で始まり 10 行まで伸び、その先はスクロールする。↵ は改行（変換中の ↵ は変換の確定だけ）。プレースホルダはブランチに居ればそのブランチ名を含み、detached・初回コミット前は名前を出さない。
- **コミットボタン**と ▾（後述）。
- **失敗の文**（後述）。
- **列**: 「ステージされている変更」「変更」の 2 区分と「ソース管理グラフ」。

git 管理外の根では、見出しの下に理由の一文だけが出る。変更が無い worktree では、列にグラフだけが出る。

## 2 区分の行

- **ステージされている変更**: index 側に変化のあるファイル（競合は含めない）。**変更**: 作業ツリー側に変化のあるファイルと競合。ステージした後に編集したファイルや `git rm --cached` したファイルは両方に出る。
- 行が 0 の区分は見出しごと出ない。区分は見出しで畳め、開閉は面の状態で永続しない。
- 行は種別チップ・名前・ディレクトリ・右端に行のボタンと変化の印。印はその区分の変化で、追加 A・未追跡 U・競合 C・ほか（削除・rename を含む）は M。名前と印はエクスプローラーと同じ色で、赤と緑に頼らない（→ [design-system](../../design/design-system.md) §3）。rename の行は新しいパスの名前だけを出す。
- 並びはパス順（区切りごとに名前を比べ、同じ階層ではファイルが先。名前の比べ方はエクスプローラー・検索結果と同じ）。
- **行のボタンはポインタに依らず全部の行に常に出す**。その分ディレクトリ名が短く省略される。「変更」は ファイルを開く / 変更を破棄 / ステージ、「ステージされている変更」は ファイルを開く / ステージを解除。作業ツリーに無いファイルの「ファイルを開く」と、競合の「変更を破棄」は押せない姿で置き、ボタンの位置は行どうしで揃える。「ファイルを開く」はファイルを普通のタブで開いて本文へ焦点を移す。
- **見出しの一括操作**: 「変更」に すべて破棄・すべてステージ、「ステージされている変更」に すべて解除。件数の印の左に常に出す。**すべてステージ・すべて破棄は競合のファイルを含めない**——競合は 1 行ずつステージして解決済みにする。一括操作で競合の印が残ったまま解決済みにならないため。
- 行は変更が数万件でも、status が変わるたびの main の仕事が件数に比例しない（行の組み立ては裏で済ませ、列は見えている行だけを描く——検索結果と同じ列の部品）。

## diff を開く

「変更」の行は作業ツリー diff、「ステージされている変更」の行はステージ済み diff を開く（→ [diff](diff.md)）。行のシングルクリックと ↑↓ は仮のタブで開き、焦点は列に残る。ダブルクリックと Enter は普通のタブで開いて本文へ焦点を移す。押し続けた ↑↓ は離すまで開かない（検索結果と同じ間引き → [search](search.md)）。

選んだ行がステージ・破棄で区分から消えたら、同じ区分のその位置の行（無ければ前の行）が選ばれる。その行は開かない。選択は行の同一性（区分とパス）で持ち、status が変わって行がずれても同じ行を指す。

## ステージ・解除・破棄

行・見出しの操作どおりに status が変わり、操作が終わった時点で行はもう移っている（監視の到着を待たない）。

**破棄**は、追跡中のファイルを含むと確認のシートを出す——作業ツリーを index の版へ戻すので元に戻せない。文は件数（1 件ならその名前）と、未追跡を含めば「未追跡の N 件はゴミ箱へ移す」。「破棄」はクリックだけで確定し、Return では確定しない（Esc はキャンセル）。未追跡だけの破棄は確認を出さずにゴミ箱へ移す（戻せる）。確認した行をそのまま根のサービスへ渡し、どのパスを戻すかは呼んだ時点の index で選び直される。

## コミットと ▾

- **コミット**: ステージ済みがあり、メッセージが空白だけでなく、コミット中でないときだけ押せる。✓・ボタン・欄での ⌘↵ が同じ。通ればメッセージは空になる（コミットの間に打ち足していれば残す）。失敗ならメッセージは残る。
- **▾**: コミット（amend）/ コミットしてプッシュ / 最後のコミットを取り消す。**HEAD が push 済みなら amend と取り消しは押せない**——force push を持たないので、書き換えれば Orbe の中では戻せない。push 済みは「どれかの remote 追跡ブランチから届く」で（→ [git](../platform/git.md) のコミットグラフ）、HEAD 1 件をその規則で読み、読んだコミットと組で持つ。今の HEAD と違うコミットを読んだ・読み直している・読めない間は分からないとして押せない側に倒す——端末で HEAD を push した直後から押せなくなる。amend はステージ済みかメッセージがあるときだけ。コミットしてプッシュはコミットが通ったときだけ push する。
- 取り消したコミットのメッセージは欄に戻さない。

## 同期と公開

コミットできる変更（ステージ済みも変更も）が 1 つも無いとき、コミットボタンは働きを替える（VS Code と同じ）。

- ブランチに居て upstream があり、先行か遅れがあれば「**同期 ↑N ↓M**」（0 の側は出さない）。押すとプル → プッシュの順に走る（数に依らず両方）。
- ブランチに居て upstream が無ければ「**ブランチを公開**」。押すと upstream を付けて push する（付け先は根のサービスの push の解決）。
- どちらでもなければ押せない「コミット」。

**⌘↵ はコミットだけ**で、ボタンが同期・公開でもネット操作は起こさず、コミットできなければ音で断る——打鍵 1 つで意図しない push が起きないため。

## プル・プッシュ・フェッチ

区分「ソース管理」の … から選ぶ。**前提が足りないときも押せる**——押せば根のサービスの分類どおりの失敗の文（「upstream がありません。先にブランチを公開してください」など）が出る。前提の判定は根のサービスの 1 か所に置き、パネルで重ねて判定しない（判定が 2 か所に割れると食い違い、押せない理由も見えない）。

**ネット操作は worktree ごとに 1 つずつ**: プル・プッシュ・フェッチ・同期・公開・コミットしてプッシュのどれかが走っている間、同じ worktree のほかのネット操作は押せない（別の窓で同じ worktree を見ていても）。ステージなどは押せ、根のサービスの順番どおりに待つ。

## 実行中と止める

どの操作も、走り始めてから 0.3 秒を超えて走っていれば、見出しの下に帯を出す——上端に流れる細い線、操作名、push / pull / fetch の段なら git の進捗の最新の行（git の語のまま・末尾省略）、右端に「止める」。短い操作で帯が点滅しない。帯は**実際に走っている**操作だけを出し、順番待ちの操作は出さない——返らない hook のコミットの後ろでステージしても、帯はコミットとその止める手を出す。走っている操作が複数あれば一番新しく走り始めたものを出す。順番待ちか走っているかは根のサービスの順番の中にしか無いので、根のサービスの「走り始めた」の知らせで決める（→ [files](files.md)）。

「止める」は今の段を止め、2 段の操作なら次の段を起こさない。止めた操作は失敗の文を出さない。hook が返らないコミットを止めても `index.lock` は残らない。ゴミ箱へ大量に破棄している間も UI は止まらず、止められる。

## 失敗

失敗はコミットボタンの下に danger の文で出す——理由と次の一手。画面と入力（メッセージ）を保ち、次の操作を始めると消える（Orbe の操作の失敗の型。検索パネルのエラーの文と同じ）。分類（認証・ホスト鍵が未知・push の拒否・プルの競合・操作の途中・ブランチに居ない・upstream が無い・push 先が無い・shallow の境界）ごとに文が違い、分類できない失敗は git の理由の行そのまま。止めた操作と git 管理外は文にしない。

## グラフ

HEAD と、在れば upstream から届くコミットを新しい順に 50 件出し、続きがあれば末尾の「さらに表示」で 50 件ずつ増やす。

- 頭にブランチの器: ブランチ名（detached は HEAD の短い sha）と先行/遅れ `↑N ↓M`（upstream があり数が分かるときだけ。0 の側は出さない）。
- 未 push のコミットは塗りの点、push 済みは中抜きの点と弱い字。縦の線は 1 本で、枝分かれ・merge の線は描かない。
- ブランチを指すコミットに ref の札（local / remote）。札が入らなければ末尾から省く（題が先に詰まる）。
- **コミットの行は押せず、乗っても地が付かない**——押しても何もしない行を押せそうに見せない。コミットの中身を見る面は持たない。
- **読み直し**: パネルを出したとき・再読込・さらに表示・自分の操作の終わり・根のサービスの「git の状態が変わった」の知らせで読み直す。status の変化だけでは読み直しの合図にしない——端末での upstream を付けない push・ブランチの作成や削除は ref だけを動かし、status は変わらない。いつも先頭から今の件数で読む（続きを継ぎ足さない——読みの間に HEAD が動くと重複・欠落する）。読んでいる間に次の合図が来たら、終わった後に 1 回だけ読み直す。読めなければ前の結果を保つ。
- グラフと HEAD の push 済みは、パネルを出している間だけ読む。

## worktree ごとの状態

打ちかけのメッセージ・走っている操作と止める手・最後の失敗は、**worktree（根）ごとに 1 つ**、アプリが動いている間持つ。同じ worktree を 2 つの窓の面で見れば同じものが見え、cd で離れて戻っても、パネルを閉じても残る（メッセージは同じ値を共有するので、2 つの窓で同時に打つ場面は想定しない）。再起動では消える（永続しない）。走っている操作は始めたときの根のサービスを、全段が終わるまで握る。

面ごとに持つのは見せ方——区分の開閉・グラフの件数・選択・パネルの中の焦点——と観測だけ。パネル（面）は面が見えている間だけ根のサービスを握る（→ [files](files.md) の握る者）。

## 件数

レールの「ソース管理」の右下に、ステージ済みの行と変更の行の和を出す（同じファイルが両方に出れば 2 と数える。1000 以上は「999+」）。変更が無い・git 管理外なら出さない。パネルを開いていなくても、面が見えていれば status の変化に追従する——行の組み立て・グラフ・HEAD の push 済みの読みはパネルを出している間だけ行い、件数のためにパネルを開かせず、隠れたパネルのために git を起こさない。

## キーと焦点

- レールで「ソース管理」を出すとメッセージ欄に焦点が入る（区分「ソース管理」を畳んでいれば列）。パネルが隠れたとき焦点がパネルにあれば、面の焦点の行き先へ戻す（→ [shell](shell.md) の焦点）。
- 欄の **⌘↵** はコミット（前述）。変換中なら確定してからコミットする。
- 列は押せば焦点を取り、検索結果と同じ型で動く: **↑↓** は区分見出しとファイル行だけを渡り（グラフの行は選べない）、ファイル行なら仮のタブで diff を開く。**←** はファイル行から区分の見出しへ、見出しなら畳む。**→** は畳んだ見出しを開き、開いた見出しなら最初のファイル行へ動いて開く。**Enter** はファイル行を普通のタブで開いて本文へ（見出しは開閉）。**⌘↑** は先頭の行（か未選択）からメッセージ欄へ戻る。**Esc** は選択を外す。ステージ・破棄のキーは持たない（ボタンで行う）。
- 行のボタン・見出しの一括操作・「さらに表示」の押下は行のクリックにならない（選択も開きもしない）。ボタンにポインタを乗せると説明が出る。

## VS Code との差

- **⌘↵ はコミットだけ**（VS Code はボタンの今の働き——同期・公開を含む——を実行する）。
- **プル等を前提不足で押せなくしない**（VS Code はメニューから消す・押せなくする）。押して理由の文を見せる。
- **すべてステージ・すべて破棄は競合を含めない**（VS Code は「マージの変更」を別の区分に分ける）。
- **グラフの線は 1 本**（VS Code は枝分かれと merge を描く）。グラフのコミットは押せない。
- **自動の fetch を持たない**。先行/遅れは手で fetch するか、端末の git で ref が動いたときに変わる。
- **印は M・A・U・C の 4 種**（VS Code の D・R は持たない）。削除の行に取り消し線も引かない。
- **行のボタンは常に出す**（VS Code はポインタを乗せた行だけ）。
- **取り消したコミットのメッセージを欄に戻さない**。
- **AI によるメッセージ生成は持たない**。
