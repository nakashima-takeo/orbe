# ソース管理

エディター面の Changes の画面の、左の列のパネルと、上のバーの部品（ブランチ名・同期・コミット）と、コミットのポップアップ（上のバーの `Changes` で出す → [shell](shell.md)）。端末へ戻らずに、変更を見る → ステージする → コミットする → push / pull / fetch するまでをエディターの中で済ませる——エージェントが書き換えた変更を 1 件ずつ diff で確かめ、選んで積む作業を、端末の `git` を打つ手間なしに回すため。パネルの git の操作は、すべて根のサービスが持つ書き込みの口を呼ぶ。書き込みの順番は根のサービス（→ [files](files.md)）が持ち、走らせ方・前提の判定・失敗の分類は git 実行の基盤（→ [git](../platform/git.md)）が持つ。ここが持つのは見せ方と、worktree ごとの状態だけ。

## パネルの構成

上から次の順に並ぶ。寸法と色は [design-system](../../design/design-system.md) §5 の Source control panel。

- **見出し**「ソース管理」。
- **親「ソース管理」**: 中に 2 つの子の区分（後述）が入る。畳むとそれらが全部隠れる——2 つの区分は「このリポジトリの変更」の 1 つのまとまりなので、見出しの深さと畳む単位をそのまとまりに揃える（VS Code のリポジトリと同じ階層）。右端に再読込（status を取り直し、グラフと HEAD の push 済みを読み直す）・…（メニュー: プル / プッシュ / フェッチ）。
- **変更の列**: 「ステージされている変更」「変更」の 2 つの子の区分。
- **境目**: 親とグラフの枠の間。上下に引くとグラフの枠の高さが変わる。親とグラフの枠の両方が開いているときだけ出る。
- **グラフの枠**: 上端の区切り線の下に見出し「グラフ」とグラフの列（後述）。グラフはコミットのまとまりの外の、履歴を見る別の道具なので、親と同じ深さの別の枠に置き、変更の列とは別にスクロールする——変更が多くても、グラフが列の末尾へ押し出されない。

高さの割り振り: 両方開いていれば、グラフの枠は持っている高さで、親は残りを取る。持っている高さは、親に「親の見出し＋3 行」が残る上限で丸めて見せる（持っている高さは変えない）。親の下限と両立しない低い窓では、グラフの枠が下限を割って縮み、見出しだけは残す（コミットの作業の側を優先する）。窓の高さを変えても、グラフの枠の高さは保ち、親が伸び縮みする。親を畳めばグラフの枠が親の見出しのすぐ下から残りを全部取り、グラフを畳めば見出しだけが下端に寄って親が下まで伸びる。両方畳めば、親の見出しは上端・グラフの見出しは下端。

境目を引く高さは、下限（見出し＋3 行）から上の上限まで連続に追従し、上限が下限に届かない窓では動かない。上限に押し付けても、持っている高さは見えている高さより伸びない（高さは境を動かしたときだけ変わる）。高さは左の列の幅と同じく、アプリ全体で 1 つで、離したときに書き戻して再起動でも残る（→ [shell](shell.md)・[persistence](../platform/persistence.md)）。既定は見出し＋8 行。変更は 0〜数万件、グラフは 50 件から増えるので、どちらが要るかは場面で変わる——固定では片方が常に余るか詰まる。

git 管理外の根では、見出しの下に「表示できません」の一言だけが出て、本体に見出し「変更を表示できません」と理由の一文（「このフォルダは git で管理されていません」）が出る。変更が無い worktree では、親の中に子の区分の代わりに「変更なし」の一言が出て、グラフの枠は出る。一言は、今の status から組んだ行の組が空と分かったときだけ出す（status を読む前・組み立ての最中は出さない）。本体には見出し「変更なし」と一文「作業ツリーは HEAD と同じです。」が出る（→ [faces](faces.md) の面の中身と空状態）。

## 2 区分の行

- **ステージされている変更**: index 側に変化のあるファイル（競合は含めない）。**変更**: 作業ツリー側に変化のあるファイルと競合。ステージした後に編集したファイルや、`.gitignore` に当たらないファイルを `git rm --cached` したものは両方に出る。`.gitignore` に当たるファイルを `git rm --cached` すると、git が作業ツリー側を出さないので「ステージされている変更」の削除だけに出る。未追跡の入れ子のリポジトリは、行にも件数にも出さない（ステージは埋め込みの gitlink になり、破棄はリポジトリごと移すため）。エクスプローラーでは中のファイルが U。
- 2 つの区分は親「ソース管理」の子で、見出しもファイル行も親より 1 段字下げする。行が 0 の区分は見出しごと出ない。区分は見出しで畳め、親・子の区分・グラフの枠の開閉は面の状態で永続しない。親を畳んで開いても、子の区分の開閉・選んでいた行・打ちかけのメッセージは畳む前のまま。
- 行は種別チップ・名前・ディレクトリ・右端に行のボタンと変化の印。印はその区分の変化で、追加 A・未追跡 U・競合 C・ほか（削除・rename を含む）は M。名前と印はエクスプローラーと同じ色で、赤と緑に頼らない（→ [design-system](../../design/design-system.md) §3）。rename の行は新しいパスの名前だけを出す。
- 並びはパス順（区切りごとに名前を比べ、同じ階層ではファイルが先。名前の比べ方はエクスプローラー・検索結果と同じ）。
- **行のボタンはポインタに依らず全部の行に常に出す**。その分ディレクトリ名が短く省略される。「変更」は ファイルを開く / 変更を破棄 / ステージ、「ステージされている変更」は ファイルを開く / ステージを解除。作業ツリーにファイルとして無い行（消えた・作業ツリーに無い競合・サブモジュールの行——ディレクトリはファイルとして開けない）の「ファイルを開く」、競合の「変更を破棄」、サブモジュールのまま変わった行（チェックアウトしているコミットが動いた・中のファイルが変わった・増えた）の「変更を破棄」、そのうち中身だけ変わった行（チェックアウトしているコミットは同じ）の「ステージ」は押せない姿で置き、ボタンの位置は行どうしで揃える——git はサブモジュールのまま変わった行を restore で戻さず、中身だけの変化は add でもステージしないので、押せる姿だと何も起きない（破棄なら、戻せない確認を通した後で）。`.gitignore` に当たるファイルを `git rm --cached` した行の「ファイルを開く」も押せない姿——作業ツリーに在っても、git が作業ツリー側を出さないので在ると分からない。中でコミットした行は ＋ でステージできる（記録するコミットが変わる）。作業ツリーで消した・ファイルに置き換えたサブモジュール（ファイルに置き換えてステージした後に編集した行も）は、ほかの行と同じく押せる。破棄はサブモジュールの中に触れない——利用者の設定が submodule.recurse でも、中の未コミットの作業や中で作ったコミットを消さない。「ファイルを開く」はファイルを普通の文書として開いて本文へ焦点を移す。
- **見出しの一括操作**: 「変更」に すべて破棄・すべてステージ、「ステージされている変更」に すべて解除。件数の印の左に常に出す。**すべてステージ・すべて破棄は競合のファイルを含めない**——競合は 1 行ずつステージして解決済みにする。一括操作で競合の印が残ったまま解決済みにならないため。すべてステージは中身だけ変わったサブモジュールを、すべて破棄はサブモジュールのまま変わった行を含めない——行のボタンと同じく、git が何も変えないため。入る行が 1 つも無ければ、すべてステージ・すべて破棄は押せない姿で置く（すべて解除の見出しは、ステージ済みが 0 なら出ない）。
- 行は変更が数万件でも、status が変わるたびの main の仕事が件数に比例しない（行の組み立ては裏で済ませ、列は見えている行だけを描く——検索結果と同じ列の部品）。
- 行・件数・ボタンの姿は、変更が数万件でも最新の status に必ず追いつく。組み立ては 1 本ずつで、走っている間に status・開閉が変われば終わった後に最新の入力でもう 1 回組む——開閉の変化で組み直しても、届いた status より古い行が残らない。グラフの列はこの組み立てに相乗りせず、グラフかブランチが変わった時点で組み直す（グラフだけの変化で、数万行の変更の行を組み直さない）。

## diff を開く

「変更」の行は作業ツリー diff、「ステージされている変更」の行はステージ済み diff を、Changes の画面の本体に開く（前の diff と入れ替わる → [diff](diff.md)）。行のシングルクリックと ↑↓・→ は開いて焦点を列に残す。ダブルクリックと Enter は開いて本文へ焦点を移す。押し続けた ↑↓ は離すまで開かない（検索結果と同じ間引き → [search](search.md)）。

左の列を閉じている間は、上のバーの今のファイルのボタンか ⌘P で出る変更ファイルの一覧（2 区分）から、別の行の diff へ切り替えられる（→ [shell](shell.md#変更ファイルの一覧)）。

Changes の diff が無ければ、一覧の行の diff を自動で開く（どの行をいつ開くかは → [diff](diff.md) の自動で開く）。変更が 1 件も無くなる（件数が 1 以上から 0 になる）と、Changes の diff を閉じる。

選んだ行がステージ・破棄で区分から消えたら、同じ区分のその位置の行（無ければ前の行）が選ばれる。その行は開かない——本体の diff は今のまま（本体は最後に開いた diff で、選択とは別に持つ）。選択は行の同一性（区分とパス）で持ち、status が変わって行がずれても同じ行を指す。

## ステージ・解除・破棄

行・見出しの操作どおりに status が変わり、操作が終わった時点で行はもう移っている（監視の到着を待たない）。

**続けて押す**: 行の ＋（ステージ）・−（解除）・ゴミ箱へ移すだけの破棄（確認を出さないもの）を押すと、押した行の上端の高さに、押した行が区分から抜けた後はその位置に来る行（同じ区分の次の行。最後の行なら前の行）を留める。上の区分が伸びて列が動いた分は列を送って打ち消す。そのため、ポインタを動かさずに同じ位置を押し続けると、次の行が次々に処理される。行を下ろすために送れるのは列の先頭が見えるまでで、**列の上に空きは作らない**——見出しごと下がってくる姿にしないため。送りきれなければ留めない（列を一番上まで送った状態で区分の最後の行を処理したとき）。行を上げる側は、送りきれなければ列の下に一時の空きを足して留める——短い列でも ＋ の連打で次の行がポインタの下に来る。区分の最後の 1 件を処理した後は、留める行が無いので今の位置のまま留める（手の下で列を跳ばさない）。ポインタが列を出るか、ホイール・つまみ・キーで列を動かすと留めるのをやめ、空きは消えて普通の位置に戻る。確認を経る破棄・見出しの一括操作では留めない。

**押し続けの守り**: 行の ＋・−・ゴミ箱へ移すだけの破棄を押した後、ポインタがその部品の枠の中に居る間は、その枠の中の押下は**留めている行の同じ部品に当たったときだけ**働く。留めきれずにポインタの下へ来た見出し（開閉・すべてステージ・すべて破棄）・別の区分の行（「ステージされている変更」の − の位置に並ぶ「変更」の ＋ など）・行の地は、押しても何も起きない——続けて押すつもりの押下で、狙っていないものを動かさないため。守りはポインタが枠を出る・枠の外を押す・キー・ホイール・窓が key でなくなると終わり、そこからはどこを押しても普通に働く（同じ位置の見出しを押したいときは、ポインタを一度枠の外へ動かす）。守りは押下の受け方の決まりで、留めるのをやめても（列を出た）ポインタが枠の中なら続く。押せない姿の部品の押下は、留めも守りも変えない（何も起きない）。列の上に居る間ずっと絞ると、別の行や見出しを狙った押下まで食われるので、枠の中に限る。押してから行が移るまでの間にもう一度押すと、同じファイルに同じ操作をするだけ（先へは進まない）。押した行は、列がそのとき描いている行の組で決まる——行の組が差し替わる瞬間に押しても、画面に見えていた行のファイルが処理される。

**破棄**は、index の版へ戻すパスを含むと確認を出す——戻すと元に戻せない。ゴミ箱へ移すのは未追跡と作業ツリーに在る intent-to-add（`git add -N`）で、rename の行の元パスは戻す側。確認は、エディター面の中のダイアログ（面の中の確認 → [shell](shell.md#面の中の確認とフォーカス)）で出す。題は件数（1 件ならその名前）、本文は「作業ツリーを index の版に戻します。この操作は元に戻せません。」に、ゴミ箱へ移す行を含めば「N 件はゴミ箱へ移します。」を添える。「破棄」はクリックだけで確定し、↵ では確定しない（esc と「キャンセル」はキャンセル）。確認が出ている間、面の後ろ（上のバー・左の列・本体）は押せず、キーも届かない。確認が出ている間に画面が替わる・焦点が外へ移る・面が隠れる・cd で根が替わると、確認はキャンセルとして閉じる——迷ったら破棄しない側に倒す。ゴミ箱へ移すものだけの破棄は確認を出さずに移す（戻せる）。確認した行と、そのとき見えていた行き先（どのパスがゴミ箱へ行くか）をそのまま根のサービスへ渡す。行き先は呼んだ時点の index で決め直され、見えていた行き先と違えば（監視が届く前に外で `git add`・`git rm --cached` された）何も書かずに「表示と食い違う」で断る——確認を出すかと文の件数を決めた分類と違う破棄は、どちらの向きでも利用者の判断の外になる（コミットの照らしと同じ）。表示が追いついてから押し直せば通る。戻すパスの場所を未追跡のもの（同じ名前のディレクトリ・入れ子のリポジトリ・ファイルに置き換えた親の階層）が塞いでいれば、それも先にゴミ箱へ移す——git は戻すときにそれを黙って消すため。

## 上のバーの部品

Changes の画面の上のバーに、git 管理下と分かっている間だけ出す（git 管理外・判定の前は出さない。並びと譲る順は → [shell](shell.md) の上のバー）。

- **ブランチ名の札**（上のバーの今の項目のボタンの後ろ。前に区切り線）: ブランチの印と名前（detached HEAD は短い sha）。表示だけで押せない——ブランチの切り替えは持たない。幅が足りなければ名前の末尾を省略し、先頭の 4 字と「…」より狭くはならない。その幅も無ければ札ごと出さない。
- **同期のボタン**（札の後ろ）: 後述の同期と公開。
- **「コミット」**（右端）: 押すとコミットのポップアップ（後述）を開閉する。git 管理下と分かっている間はいつも押せる——変更が無くても開き、▾ から amend と取り消しに届く。ポップアップが開いている間は開いている姿。ステージ済みの行数（後述の件数）を読めていれば、名前の後ろに「ステージ済み +N −M」を添える（追加は青、削除はオレンジで、＋・− の記号でも区別する → [design-system](../../design/design-system.md) §3）。0 の側は出さない——削除が 0 なら「ステージ済み +N」、両方 0（バイナリだけ・名前だけ変えたファイルだけ）なら「ステージ済み」だけ（同期の数と同じ決まり）。ツールチップは「コミット」、VoiceOver の名前は、行数を読めていれば「コミット、ステージ済み +N −M」（0 の側は同じく読まない）。

## コミットのポップアップ

上のバーの右下に開く（位置・外の押下・画面の切り替え・⌘E・cd・焦点が外へ移ったときに閉じる決まりは、上のバーの右下の置き場の決まり → [shell](shell.md)）。上の行に、記号「❯」・メッセージ欄・分割ボタン（「コミット ↵」と ▾）を置く。コミットの操作の失敗があれば、その下に赤い行（後述の失敗）を出す。VoiceOver ではポップアップは「コミット」、欄は「メッセージ」。寸法と色は [design-system](../../design/design-system.md) §5 の Commit popup。

- **メッセージ欄**: 空のときの文は「メッセージ」。1 行で始まり、改行するたびにその場で 1 行ずつ伸びて 10 行まで、その先は中がスクロールし、キャレットの行が見えるように送られる。スクロールバーは字に重ねて出し、字の幅を狭めない。打鍵・貼り付け・取り消し・折り返し・外からの差し替え・ポップアップの幅の変化のどれでも高さは中身に合い、空にすれば 1 行に戻る。中身は worktree のメッセージそのもので、ポップアップを閉じても・画面を切り替えても・cd で離れて戻っても残る（後述の worktree ごとの状態）。取り消しの履歴は欄ごとに持ち、ポップアップを閉じれば（cd・画面の切り替えで閉じたときも）履歴も消える——ほかの欄・ほかの連・ほかの窓での ⌘Z は、この欄の打鍵を戻さない。中身が外から変わった（コミットで空になった・別の窓で打った）ときは、それまでの取り消しの履歴を捨てる——⌘Z で差し替え前の文には戻らない。キーは後述（キーと焦点）。
- **開く**: 「コミット」を押す・変更の列に焦点がある間の ⌘↑（後述のキーと焦点）。開くと欄に焦点が入る。
- **閉じる**: 「コミット」をもう一度押す・欄で esc（変換中でないとき）・コミット・amend・コミットしてプッシュの 1 段目が通ったとき。取り消しの後は開いたまま（続けて書き直せる）。失敗のときも開いたまま。閉じる直前に、変換中の字を確定してメッセージへ入れる。閉じた後の焦点は、開く前に在った所——変更の列（列のために面が預かっていた焦点を含む）から開いたなら列、そうでなければ本体——へ戻る。コミットした後すぐ次の変更をステージできるようにするため。列へ戻るときに列の行が無くなっていれば（変更を全部コミットした・左の列を閉じた）、本体へ移る。焦点が外へ移って閉じたときは、焦点に触れない。

## コミットと ▾

- **コミット**: ステージ済みか、コミットに入る変更（競合と中身だけ変わったサブモジュールを除く）が 1 つでもあり、メッセージが空白だけでなく（欄に見えている字で決める——変換中の字も含む）、コミット中でないときに押せる。ポップアップの「コミット」と欄の ↵ が同じ。ステージ済みがあればステージ済みだけをコミットする（作業ツリーの変更は残る）。ステージ済みが 0 なら、確認を出さずに「変更」の行を全部（未追跡・削除を含み、競合と中身だけ変わったサブモジュールを除く——すべてステージと同じ行）コミットする。何を入れるかは押した時点に見えていたもので決める（見たものをコミットする）。見えていたものは、見えている行と HEAD に、そのパネルで押してまだ行に出ていない書き込み（行の ＋・−・すべてステージ・すべて解除・破棄、コミット・amend・コミットしてプッシュ・最後のコミットの取り消し、プル・同期）を押した順に重ねたもの——自分の操作は、走っている・順番を待つ・終わって行に出るまでのどの間に押しても数え（面を隠している間に終わったものは、出し直して行に出るまで）、押すのが早くても遅くても結果は同じ。ステージ済みの行は index の版ごと見えていたものに数え、自分のステージが入れる版は押した時点に分からないので問わない。自分のコミット・amend・プル（同期のプル）は終わった時点の HEAD を、取り消しは 1 つ戻った HEAD を、見えていた HEAD とする（コミット・プルが走っている間は、動かす先が分からないので HEAD を照らさない）。落ちたコミットは、先にステージする段が index に書いたとき（ステージが通ってからコミットが落ちた）だけ、そのステージを見えていたものに数える——何も書かずに断ったコミットは何も重ねない。コミットは根のサービスの順番で走る。裏の fetch に譲って待っているプル・同期より先に走ることがあり、そのとき次のコミットが一時的に「表示と食い違う」で断られることがある（→ 自動 fetch）。自分が押していない変化（端末での `git add`・`git reset --soft`・外でのコミット、面を隠していた間の外のステージなど）は監視が届くまで行に出ないのに、その間も押せてしまう。そのため根のサービスはコミットの直前に、HEAD が見えていた HEAD か、コミットに入るものが見えていたもの（ステージ済みの範囲ならそのステージ済みのパスと版、全部の範囲ならその「変更」の行）と一致するかを照らし、違えばステージもコミットもせず「表示と食い違う」の文で断る（amend・コミットしてプッシュも同じ → [git](../platform/git.md)）——外でのコミットの上に重ねない（コミットしてプッシュなら、押す前の外のコミットを一緒に送らない）・外で同じファイルをステージし直した版を入れない。表示が追いついてから押し直せば通る。根のサービスはステージとコミットを 1 つの書き込みとして続けて走らせる（→ [files](files.md)）——間に別の書き込みが割り込んで、押したときの姿とコミットの中身がずれることが無い。ステージが通ってコミットが落ちたら（hook の拒否など）、ステージしたものは残る。通ればメッセージは空になる（コミットの間に打ち足していれば残す）。失敗ならメッセージは残る。
- **競合が残っている間のコミット**は、ステージもコミットもせず「競合が残っている」の文で断る（amend・コミットしてプッシュも同じ）。git は競合のある index のコミットを必ず断るので、全部のコミットが通る場面は無く、先にステージしたものが merge のコミットに混ざるだけになるため。変更が競合だけなら、コミットは押せない。
- **押せない姿**: 「コミット」が押せないとき（メッセージが空・入れるものが無い・変更が競合だけ・コミット中）は、分割ボタン全体の地を中立の色にし、「コミット」の字を薄くする（design-system の disabled）——紫の地が押せる姿のまま残らないため。▾ はいつも押せる——「コミット」が押せない間も、amend と取り消しにはここから届く。
- **▾**: コミット（amend）/ コミットしてプッシュ / 最後のコミットを取り消す。ポップアップのすぐ下に、右寄せで一覧を開く（行の部品・↑↓・↵・ホバーは開いているファイルの一覧と同じ → [shell](shell.md#開いているファイルの一覧)）。開くと焦点は一覧へ移る。開いた時点では何も選ばない——↵ で思わず amend しないため。↑↓ で押せる項目を選び、↵・クリックで決めると、その働きを起こして一覧を閉じ、焦点は欄へ戻る。押せない項目は薄い姿で選べない。「コミットしてプッシュ」の右にキーの札 ⌘↵。esc・▾ の再押下・ポップアップの地の押下は一覧だけを閉じて、焦点を欄へ戻す。**HEAD が push 済みなら amend と取り消しは押せない**——force push を持たないので、書き換えれば Orbe の中では戻せない。push 済みは「どれかの remote 追跡ブランチから届く」で（→ [git](../platform/git.md) のコミットグラフ）、HEAD 1 件をその規則で読み、読んだコミットと組で持つ。今の HEAD と違うコミットを読んだ・読めない間と、remote 追跡 ref が動きうるきっかけ（Changes の画面を出した・再読込・remote 追跡 ref の変化・自分のネット操作の終わり）の後で読み直している間は、分からないとして押せない側に倒す——端末で HEAD を push した直後・自分の push が終わった時点から押せなくなる。push 済みは HEAD のコミットと remote 追跡 ref だけで決まるので、それ以外（HEAD・ローカルのブランチ・index の変化、ステージ等の終わり）での読み直しの間は、同じ HEAD なら前の値を使う（ステージやコミットのたびに ▾ が押せない姿へ点滅しない。HEAD が動けば、違うコミットとして分からないになる。ref が reftable 形式のリポジトリでは、どの ref が動いたかを名前で分けられないので、コミットのたびに読み直す間だけ分からないへ倒れる → [files](files.md)）。押せる・押せないは見せ方で、契約は書き込みが持つ——amend・取り消しは、根のサービスが書き換えの直前に HEAD の push 済みを同じ規則で読み、push 済みなら何も書かずに断って失敗を出す（▾ を開いている間や、外の push が監視に届くまでの間にも押せてしまうため）。取り消しも、HEAD が押した時点に見えていた HEAD（コミットと同じく自分の操作を重ねたもの）でなければ何も書かずに「表示と食い違う」で断る——外でのコミットを取り消さない。▾ の項目（amend・コミットしてプッシュ・取り消し）の「押した時点に見えていたもの」と押せるかは、一覧を開いた時点のもの——開いている間も行は外の書き込みに追いつくが、選んだのは開いた時点の姿なので、開いている間に外でコミットされれば、どれも何も書かずに「表示と食い違う」で断る。ネット操作が走っている・順番を待っている間も押せない（push と並んで走ると、push したコミットを書き換えうる）。amend はコミットと同じ範囲で直前のコミットを差し替える——ステージ済みがあればそれだけ、0 なら「変更」の行を全部。メッセージが空なら前のメッセージのまま中身だけを差し替え、入れるものが無ければメッセージがあるときだけ押せる（メッセージだけの差し替え）。コミットしてプッシュはコミットと同じ範囲でコミットし、通ったときだけ push する。push は push の時点の HEAD を送る——自分のコミットの後、push が始まるまでに外でされたコミットも一緒に送る。
- 取り消したコミットのメッセージは欄に戻さない。

## 同期と公開

上のバーの同期のボタンは、「コミット」と別に、変更の有無に依らず出す——コミットのボタンが同期・公開に替わると、変更がある間は同期に届かず、同じ位置のボタンの働きが状況で替わるため。

- ブランチに居て upstream があれば「**同期**」。先行・遅れの数が分かり、和が 1 以上なら数を添える（↑N ↓M。0 の側は出さない）。押すとプル → プッシュの順に走る（数に依らず両方）。
- upstream があっても、その ref が手元に無い（リモートのブランチが消され、prune 付きの fetch で追跡の ref も消えた——PR のマージ後の自動削除で普通に起きる）なら、「同期」を薄い姿で押せなくする。プルは必ず断られ、プッシュはマージ後のブランチをリモートに作り直すので、どちらも押せる姿で出さない。「ブランチを公開」にも替えない（同じ理由）。説明と VoiceOver の名前は「同期（upstream の origin/feat がリモートにありません）」の形。
- ブランチに居てコミットがあり、upstream が無ければ、同じ位置に「**ブランチを公開**」。押すと upstream を付けて push する（付け先は根のサービスの push の解決）。
- detached HEAD・初回コミットの前は出さない。
- ネット操作が走っている・順番を待っている間は、薄い姿で押せない。説明と VoiceOver の名前は「同期 ↑2 ↓1」の形。

欄のキー（↵ のコミット・⌘↵ のコミットしてプッシュ）は同期・公開を起こさない——押せなければ音で断る。

## プル・プッシュ・フェッチ

親「ソース管理」の … から選ぶ。**前提が足りないときも押せる**——押せば git 実行の基盤の分類どおりの失敗（「upstream がありません。先にブランチを公開してください」など）が失敗の札に出る。前提の判定は git 実行の基盤の 1 か所に置き、パネルで重ねて判定しない（判定が 2 か所に割れると食い違い、押せない理由も見えない）。

**ネット操作は worktree ごとに 1 つずつ**: プル・プッシュ・フェッチ・同期・公開・コミットしてプッシュのどれかが走っている（順番待ちを含む）間、同じ worktree のほかのネット操作は押せない（裏の fetch は数えない——後述）（別の窓で同じ worktree を見ていても）。ボタンの可否は見せ方で、契約は worktree ごとの状態が持つ——メニューを開いている間に別の窓で始まったなどで押せてしまっても、始めずに断り、失敗の札で知らせる。ステージなどは押せ、根のサービスの順番どおりに待つ。

**push と HEAD の書き換えは並ばない**: ネット操作が列にある間の amend・取り消しと、amend・取り消しが列にある間のプッシュ・公開は、始めずに断って失敗の札で知らせる。push は根のサービスの順番に並ばないので、並べば push したコミットを書き換える・書き換える前のコミットを送る。プル・同期・コミットしてプッシュは順番どおり書き換えの後に走る（送るのは書き換えた後の HEAD）ので断らない。

## 自動 fetch

そのリポジトリのエディター面が見えていて（ソース管理パネルを出しているかに依らない）、Orbe が前面にある間、裏で fetch して先行・遅れ（↑N ↓M・同期 ↓N）を新しくする。間隔は、前回の fetch・pull の段（裏・手を問わない。同期のプル、競合で止まったプルを含む）が remote 追跡 ref を取り込んだ終わり、または裏の fetch が認証・ホスト鍵以外で失敗した終わりから 180 秒で、面が見えた・前面に戻った時点で過ぎていればすぐ 1 回撃つ。エディター面が見えていない間と Orbe が背後にある間は撃たない（窓が背後にあるだけで Orbe が前面なら撃つ）。Changes の画面を出していない間も件数とボタンの先行・遅れは status で新しくなり、グラフと HEAD の push 済みは Changes の画面を出したときに読む。設定 `scm-auto-fetch`（既定オン。workspace で上書きできる）でオフにでき、面は自分の workspace の実効値を見る（→ [settings](../palette/settings.md)）。

- **リポジトリごとに 1 本**: 同じリポジトリの worktree は remote 追跡 ref を共有し、並んだ fetch・pull は後の側が落ちる（→ [git](../platform/git.md)）。同じリポジトリの worktree の面がいくつ見えていても、撃つのは周期ごとに 1 回で、見えていて設定がオンになったのが最も早い面の worktree で、remote を名指ししない `git fetch` を走らせる。取る remote は利用者の設定のまま git が選ぶ（既定では今のブランチが追う remote。`fetch.all` なら全部）。ref が動いた後の監視で、取った remote を追う面すべての先行・遅れが新しくなる。既定のままで worktree ごとに追う remote が違う（fork の運用で、片方は upstream、片方は origin を追う）と、裏の fetch が取るのは最も早い面の worktree が追う remote だけになる。どの面が最も早いかは画面からは分からないので、ほかの remote を追う面の先行・遅れが裏の fetch で新しくなるかも分からない。新しくならない面は、その面のフェッチ・プルで取る。
- **人の邪魔をしない**: 裏の fetch は worktree の操作の列に載らない——実行中の札・失敗の札・ボタンの可否に出ず、出ている失敗の札も消さない。失敗は黙って次の周期を待つ。認証・ホスト鍵の失敗なら、そのリポジトリでは、リモートと話せたと分かる手の段（通った・競合で止まったプル・拒否された push・サーバーが断った push）が終わるか、remote 追跡 ref（`refs/remotes` の下）の値が止まった時点から変わっている（端末・エージェントの push・fetch）と分かるまで（か再起動まで）撃たない。段は 1 段ずつ見る——同期でプルが通れば、後の push が落ちても止まりは解ける。値は、面が見えた・前面に戻った・面が見えている間に remote 追跡 ref が動きうる変化が届いたときに比べるので、エディター面を隠していた間・Orbe が背後にあった間の変化でも、次に面が見えたときに再開する。何も取れなかった外の fetch・pull では値が変わらず再開しない。askpass・資格情報の窓は出させず、無出力が続けば打ち切る（→ [git](../platform/git.md)）。ssh-agent の側の承認（1Password・Secretive・FIDO 鍵）は封じられないので、毎回承認を求められる人のために設定のオフを持つ。
- **人に譲る**: 人が同じリポジトリでネット操作を押すと（別の worktree のパネルからでも）、その操作が終わるまで裏の fetch は撃たない。人の操作がネットの段（プル・プッシュ・フェッチ）を起こす直前に裏の fetch が走っていれば、それを止め、その終わりを待ってから段を走らせる。譲るのはネットの段の前だけで、コミットしてプッシュのコミットは押した時点で順番に入る——待つ間に押したステージ・解除・破棄がコミットより先に走って、コミットの中身が押した時点の姿からずれることが無い（プル・同期は 1 段目がネットの段なので、待つ間に押したステージ等が先に走る）。待つのは人の操作を走らせるための一部なので、待つ間も人の操作は走っていて、0.3 秒を越えれば実行中の札に出る。塞いでいる裏の fetch は見せず、人には止められないため。札で止めると、裏の fetch の終わりを待たずにその場で終わる。

## 実行中と止める

どの操作も、走り始めてから 0.3 秒を超えて走っていれば、上のバーの右下の置き場（→ [shell](shell.md)）に実行中の札を出す——上端に流れる細い線、操作名、push / pull / fetch の段なら git の進捗の最新の行（git の語のまま・末尾省略）、右端に「止める」。進捗の行がある間、札の幅は行の字数に依らず一定（届くたびに字数が変わる行で、札の左端が揺れない）。左の列を閉じていても見える。面が狭くて札が置き場の幅に収まらなければ、進捗の行から縮めて末尾を省く（操作名と「止める」は縮めない）。短い操作で札が点滅しない。札は**実際に走っている**操作（裏の fetch に譲って待つ間を含む）だけを出し、順番待ちの操作は出さない——返らない hook のコミットの後ろでステージしても、札はコミットとその止める手を出す。走っている操作が複数あれば一番新しく走り始めたものを出す。順番待ちか走っているかは根のサービスの順番の中にしか無いので、根のサービスの「走り始めた」の知らせで決める（→ [files](files.md)）。コミットのポップアップを開いている間は、札はポップアップの下に出る——返らない hook のコミットも、ポップアップを開いたまま止められる。

「止める」は今の段を止め、2 段の操作なら次の段を起こさない。止めた操作は失敗の札を出さない。hook が返らないコミットを止めても `index.lock` は残らない。ゴミ箱へ大量に破棄している間も UI は止まらず、止められる。

## 失敗

失敗は、上のバーの右下の置き場の失敗の札（danger の文。文は選んでコピーできる）に出す——頭に操作の名前（プル・プッシュ・フェッチ・同期・ブランチを公開・コミット・コミット (amend)・コミットしてプッシュ・最後のコミットを取り消す・変更をステージ・ステージを解除・変更を破棄）を置き、続けて理由と次の一手（例:「同期　認証できませんでした。端末で git の認証（ssh の鍵・資格情報）を設定してください。」）。札だけで何の操作の失敗かが分かるように。左の列を閉じていても見える。ただし、コミットの操作（コミット・amend・取り消し・コミットしてプッシュ）の失敗は、コミットのポップアップが開いていれば、ポップアップの下の赤い行（警告の印と文。文は選べる）に出し、札には重ねない。ポップアップを閉じても失敗は消えず、閉じている間は札に出る（開き直せば赤い行に戻る）——hook の失敗の理由を見て直そうと、ほかの所を押した一手で理由が消えないように。ポップアップが閉じている間に届いたコミットの失敗（コミットしてプッシュのプッシュの失敗など）も、札に出る。最後の失敗は worktree に 1 つで、出し場所は面ごとに決まる——同じ worktree を 2 つの窓で見ていると、片方でポップアップを開いていても、もう片方では札に出る。画面と入力（メッセージ）を保ち、札の × か、次の操作を始めると消える（Orbe の操作の失敗の型。検索パネルのエラーの文と同じ）。× は worktree の最後の失敗を消すので、同じ worktree を見ているほかの窓の札も消える。最後の失敗は人が起こした操作 1 回の結果なので、消した失敗は出ず、次に起きた失敗はまた出る。分類（認証・ホスト鍵が未知・push の拒否・プルの競合・操作の途中・ブランチに居ない・upstream が無い・upstream がリモートに無い・push 先が無い・push 済みの書き換え・shallow の境界・競合が残っている・表示と食い違う）ごとに文が違い、サーバーが断った push（hook・保護ブランチ）と分類できない失敗は git の理由の行そのまま。ブランチに居ない断りは、断った操作（プル・プッシュか、初回コミットの取り消しか）を言う。ネット操作や書き換えと重なって断ったときも、同じ型の文（何が走っていたので始めなかったか・終わってから試す）で出す。止めた操作と git 管理外は文にしない。

## グラフ

グラフの枠に、HEAD と、在れば upstream から届くコミットを新しい順に 50 件出し、続きがあれば末尾の「さらに表示」で 50 件ずつ増やす。

- 見出し「グラフ」は、押せば枠を開閉する。乗ると見出しの帯にだけ地が付き、キーでは選べない（列の外の、枠の見出し）。右端に再読込。グラフと HEAD の push 済みだけを読み直す（status の取り直しは親「ソース管理」の再読込が持つ）。
- 頭にブランチの行: ブランチ名（detached は HEAD の短い sha）と先行/遅れ `↑N ↓M`（upstream があり数が分かるときだけ。0 の側は出さない）。押せないラベルなので、枠も地も持たない行としてコミットの行と同じ列に置き（印は点の列、名前はコミットの題の左端から）、見出しの直下に空きを置かずに続ける——入力欄の形の器にすると、見出しの地が器の枠と繋がって見える。乗っても地は付かず、押しても何も起きない。左の列が狭くて入らなければブランチ名を優先し、`↑N ↓M` を末尾から省く（入らなければ消える）——どのブランチに居るかが先、数はボタン（同期 ↑N ↓M）にも出るため。
- 未 push のコミットは塗りの点、push 済みは中抜きの点と弱い字。縦の線は 1 本で、枝分かれ・merge の線は描かない。
- ブランチを指すコミットに ref の札（local / remote）。札が入らなければ末尾から省く（題が先に詰まる）。
- **コミットの行は押せず、乗っても地が付かない**——押しても何もしない行を押せそうに見せない。コミットの中身を見る面は持たない。
- グラフの列は選べる行を持たないので、押しても焦点を取らない——変更の列の焦点と選択はそのままで、続けて ↑↓ が効く。押して働くのは「さらに表示」だけ。
- **読み直し**: Changes の画面を出したとき・再読込・さらに表示・自分の操作の終わり・根のサービスの「git の状態が変わった」の知らせで読み直す。status の変化だけでは読み直しの合図にしない——端末での upstream を付けない push・ブランチの作成や削除は ref だけを動かし、status は変わらない。いつも先頭から今の件数で読む（続きを継ぎ足さない——読みの間に HEAD が動くと重複・欠落する）。読んでいる間に次の合図が来たら、終わった後に 1 回だけ読み直す。読めなければ前の結果を保つ。
- グラフと HEAD の push 済みは、Changes の画面を出している間だけ読む。読む条件は行の組み立てと同じで、左の列の開閉を見ない——左の列を閉じている間も git の状態が変わるたびに読み直し、左の列を開いたときには読み終わったグラフと push 済みが出る（読みを待たない）。

## worktree ごとの状態

打ちかけのメッセージ・走っている操作と止める手・最後の失敗は、**worktree（根）ごとに 1 つ**、アプリが動いている間持つ。同じ worktree を 2 つの窓の面で見れば同じものが見え、cd で離れて戻っても、パネルが隠れても残る（メッセージは同じ値を共有するので、2 つの窓で同時に打つ場面は想定しない）。再起動では消える（永続しない）。走っている操作は始めたときの根のサービスを、全段が終わるまで握る。

面ごとに持つのは見せ方——親・子の区分・グラフの枠の開閉・グラフの件数・選択・変更の列の焦点・ステージ済みの行数——と観測だけ（グラフの枠の高さはアプリ全体で 1 つ）。根が変われば（cd）見せ方は新しい根のもので初めからになり、開いていたコミットのポップアップは閉じ、Changes の画面を出したままでも列はすぐ新しい根を見せる。パネル（面）は面が見えている間だけ根のサービスを握る（→ [files](files.md) の握る者）。

## 件数

上のバーの `Changes` に、ステージ済みの行と変更の行の和を添える（同じファイルが両方に出れば 2 と数える。1000 以上は「999+」。→ [shell](shell.md) の上のバー）。変更が無い・git 管理外なら出さない。ほかの画面に居ても・左の列を閉じていても、面が見えていれば status の変化に追従する——行の組み立て・グラフ・HEAD の push 済みの読みは Changes の画面を出している間だけ行い（左の列を閉じていても。行は本体に自動で開く行を決めるのに要り、グラフと push 済みは行と同じ条件で読む）、件数のために行を組ませず、ほかの画面のために git を起こさない。

**ステージ済みの行数**（「コミット」の添え書き）は、index と HEAD の差の追加と削除の行数（→ [git](../platform/git.md) のステージ済みの行数）。バイナリのファイルと、名前だけ変えたファイルは 0 行。読み直すのは、ステージ済みの中身——HEAD と、ステージ済みのパスと index の版——が変わったときだけで、行の組を組み直したときに、その 2 つから作った鍵を、持っている行数の鍵と比べて決める（数万件でも main の仕事は鍵の比較だけ）。remote 追跡 ref だけ・作業ツリーだけの変化では読まない。読みは 1 本ずつで、読んでいる間に中身が変われば、読み終わってからもう 1 回読む。読み終わるまでの間は前の数のまま——ステージのたびにボタンの幅が跳ねないため（ステージ済みが無い状態から初めてステージしたときは、読み終わるまで添え書きが出ない）。ステージ済みが空になれば、読まずに添え書きを消す。読めなければ前の数を残す。行の組と同じく、Changes の画面を出している間だけ読む。

## キーと焦点

- 上のバーで Changes の画面へ切り替えたときの焦点は → [shell](shell.md#焦点)。メッセージ欄へは、コミットのポップアップを開いて入る（「コミット」を押す・変更の列で ⌘↑）。パネルが隠れたとき焦点がパネルにあれば、面の焦点の行き先へ戻す（→ [shell](shell.md) の焦点）。親を畳んで焦点のあった列が隠れるとき、cd でパネルが作り直されるときも同じく、隠れる前に面の焦点の行き先へ戻す（隠れた後では焦点が窓へ落ち、キーがどこにも届かない）。当てられないまま隠れた焦点の要求は捨てる——後で列が現れても焦点を奪わない。選んでいた行は残り、開いた後に列を押せば列が焦点を取り直す。
- 欄のキー: **↵**（テンキーの Enter も）はコミット、**⌘↵** はコミットしてプッシュ（▾ の項目と同じ条件と範囲）。どちらも押した時点の姿で照らし、押せなければ音で断って何も入れない。改行は **⇧↵・⌥↵・⌃↵** のどれでも `\n` を入れる（⌃↵ も見えない行区切りの字ではなく改行）。変換中の ↵ は変換の確定だけで、コミットしない（IME が使った ↵ はコミットの合図として届かない）。変換中でない **esc** はポップアップを閉じる（変換中の esc は変換の取り消し）。⌘↵ は、焦点がポップアップの中（欄・▾ の一覧）にある間に効く。「コミット」・▾・⌘↵ は、押した・開いた時点で変換を確定してから働く（見えていた字が全部コミットに入る）。↵・⌘↵ は押した瞬間だけをコミットの合図にし、押し続けたときのキーリピートでは何も起きない（音も鳴らない）——変換の確定に使った ↵ を押し続けても続くリピートでコミットが走らず、押した瞬間に断られたコミットが、押し続けている間に条件が整って見直していない姿のまま通ることも無いようにするため。修飾の無い ↵ だけをコミットにし、ほかの修飾の組と押下の無い改行の命令は改行にする——押し間違いを軽い側に倒すため。
- 変更の列は押せば焦点を取り、検索結果と同じ型で動く: **↑↓** は子の見出しとファイル行を渡り（グラフは別の枠で、キーでは入らない）、ファイル行なら diff を開く。**←** はファイル行から区分の見出しへ、見出しなら畳む（畳んだ見出しでは何もしない。親の見出しは列の外にある）。**→** は畳んだ見出しを開き、開いた見出しなら最初のファイル行へ動いて開く。**Enter** はファイル行を開いて本文へ（見出しは開閉）。**⌘↑** はどの行を選んでいても・何も選んでいなくても、コミットのポップアップを開いて欄へ焦点を移す——⌘↑ で開く・書く・↵（か ⌘↵）でコミットするまでを、キーだけで回せる。コミットが通って閉じた後、列に行が残っていれば焦点は列へ戻り、行が無くなれば（全部をコミットした）本体へ移る。左の列を閉じている間と、本文に焦点がある間は、キーでは開けない（「コミット」を押す）。**Esc** は選択を外す。ステージ・破棄のキーは持たない（ボタンで行う）。
- 行のボタン・見出しの一括操作・「さらに表示」の押下は行のクリックにならない（選択も開きもしない）。ボタンにポインタを乗せると説明が出る。説明は、行が読み直されても、ポインタの下の部品のものに合わせ直す。

## VS Code との差

- **初回コミット前は「ブランチを公開」を出さない**（VS Code は出す。中身の無いブランチは push できない）。
- **upstream の無いプッシュは尋ねずに公開する**（VS Code は公開するかを尋ねる）。「ブランチを公開」と同じく upstream を付けて出す。
- **すべてステージ・すべて破棄は競合を含めない**（VS Code は「マージの変更」を別の区分に分ける）。
- **グラフの線は 1 本**（VS Code は枝分かれと merge を描く）。グラフのコミットは選べず、押せない。
- **親（リポジトリ）の見出しはキーで選べない**（VS Code はリポジトリの行も ↑↓ で選べ、畳んだ見出しの ← で親へ上がる）。
- **メッセージ欄とコミットのボタンは左の列に無く、上のバーの「コミット」から開くポップアップに在る**（VS Code は左の列の上端）。左の列を閉じていても、本体の diff を見たままコミットできる。
- **同期は、変更があっても上のバーのボタンで押せる**（VS Code はコミットのボタンが、変更が無いときだけ同期に替わる）。
- **実行中と失敗は、左の列ではなく上のバーの右下の札に出す**（VS Code はビューの上端の線と、通知）。左の列を閉じていても見え、失敗は × で消せる。
- **破棄の確認は、エディター面の中のダイアログで出す**（VS Code は窓のダイアログ）。「破棄」は ↵ で確定しない。
- **自動 fetch は既定でオン**（VS Code の既定はオフ）。そのリポジトリのエディター面が見えていて Orbe が前面のときだけ撃つ。
- **ステージ済みが無ければ、確認を出さずに全部をコミットする**（VS Code の smart commit を「常に」にした状態。VS Code の既定は確かめる）。amend も同じ。全部に競合は含めない（VS Code は含める）。
- **欄の ↵ はコミット、⌘↵ はコミットしてプッシュ**（VS Code は ⌘↵ がコミットで、↵ は改行）。改行は ⇧↵・⌥↵・⌃↵ で打つ。
- **同じ位置で続けてステージ・解除できる**（VS Code は押した後に列がずれる）。押し続けている間、留めきれずに来た見出しや別の行は働かない。
- **印は M・A・U・C の 4 種**（VS Code の D・R は持たない）。削除の行に取り消し線も引かない。
- **行のボタンは常に出す**（VS Code はポインタを乗せた行だけ）。
- **取り消したコミットのメッセージを欄に戻さない**。
- **AI によるメッセージ生成は持たない**。
