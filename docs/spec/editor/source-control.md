# ソース管理

エディター面のレールの「ソース管理」で出すサイドバーのパネル。端末へ戻らずに、変更を見る → ステージする → コミットする → push / pull / fetch するまでをエディターの中で済ませる——エージェントが書き換えた変更を 1 件ずつ diff で確かめ、選んで積む作業を、端末の `git` を打つ手間なしに回すため。git の操作はすべて根のサービスの書き込みの口を呼び（→ [files](files.md)）、走らせ方・順番・前提の判定・失敗の分類はそちら（→ [git](../platform/git.md)）が持つ。ここが持つのは見せ方と、worktree ごとの状態だけ。

## パネルの構成

上から次の順に並ぶ。寸法と色は [design-system](../../design/design-system.md) §5 の Source control panel。

- **見出し**「ソース管理」。
- **実行中の帯**（後述）。走っている操作があるときだけ出る。
- **区分「ソース管理」**: 畳むと下の欄・ボタン・失敗の文が隠れる。右端に ✓（コミット。欄の ↵ と同じ条件）・再読込（status を取り直し、グラフと HEAD の push 済みを読み直す）・…（メニュー: プル / プッシュ / フェッチ / コミット (amend) / 最後のコミットを取り消す）。… はボタンの姿に縛られず常に開く——ボタンが押せない間（欄が空など）も、amend と取り消しにはここから届く。2 つの項目の押せる条件・照らし方は ▾ の同じ項目と同じ（後述）。
- **メッセージ欄**: 1 行で始まり、改行するたびにその場で 1 行ずつ伸びて 10 行まで、その先は中がスクロールし、キャレットの行が見えるように送られる。スクロールバーは字に重ねて出し、字の幅を狭めない。打鍵・貼り付け・取り消し・折り返し・外からの差し替え・サイドバーの幅の変化のどれでも高さは中身に合い、空にすれば 1 行に戻る。下のボタン・失敗の文・列は欄に付いて動く。キーは後述（キーと焦点）。プレースホルダはブランチに居ればそのブランチ名を含み、detached・初回コミット前は名前を出さない。取り消しの履歴は欄ごとに持ち、欄が消えれば（cd・パネルを閉じる・区分「ソース管理」を畳む）履歴も消える——ほかの欄・ほかの連・ほかの窓での ⌘Z は、この欄の打鍵を戻さない。中身が外から変わった（コミットで空になった・別の窓で打った）ときは、それまでの取り消しの履歴を捨てる——⌘Z で差し替え前の文には戻らない。
- **コミットボタン**と ▾（後述）。
- **失敗の文**（後述）。
- **列**: 「ステージされている変更」「変更」の 2 区分と「ソース管理グラフ」。

git 管理外の根では、見出しの下に理由の一文だけが出る。変更が無い worktree では、列にグラフだけが出る。

## 2 区分の行

- **ステージされている変更**: index 側に変化のあるファイル（競合は含めない）。**変更**: 作業ツリー側に変化のあるファイルと競合。ステージした後に編集したファイルや `git rm --cached` したファイルは両方に出る。
- 行が 0 の区分は見出しごと出ない。区分は見出しで畳め、開閉は面の状態で永続しない。
- 行は種別チップ・名前・ディレクトリ・右端に行のボタンと変化の印。印はその区分の変化で、追加 A・未追跡 U・競合 C・ほか（削除・rename を含む）は M。名前と印はエクスプローラーと同じ色で、赤と緑に頼らない（→ [design-system](../../design/design-system.md) §3）。rename の行は新しいパスの名前だけを出す。
- 並びはパス順（区切りごとに名前を比べ、同じ階層ではファイルが先。名前の比べ方はエクスプローラー・検索結果と同じ）。
- **行のボタンはポインタに依らず全部の行に常に出す**。その分ディレクトリ名が短く省略される。「変更」は ファイルを開く / 変更を破棄 / ステージ、「ステージされている変更」は ファイルを開く / ステージを解除。作業ツリーに無いファイルの「ファイルを開く」、競合の「変更を破棄」、サブモジュールのまま変わった行（チェックアウトしているコミットが動いた・中のファイルが変わった・増えた）の「変更を破棄」、そのうち中身だけ変わった行（チェックアウトしているコミットは同じ）の「ステージ」は押せない姿で置き、ボタンの位置は行どうしで揃える——git はサブモジュールのまま変わった行を restore で戻さず、中身だけの変化は add でもステージしないので、押せる姿だと何も起きない（破棄なら、戻せない確認を通した後で）。中でコミットした行は ＋ でステージできる（記録するコミットが変わる）。作業ツリーで消した・ファイルに置き換えたサブモジュール（ファイルに置き換えてステージした後に編集した行も）は、ほかの行と同じく押せる。破棄はサブモジュールの中に触れない——利用者の設定が submodule.recurse でも、中の未コミットの作業や中で作ったコミットを消さない。「ファイルを開く」はファイルを普通のタブで開いて本文へ焦点を移す。
- **見出しの一括操作**: 「変更」に すべて破棄・すべてステージ、「ステージされている変更」に すべて解除。件数の印の左に常に出す。**すべてステージ・すべて破棄は競合のファイルを含めない**——競合は 1 行ずつステージして解決済みにする。一括操作で競合の印が残ったまま解決済みにならないため。すべてステージは中身だけ変わったサブモジュールを、すべて破棄はサブモジュールのまま変わった行を含めない——行のボタンと同じく、git が何も変えないため。入る行が 1 つも無ければ、すべてステージ・すべて破棄は押せない姿で置く（すべて解除の見出しは、ステージ済みが 0 なら出ない）。
- 行は変更が数万件でも、status が変わるたびの main の仕事が件数に比例しない（行の組み立ては裏で済ませ、列は見えている行だけを描く——検索結果と同じ列の部品）。
- 行・件数・ボタンの姿は、変更が数万件でも最新の status に必ず追いつく。組み立ては 1 本ずつで、走っている間に status・グラフ・開閉が変われば終わった後に最新の入力でもう 1 回組む——グラフや開閉の変化で組み直しても、届いた status より古い行が残らない。

## diff を開く

「変更」の行は作業ツリー diff、「ステージされている変更」の行はステージ済み diff を開く（→ [diff](diff.md)）。行のシングルクリックと ↑↓ は仮のタブで開き、焦点は列に残る。ダブルクリックと Enter は普通のタブで開いて本文へ焦点を移す。押し続けた ↑↓ は離すまで開かない（検索結果と同じ間引き → [search](search.md)）。

選んだ行がステージ・破棄で区分から消えたら、同じ区分のその位置の行（無ければ前の行）が選ばれる。その行は開かない。選択は行の同一性（区分とパス）で持ち、status が変わって行がずれても同じ行を指す。

## ステージ・解除・破棄

行・見出しの操作どおりに status が変わり、操作が終わった時点で行はもう移っている（監視の到着を待たない）。

**続けて押す**: 行の ＋（ステージ）・−（解除）・未追跡の破棄（確認を出さないもの）を押すと、押した行の上端の高さに、押した行が区分から抜けた後はその位置に来る行（同じ区分の次の行。最後の行なら前の行）を留める。上の区分が伸びた・実行中の帯や失敗の文が出入りして列が動いた分は列を送って打ち消す。そのため、ポインタを動かさずに同じ位置を押し続けると、次の行が次々に処理される。行を下ろすために送れるのは列の先頭が見えるまでで、**列の上に空きは作らない**——見出しごと下がってくる姿にしないため。送りきれなければ留めない（列を一番上まで送った状態で区分の最後の行を処理したとき・短い列で失敗の文や帯が消えたとき）。行を上げる側は、送りきれなければ列の下に一時の空きを足して留める——短い列でも ＋ の連打で次の行がポインタの下に来る。区分の最後の 1 件を処理した後は、留める行が無いので今の位置のまま留める（手の下で列を跳ばさない）。ポインタが列を出るか、ホイール・キーで列を動かすと留めるのをやめ、空きは消えて普通の位置に戻る。確認のシートを経る破棄・見出しの一括操作では留めない。

**押し続けの守り**: 行の ＋・−・未追跡の破棄を押した後、ポインタがその部品の枠の中に居る間は、その枠の中の押下は**留めている行の同じ部品に当たったときだけ**働く。留めきれずにポインタの下へ来た見出し（開閉・すべてステージ・すべて破棄）・別の区分の行（「ステージされている変更」の − の位置に並ぶ「変更」の ＋ など）・行の地、帯や失敗の文の出入りで枠の中に来た列の外のもの（コミットボタン・帯の「止める」）は、押しても何も起きない——続けて押すつもりの押下で、狙っていないものを動かさないため。守りはポインタが枠を出る・枠の外を押す・キー・ホイール・窓が key でなくなると終わり、そこからはどこを押しても普通に働く（同じ位置の見出しを押したいときは、ポインタを一度枠の外へ動かす）。守りは押下の受け方の決まりで、留めるのをやめても（列を出た）ポインタが枠の中なら続く。列の上に居る間ずっと絞ると、別の行や見出しを狙った押下まで食われるので、枠の中に限る。押してから行が移るまでの間にもう一度押すと、同じファイルに同じ操作をするだけ（先へは進まない）。押した行は、列がそのとき描いている行の組で決まる——行の組が差し替わる瞬間に押しても、画面に見えていた行のファイルが処理される。

**破棄**は、追跡中のファイルを含むと確認のシートを出す——作業ツリーを index の版へ戻すので元に戻せない。文は件数（1 件ならその名前）と、未追跡を含めば「未追跡の N 件はゴミ箱へ移す」。「破棄」はクリックだけで確定し、Return では確定しない（Esc はキャンセル）。未追跡だけの破棄は確認を出さずにゴミ箱へ移す（戻せる）。確認した行をそのまま根のサービスへ渡し、どのパスを戻すかは呼んだ時点の index で選び直される。戻すパスの場所を未追跡のもの（同じ名前のディレクトリ・入れ子のリポジトリ・ファイルに置き換えた親の階層）が塞いでいれば、それも先にゴミ箱へ移す——git は戻すときにそれを黙って消すため。

## コミットと ▾

- **コミット**: ステージ済みか、コミットに入る変更（競合と中身だけ変わったサブモジュールを除く）が 1 つでもあり、メッセージが空白だけでなく、コミット中でないときに押せる。✓・ボタン・欄での ↵ が同じ。ステージ済みがあればステージ済みだけをコミットする（作業ツリーの変更は残る）。ステージ済みが 0 なら、確認を出さずに「変更」の行を全部（未追跡・削除を含み、競合と中身だけ変わったサブモジュールを除く——すべてステージと同じ行）コミットする。何を入れるかは押した時点に見えていたもので決める（見たものをコミットする）。見えていたものは、見えている行と HEAD に、そのパネルで押してまだ行に出ていない書き込み（行の ＋・−・すべてステージ・すべて解除・破棄、コミット・amend・コミットしてプッシュ・最後のコミットの取り消し、プル・同期）を押した順に重ねたもの——自分の操作は、走っている・順番を待つ・終わって行に出るまでのどの間に押しても数え（面を隠している間に終わったものは、出し直して行に出るまで）、押すのが早くても遅くても結果は同じ。ステージ済みの行は index の版ごと見えていたものに数え、自分のステージが入れる版は押した時点に分からないので問わない。自分のコミット・amend・プル（同期のプル）は終わった時点の HEAD を、取り消しは 1 つ戻った HEAD を、見えていた HEAD とする（コミット・プルが走っている間は、動かす先が分からないので HEAD を照らさない）。コミットはそれらの書き込みが順番どおり終わってから走る。自分が押していない変化（端末での `git add`・`git reset --soft`・外でのコミット、面を隠していた間の外のステージなど）は監視が届くまで行に出ないのに、その間も押せてしまう。そのため根のサービスはコミットの直前に、HEAD が見えていた HEAD か、コミットに入るものが見えていたもの（ステージ済みの範囲ならそのステージ済みのパスと版、全部の範囲ならその「変更」の行）と一致するかを照らし、違えばステージもコミットもせず「表示と食い違う」の文で断る（amend・コミットしてプッシュも同じ → [git](../platform/git.md)）——外でのコミットの上に重ねない（コミットしてプッシュなら、押す前の外のコミットを一緒に送らない）・外で同じファイルをステージし直した版を入れない。表示が追いついてから押し直せば通る。根のサービスはステージとコミットを 1 つの書き込みとして続けて走らせる（→ [files](files.md)）——間に別の書き込みが割り込んで、押したときの姿とコミットの中身がずれることが無い。ステージが通ってコミットが落ちたら（hook の拒否など）、ステージしたものは残る。通ればメッセージは空になる（コミットの間に打ち足していれば残す）。失敗ならメッセージは残る。
- **競合が残っている間のコミット**は、ステージもコミットもせず「競合が残っている」の文で断る（amend・コミットしてプッシュも同じ）。git は競合のある index のコミットを必ず断るので、全部のコミットが通る場面は無く、先にステージしたものが merge のコミットに混ざるだけになるため。変更が競合だけなら、コミットは押せない。
- **押せない姿**: コミットボタンは主の働きと ▾ で 1 つの可否を持つ——主の側が押せないときは ▾ も同じ姿で開かない（中の項目が押せても）。1 つのボタンの中で明暗を割らないため（VS Code と同じ）。主の側が押せる間は、中の項目が 1 つも押せなくても ▾ は開き、項目が押せない姿で並ぶ。押せない間は地・印・字をまとめて薄くする（design-system の disabled）——字だけ薄くすると紫の地が押せる姿のまま残る。ボタンが押せない間の amend・取り消しは、区分「ソース管理」の … から選ぶ。
- **▾**: コミット（amend）/ コミットしてプッシュ / 最後のコミットを取り消す。**HEAD が push 済みなら amend と取り消しは押せない**——force push を持たないので、書き換えれば Orbe の中では戻せない。push 済みは「どれかの remote 追跡ブランチから届く」で（→ [git](../platform/git.md) のコミットグラフ）、HEAD 1 件をその規則で読み、読んだコミットと組で持つ。今の HEAD と違うコミットを読んだ・読めない間と、remote 追跡 ref が動きうるきっかけ（パネルを出した・再読込・remote 追跡 ref の変化・自分のネット操作の終わり）の後で読み直している間は、分からないとして押せない側に倒す——端末で HEAD を push した直後・自分の push が終わった時点から押せなくなる。push 済みは HEAD のコミットと remote 追跡 ref だけで決まるので、それ以外（HEAD・ローカルのブランチ・index の変化、ステージ等の終わり）での読み直しの間は、同じ HEAD なら前の値を使う（ステージやコミットのたびに ▾ が押せない姿へ点滅しない。HEAD が動けば、違うコミットとして分からないになる。ref が reftable 形式のリポジトリでは、どの ref が動いたかを名前で分けられないので、コミットのたびに読み直す間だけ分からないへ倒れる → [files](files.md)）。押せる・押せないは見せ方で、契約は書き込みが持つ——amend・取り消しは、根のサービスが書き換えの直前に HEAD の push 済みを同じ規則で読み、push 済みなら何も書かずに断って失敗の文を出す（▾ を開いている間や、外の push が監視に届くまでの間にも押せてしまうため）。取り消しも、HEAD が押した時点に見えていた HEAD（コミットと同じく自分の操作を重ねたもの）でなければ何も書かずに「表示と食い違う」で断る——外でのコミットを取り消さない。▾ の項目（amend・コミットしてプッシュ・取り消し）と … の amend・取り消しの「押した時点に見えていたもの」と押せるかは、メニューを開いた時点のもの——開いている間も行は外の書き込みに追いつくが、選んだのは開いた時点の姿なので、開いている間に外でコミットされれば、どれも何も書かずに「表示と食い違う」で断る。ネット操作が走っている・順番を待っている間も押せない（push と並んで走ると、push したコミットを書き換えうる）。amend はコミットと同じ範囲で直前のコミットを差し替える——ステージ済みがあればそれだけ、0 なら「変更」の行を全部。メッセージが空なら前のメッセージのまま中身だけを差し替え、入れるものが無ければメッセージがあるときだけ押せる（メッセージだけの差し替え）。コミットしてプッシュはコミットと同じ範囲でコミットし、通ったときだけ push する。push は push の時点の HEAD を送る——自分のコミットの後、push が始まるまでに外でされたコミットも一緒に送る。
- 取り消したコミットのメッセージは欄に戻さない。

## 同期と公開

コミットできる変更（ステージ済みも変更も）が 1 つも無いとき、コミットボタンは働きを替える（VS Code と同じ）。

- ブランチに居て upstream があり、先行か遅れがあれば「**同期 ↑N ↓M**」（0 の側は出さない）。押すとプル → プッシュの順に走る（数に依らず両方）。
- ブランチに居てコミットがあり、upstream が無ければ「**ブランチを公開**」。押すと upstream を付けて push する（付け先は根のサービスの push の解決）。
- どちらでもなければ押せない「コミット」。

欄のキー（↵ のコミット・⌘↵ のコミットしてプッシュ）は、ボタンが同期・公開でも同期・公開を起こさない——押せなければ音で断る。

## プル・プッシュ・フェッチ

区分「ソース管理」の … から選ぶ。**前提が足りないときも押せる**——押せば根のサービスの分類どおりの失敗の文（「upstream がありません。先にブランチを公開してください」など）が出る。前提の判定は根のサービスの 1 か所に置き、パネルで重ねて判定しない（判定が 2 か所に割れると食い違い、押せない理由も見えない）。

**ネット操作は worktree ごとに 1 つずつ**: プル・プッシュ・フェッチ・同期・公開・コミットしてプッシュのどれかが走っている（順番待ちを含む）間、同じ worktree のほかのネット操作は押せない（裏の fetch は数えない——後述）（別の窓で同じ worktree を見ていても）。ボタンの可否は見せ方で、契約は worktree ごとの状態が持つ——メニューを開いている間に別の窓で始まったなどで押せてしまっても、始めずに断り、失敗の文で知らせる。ステージなどは押せ、根のサービスの順番どおりに待つ。

**push と HEAD の書き換えは並ばない**: ネット操作が列にある間の amend・取り消しと、amend・取り消しが列にある間のプッシュ・公開は、始めずに断って失敗の文で知らせる。push は根のサービスの順番に並ばないので、並べば push したコミットを書き換える・書き換える前のコミットを送る。プル・同期・コミットしてプッシュは順番どおり書き換えの後に走る（送るのは書き換えた後の HEAD）ので断らない。

## 自動 fetch

そのリポジトリのエディター面が見えていて（ソース管理パネルを出しているかに依らない）、Orbe が前面にある間、裏で fetch して先行・遅れ（↑N ↓M・同期 ↓N）を新しくする。間隔は、前回の fetch・pull（裏・手を問わず）が通った終わり、または裏の fetch が認証・ホスト鍵以外で失敗した終わりから 180 秒で、面が見えた・前面に戻った時点で過ぎていればすぐ 1 回撃つ。エディター面が見えていない間と Orbe が背後にある間は撃たない（窓が背後にあるだけで Orbe が前面なら撃つ）。パネルを出していない間も件数とボタンの先行・遅れは status で新しくなり、グラフと HEAD の push 済みはパネルを出したときに読む。設定 `scm-auto-fetch`（既定オン。workspace で上書きできる）でオフにでき、面は自分の workspace の実効値を見る（→ [settings](../palette/settings.md)）。

- **リポジトリごとに 1 本**: 同じリポジトリの worktree は remote 追跡 ref を共有し、並んだ fetch・pull は後の側が落ちる（→ [git](../platform/git.md)）。同じリポジトリの 2 つの worktree の面が見えていても、周期ごとに 1 回撃ち、ref が動いた後の監視で両方の数字が変わる。
- **人の邪魔をしない**: 裏の fetch は worktree の操作の列に載らない——帯・失敗の文・ボタンの可否に出ず、出ている失敗の文も消さない。失敗は黙って次の周期を待つ。認証・ホスト鍵の失敗なら、そのリポジトリでは手の push・pull・fetch が通るまで（か再起動まで）撃たない。askpass・資格情報の窓は出させず、無出力が続けば打ち切る（→ [git](../platform/git.md)）。ssh-agent の側の承認（1Password・Secretive・FIDO 鍵）は封じられないので、毎回承認を求められる人のために設定のオフを持つ。
- **人に譲る**: 人が同じリポジトリでネット操作を押すと（別の worktree のパネルからでも）、その操作が終わるまで裏の fetch は撃たない。人の操作がネットの段（プル・プッシュ・フェッチ）を起こす直前に裏の fetch が走っていれば、それを止め、その終わりを待ってから段を走らせる。譲るのはネットの段の前だけで、コミットしてプッシュのコミットは押した時点で順番に入る——待つ間に押したステージ・解除・破棄がコミットより先に走って、コミットの中身が押した時点の姿からずれることが無い（プル・同期は 1 段目がネットの段なので、待つ間に押したステージ等が先に走る）。待つのは人の操作を走らせるための一部なので、待つ間も人の操作は走っていて、0.3 秒を越えれば帯に出る。塞いでいる裏の fetch は見せず、人には止められないため。帯で止めると、裏の fetch の終わりを待たずにその場で終わる。

## 実行中と止める

どの操作も、走り始めてから 0.3 秒を超えて走っていれば、見出しの下に帯を出す——上端に流れる細い線、操作名、push / pull / fetch の段なら git の進捗の最新の行（git の語のまま・末尾省略）、右端に「止める」。短い操作で帯が点滅しない。帯は**実際に走っている**操作（裏の fetch に譲って待つ間を含む）だけを出し、順番待ちの操作は出さない——返らない hook のコミットの後ろでステージしても、帯はコミットとその止める手を出す。走っている操作が複数あれば一番新しく走り始めたものを出す。順番待ちか走っているかは根のサービスの順番の中にしか無いので、根のサービスの「走り始めた」の知らせで決める（→ [files](files.md)）。

「止める」は今の段を止め、2 段の操作なら次の段を起こさない。止めた操作は失敗の文を出さない。hook が返らないコミットを止めても `index.lock` は残らない。ゴミ箱へ大量に破棄している間も UI は止まらず、止められる。

## 失敗

失敗はコミットボタンの下に danger の文で出す——理由と次の一手。画面と入力（メッセージ）を保ち、次の操作を始めると消える（Orbe の操作の失敗の型。検索パネルのエラーの文と同じ）。分類（認証・ホスト鍵が未知・push の拒否・プルの競合・操作の途中・ブランチに居ない・upstream が無い・push 先が無い・push 済みの書き換え・shallow の境界・競合が残っている・表示と食い違う）ごとに文が違い、分類できない失敗は git の理由の行そのまま。ネット操作や書き換えと重なって断ったときも、同じ型の文（何が走っていたので始めなかったか・終わってから試す）で出す。止めた操作と git 管理外は文にしない。

## グラフ

HEAD と、在れば upstream から届くコミットを新しい順に 50 件出し、続きがあれば末尾の「さらに表示」で 50 件ずつ増やす。

- 見出しの上に空きを置く。空きは行ではない——乗っても選んでも地が付くのは見出しの帯だけで、空きを押しても何も起きない。
- 見出しの右端に再読込。グラフと HEAD の push 済みだけを読み直す（status の取り直しは区分「ソース管理」の再読込が持つ）。
- 頭にブランチの器: ブランチ名（detached は HEAD の短い sha）と先行/遅れ `↑N ↓M`（upstream があり数が分かるときだけ。0 の側は出さない）。器と見出しの間に空きを置き、見出しを選んだ・乗ったときの地が器の枠と繋がって見えないようにする（空きも押して何も起きない）。サイドバーが狭くて入らなければブランチ名を優先し、`↑N ↓M` を末尾から省く（入らなければ消える）——どのブランチに居るかが先、数はボタン（同期 ↑N ↓M）にも出るため。
- 未 push のコミットは塗りの点、push 済みは中抜きの点と弱い字。縦の線は 1 本で、枝分かれ・merge の線は描かない。
- ブランチを指すコミットに ref の札（local / remote）。札が入らなければ末尾から省く（題が先に詰まる）。
- **コミットの行は押せず、乗っても地が付かない**——押しても何もしない行を押せそうに見せない。コミットの中身を見る面は持たない。
- **読み直し**: パネルを出したとき・再読込・さらに表示・自分の操作の終わり・根のサービスの「git の状態が変わった」の知らせで読み直す。status の変化だけでは読み直しの合図にしない——端末での upstream を付けない push・ブランチの作成や削除は ref だけを動かし、status は変わらない。いつも先頭から今の件数で読む（続きを継ぎ足さない——読みの間に HEAD が動くと重複・欠落する）。読んでいる間に次の合図が来たら、終わった後に 1 回だけ読み直す。読めなければ前の結果を保つ。
- グラフと HEAD の push 済みは、パネルを出している間だけ読む。

## worktree ごとの状態

打ちかけのメッセージ・走っている操作と止める手・最後の失敗は、**worktree（根）ごとに 1 つ**、アプリが動いている間持つ。同じ worktree を 2 つの窓の面で見れば同じものが見え、cd で離れて戻っても、パネルを閉じても残る（メッセージは同じ値を共有するので、2 つの窓で同時に打つ場面は想定しない）。再起動では消える（永続しない）。走っている操作は始めたときの根のサービスを、全段が終わるまで握る。

面ごとに持つのは見せ方——区分の開閉・グラフの件数・選択・パネルの中の焦点——と観測だけ。根が変われば（cd）見せ方は新しい根のもので初めからになり、パネルを出したままでも列と欄はすぐ新しい根を見せる。パネル（面）は面が見えている間だけ根のサービスを握る（→ [files](files.md) の握る者）。

## 件数

レールの「ソース管理」の右下に、ステージ済みの行と変更の行の和を出す（同じファイルが両方に出れば 2 と数える。1000 以上は「999+」）。変更が無い・git 管理外なら出さない。パネルを開いていなくても、面が見えていれば status の変化に追従する——行の組み立て・グラフ・HEAD の push 済みの読みはパネルを出している間だけ行い、件数のためにパネルを開かせず、隠れたパネルのために git を起こさない。

## キーと焦点

- レールで「ソース管理」を出すとメッセージ欄に焦点が入る（区分「ソース管理」を畳んでいれば列）。パネルが隠れたとき焦点がパネルにあれば、面の焦点の行き先へ戻す（→ [shell](shell.md) の焦点）。
- 欄のキー: **↵**（テンキーの Enter も）はコミット、**⌘↵** はコミットしてプッシュ（▾ の項目と同じ条件と範囲）。どちらも押した時点の姿で照らし、押せなければ音で断って何も入れない。改行は **⇧↵・⌥↵・⌃↵** のどれでも `\n` を入れる（⌃↵ も見えない行区切りの字ではなく改行）。変換中の ↵ は変換の確定だけで、コミットしない（IME が使った ↵ はコミットの合図として届かない）。⌘↵ は変換中なら確定してから働く。押し続けても ↵ のコミットは重ねて走らない（2 回目からはコミット中か欄が空で、音で断る）。修飾の無い ↵ だけをコミットにし、ほかの修飾の組と押下の無い改行の命令は改行にする——押し間違いを軽い側に倒すため。
- 列は押せば焦点を取り、検索結果と同じ型で動く: **↑↓** は区分見出しとファイル行だけを渡り（グラフの行は選べない）、ファイル行なら仮のタブで diff を開く。**←** はファイル行から区分の見出しへ、見出しなら畳む。**→** は畳んだ見出しを開き、開いた見出しなら最初のファイル行へ動いて開く。**Enter** はファイル行を普通のタブで開いて本文へ（見出しは開閉）。**⌘↑** は先頭の行（か未選択）からメッセージ欄へ戻る（区分「ソース管理」が畳まれて欄が隠れているときは戻らない）。**Esc** は選択を外す。ステージ・破棄のキーは持たない（ボタンで行う）。
- 行のボタン・見出しの一括操作・「さらに表示」の押下は行のクリックにならない（選択も開きもしない）。ボタンにポインタを乗せると説明が出る。

## VS Code との差

- **初回コミット前は「ブランチを公開」を出さない**（VS Code は出す。中身の無いブランチは push できない）。
- **upstream の無いプッシュは尋ねずに公開する**（VS Code は公開するかを尋ねる）。「ブランチを公開」と同じく upstream を付けて出す。
- **すべてステージ・すべて破棄は競合を含めない**（VS Code は「マージの変更」を別の区分に分ける）。
- **グラフの線は 1 本**（VS Code は枝分かれと merge を描く）。グラフのコミットは押せない。
- **自動 fetch は既定でオン**（VS Code の既定はオフ）。そのリポジトリのエディター面が見えていて Orbe が前面のときだけ撃つ。
- **ステージ済みが無ければ、確認を出さずに全部をコミットする**（VS Code の smart commit を「常に」にした状態。VS Code の既定は確かめる）。amend も同じ。全部に競合は含めない（VS Code は含める）。
- **欄の ↵ はコミット、⌘↵ はコミットしてプッシュ**（VS Code は ⌘↵ がコミットで、↵ は改行）。改行は ⇧↵・⌥↵・⌃↵ で打つ。
- **同じ位置で続けてステージ・解除できる**（VS Code は押した後に列がずれる）。押し続けている間、留めきれずに来た見出しや別の行は働かない。
- **印は M・A・U・C の 4 種**（VS Code の D・R は持たない）。削除の行に取り消し線も引かない。
- **行のボタンは常に出す**（VS Code はポインタを乗せた行だけ）。
- **取り消したコミットのメッセージを欄に戻さない**。
- **AI によるメッセージ生成は持たない**。
