# コード

エディター面の文書。ファイルを開き、色を付けて描き、編集して保存する——端末の隣で、別のアプリへ行かずにコードを直すための場所。焦点の文書のコードビューは[面の骨](shell.md)の本体に出て、文書が無ければそこに[面の機構](faces.md)の空状態が出る。

## 文書とテキスト面

タブ 1 枚が**セッション**——開いた文書の列と焦点の文書——を持つ。**文書**は開いたファイル 1 つで、識別（URL）・言語・未保存の有無を持つ。文字を描き編集を受けるのは文書と対になる**テキスト面**（[Metal で描く](#テキスト面metal)）で、本文の正は文書の写しにある。文書 1 つにテキスト面 1 つを、開いてから閉じるまで対で持つ。切り替えは「どの文書の面を見せるか」を変えるだけなので、undo・選択・スクロール位置は文書ごとに残り、戻ればそのまま続きが打てる。変換中の IME は切り替えで確定する（面が焦点を失う入口で確定する）。

文書は本文の**写し**を持ち、面の編集を追う——面は本文が変わるたびに、1 回の操作の編集を**束**（重ならない昇順の置換の列で、どの範囲も束の前の本文の座標）にして、置換後の中身を UTF-16 の単位のまま文書へ渡し（サロゲートの対を割る置換とその undo でも、片割れを化かさずに運ぶ）、文書は束を後ろの編集から当てて写しを置き換え、編集 1 つごとに**版**を 1 つ進める。Orbe の配り先（検索・出現・プロジェクト検索）への知らせは束ごとに 1 回で、適用した順の編集の列（どれもその直前の本文の座標で、編集ごとの行の増減が分かる行と桁つき）が届く——配り先は列を順に畳み、束の途中の本文を見ない（差し引きで行の数が変わらない束でも、行がずれた区間を取り違えない）。座標の変換は文書の 1 か所だけにある。文書が扱う編集は、置換の前後で変わらない先頭と末尾を落とした、本文が実際に変わった区間——外部変更の差し替えでも、変わっていない字の色・ハンク・一致はそのまま残る。Orbe の中で本文を読むのはこの写しだけで、面に本文を読む口は無い（全文を写す道が型の上に無い）。写しは本文を小さな塊に分けて木に載せたもので、行とオフセットの変換・部分の取り出し・置換が文書の大きさに依らない。値として写しても変わらないので、裏のスレッドが同じ本文をそのまま読める。構文色・ハンク・検索の一致・出現は、この写しから裏で作る——打鍵 1 回で main がする仕事は、写しの置き換えと裏への依頼だけで、文書の大きさに依らない。裏の仕事は依頼ごとに写しを読み、本文の写しを持ち続けない（検索と出現は窓ごとに読み、行差分は取る間だけ連続した列に写す）。裏の結果はどの版の写しから作ったかを持ち、今の版より古ければ、その後の編集に合わせてずらしてから使う（字から離れない）。

文書の識別は symlink を解いた実体のパスで、同じファイルをもう一度開いても（別の綴り・リンク経由でも）文書は増えず、焦点がそこへ移るだけ。文書の列・焦点・未保存の有無・「ディスクが変わった」の有無が変わると、タブは 1 本の通知で上位へ上げる。

文書は開いてから閉じるまで、自分の実体が属する根のサービスと結ばれる（→ [files](files.md)）。外で書き換えられたファイルの反映と、index の版（baseline）はそこから届く。

## 開く・保存する

ファイルは UTF-8 として読む。読めない・UTF-8 として解けないファイルは開けず、呼び手にエラーで返る（面は変わらない）。Metal の装置が取れない環境ではテキスト面を作れないので、どのファイルも同じく開けない（→ [テキスト面](#テキスト面metal)）。文法の無いファイル（`.txt` 等）は色無しで開ける。

⌘S は焦点の文書をそのファイル（symlink なら実体）へ書く。リンク自体は置き換えない。書くのは文書の写しそのもので、改行の種類も末尾の改行も本文のまま（勝手に足さない・直さない）。先頭の UTF-8 BOM は本文に含めず、最後に読んだ／書いたときの有無を保存で保つ（あれば付け直し、無ければ足さない。外の内容に差し替えたときはその有無に倣う）。書いた時点で未保存は消える。未保存は「最後に開いた／保存した内容と本文が違うか」ではなく「保存の後に編集があったか」——⌘Z で保存時の状態に戻しても未保存のまま。保存は undo の区切りでもある——打鍵のまとまり（→ [キー](#キー)）は保存をまたがない（打つ → ⌘S → 打つ → ⌘Z は保存の後の打鍵だけを戻す）。

⌘S の直前にディスクを読み直し、監視が届いたときと同じ照合をする——印が立たなければ（未編集の文書は外の内容に差し替えてから）書き、印が立てば保存は失敗してディスクに触れない。外のツール（エージェント）の編集を黙って潰さないため。この失敗は force の保存だけが越え、その入口は印の立った文書の ⌘S が出す上書きの確認（→ [shell](shell.md)）。外部変更の照合と印の規則は [files](files.md)。

未保存の文書を捨てる人の操作（ファイルタブの ×・タブを閉じる・終了）は確認を挟み、シェル終了・制御 API は黙って捨てる（→ [shell](shell.md)）。開いていた文書は再起動で戻るが未保存の内容は戻らない（→ [persistence](../platform/persistence.md)）。外部変更以外の保存の失敗は音で断り、ログに残す（エラー面は持たない）。大きなファイルに上限は無い。

## ハンク

文書は baseline（比べる底の本文。無ければハンクは空）と、baseline と本文の行差分——追加・変更・削除の行区間——を持つ。区間は unified diff の `@@ -a,b +c,d @@` と同じ形で、片側が 0 件の区間はその直前の行を指す。行は `\n` で割り、`\r` は行の中身に残す（CRLF と LF は正規化しない）。末尾の改行の有無も最後の行の違いとして数える。

差分は裏で、本文の写しと baseline だけで取る（1 打鍵ごとにサブプロセスは起きない）。baseline を置いたときと編集のたびに頼み、続けて頼めば最新の版の 1 回に畳まれる。結果が届くまで（普通は数 ms、大きな文書では数百 ms）は前のハンクを出し、編集で行が増減した分だけ後ろの区間をずらしておく。共通の先頭・末尾を落とした残りが大きすぎる入れ替え（両側の和で 1000 行超）は、残り全体を 1 つの変更区間にして時間を有界にする。

## 色付け

言語は拡張子（と `Dockerfile` のようなファイル名）から決まる。対応は Swift / Markdown / JSON / TypeScript / JavaScript / TSX / CSS / HTML / Python / Go / Rust / YAML / TOML / Bash / Dockerfile の 15 で、色は tree-sitter の構文木から付ける。

中に別の言語が埋まる箇所（**注入**: HTML の script / style、Markdown の inline とコードブロック、JS / TS のタグ付きテンプレート、Rust のマクロ）はその言語の色で塗る。注入は 1 つずつ別の構文木で解く——コードブロックの `/*` が次のコードブロックへ続いたり、インラインの `` ` `` が段落をまたいでコードスパンを作ったりしない。1 本に束ねるのは、規則が束ねると指定したもの（タグ付きテンプレートの `${}` で割れた断片）だけ。注入の範囲は中身の節から名前付きの子（段落の続きの `>` など）を除いたもので、注入の色はその範囲の中に閉じる。注入の中の注入は 4 段まで解く。注入は、その注入を生んだマッチ（中身と言語の指定の節）で存否が決まる——言語の指定だけを書き換えれば（```` ```js ```` → ```` ```py ````）その場で言語が替わり、消えた注入の色は残らない。編集を重ねた文書の色は、同じ本文を新しく開いた色と同じになる（構文の誤りを含む間の例外は後述）。

色は 8 つの**役割**（keyword / 制御の keyword / type / function / string / comment / variable / punctuation）に付き、役割を持たない文字（数値・定数・マークアップの強調など）は素の文字色で描く。文法ごとに揺れる capture 名は 1 枚の正規化表で役割へ写す——見本の 8 色を超えて色を増やさない。

役割は文書全体の**役割の並び**（役割か役割なしの連なりの列）として裏で作り、面とミニマップはそれを引くだけにする。構文木は文書ごとの裏の仕事が持ち、打鍵が続けば編集をまとめて当ててから 1 回だけ差分で解析する。作り直すのは「構文木が変わった区間 ∪ 編集の区間」に掛かる行を丸ごと——字の中身で役割が決まる箇所（JS の大文字で始まる識別子など）は、構文木が変わらなくても役割が変わるから（`Foo` の F を消すと `oo` は変数の色になる）。作り直しは見えている行から先に行う。打鍵が続く間は見えている行だけを作り直し、見えていない範囲は打鍵が止んでから（最後の打鍵から少し置いて）裏で順に埋める（開いてから打鍵が無ければ待たずに埋める）——構文の崩れる打鍵（括弧を開くなど）は文書の末尾までを作り直す範囲に変えるので、打鍵のたびにそこまで作り直すと、打ち続ける間ずっと 1 コアを使う。遠くの色とミニマップの色は、打鍵が止むまでずらした前の色のまま。スクロールで新しく見えた行は待たずに作る。作り直していない範囲は前の役割を編集に合わせてずらしたまま持つので、一度色が付いた字が作り直しの途中で素の色に戻ることはない。

構文木が構文の誤りを含む（書きかけの括弧など）とき、tree-sitter の問い合わせは後ろに続く文書の長さに比例して重くなる。そこで誤りを含む構文木では、色を本文の固定の区画ごとに問い、区画の前後に余白を取った枠の中に収まる構文だけに色を付ける。そのため、余白を超える大きな構文（誤りで数十 KB に伸びた呼び出しの関数名など）の色が付かないことがある。区画は本文のオフセットの格子なので、同じ本文の同じ字は、どこから作り直しても同じ色になる。誤りを含まない構文木には枠を掛けず、落ちる色は無い。構文木が誤りを含むかどうかが変われば、その構文木の範囲を丸ごと作り直す。

誤りを含む間は、編集を重ねた文書の色が、同じ本文を新しく開いた色と違うことがある。1 つは枠——編集で後ろの字がずれた後、作り直していない範囲は前の区画の枠で問うた色のまま残るので、余白を超える構文の色が違いうる。もう 1 つは誤りの回復——誤りを含む構文木は、差分で解き直した木が同じ本文を新しく解いた木と違うことがある（tree-sitter の誤りの回復は、前の木から使い回す節に左右される。どちらの木も誤りの回復の 1 つの結果で、どちらが正しいということはない）。誤りを直せば、色は同じ本文を新しく開いた色に揃う。

文書を閉じると、走っている構文解析を打ち切る（1MB の全体の解析の途中で閉じても、裏がそれを最後まで走らせない）。

打鍵の直後は、文書が役割の並びを編集に合わせてずらす——挿した字は挿入点を含む連なり（境なら前の連なり）を伸ばし、消した字は縮める。打ち込み中の語は前の色を引き継ぎ、裏から役割が届くと正しい色に変わる。届くまでの時間は、tree-sitter が構文木を差分で解き直す時間（編集点より後ろの長さに比例する。1MB の Swift で構文の崩れる打鍵なら 70ms 前後）に、見えている行の作り直しと届け（15ms 以内）を足したもの。その間は編集に合わせてずらした前の色が出続け、ちらつかない。

開いた直後の色: 文書を初めて画面に出すとき、裏がまだ見えている範囲の役割を作り終えていなければ、main は最大 50ms だけ待つ（待つ間は裏の優先度を上げる）。普通の大きさのファイルは最初の描画から色付きで、1MB 級は無色で出て揃い次第色が付く。再起動の復元で開くだけの見えていない文書と、エディター面が畳まれた・窓に無いときに結んだ文書は待たない（面が見えたときに待つ）。2 回目以降に見せるとき・打鍵・スクロールでは待たない。文書全体の役割が揃う前に遠くへ飛ぶと、飛んだ先が無色の区間として見えうる（1MB で数十〜百数十 ms）。

面は色を覚えず、描くときに写しの役割の並びから、横に見えている字の区間の役割を引いて色を出す——全文に色を置く手間も、色を置き直す手間も無く、打鍵もスクロールも文書の大きさに依らない。見えている字は常に文書の今の役割の色で描かれる（遠くへ飛んだ先の字も、役割が揃っていれば飛んだそのコマから色付き）。裏から役割が届けば、役割が変わった行を描き直す。色は描画のためのもので本文に載らないので、undo 履歴にも保存する内容にも混ざらない。外観（dark / light）の切替は色を解き直して描くだけ。

色付けの規則（queries）は `.app` に同梱する。同梱が無い・読めない・言語が無いときは色無しで開け、失敗として扱わない。

構文の裏の仕事は、[アウトライン](outline.md)が要る文書では、見えていない範囲を作り始めるのと同じ静けさが明けた時点で、根の構文木の写し（部分木を共有するので大きさに依らない）と本文の写しと版を、アウトラインの裏の仕事へ手放す——取り出しの問い合わせは全文に 1 回かかるので、色の作り直しと同じ仕事の中で走らせると、見えている行の色を待たせる。アウトラインの規則（言語ごとの問い合わせ）も Orbe 自身の資源として `.app` に同梱し、無い・読めないときはアウトラインを出さないだけで、失敗として扱わない。

## 行の装備

文書の行には、本文の字とは別の**装備**が付く——行番号の右の git ガター、本文に重なる空白の丸点・⌘ で乗せた URL の下線。どれも本文と undo に載らない描画で、選択の地は装備を覆う（選択中の行の点や下線は見えない）。

**行番号の列**は本文の左に並び、文書の行（`\n` で割った行）ごとに番号を描く。空の文書にも行 1 がある。列は最大の行番号が収まる幅で、桁が増えれば広がる。番号を押すとその行を改行まで選ぶ（最終行は行末まで）。押したままドラッグすると押した行を起点に行単位で伸びる。ポインタが本文の上下の外へ出ると本文が縦に、行番号の上（本文の左の外）にあると本文が左へ横に、ポインタが止まっていても外れた距離に応じた速さでスクロールし、選択が伸び続ける。⇧クリック（⇧を押したままのドラッグ）は今の選択の元の区間から押した行まで伸ばす——元の区間は、列で行を選んだ後にキーで伸ばしただけならその行、語や段落の単位で選んだ選択（ダブル・トリプルクリック）ならその選択、それ以外は動かない側の端で、上へ伸ばせば元の区間は選択に残る。選択の動く側の端はポインタの側（上へ伸ばせば先頭）で、押したときと本文の上へドラッグしたときは、そこが見えるところまで最小限スクロールする。規則は VS Code の既定と同じで、どれもテキスト面へ焦点を移す。⌃クリックは行を選ばない。その右の git ガターは押しても何もしない。ドラッグの自動スクロールの速さの式は本文のドラッグと同じ 1 か所にある。

**git ガター**は文書のハンク（→ 上）を行の印に写す。index 版に対して追加された行にはバー、変更された行には別の色のバー、削除があった境（消えた行があった場所の上下の行の間）には三角が出る。色と形は [design-system](../../design/design-system.md) §5。baseline が無い文書（index に無い・非 git・競合中）はガターが空。印は編集に追従する——打鍵の直後はずらした前のハンクが同じ描画に載り（同じ行の中を打っても区間が本文に付いてくる）、裏の差分が届くと追いつく（普通は数 ms、大きな文書では数百 ms）。端末で `git add` / `git checkout` すれば index に追従して消える／変わる。baseline は index の版を作業ツリーに出したときの中身なので（→ [files](files.md)）、`eol=crlf` や smudge filter のあるリポジトリでも `git status` が clean と言うファイルはガターが空。

**インデント**の単位（1 段のスペース数）は文書ごとに本文から検出する——隣り合う非空行の行頭スペース数の差のうち 2 / 4 / 8 に当たるものの最頻値、同数なら小さい方、候補が無ければ 4。行頭がタブの行は差の計算に入れず、タブ行を挟むと、その前後の非空行は差の対にならない。文書は単位と一緒に**タブで字下げしているか**も検出する（VS Code の推定と同じく、行頭の空白にタブを含む行とスペース 2 個以上で始まる行の数を比べ、タブの行が多ければタブ。同数なら空白）——[テキスト面](#テキスト面metal)の Tab と Enter が入れる字はこれに従う。単位とタブかは開いたとき、および本文を丸ごと置き換えたときに検出し直す。**タブの表示幅は検出した単位**——タブ 1 個がスペースの 1 段と同じ幅に見える。

**空白の丸点**は、行頭の連続スペース・行末の連続スペース・中間の 2 個以上の連続スペースに、セルごとに 1 つ出る。対象は半角スペース（U+0020）だけで、タブ・NBSP・改行には何も出ない。単語間の 1 個のスペースには出ない。

**URL** は `http://` / `https://` で始まり、空白・`<` `>` `"` `` ` `` の手前までを 1 つとし、末尾の句読点（`.` `,` `;` `:` `!` `?` `'`）と、その中に対応する開き括弧が無い末尾の `)` `]` `}` は含めない。行をまたがない。⌘を押して URL の上にポインタを乗せている間だけ、その URL に文字と同じ色の下線が付いて指カーソルになり（テキスト面が焦点のとき。⌘を離す・ポインタが外れる・スクロールで URL がポインタの下から外れると消える）、**⌘クリック**で既定のブラウザに開く（素のクリックは通常どおりキャレットを置く——URL の文字列にキャレットを置けなくしないため）。開くのは**離したとき**——押した URL の上で離せば開き、押したまま動かして離せば何もしない（その間は選択も伸びない）。⌘に ⇧・⌥・⌃ が重なるクリックは URL でも開かず、通常の選択操作になる。URL の行き先を決めるのはエンジンではなく Orbe 本体で、面を載せる側が既定ブラウザで開く。

## 俯瞰

本体の右端に、左から**ミニマップ**と**縦スクロールバー**が立つ。見えている行の外に何があるか（文書のどこにいるか・どこに変更や一致があるか・キャレットがどこか）を本文をスクロールせずに示し、そこから本文を動かすためのもの。使い勝手の基準は VS Code の既定で、配置・帯とつまみの動き・印の写像は VS Code と同じ式で決まる。

**最終行の先までスクロールできる**——最終行（本文が改行で終わるなら末尾の空行）を画面の最上段まで送れる。そのとき最終行より下は空き地で、そこを押すとキャレットは文書の末尾へ行く（そのままドラッグすれば選択が伸びる。ポインタは本文の上と同じ I ビーム）。End は最終行を下端に出す位置へ送る（最後の 1 画面が見える）。スクロールバーとミニマップの位置の計算も、この送れる範囲を含む。

**ミニマップ**は文書の縮図で、1 行を細い 1 段、1 字を 1 桁に縮め、字の形を構文の色で描く（役割の無い字は素の文字色）。役割は文書の役割の並びを引くだけなので、新しく見えた区画もその時点の役割の色で描く（役割がまだ揃っていない区間は素の文字色）。裏から役割が届けば、役割が変わった区画だけを描き直す。空白は描かずに 1 桁進み、タブは次のタブ位置まで空け、全角は 2 桁。幅は本文の幅から決まり（本文の桁とミニマップの桁が釣り合う幅に上限を置く）、列が狭ければ細くなる。幅に入らない桁は描かない。縮図は本文と色付けの変化に追従する。git の追加・変更・削除の印が左端に、検索の一致と語の出現がその範囲と行の薄い地で、選択が選択の色で重なる（複数行の選択は途中の行を行末まで塗り、その先は行の薄い地）。

文書がミニマップに収まらなければ、ミニマップはスクロールに合わせてスライドする（先頭で上端、最終行を最上段へ送れば末尾が見える）。見えている範囲を示す**帯**は普段は隠れ、ミニマップの上にポインタがあるときに現れる（帯の上とドラッグ中は濃くなる）。帯を掴んでドラッグすると本文がすぐに追従し、帯の外を押すとその行の上端が本文の中央に来る（横位置は動かさない）。

**スクロールバー**のつまみの長さは見えている割合で決まり（掴めるよう最小の長さがある）、掴んでドラッグできる。トラックを押すとつまみの中央がそこへ来るよう飛び、押したままドラッグを続けられる。つまみは本体の上にポインタがある間とドラッグ中に見え（押したまま本体の外で離せば消える）、スクロールの状態が変わると——縦横のスクロール・窓の大きさの変化・改行で行数が変わったとき——現れて、止まってしばらくすると消える（文書を開いた直後は、最も長い行を初めて測って横の範囲が決まっても出ない）。

スクロールバーの上には**印**が常に出る——左に git の追加・変更・削除、中央に検索の一致と語の出現、全幅にキャレット（選択の動く側の端）の行。位置はスクロール全体に対する比例で、短いものは最小の高さに広げ、接するものは 1 つに繋がる。つまみは印の上に半透明で重なる。色はガター・強調と同じ意味の色（→ [design-system](../../design/design-system.md) §5）。

先頭の行が上へ隠れている間は本文の上端に影が、本文が右にまだ続くときはミニマップの左端に影が出る。どちらも本文の上だけに描く。

俯瞰の上のホイール・トラックパッドは、本文の上と同じように本文をスクロールする。俯瞰の上のポインタは矢印。OS のスクロールバーは出さない。本文の区画の下端には VS Code と同じ**横スクロールバー**が重なる——横に続く本文があるときだけ出て（無ければその所は本文として押せる）、行番号の列の右からミニマップの左まで、つまみの長さと位置・トラックの押下とそのままのドラッグ・現れ方と消え方は縦と同じ規則で、印は持たない。本文の見えている高さは削らない（最終行の先まで送れるので、下端の行も送れば見える）。

俯瞰はテキスト面自身が本文と同じ 1 コマに描いて動かすので、ミニマップの帯・つまみ・影の有無は、どのコマでもそのコマの本文のスクロール位置を表す（端を越えて弾む間は端の位置）。つまみを見せる「スクロールの状態の変化」には横の範囲（見たことのある最も長い行）の変化も入り（VS Code と同じ）、帯とつまみの上かはそのコマの配置で決まる（ポインタを止めたままスクロールしても、濃さが今の配置に合う）。俯瞰の上の押下は俯瞰が受け、テキストの選択・ドラッグ＆ドロップ・右クリックのメニューは出さない。俯瞰を押しても焦点は動かない（検索バーで打っている途中に俯瞰で位置を確かめても、続きは検索バーに入る）——俯瞰の区画の上だけ当たる焦点を取らない子 view が押下を受けて面へ渡す。

俯瞰は焦点の文書 1 つに結ばれ、文書を切り替えれば結び直す。文書が無ければ無い。

## ファイル内検索

エディター焦点中の ⌘F は焦点の文書の中を探す。バーは[スクロールバック検索](../terminal/search.md)と同じ部品——同じ見た目・同じキー（Enter で次・⇧Enter で前・Esc で閉じる。本文に焦点があるときの Esc でも閉じる。変換中の Esc は変換の取り消し）・同じ件数表示（selected/total、位置が無ければ ?/total、一致なしは danger）——で、本文の右上（ミニマップの左）に浮く。文書が無ければ ⌘F は何も起こさない。表示中の ⌘F はバーを二重に出さず、種があれば needle をそれで取り直し（種が無ければ前の needle のまま）、入力欄に焦点を入れて全選択する。

⌘F を押したとき、1 行以内の非空の選択があればそれが、選択が空ならキャレットの語（→ 出現の強調の「語」）が needle に入って即検索される。選択は動かさない（キャレットの語が種なら現在の一致は無く、件数の位置は「?」）。

一致はリテラル・大小無視・重ならない。打つたびに一致を取り直し、全一致に地が敷かれ、起点以降に始まる最初の一致（無ければ先頭へ循環）が選択される。起点は検索が選んだのではない最後のキャレット——開いたときのキャレットで、本文でキャレットを動かせばそこ（打ち直して検索語を短くしても、検索が選んだ一致ではなく起点から選び直す）。**現在の一致**は状態として持たず、常に選択から導く——選択がちょうど一致のどれかならそれで、そうでなければ無い（本文をクリック・打鍵して選択が一致から外れれば、現在の一致の地は消え、件数の位置は「?」になる）。Enter は選択の終わり以降に始まる最初の一致へ（選択が一致ならその次、キャレットが一致の中ならその次の一致）、⇧Enter は選択の先頭までに終わる最後の一致へ（両端で循環）。選んだ一致は面の「見えていなければ中央へ」の方針で見せる（→ [区間を見せる](#区間を見せる)）——一致の行が縦に見えていなければその行を本文の中央に、縦に見えていれば最小限のスクロールで（横に隠れていれば横だけ寄り、見えていれば動かない）。

現在の一致は、選択の地の上に全一致と違う不透明の地で見分けられ（選択の色は見えなくなる）、その行全体にも薄い地が付く。面の「一致の地」の口は 1 つで、ファイル内検索と[プロジェクト検索](search.md)（検索パネルが見えている間の、焦点の文書の一致と選んだ一致）の 2 つの出どころの和を面を載せる側が押す——どちらかが変わったとき・文書の切替・検索パネルの見え隠れで押し直し、両方を同時に使えば両方の一致が出る。一致は俯瞰にも出る——ミニマップに範囲と行の薄い地、スクロールバーの中央に印。一致を集めるのは上限までで、上限に届けば件数は「上限+」と出す。一致が多いとき（千件を超える）はミニマップには現在の一致だけが出て、スクロールバーは近い行をまとめた印になる（全部を描いて固まらないため）。

一致は文書の写しから裏で探す。検索語を打ち換えると、新しい検索語の一致が届くまで（普通は数 ms）は前の検索語の地と件数が出たまま（打つたびに地が消えてちらつかない）。その間の打鍵での最初の一致の選択と Enter・⇧Enter（最後の 1 回ぶん）は、新しい検索語の一致が届いてから、その順に行う（最初の一致を選んでから一歩進む・戻る）——前の検索語の一致へ飛ばず、行き先は届く速さに依らない。待っている間に本文をクリックするなどして選択を動かせば、その後回しの操作は取り消す（届いた一致が人の選択を覆さない）。バーを開いたまま本文を編集すると、一致と件数は少し遅れて追従し（打鍵のたびに文書全体を探さない）、その間の地は編集に合わせてずれて字から離れない。検索語は同じなので、その間の Enter・⇧Enter はずれた一致に対して行う。選択は動かさない（打ち込みを乱さない）。文書を切り替えると同じ needle で新しい文書の一致を敷き直す（ジャンプしない）。新しい文書の一致が届くまで、その間に選択が動いても件数は前のまま（一致があるのに「一致なし」を出さない）。文書が無くなればバーは閉じる。Esc で閉じると地は消え、選択はそのまま残り、焦点はテキスト面へ戻る。一致の地は本文と undo に載らない。

端末焦点中の ⌘F はスクロールバック検索（→ [layout](../chrome/layout.md) の「両面のキー」）。

## 出現の強調

同じものが他のどこにあるかを、探さずに見せる。2 種類あり、どちらも本文と undo に載らない地で、規則は VS Code の既定に合わせる。出現は文書の写しから裏で探し、少し遅れて（普通は数 ms）地が付く（選択やキャレットが変わった後に届いた前の問いの結果は出さない）。

**選択文字列の出現**——1 行以内・空白だけでない・長すぎない文字列を選択すると、他の出現（大小無視）にうっすら地が付く。選択自身と、選択より前から始まって選択に重なる出現には付かない。本文だけに出て俯瞰には出ない。選択の変化ですぐに取り直す（本文を変える操作は選択の変化を伴うので、そこで取り直される）。検索バーが同じ文字列を探している間と、検索バーの入力欄に焦点があり検索語が空でない間は出さない（検索の一致と二重にしない）。面に焦点が無いときは地が薄くなる。

**語の出現**——キャレットが語の上にあると（または選択がちょうど 1 語か 1 語の内側だと）、少し遅れて同じ語（大小区別・語の境界つき）の全出現に地が付き、スクロールバーの中央とミニマップにも出る。語は英数字などの並びで、記号と空白で切れる（全言語で同じ定義。数の語の「数字」は ASCII だけ）。長い行（千字を超える行）ではキャレットの前 499 字から後ろ 501 字までの範囲だけから探す（VS Code と同じ。範囲の端にかかる語は端で切れる）。打鍵・本文の変更で消え、次にキャレットを動かすと出直す——打鍵に伴うキャレットの移動では出ない（本文の変更と同じ runloop の選択の変化は打鍵と見なす）。キャレットが出ている範囲の中を動く間は取り直さない。焦点が本文と検索バーの外へ出ると消え、本文へ戻るとキャレットを動かさなくても出直す（⌘F で検索バーへ移っても消えない）。

## 見え方

見本「コード本体」の値を持つ（→ [design-system](../../design/design-system.md) §5「Code view」）。行番号のガター（右寄せ）とその右の git ガター（本文はその右端から）・固定の行高・上端の余白・キャレットの色と寸法・役割ごとの色・装備の色と寸法はトークンで、フォントの決め方は 1 か所に閉じる。俯瞰（ミニマップ・スクロールバー・印・影）と強調の地は、寸法を VS Code の既定に、色を VS Code Dark Modern / Light Modern の値に合わせ（見本から外れる）、同じ意味の Orbe のトークンがあるもの（git の印・キャレット・縁）はそれを使う。本体の最低幅の中に俯瞰の幅も入る——極端に狭い列では本文とミニマップが縮む（俯瞰を自動で隠す規則は持たない）。地は chrome と同じ veil で、背景透過の設定に追従する。地は面を載せる側が本体ごと 1 層で塗り、テキスト面と俯瞰は地を持たない（透過の濃度が二重にならない）。行番号の列（行番号と印の列）は本文の左に並び、本文はその下をくぐらない——横スクロールバーは列の右から始まる。テキスト選択の地は VS Code の選択の地の色（`editor.selectionBackground`）で、面は見え方としてそれを受け取って自分で描き、焦点が無ければ焦点の無い面の選択の色（`editor.inactiveSelectionBackground`）にする。

## キー

エディター焦点中の chrome キーは面が先取りする。分類は[レイアウト](../chrome/layout.md)の「chrome キーの分類」——window コマンドはタブ経由で上位へ、⌘S は保存、端末のキー（フォント）は何も起こさず端末にも届かず、両面のキーのうち ⌘F はファイル内検索、⌘↑↓ はテキスト面の文書先頭／末尾へ。chrome キーでない F4 / ⇧F4 も、プロジェクト検索の結果があれば面が先に取り、次・前の一致を開く（→ [search](search.md)）。それ以外の打鍵はテキスト面へ届く（日本語 IME を含む）。検索バーは面の配下なので、バーに焦点がある間も chrome キーは効く（⌘↑↓ だけはバーの入力欄の中で先頭／末尾へ動く）。⌘Z / ⌘⇧Z / ⌘X / ⌘C / ⌘V / ⌘A は Edit メニューの key equivalent が responder chain でテキスト面へ届く。⌘Z は VS Code と同じく語と直前の空白 1 つごとに戻す（→ [テキスト面](#テキスト面metal)の undo）。

変換中の ⌘ 付きのキーは窓の根でまず IME へ渡る（→ [レイアウト](../chrome/layout.md)の「chrome キーの分類」）。IME が使わなければ chrome キーの分類の順（変換中でないときと同じ順）で流れる。pane が解く chrome キーは、走らせる前に焦点の文書の変換を確定する（タブに依らない window コマンドは窓の根が先に走らせるので除く）——⌘F の種の読み取りや焦点の移動の前に、変換の状態と IME の状態を揃えるため。未確定の文字は既に本文にあるので、変換中の ⌘S は見えている本文を保存し、変換を確定する（確定しても本文は変わらない）。

端末焦点の ⌘S は端末へ届く（Orbe は束縛しない）。

## 焦点

焦点の文書があるとき、エディター面の焦点 view はそのテキスト面（無ければ面自身）。タブ切替・パレット閉・⌘R 確定・制御 API でエディター面へ戻るフォーカスはここへ来る。テキスト面をクリックしてフォーカスを取ると、面の記憶がエディターへ移る（→ [faces](faces.md)）。文書を開いた・切り替えた瞬間に焦点が面の中にあれば、新しく見せた文書のテキスト面へ移す（サイドバーにある焦点は動かさない）。

## テキストエンジンの境界

テキスト面は文書のモジュールにある契約で表し、その実装のテキストエンジン（Metal）は 1 モジュールに閉じる。エンジンの公開は「面を作る 1 関数」・「描く用意を裏で始める 1 関数」・面の view の型（変換中の ⌘ キーを IME へ先に渡す口。窓のキーの層の口への準拠は合成点が宣言する）だけ。面の契約に本文を読む口は無い——面は本文が変わるたびに、1 回の操作の編集の束（置換前の区間と置換後の中身の組の列。重ならない昇順で、範囲は束の前の本文の座標）を編集の通知で文書へ渡す（面の本文のすべての変更がこの通知を通る）。文書は束を後ろから当て、Orbe の配り先へは束ごとに 1 回、当てた順の編集の列（行の増減が分かる行と桁つき）で知らせる——複数の区間を変える操作（複数行の字下げとその undo など）でも、配り先は束の途中の本文を見ない。契約は undo の区切り・「行の印を置く」1 操作（文書がハンクから作り、他の区間と同じくオフセットで押す）・「変換中の IME の文字を確定する」1 操作（載せる側が、面の外へ焦点や読み取りが移るコマンドの前に呼ぶ。未確定の文字は本文にあるので本文は変わらない）・**面を載せる側**の口に加え「本文を丸ごと置き換える」1 操作を持ち、置き換えは通常の編集と同じく undo に載り、同じ通知で呼び出しから戻るまでに文書へ届く（写し・構文・ハンクが打鍵と同じ経路で追従する）。置き換えの前に変換中の IME セッションを畳み、置き換え後の選択は解け、キャレットは同じオフセット（本文が短ければ末尾）に置く。面は文書の**写し**（本文・役割の並び・版の組。値として渡るので、描画のスレッドがそのまま読める）を引いて描く——文書と結ばれたとき・役割が変わったと知らされたとき・行の印を受けたとき・自分の編集の通知から戻ったときに引き、文書はどの知らせも写しを更新した後に出すので、引いた写しは知らせと同じ版になる。文書が写しを面へ押す口は持たない（知らせは何が変わったかを言い、面が写しを引く、の 1 本）。文書は裏から役割が届くと「役割が変わった区間」を面へ知らせ、面はそこに掛かる行を描き直す。

面の外とのやりとりの口は、面の外に使い手がいるものだけ——見えている範囲を**本文の言葉**で読む（先頭に見えている行のオフセットと、見えている高さに入る行の数。文書の構文が、見えている行を先に解くのに使う）、[区間を見せる](#区間を見せる) 1 操作、選択の読み書き（置くだけで見せない）とキャレット（選択の動く側の端）の読み、「強調の地を種類ごとに置く」1 操作（検索の一致・現在の一致・選択文字列の出現・語の出現。地は選択の地の上・文字の下に出る）、「字下げの作法（単位とタブか）を置く」1 操作（検出するのは文書——開いたときと丸ごと置き換えたとき——で、面は単位をタブの表示幅と装備の段に写し、Tab で入れる字と字下げの幅にも使う）、「改行の作法（LF か CRLF。CRLF と LF の多い方、同数と改行の無い本文は LF）を置く」1 操作（検出の時機は字下げと同じ。面は Enter で入れる改行と、貼る・落とす文字列の改行に使う）、**右列の幅**（ミニマップ＋縦スクロールバー）、「見える範囲が変わった」「選択が変わった」の通知。右列の幅は本文の座標ではなく view の配置の事実で、view の幅と行番号の列の桁で変わり、載せる側は大きさを変えたときと見えている範囲の知らせで読み直す——載せる側が面の上に浮かべる部品（検索バー）を置くためだけに使う、契約に面の pt が出る唯一の所。面は Esc（変換中でない）を使わず、responder chain の上へ渡す（載せる側が検索バーを閉じるのに使う）。ここでいう行は文書の行（`\n` だけで割る。CRLF の `\r` は行の中身で、単独の `\r`・U+2028・U+2029 は行を割らない。本文が改行で終わるときの末尾の空行を含む）。面の pt と行高は、右列の幅を除いて契約に出ない——契約を横切る値は本文のオフセットと行だけ。

**面を載せる側**は、面が本文の外のことを問う 1 つの口——ファイルを開く（本文へ落とされた）・ファイルのパスを本文に入れる文字列にする・右クリックのメニューを組む・⌘クリックされた URL を開く。開くこと・根・言語は載せる側の関心で、エンジンは知らない。口は契約（文書のモジュール）にある。エディター面の pane が焦点の文書の面に自分を置き（面は弱く持つ）、パスは根（ツリーの根）からの相対パス、根の外なら絶対パスで、複数は空白で区切る（VS Code と同じ）。メニューはカット・コピー・ペーストを Orbe の言語の文言で並べ、項目は焦点の面へ届く。

文書・本文の写し・言語・色付け・役割・裏の仕事は別モジュールで、エンジンも chrome のトークンも知らず、構文解析器の型もその公開面に出ない。構文解析器（tree-sitter）は、このモジュールが C API を直接呼ぶ——構文解析器・構文木・問い合わせの状態の所有と解放はこのモジュールの中に閉じる。このモジュールは Swift 6 の言語モードで検査する——main と裏の間で本文や結果を渡すところの取り違えや、複数の文書の裏の仕事が共有のもの（文法と queries の登録簿）を同時に書く誤りがコンパイルエラーで止まる。構文木は裏の仕事の中だけにあり、main からは触れない。アウトラインの規則とシンボルの名前の組み立て、取り出した結果の版と今の版の間の位置の写しもこのモジュールが持ち、Orbe には位置の無い面（名前・種類・木の形）だけを渡す。装備も俯瞰も検索も強調も見せ方も同じ境界に従う——「何を描くか」と「どこへ着くか」（ハンクからどの行が追加か、行の文字列からどの桁に線か・どの空白に点か・どこが URL か、ミニマップの字の列と配置と字形の表・スクロールバーのつまみ（縦横で同じ写像）と印の写像、一致の列と次／前、出現の規則、区間を見せる方針の着地の式）はその別モジュールの純関数で、どのスレッドからも呼べる。「どう描くか」（行の座標に写す・区間の矩形に地を敷く・俯瞰を描いて動かす）はエンジンが持つ。面は俯瞰のための入力の口を持たず、押された強調の地（検索の一致・現在の一致・語の出現）と行の印と自分のカーソルから俯瞰を描く——一致の地の和（ファイル内検索とプロジェクト検索）が面の口 1 つに押されれば、本文と俯瞰に同じく出る。契約の見え方には俯瞰の色・寸法・時間も入る。面を載せる側は面に本体全体を渡す。文書は構文の事実と行の印を写しと知らせで渡すだけで、描く範囲もキャッシュも知らない。`Sources` では、エンジンのモジュールの import はそのモジュールと合成点の外で、構文解析器の import は文書のモジュールの外で lint が落とす。Orbe 本体がエンジンと合成する場所は 1 か所（見え方をトークンから組む場所）。合成点は面を作れなければ何も返さず、セッションがそれを開けないエラーにする。

### 区間を見せる

面は区間を**方針つき**で見せる 1 操作を持つ。縦は方針で、横はどの方針でも区間が見えるところまで最小限に寄せる（区間が 1 行の中なら区間の両端、行をまたぐなら先頭）。方針は 4 つ（VS Code の `revealRange*` と同じ考え方）:

- **中央へ**——区間の先頭の行を見えている高さの中央へ（見えていても送る）。プロジェクト検索の結果・結果の列から開いた一致。
- **見えていなければ中央へ**——区間の先頭の行が縦に見えていなければ中央へ（上へ一部が隠れている行は外）、見えていれば最小限。ファイル内検索の一致。
- **見えていなければ上寄りに**——区間が見えている高さより高ければ先頭の行を上端へ、そうでなく縦に見えていなければ先頭の行を上から max(5 行, 高さの 20%) 下へ（区間の終わりが下へ押し出されない範囲で）、見えていれば動かさない。[アウトライン](outline.md)のシンボル。
- **最小限**——区間が縦に見えるところまで。区間が見えている高さより高ければ先頭の行を上端へ。

中央へ見せた後も、区間の終わりが下へはみ出せば終わりを下端へ、区間が見えている高さより高ければ先頭の行を上端へ置く。着地の式は文書のモジュールの純関数（今の先頭と見えている行の数と区間の行から、新しい先頭を出す）で、面はそれを自分の最新の位置——同じ周に置いてまだ描いていない位置を含む——で判定し、スクロールできる範囲に収める。同じ周に選択を置いてから見せても（検索の Enter）、その周の位置で判定する。見せた位置は、選択・強調の地と同じコマに出る（→ [出す 1 か所](#テキスト面metal)）。Orbe の側（ファイル内検索・プロジェクト検索・アウトライン）は方針を選んで渡すだけで、面の位置を読んで指示し返さない。

## テキスト面（Metal）

描画専用のスレッドが Metal で 1 コマを描くテキスト面。指で動かしたとき・打ったとき本文が遅れずに付いてくることと、main の他の仕事（端末・chrome）でコマが落ちないことのためにある。本文・構文色・行番号・git の印・行の装備・選択の地・強調の地・キャレット・変換中の文字と、俯瞰（ミニマップ・縦横のスクロールバーと印・影）を描き、打鍵・キー・IME・マウス・undo・クリップボード・ドラッグ＆ドロップ・サービスで編集する。振る舞いの基準は VS Code の既定——キーからコマンドへの割り当ては macOS 標準に従い、各コマンドの意味は VS Code の同じ役のコマンドに合わせる。日本語入力は macOS 標準（NSTextView）より悪い点が無いことを最低線にする。アクセシビリティは持たない。

**用意と開けないとき**: 描画スレッドとシェーダは、エディター面が初めて画面に見えたとき（窓に付き、隠れていない）に裏で用意する——Metal の装置を取り、描画スレッドを起こし、シェーダを実行時にコンパイルする（どれも main を待たせない）。最初のファイルを開く前に済み、端末だけを使う間は払わない（Metal の装置そのものは端末も使う）。見えていない面へ開いた（制御 API・再起動の復元）ときは面を作ることが用意を始め、描くのは済んでから（数十 ms。撮影は済むまで待つ）。Metal の装置が取れない環境（装置の無い仮想マシンなど）では面を作れないので、ファイルを開けない——読めないファイルと同じ扱いで、骨の操作は音で断り、制御 API の `open_file` はエラーで返し（→ [control/api](../control/api.md)）、面も文書も増えない。

**写しを描く**: 面は本文を持たず、契約の口で引いた文書の写しを描く。main がするのは、出来事をスクロールの状態の箱に書くことと、写し・行の印（受け取ったときに写しで行へ写す）・選択とキャレット・外観で解いた色・タブ幅・大きさと倍率を描く材料の箱に置くことだけで、組版も描画も描画スレッドが行う。main の面は写しを自分では持たず、要るときは箱から読む。面を閉じたら、写しの最後の解放は描画スレッドで行う。材料の箱の写しを新しい写しに置き換えたときは、前の写しを裏で手放す——文書が役割の並びを丸ごと差し替えた後は、箱が古い並びの最後の持ち主になりうる（どちらも大きな木の解放を main で行わない）。外部変更の差し替えは、丸ごとの置き換えを変わらない先頭と末尾を落とした 1 つの編集として、打鍵と同じ道で文書へ渡す（undo に載り、前後で区切る）。

**編集の道**: 本文を変える道は、面の編集係から文書への 1 本だけ——打鍵・IME の変換・削除・貼り付け・ドロップ・undo・redo・丸ごと置き換えのどれもここを通るので、undo の履歴と変換の状態を合わせれば本文のすべての変化を知っていて、undo が知らない本文の変化は起こりえない。中身を変えない編集（同じ字での上書き・大文字の語の大文字化）は文書へ渡さず、版・未保存の印・undo を進めない。入力の出来事 1 つ（打鍵・マウスの出来事・IME の呼び出し・コピーやペーストなどのメニューのコマンド・右クリック・ドラッグの出来事とドロップ）は 1 つの**取引**で、その中で届いたコマンドと IME の呼び出しは同じ取引に入る（セレクタが 2 つ届く ⌥↓・⌃O も、IME が「確定 → 次の未確定」を続けて呼ぶ打鍵も、途中の状態を描かない）。取引の間に文書から届く知らせ（行の印・役割）と、見え方・焦点・大きさの変化は控えるだけにし、終わりに確定した結果（写し・行の印・変わった行・カーソル・点滅の起点・打鍵の時刻・行の数の上限と見せ方の縦の位置）を面の**出す前の状態**に積む（→ 出す 1 か所）。横の「見えるところまで」は区間を材料に添え、行を組む描画スレッドがその版を描くコマで解いて横の位置を寄せる（main は打鍵のたびに行を組まない。↑↓の横位置・クリックの当たり・IME が問う未確定の外の文字の矩形と点の下の字だけ、同じ規則の口でその場で 1 行組む）。本文の通知と選択の通知は、この順で届く。編集の状態は VS Code と同じ形のカーソルの列（選択は「起点の範囲」と「動く端」の和で、伸ばしても起点の範囲は動かない）で、操作が作るのはいつも 1 本。契約の選択とキャレットは主のカーソルを表す。編集の規則は窓も描画の装置も持たない純粋な層にあり、語の規則は VS Code を動かした正解と突き合わせてある。

**出す 1 か所**: 面が描画スレッドへ出す道は 1 本——出す前の状態から、材料の次の版を先に決め、行の数の上限と置いた位置をその版を添えてスクロールの箱へ置き、材料の箱へ 1 回書き、描画スレッドを 1 回起こす。スクロールの箱は、版を置く直前の位置と範囲を「その版より前の材料に組む位置」として版ごとに残し、描画スレッドは引き取った材料の版に組む位置で描く。位置を先・材料を後のこの順と、この版ごとの組で、新しい本文に古いキャレットや古い位置が付いたコマ・束の半分だけのコマ・スクロールだけ先に動いたコマは出ない——描画スレッドが材料を引き取ってから位置を読むまでに次の版が出ても、引き取った版に組む位置で描く。出すきっかけは 2 つ。面自身の入力（キー・マウス・スクロール・IME の呼び出し・メニューのコマンド・ドラッグの出来事・俯瞰の操作）は、その処理の一番外側の終わりで出す——処理の中で面は選択・見えている範囲・本文の通知を同期に出し、Orbe の反応（現在の一致の地の差し替え・出現の消去・一致のずらし）も入れ子で返るので、処理の終わりには全部が揃っている（スクロールと打鍵の遅れは増えない）。Orbe から始まる呼び出し（検索バーの Enter による選択と見せ方・検索の結果の到着・一致の地の和・文書の知らせ）は、main の runloop の 1 周の終わり（待ちに入る前と runloop を抜けるとき。共通のモード——既定・イベントの追跡・モーダルのパネル）に出す——同じ周の呼び出しの並びは 1 回で出て、途中の状態（新しい選択に古い現在の一致の地、選んだ一致にまだスクロールしていない位置）を描くコマは無い。main の読み取り（見えている範囲・選択・位置・写し）は出す前の状態を当てた値を読むので、周の中で面を動かした直後に読んでも今の値が返る。指の出来事はその場で箱の物理へ当てて描画スレッドを起こし（当てた位置は当てた時点で描画スレッドから見えるので、処理の終わりまで待たない）、その前に置いてまだ出していない位置があれば先に出す。撮影は出す前の状態をその場で出してから撮る。

**キー**: 割り当ては macOS のキー割り当て（利用者の DefaultKeyBinding を含む）で、届いた標準のセレクタを VS Code の意味のコマンドへ写す。
- ←→・⌦ は書記素（Unicode の拡張書記素クラスタ。絵文字の ZWJ・国旗・肌の色、結合文字、タイ語の SARA AM、インド系の合字、CRLF を割らない）ごと。境は UAX #29 の拡張書記素に従うので、NSTextView と境が異なる文字体系がある（例: ←→ ではグルムキー・タミル・シンハラの合字、⌦ ではタイ語の SARA AM・デーヴァナーガリーの合字）。⌫ は macOS（NSTextView）と同じ後ろ向きの削除の単位——絵文字の並び・国旗・CRLF・分解した濁点やアクセント・ハングルの字母は書記素ごと、インド系・タイ・アラビア・ヘブライの記号は 1 つずつ。⌫ が字下げの空白の中なら前のタブ位置まで消す。⌃⌫ は前の字を分解して最後の結合文字だけを消す。行の区切りをまたいで消す削除（⌫・⌦・⌃⌫・⌥⌫・⌥⌦・⌘⌫・⌃K など）は `\r\n` を割らない。
- ↑↓は描いた位置（pt）で横位置を覚え、短い行を越えても元の位置へ戻る。先頭の行の ↑ は文書の先頭、最終行の ↓ は文書の末尾。選択を畳むときは ↑ は始まり・↓ は終わりから動く。
- ⌥←→ は VS Code の語の移動（前の語の始まり・次の語の終わり。1 字の区切りは飛ぶ）、⌥⌫・⌥⌦ は VS Code の語の削除（空白の並びの特例つき）。
- ⌘← は最初の非空白と 1 列目を行き来し、⌘→ は行末。⌃A・⌃E は 1 列目・行末（行き来しない）。⌘⌫ は行頭まで（1 列目なら前の改行、選択があれば選択の始まりの行頭から）。⌘↑↓ は文書の端、⌥↑↓ は段落（行）の端、⌥⇧↑↓ は段落ごとに伸ばす。⌃V・⌥PgUp などのページ送りは、見えている行数 − 2 行ぶんキャレットとスクロールを動かす。⌃L は主のキャレットの行を中央へ。
- Home・End・PgUp・PgDn はスクロールだけで、キャレットは動かない（End は最後の 1 画面）。
- ⌃K は行末まで（行末なら改行）を消してキルバッファへ入れ、続けた ⌃K は足す（キルバッファへ入れるコマンドが続いたときだけ。何もしなかったコマンドを挟めば入れ直す）。消すものが無い ⌃K はキルバッファを変えない。⌃Y で入れる。キルバッファはアプリ全体で 1 つ（エンジンが持つ）。⌃T はキャレットの前後の書記素を入れ替える（行末なら前の 2 つ）。大文字化・小文字化・先頭だけ大文字（DefaultKeyBinding で割り当てたとき）は選択か、キャレットに接する語に効き、語の外なら何もせず選択も元のまま。変えた後は変えた範囲を選ぶ。マークは面ごと。
- テンキーの Clear（`delete:`）は選択を消す（選択が無ければ何もしない）。⌃/（`insertRightToLeftSlash:`）は右から左の印（U+200F）と `/` を入れる。どちらもセレクタの意味が NSTextView と同じで、キーを押したときに NSTextView で起きることは入力ソースに依る。
- 補完（F5・⌥Esc）と書字方向の変更は何もしない。Esc は上の responder へ渡す（変換中に IME が使わなかった Esc は何もしない——検索バーを閉じない）。⌘A は全体を選ぶ。

**語**: 空白（space・tab）・VS Code の区切り文字・それ以外の 3 種類で、同じ種類の最長の並びが 1 語。日本語など CJK を含む字の並びの中では、OS の語の分割（ロケールは `ja` に固定）の境でも止まる（記号と空白の規則はそのまま）。ダブルクリックの語は、通常の字の語に触れていればその語（語の終わりでは左）、区切りの並びの内側ならその並び、どちらでもなければ前後の語の間の空白。長い行では、キャレットの前後の窓（端は書記素の境まで広げる）だけを見る。

**Tab と Enter**: Tab は選択が無いか 1 行の中なら、選択を次のタブ位置までの空白（桁は VS Code と同じ見た目の桁——書記素ごとに数え、全角と絵文字は 2 桁。文書がタブで字下げしていればタブ文字）に置き換え、行をまたぐか行全体を選んでいれば字下げする。⇧Tab は字下げを前のタブ位置へ戻す。⌥⇥ はタブ文字を入れる。Enter は文書の改行の作法（LF か CRLF）の改行を入れ、今の行の字下げ（キャレットより左の空白）を文書の作法に揃えて引き継ぐ。⌥↩・⌃↩ は字下げしない改行。言語の規則による字下げの増減・括弧の自動閉じ・自動の空白の掃除・括弧の中身のダブルクリック選択は持たない。

**undo**: 面ごとの undo の入れ物（Edit メニューの ⌘Z / ⌘⇧Z の有効・無効もこれを見る）に、まとまり 1 つを要素 1 つとして積む。まとめ方は VS Code と同じ——語と直前の空白 1 つがまとまり、空白が 2 つ続けばそこで切れる。Enter の前で切れ、Enter の後に続けて打った字は同じまとまり。⌫・⌦ はそれぞれ続けてまとまり、行を結合する削除で切れる。語の削除・行頭／行末までの削除・キル・ヤンク・入れ替え・大小文字・字下げ・丸ごと置き換えは前後で切れる。キャレットの移動・クリック・外から選択を置くこと（⌘F が一致を選ぶ）・保存・外部変更の差し替えも区切り。まとまりは 1 つの編集の束に合成し、undo・redo は束 1 つで文書へ渡す。undo は要素の前の選択を戻し、そこが見えるところまでその場でスクロールする。当てる前に、束の範囲が今の本文に収まり中身が記録と一致するかを確かめ、一致しなければ（あってはならない）本文に触れず、その面の undo を空にして OS のログへ残す。未保存の印は[開く・保存する](#開く保存する)の規則のまま（⌘Z で戻しても消えない）。

**マウス**: クリックの回数で単位が決まる——1 回でキャレット、2 回で語、3 回で行（改行まで）、4 回以上で全体。その後のドラッグと ⇧クリックは、最初に選んだ単位と起点の範囲を保って伸びる（語の単位なら語の端へ揃い、元の語は選択に残る）。4 回以上のクリックの全体はドラッグで縮まず、⌘A と同じく位置を動かさない。当たりは描いた字と同じ組版の行から Core Text の双方向の対応で引き（右から左の字の並びでも、押した字の見た目の位置に当たる）、行は固定の行高で並び推定が無い——遠くへ飛んだ直後でも、ポインタの下の行・字に当たる。最終行より下の空き地を押すとキャレットは末尾へ行く。ドラッグが本文の上下左右の外（左は行番号の列の上、右は面の右の外）へ出ると、行番号の列と同じ速さの式で自動スクロールし、ポインタを止めても選択が伸び続ける。外へ出たときに伸ばす先は VS Code と同じ——上は見えている上端の行の行頭、下は見えている下端の行のポインタの桁（最終行が見えればその行末）、左はポインタの行の行頭、右は行末。行番号の列と git の印の列、⌘クリックの URL は[行の装備](#行の装備)の規則のまま。俯瞰（ミニマップ・縦横のスクロールバー）の上の押下は[俯瞰](#俯瞰)の規則で、選択は動かない。選択の字の上の 1 回のクリック（⇧・⌘ なし。行末より右・最終行より下の空き地は選択の地の上でも新しい選択）は本文のドラッグの候補で、押した位置から 4pt を越えて動かせば文字のドラッグが始まり、越えずに離せばその位置にキャレットを置く（→ ドラッグ＆ドロップ）。右クリックと ⌃クリックはメニューを出す（→ サービス・右クリック）。変換中のマウスの出来事は、まず IME へ渡る。ポインタは行番号の列と俯瞰の上で矢印、本文で I ビーム、⌘を押して URL の上なら指（面に焦点があるとき）。

**IME**: 面は NSTextInputClient で、呼び出しの意味は NSTextView と同じ（範囲は文書の座標。置き換えの範囲が無いか、本文（未確定を含む）に収まらなければ、未確定を、未確定も無ければ選択を置き換える。未確定の文字の中の選択は文字列の先頭から。空の未確定は取り消し）。範囲を指した確定の後の選択は、置き換えが選択より前なら選択をずらし、後ろなら保ち、重なれば入れた文字の終わりのキャレット（変換中は IME の選択に当て、未確定の文字は確定として残る）。変換中の文字は打鍵と同じ 1 本の道で文書に入る——変換を始めた時点で未保存の印・git の印・ミニマップ・検索が追従し、描画・クリックの当たり・候補窓の位置は特別扱いなしに正しい。IME の呼び出しは 1 回ずつその場で編集の状態を更新し（IME が直後に読み返す値は本文と一致する）、打鍵 1 回で「確定 → 次の未確定」が来ても描くのは打鍵の後の 1 状態だけ。IME が選んでいる文節（未確定の中の選択）は変換の状態だけが持ち、契約の選択・選択の通知・検索の種・出現・ミニマップから見えるのは未確定の末尾のキャレット。
- **undo**: 変換中の変化は文書へ渡すだけで積まず、変換の終わり（確定・取り消し）に、変換前の本文との正味の変化を 1 回だけ記録する。確定済みの字を置き換えないもの（挿入と、変換を始めた選択の置き換え）は打鍵と同じまとまり（確定した字は前後の打鍵とまとまり、選択の上の変換は選択の上の打鍵と同じく後の打鍵とまとまる）で、確定済みの字を置き換えたもの（再変換・変換の外を指した置き換え——長押しのアクセントなど）は前後で区切る。IME 自身の取り消しで本文が元に戻れば何も載らず、打鍵のまとまりも切らない（後の打鍵は前の打鍵とまとまる）。取り消しても未保存の印は[開く・保存する](#開く保存する)の規則のまま残る。
- **入口**: IME 以外の入口——クリック・焦点の喪失・外からの選択・保存・コマンド・コピー・カット・ペースト・ドロップ・サービス・右クリック——は先に変換を確定してから動き、IME にも古い未確定を捨てさせる。丸ごと置き換え（外部変更）は変換を取り消してから置き換える。変換中の ⌘Z / ⌘⇧Z は、IME が使わなければ変換を取り消すだけで undo と redo の履歴に触れない（それより前に確定した字は残る。Edit メニューの取り消す・やり直すは変換中はいつも有効）。IME 以外の取り消し（⌘Z・⌘⇧Z・丸ごと置き換え）は変換が無かったことにする——再変換や選択の上の変換で置き換えた元の字も、カーソルと選択も変換の前へ戻る。IME 自身の取り消し（空の未確定）は NSTextView と同じく、未確定を消した本文のまま終える。入口が変換を終えるのは、入口の仕事と同じ 1 つの取引の中。窓が key でなくなるだけなら変換は続く。
- **見た目**: 本文と同じ 1 コマに描く。文節の属性が来たら、文節ごとに角の丸い下線を引く——IME が選んでいる文節（太い下線の文節）は本文の色、他は灰色で、太さは同じ、文節の境を少し空ける。属性の無い文字列は NSTextView の既定の未確定の地で塗る。IME が下線や地の色を指定すれば従う（透明な下線の色は指定なし）。指定の色も他の色と同じく描く色空間で解く（変換中に窓が別の色空間の画面へ移れば、IME が次に未確定の文字列を送るまで前の色空間の値のまま）。右から左の字を挟めば、選択の地と同じく見た目の区間ごとに引く。色は OS の文字入力の見た目で、見え方の契約には出さない。変換中のキャレットは IME の注目位置に出し（文節を選んでいる間は出さない）、主のキャレットは描かない。
- **候補窓**: 文字の矩形（スクリーン座標の 1 行目で切る）と点の下の字は、その場で答える——IME は呼び出しの直後に読み返すので、描画スレッドが最後に描いたコマの値では古い。点の下の字は点を含む字（字の上でなければ無い——行末より右・字の無い行・本文の外。NSTextView と同じ）。未確定の中は、未確定の先頭の x に未確定の文字列だけを組んだ x を足して答える（変換中は未確定より前の中身が変わらないので、先頭の x は変換の前の行から出し、行を組むのは変換ごとに 1 回——1 万字近い行の先頭で変換を始める 1 回だけ、その行を組む重さが乗る）。境目の字詰め・合字・右から左の字・タブの位置で描画とわずかにずれうるのは、候補窓の位置の用途として受け入れる。未確定の外は、↑↓・クリックと同じ「その場で 1 行組む」口で答える。変換中の取引と変換の終わり、変換中に本文が動いたとき（見せている位置が前に知らせた位置から動いた。横だけの動き——キャレットへの横の寄せ・横ホイール・横の弾性の戻り——も含む）に IME へ文字の座標の変化を知らせ、指のスクロールの始まりと終わりも知らせる（候補窓・音声入力の印が追従する）。変換の外の取引では知らせない（知らせると IME がその場で座標を読み返し、普通の打鍵の道で行を組むことになる）。

**クリップボード**（VS Code の既定）: ⌘C / ⌘X は選択を写す・切る。選択が空ならキャレットの行を改行込みで写し（改行の無い最終行は文書の改行を足す）、⌘X はその行を消す（最終行なら前の行の改行から）。行ごと写したときは Orbe の型の印も載せ、色の付く文書で、写したものが本文の 1 つの範囲（選択 1 つか、選択が空のときの 1 行）で 64KB 未満なら構文色付きの HTML（VS Code と同じ形——地の色・本文の色・フォント・行高・`white-space: pre`、役割ごとの span。文字コードの指定を添える）も載せる——メモやメールへ色付きで貼れる。⌘V は平文を貼り、改行を文書の作法へ揃える。行ごと写した文字列を選択なしで貼る（文字列の改行が末尾の 1 つだけ）と、キャレットの行の上に行として入り、キャレットは同じ字のまま 1 行下がる。Finder でコピーしたファイルなら、面を載せる側が決めたパスの文字列を入れる。RTF と HTML は読まない。貼ると前後で undo が区切れ、キャレットは末尾で、見えるところまでスクロールする。Edit メニューのコピー・カットはいつも有効、ペーストは平文かファイルがあるときだけ。複数のカーソルへの配り分けは持たない。

**ドラッグ＆ドロップ**: 本文のドラッグは AppKit のドラッグで、選択の字の上を押して 4pt を越えて動かせば始まる（時間の待ちは無い）。同じ面の中へ落とすと移動（⌥ でコピー）で、削除と挿入を 1 つの束・1 回の undo で渡し、落とした文字列を選ぶ。選択の中（端を含む）へ落とすと何もしない（⌥ で端ならその隣へコピー）。他の文書・他のアプリへはコピーで出し、他のアプリの文字も受ける（貼るときと同じ改行の揃え）。ドラッグ中は落とす位置にキャレットの色の点線の印（VS Code の印）を同じ 1 コマに出し、本文の上下の端から 1 行の帯の中では選択のドラッグと同じ速さの式で自動スクロールする（本文に重なる横スクロールバーの上でも送り、右列——ミニマップと縦スクロールバー——の上では送らない）。Finder のファイルは、本文へ落とすと面を載せる側が開き（フォルダは開かない）、⇧ を押して落とすと落とした位置にパスが入る。

**サービス・右クリック**: 選択の平文をサービスへ送り、返した平文で選択を置き換える（貼るのと同じく前後で区切る）。右クリックと ⌃クリックは、先に変換を確定し、選択の外で押せばキャレットをそこへ動かし（選択の中なら両端を含めて保つ）、面を載せる側が組むメニュー（カット・コピー・ペースト）を出す。サービスは AppKit が開くときに足す。Writing Tools はメニューに足させず、AutoFill の項目は取り除く。

**抑止**: 自動修正・スペル・文法・引用符とダッシュの置換・挿入の空白・テキストの置換・データとリンクの検出・補完・予測入力・数式の補完・Writing Tools は働かない（コードを書く面なので）。

**キャレットと選択の地**: 本文と同じ 1 コマに描く。選択の地は字の下に行の高さいっぱいの角なしの矩形で、改行を含む行は行の右端から半角 1 字ぶん伸びる。右から左の字を挟む選択は、見た目の区間ごとに分けて塗る（VS Code と同じ）。位置と x の対応は組んだ行の双方向の対応（Core Text）から引き、キャレットは位置の前の字の後ろの縁に描く。等幅のフォントで組んだ ASCII の字とタブだけの行は、対応をグリフの位置から作る（字の縁がグリフの位置と送りに一致し、Core Text と同じ答えになる。1 万字の行でも Core Text に縁を数えさせない）。色は選択の地の色で、焦点が無ければ焦点の無い面の選択の色。キャレットは面に焦点がある（first responder で、窓が key）間だけ描き、500ms ごとに点滅し、動くたびに表示から始まる（スクロールだけでは始め直さない）。アクセシビリティの「点滅しない挿入ポイント」（macOS 15 以降）が有効なら点滅しない。macOS 14 の標準キャレットの部品（音声入力や Caps Lock の印を出すもの）は使わない——部品は main の Core Animation で動き、本文のコマと最大 1 コマずれる。

**1 コマ**: 描画スレッドはプロセスに 1 本で、面ごとに view の display link をそのスレッドに載せる。描画スレッドは最初のコマから時間制約つき（Mach の time constraint）のスレッドで、結ばれた面の最も短い表示の刻みを周期に、「刻みごとに 2ms の計算を、起きてから刻み − 1ms 以内に」と申告する（刻みが変われば申告し直す）——機械が混んでいても、普通の優先度の仕事に待たされて遅れて起きない。どのコアに載るかは OS が決め、コマの多くは効率コアで動く（申告の計算の量や優先度では変わらない）。面の view は本体全体を覆い、区画の配置（行番号の列｜本文の区画｜ミニマップ｜縦スクロールバー、本文の区画の下端に横スクロールバー）は 1 つの規則で決まる——ミニマップの幅は VS Code の式に面の実の行番号の列の幅を入れて出し、当たり・ドラッグの自動スクロールの境・見せるところまで・見えている範囲・IME の文字の矩形・本文の切り取りはどれもこの配置を使う。コマの中身は下から、本文の区画で、行の装備 → 選択の地・未確定の文字の地 → 強調の地（下から、現在の一致の行全体 →〔一致が千件を超えるとき検索の一致〕→ 選択文字列の出現 → 語の出現 →〔検索の一致〕→ 現在の一致）→ 本文の字と長い行の末尾の印 → 色付きの字、行番号の列で行番号 → git の印、本文の区画で未確定の文字の下線・キャレット・落とす位置の印、その上に上端の影（行番号の列から本文の区画の右端まで）→ ミニマップの左の影、ミニマップ（字 → 装飾 → 帯）、縦スクロールバー（印 → 縁 → つまみ）、横スクロールバー（つまみ）で、地は描かず下の veil を透かす。行は `y = 上端の余白 + 行 × 行高` に並び折り返さない。見えている行だけその場で組版して覚え（前のコマで描いた行は写しの版と行で引き直し、本文の編集では変わった行だけを捨てて後ろをずらす。行の中身でも覚え、同じ中身の行は組み直さない。色は覚えず、描くときに役割から引く——役割が届いても組み直さない）、字の色は行ごとに、横に見えている字の区間の役割だけを役割の並びから引く（長い行でも行全体の役割は引かない）。描くものが変わらないコマが続いたら、また面が窓に無い・隠れている・窓が覆われているときは刻みを止める。止まっている間、焦点の無い面は描画スレッドを起こさず、焦点のある面は、点滅が切り替わってから最初の刻みの半刻み前にだけ起き、その場でその刻みへ描いてすぐ止める（点滅 1 回で 1 回だけ起きる。点滅しない設定なら起きない）。止めていた面に描くもの（点滅の切り替わりを含む）が来たら、次に画面に出る刻みまでに描き終えられる限り（残りが 2ms を越えれば）、刻みを待たずにその場で 1 コマ描いてから刻みに戻る（止まっていた面の最初の変化が、次の刻みまでの待ちのぶん遅れない）。描画スレッドは main を待たず、どの面のためにも待たない——面ごとに画面に出ていないコマと GPU の空きを数え、上限なら待たずにそのコマを飛ばし、画面に出た知らせを受けた時点で次の刻みを待たずに描く（ある面の詰まりが他の面を止めない）。位置は描く直前に、そのコマが画面に出る予定の時刻で読む。俯瞰は同じコマの同じ位置から描くので、本文とずれない。帯とつまみのフェードの間だけ刻みを回し、見えている面はつまみが消え始める時刻にだけ起き、消え終われば起きない（隠れた面はその時刻にも起きない）。

**俯瞰の描き方**: ミニマップの字は GPU で描く——64 行ずつのまとまりごとに、行の頭（描ける桁ぶんだけ。長い行でも残りは読まない）と「桁・行・字形・役割」の列を覚え、字形の表（本文フォントから作る）と役割の色の表を引いて描く（色を覚えないので外観が変わっても作り直さない）。装飾の区間の行と x も覚えた行の頭から引く（前の行の編集で位置がずれたまとまりは、今の本文のまとまりの頭へずらして読む）。ミニマップが動いている間は、コマを出した後に、動く向きの先のまとまりを作っておく——次のコマに間に合わなければそのコマで作るので、字が抜けたり古い字が出たりはしない。本文の編集と役割の変化は届いた順に 1 本の列で当て、変わった行のまとまり（行の数が増減した編集ではその後ろ全部）だけを捨てる。装飾は画面外の 1 枚に描いてから組として不透明度 .9 で重ね、字は 8bit の乗算済みの絵にしてから不透明度を掛ける段で丸める。スクロールバーの印は、検索の一致と語の出現を行へ写した結果を覚え、本文の編集ではずらして使い回す——打鍵のたびに一致がずらして押し直されても写し直さず、写し直すのは区間の列が本当に変わったとき（検索語を変えた）だけ。印の図形は元（行・行の数・高さ・倍率）が変わったときだけ作り直す。装備の素（空白の並び・URL の区間）は組版と一緒に覚える。強調の地と装備は長い行でも横に見えている字の区間に掛かるものだけを描く。ミニマップの押下と帯のドラッグの起点は最後に描いた配置で解き（配置は揺れ止めの前回の配置に依る）、縦横のつまみとトラックは今の状態で解く。帯とつまみの濃さは、main が書くポインタとドラッグの状態と、描画スレッドのコマの時刻から出す。

**字**: Core Text でグリフをラスタライズしてアトラスに置き、Core Text の描き方を再現する——横の少数ピクセル位置は Core Text の量子化と同じ（2x で 1/2px、1x で 1/3px）、色付きの字（絵文字）は別の頁で、Core Text と同じく少数位置に置かず絵の左端を画素に丸める。代替フォントは組版に出たフォントのまま、結合文字の記号は組版の高さに置く。字の太らせ（macOS の font smoothing 相当）は、字の色と倍率ごとに Core Graphics が選ぶ段を実測で合わせる（段の分け方は明るさの単純な丸めと一致せず、1x は 2x より段が 1 つ多い）。1x でも 2x でも、同じ行を Core Text で同じ色空間の不透明な地に描いたものと、字のある画素で sRGB では 1 段（8bit）以内、Display P3 では 2 段以内（太らせの縁は段ごとのマスクで近似するので、色の値によって縁の 1 画素が 2 段になる）に収まる（字どうしのインクが重なる形——アラビア語のつながりなど——の重なる画素を除く）。色は面が載る窓の色空間（AppKit が窓の view を描く色空間。既定は窓が載る画面の色空間）で描く——字の色をその色空間で解き、字の縁はその色空間の値のまま（線形にせず、Core Graphics と同じく）合成し、絵文字もその色空間で描き、層はその色空間の中身として画面に出す。別の色空間で描いて画面の合成で色を合わせると、透ける字の縁と絵文字の色が AppKit の描く字とずれるため。窓が別の色空間の画面へ移れば解き直して描き直す。窓に無いとき（画面外の計測）は sRGB で描く。撮影の絵も描いた色空間のまま返す。

**行の見せ方**（VS Code の既定と同じ）: 行は `\n` だけで割り、行末の `\r` は描かない。タブはインデント単位の桁まで空ける。C0 の制御文字は U+2400 台の記号、DEL は U+2421、U+2028・U+2029・U+0085・U+FEFF は U+FFFD で見せる。方向を変える書式文字（U+202A〜202E・U+2066〜2069・U+200E・U+200F・U+061C）は `[U+202E]` の形の箱で見せ、字の並びを変えない（見た目の順と実際の字の順が食い違わない）——箱はタブと同じく 1 字のまま何桁かの幅を持ち、字の位置は元の行の位置のまま。行は常に左から右の段落として並べる（右から左の字で始まる行でも、行頭の字が左端に来る）。1 行で描くのは 10000 字（UTF-16 の単位。書記素の境で切る）までで、超えた分は描かず、行末に「ほか N 字」（1 万以上は「1.2万」のように略し、丸めて次の単位に届けば「1億」のように次の単位で出す）を出す——minified の 1 行 1MB のような行でも、1 コマの手間は 10000 字を越えた分には依らない。押して展開する操作は持たない。行は塊に分けずに組むので、初めて見える行を組む手間はその行の長さ（10000 字まで）に比例する——10000 字近い行が並ぶ文書では、1 画面ぶん遠くへ飛んだコマが数十 ms 級止まりうる（その間は描画スレッドの全部の面のコマが遅れる）。

**スクロール**: トラックパッドの出来事の量はその場で位置に足し、次のコマに入る（補間・予測はしない）。はじいた後の慣性は OS の momentum の出来事をそのまま同じ経路で当て、自前の慣性は持たない。動く軸は主な軸だけ（120ms で減衰する縦横の量の累積で決め、縦に動かしている間に横へ流れない）。端を越えた量は 1/20 に縮めて見せ（端の弾性）、端の外で指を離すと端へ戻る。OS の momentum が端を越えたら、その時点の速さのまま少し伸びてから戻り始め、残りの momentum は次に指が触れるまで捨てる（はじいて端に当てても、momentum が尽きるまで端の外に留まらない。WebKit・AppKit と同じ形で、戻りの曲線も AppKit と同じ式）。戻りの途中に指が触れたらそこで止まる。縦は最終行が最上段に来るまで、横は見たことのある最も長い行の右端から 5 桁先まで送れる（最も長い行は組版した行から伸びるだけで、伸びたら main へ知らせる。本文を丸ごと置き換えたら、新しい本文を描いたコマで測り直し、それまで横の位置は保つ。右の先の長い行は、見るまで範囲に入らない）。マウスのホイールの 1 目盛りは NSScrollView の行送りと同じ 10pt で、その場で当てる。ミニマップ・スクロールバーの操作と[区間を見せる](#区間を見せる)操作はその場で位置を置き（アニメーションしない）、端への戻りを打ち切る。横の「見えるところまで」は、行を組む描画スレッドが次のコマで解いて寄せる。本文が縮んで範囲を越えたら範囲に収める。見えている範囲（先頭に見えている行と行の数。端を越えて見せている分は端で数える）は、main で位置を変えたときにその場で出し直し、変わったときだけ通知する。描画スレッドだけが進める動き（端への戻り・横の寄せ・横の範囲の伸び）は見えている範囲を変えず、コマごとに main へ知らせて変換中の IME に座標の変化を伝える（→ 候補窓）。指が触れている間と OS の慣性の間の出来事は main に届くので、main が詰まればその分だけ遅れる。

**記録**: 面は各コマの描画の CPU 時間・画面に出た時刻（present）・そのコマに初めて入った指の出来事と打鍵の時刻・drawable の大きさの食い違いを取り、ジェスチャーごとに要約（出来事→present の中央値・p95・最大、描いたコマの数、落ちたコマの数と時間の割合、大きさの食い違ったコマの数）を 1 行、OS のログ（カテゴリ `editor-frames`）へ出す。落ちたコマは、ジェスチャーの間に描いたコマ（描くものが変わった刻みのコマ全部。1 画素未満の動きも含む）の続く 2 つの present の間隔が 1.5 刻みを越えたもの。描くものが変わらない刻み（指を止めていた間・刻みを止めていた間）を挟んだ間隔は数えない——ただし次のコマに、その刻みより前の指の出来事が入っていれば（main が詰まって出来事が遅れた）数える。割合は落ちた時間の合計を、数えた間隔の合計で割る。打鍵は、出来事の時刻を取引が本文と同じ書き込みで材料の箱へ添え（移動の打鍵も数える）、その打鍵が入ったコマが画面に出た時刻までを打鍵→present とし、打鍵の塊（間が 1 秒空けば区切る）ごとに中央値・p95・最大を 1 行出す。

**撮影**: gallery・flow の撮影（`cacheDisplay`）では、面が同じ 1 コマを描画スレッドで画面の外に描き、その完了を待って返す（AppKit の view と同じ撮り方）。画面の合成でだけ起きること（drawable の大きさのずれ）は撮影には出ないので、記録の食い違いの数で見る。

## 入口

人がファイルを開く入口は[面の骨](shell.md)のエクスプローラー（ツリーのクリック・新規作成）と、Finder からエディター面（本文・ツリー・タブ行・空状態）へのファイルのドロップ（フォルダは開かない。本文へ ⇧ を押して落とすとパスが入る）、エージェントの入口は制御 API の `open_file`（→ [control/api](../control/api.md)）。`open_file` は開けたらエディター面が見える配置にして（隠れていれば全面、分割中は焦点だけ）、そのタブを選び、テキスト面へフォーカスする。どちらもツリーがその文書の祖先を開いて選択表示する。
