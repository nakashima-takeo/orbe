# コード

エディター面の中身。ファイルを開き、色を付けて描き、編集して保存する——端末の隣で、別のアプリへ行かずにコードを直すための場所。面の骨（レール・ツリー・ファイルタブ・パンくず）はまだ無く、焦点の文書が無ければ[面の機構](faces.md)の空状態、あればその文書のコードビューが面いっぱいに出る。

## 文書とテキスト面

タブ 1 枚が**セッション**——開いた文書の列と焦点の文書——を持つ。**文書**は開いたファイル 1 つで、識別（URL）・言語・未保存の有無を持ち、本文の正はその文書と対になる**テキスト面**（文字を描き編集を受ける面）にある。文書 1 つにテキスト面 1 つを、開いてから閉じるまで対で持つ。切り替えは「どの文書の面を見せるか」を変えるだけなので、undo・選択・スクロール位置・変換中の IME は文書ごとに残り、戻ればそのまま続きが打てる。

同じファイルをもう一度開いても文書は増えず、焦点がそこへ移るだけ。文書の列・焦点・未保存の有無が変わると、タブは 1 本の通知で上位へ上げる（chrome の更新はそこから）。

## 開く・保存する

ファイルは UTF-8 として読む。読めない・UTF-8 として解けないファイルは開けず、呼び手にエラーで返る（面は変わらない）。文法の無いファイル（`.txt` 等）は色無しで開ける。

⌘S は焦点の文書をそのファイルへ書く。書くのは面の本文そのもので、改行の種類も末尾の改行も本文のまま（勝手に足さない・直さない）。書いた時点で未保存は消える。未保存は「最後に開いた／保存した内容と本文が違うか」ではなく「保存の後に編集があったか」——⌘Z で保存時の状態に戻しても未保存のまま。保存は undo の区切りでもある——続けて打った文字はまとめて戻るが、保存をまたいでは戻らない（打つ → ⌘S → 打つ → ⌘Z は保存の後の打鍵だけを戻す）。

未保存のままタブを閉じると黙って捨てる。再起動で文書は戻らない。保存に失敗しても面には出ない（ログだけ）。大きなファイルに上限は無い。

## 色付け

言語は拡張子（と `Dockerfile` のようなファイル名）から決まる。対応は Swift / Markdown / JSON / TypeScript / JavaScript / TSX / CSS / HTML / Python / Go / Rust / YAML / TOML / Bash / Dockerfile の 15 で、色は tree-sitter の構文木から付ける。中に別の言語が埋まる箇所（HTML の script / style、Markdown の inline とコードブロック）はその言語の色で塗る。

色は 8 つの**役割**（keyword / 制御の keyword / type / function / string / comment / variable / punctuation）に付き、役割を持たない文字（数値・定数・マークアップの強調など）は素の文字色で描く。文法ごとに揺れる capture 名は 1 枚の正規化表で役割へ写す——見本の 8 色を超えて色を増やさない。

色付けは編集に追従する。打鍵のたびに構文木を差分で更新し、変わった範囲だけ塗り直す。色は描画のための属性で本文に載らないので、undo 履歴にも保存する内容にも混ざらない。外観（dark / light）の切替は描画時に解け、塗り直しを要しない。

色付けの規則（queries）は `.app` に同梱する。同梱が無い・読めない・言語が無いときは色無しで開け、失敗として扱わない。

## 見え方

見本「コード本体」の値を持つ（→ [design-system](../../design/design-system.md) §5「Code view」）。行番号のガター（右寄せ）・固定の行高・上端の余白・キャレットの色と寸法・役割ごとの色はトークンで、フォントの決め方は 1 か所に閉じる（設定が入るときはそこだけが読み、開いている面へ配り直す）。地は chrome と同じ veil で、背景透過の設定に追従する。テキスト選択の地はシステムの選択色（テキストエンジンに差し替え口が無い）。

## キー

エディター焦点中の chrome キーは面が先取りする。分類は[レイアウト](../chrome/layout.md)の「chrome キーの分類」——window コマンドはタブ経由で上位へ、⌘S は保存、端末のキー（⌘F・フォント）は何も起こさず端末にも届かず、⌘↑↓ はテキスト面の文書先頭／末尾へ。それ以外の打鍵はテキスト面へ届く（日本語 IME を含む）。⌘Z / ⌘⇧Z / ⌘X / ⌘C / ⌘V / ⌘A は Edit メニューの key equivalent が responder chain でテキスト面へ届く。⌘Z は続けて打った文字をまとめて戻す。

端末焦点の ⌘S は従来どおり端末へ届く（Orbe は束縛しない）。

## 焦点

焦点の文書があるとき、エディター面の焦点 view はそのテキスト面（無ければ面自身）。タブ切替・パレット閉・⌘R 確定・制御 API でエディター面へ戻るフォーカスはここへ来る。テキスト面をクリックしてフォーカスを取ると、面の記憶がエディターへ移る（→ [faces](faces.md)）。文書を開いた・切り替えた瞬間に焦点が面の中にあれば、新しいテキスト面へ移す。

## テキストエンジンの境界

テキストエンジン（TextKit 2 の自前ビュー）は 1 モジュールに閉じ、公開は「面を作る 1 関数」だけ。文書・行索引・言語・色付け・役割は別モジュールで、エンジンも chrome のトークンも知らない。Orbe 本体がエンジンと合成する場所は 1 か所（見え方をトークンから組む場所）に限り、lint がそれ以外での import を落とす。エンジンの移行はそのモジュールの差し替えで済む。

## 入口

人とエージェントがファイルを開く入口は制御 API の `open_file`（→ [control/api](../control/api.md)）。開けたらエディター面が見える配置にして（隠れていれば全面、分割中は焦点だけ）、そのタブを選び、テキスト面へフォーカスする。面の骨からの入口（ツリー・ファイルタブ）は後続。
