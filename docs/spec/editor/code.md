# コード

エディター面の文書。ファイルを開き、色を付けて描き、編集して保存する——端末の隣で、別のアプリへ行かずにコードを直すための場所。焦点の文書のコードビューは[面の骨](shell.md)の本体に出て、文書が無ければそこに[面の機構](faces.md)の空状態が出る。

## 文書とテキスト面

タブ 1 枚が**セッション**——開いた文書の列と焦点の文書——を持つ。**文書**は開いたファイル 1 つで、識別（URL）・言語・未保存の有無を持ち、本文の正はその文書と対になる**テキスト面**（文字を描き編集を受ける面）にある。文書 1 つにテキスト面 1 つを、開いてから閉じるまで対で持つ。切り替えは「どの文書の面を見せるか」を変えるだけなので、undo・選択・スクロール位置・変換中の IME は文書ごとに残り、戻ればそのまま続きが打てる。

文書の識別は symlink を解いた実体のパスで、同じファイルをもう一度開いても（別の綴り・リンク経由でも）文書は増えず、焦点がそこへ移るだけ。文書の列・焦点・未保存の有無・「ディスクが変わった」の有無が変わると、タブは 1 本の通知で上位へ上げる。

文書は開いてから閉じるまで、自分の実体が属する根のサービスと結ばれる（→ [files](files.md)）。外で書き換えられたファイルの反映と、index の版（baseline）はそこから届く。

## 開く・保存する

ファイルは UTF-8 として読む。読めない・UTF-8 として解けないファイルは開けず、呼び手にエラーで返る（面は変わらない）。文法の無いファイル（`.txt` 等）は色無しで開ける。

⌘S は焦点の文書をそのファイル（symlink なら実体）へ書く。リンク自体は置き換えない。書くのは面の本文そのもので、改行の種類も末尾の改行も本文のまま（勝手に足さない・直さない）。先頭の UTF-8 BOM は本文に含めず、最後に読んだ／書いたときの有無を保存で保つ（あれば付け直し、無ければ足さない。外の内容に差し替えたときはその有無に倣う）。書いた時点で未保存は消える。未保存は「最後に開いた／保存した内容と本文が違うか」ではなく「保存の後に編集があったか」——⌘Z で保存時の状態に戻しても未保存のまま。保存は undo の区切りでもある——続けて打った文字はまとめて戻るが、保存をまたいでは戻らない（打つ → ⌘S → 打つ → ⌘Z は保存の後の打鍵だけを戻す）。

⌘S の直前にディスクを読み直し、監視が届いたときと同じ照合をする——印が立たなければ（未編集の文書は外の内容に差し替えてから）書き、印が立てば保存は失敗してディスクに触れない。外のツール（エージェント）の編集を黙って潰さないため。この失敗は force の保存だけが越え、その入口は印の立った文書の ⌘S が出す上書きの確認（→ [shell](shell.md)）。外部変更の照合と印の規則は [files](files.md)。

未保存の文書を捨てる人の操作（ファイルタブの ×・タブを閉じる・終了）は確認を挟み、シェル終了・制御 API は黙って捨てる（→ [shell](shell.md)）。開いていた文書は再起動で戻るが未保存の内容は戻らない（→ [persistence](../platform/persistence.md)）。外部変更以外の保存の失敗は面には出ない（ログだけ）。大きなファイルに上限は無い。

## ハンク

文書は baseline（比べる底の本文。無ければハンクは空）と、baseline と本文の行差分——追加・変更・削除の行区間——を持つ。区間は unified diff の `@@ -a,b +c,d @@` と同じ形で、片側が 0 件の区間はその直前の行を指す。行は `\n` で割り、`\r` は行の中身に残す（CRLF と LF は正規化しない）。末尾の改行の有無も最後の行の違いとして数える。

baseline を置いた瞬間は即時に、編集は runloop 1 回に間引いて作り直す——1 打鍵ごとにサブプロセスは起きず、差分は本文と baseline だけで取る。共通の先頭・末尾を落とした残りが大きすぎる入れ替え（両側の和で 1000 行超）は、残り全体を 1 つの変更区間にして時間を有界にする。

## 色付け

言語は拡張子（と `Dockerfile` のようなファイル名）から決まる。対応は Swift / Markdown / JSON / TypeScript / JavaScript / TSX / CSS / HTML / Python / Go / Rust / YAML / TOML / Bash / Dockerfile の 15 で、色は tree-sitter の構文木から付ける。中に別の言語が埋まる箇所（HTML の script / style、Markdown の inline とコードブロック）はその言語の色で塗る。

色は 8 つの**役割**（keyword / 制御の keyword / type / function / string / comment / variable / punctuation）に付き、役割を持たない文字（数値・定数・マークアップの強調など）は素の文字色で描く。文法ごとに揺れる capture 名は 1 枚の正規化表で役割へ写す——見本の 8 色を超えて色を増やさない。

色付けは編集に追従する。打鍵のたびに構文木を差分で更新し、変わった範囲と今見えている範囲を塗り直す（隣の字の変化で役割が変わる字を画面に残さない）。見えていない範囲は次に見えたときに塗る。色は描画のための属性で本文に載らないので、undo 履歴にも保存する内容にも混ざらない。外観（dark / light）の切替は描画時に解け、塗り直しを要しない。

色付けの規則（queries）は `.app` に同梱する。同梱が無い・読めない・言語が無いときは色無しで開け、失敗として扱わない。

## 行の装備

文書の行には、本文の字とは別の**装備**が付く——行番号の右の git ガター、本文に重なるインデント線・空白の丸点・URL の下線。どれも本文と undo に載らない描画で、選択の地は装備を覆う（選択中の行の点や線は見えない）。

**git ガター**は文書のハンク（→ 上）を行の印に写す。index 版に対して追加された行にはバー、変更された行には別の色のバー、削除があった境（消えた行があった場所の上下の行の間）には三角が出る。色と形は [design-system](../../design/design-system.md) §5。baseline が無い文書（index に無い・非 git・競合中）はガターが空。印は編集に追従する——打鍵で作り直したハンクが同じ描画に載り、同じ行の中を打っても区間が本文に付いてくる。端末で `git add` / `git checkout` すれば index に追従して消える／変わる。baseline は index の版を作業ツリーに出したときの中身なので（→ [files](files.md)）、`eol=crlf` や smudge filter のあるリポジトリでも `git status` が clean と言うファイルはガターが空。

**インデント線**は行頭の空白の段ごとに 1 本立つ。単位（1 段のスペース数）は文書ごとに本文から検出する——隣り合う非空行の行頭スペース数の差のうち 2 / 4 / 8 に当たるものの最頻値、同数なら小さい方、候補が無ければ 4。行頭がタブの行は差の計算に入れない。段の数え方はタブが 1 段（次の段の境まで）、スペースは単位ごとに 1 段で、端数は段にならない。段の線は「その段ぶんの空白の直後の文字」の左端に立つ。空白だけの行は前後の非空行の浅い方の段まで線が続く（片側が無ければ 0）。タブ行を挟むと、その前後の非空行は差の対にならない。単位は開いたとき、および本文を丸ごと置き換えたときに検出し直す。**タブの表示幅は検出した単位**——タブを 1 段と数えるモデルと描画を一致させ、空白だけの行の線がタブで書かれた隣の行の線と揃う。

**空白の丸点**は、行頭の連続スペース・行末の連続スペース・中間の 2 個以上の連続スペースに、セルごとに 1 つ出る。対象は半角スペース（U+0020）だけで、タブ・NBSP・改行には何も出ない。単語間の 1 個のスペースには出ない。

**URL** は `http://` / `https://` で始まり、空白・`<` `>` `"` `` ` `` の手前までを 1 つとし、末尾の句読点（`.` `,` `;` `:` `!` `?` `'`）と、その中に対応する開き括弧が無い末尾の `)` `]` `}` は含めない。行をまたがない。URL には文字と同じ色の下線が付き、**⌘クリック**で既定のブラウザに開く（素のクリックは通常どおりキャレットを置く——URL の文字列にキャレットを置けなくしないため）。開くのは**離したとき**——押した URL の上で離せば開き、押したまま動かして離せば何もしない（その間は選択も伸びない）。⌘に ⇧・⌥・⌃ が重なるクリックは URL でも開かず、通常の選択操作になる。⌘を押している間だけ、その上で指カーソルになる（テキスト面が焦点のとき）。URL の行き先を決めるのはエンジンではなく Orbe 本体で、面を組む場所が「既定ブラウザで開く」を渡す。

## 俯瞰

本体の右端に、左から**ミニマップ**と**縦スクロールバー**が立つ。見えている行の外に何があるか（文書のどこにいるか・どこに変更や一致があるか・キャレットがどこか）を本文をスクロールせずに示し、そこから本文を動かすためのもの。使い勝手の基準は VS Code の既定で、配置・帯とつまみの動き・印の写像は VS Code と同じ式で決まる（行の単位で持つので、面の pt やエンジンの推定の文書高に依らない）。

**最終行の先までスクロールできる**——最終行（本文が改行で終わるなら末尾の空行）を画面の最上段まで送れる。そのとき最終行より下は空き地で、そこを押すとキャレットは文書の末尾へ行く（そのままドラッグすれば選択が伸びる。ポインタは本文の上と同じ I ビーム）。End は最終行を下端に出す位置へ送る（最後の 1 画面が見える）。スクロールバーとミニマップの位置の計算も、この送れる範囲を含む。

**ミニマップ**は文書の縮図で、1 行を細い 1 段、1 字を 1 桁に縮め、字の形を構文の色で描く（役割の無い字は素の文字色）。空白は描かずに 1 桁進み、タブは次のタブ位置まで空け、全角は 2 桁。幅は本文の幅から決まり（本文の桁とミニマップの桁が釣り合う幅に上限を置く）、列が狭ければ細くなる。幅に入らない桁は描かない。縮図は本文と色付けの変化に追従する。git の追加・変更・削除の印が左端に、検索の一致と語の出現がその範囲と行の薄い地で、選択が選択の色で重なる。

文書がミニマップに収まらなければ、ミニマップはスクロールに合わせてスライドする（先頭で上端、最終行を最上段へ送れば末尾が見える）。見えている範囲を示す**帯**は普段は隠れ、ミニマップの上にポインタがあるときに現れる（帯の上とドラッグ中は濃くなる）。帯を掴んでドラッグすると本文がすぐに追従し、帯の外を押すとその行が本文の中央に来る（横位置は動かさない）。

**スクロールバー**のつまみの長さは見えている割合で決まり（掴めるよう最小の長さがある）、掴んでドラッグできる。トラックを押すとつまみの中央がそこへ来るよう飛び、押したままドラッグを続けられる。つまみは本体の上にポインタがある間とドラッグ中に見え、スクロールすると現れて、止まってしばらくすると消える。

スクロールバーの上には**印**が常に出る——左に git の追加・変更・削除、中央に検索の一致と語の出現、全幅にキャレットの行。位置はスクロール全体に対する比例で、短いものは最小の高さに広げ、接するものは 1 つに繋がる。つまみは印の上に半透明で重なる。色はガター・強調と同じ意味の色（→ [design-system](../../design/design-system.md) §5）。

先頭の行が上へ隠れている間は本文の上端に影が、本文が右にまだ続くときはミニマップの左端に影が出る。どちらも本文の上だけに描く。

俯瞰の上のホイール・トラックパッドは、本文の上と同じように本文をスクロールする。本文の縦スクロールバーは OS のものを出さない（位置はこのスクロールバーが担う）。横スクローラーは OS のもので、表示の様式はオーバーレイに固定する——OS の「スクロールバーを常に表示」やマウスの有無で本文の下が削られない。

俯瞰は焦点の文書 1 つに結ばれ、文書を切り替えれば結び直す。文書が無ければ無い。

## ファイル内検索

エディター焦点中の ⌘F は焦点の文書の中を探す。バーは[スクロールバック検索](../terminal/search.md)と同じ部品——同じ見た目・同じキー（Enter で次・⇧Enter で前・Esc で閉じる）・同じ件数表示（selected/total、位置が無ければ ?/total、一致なしは danger）——で、本文の右上（ミニマップの左）に浮く。文書が無ければ ⌘F は何も起こさない。表示中の ⌘F は入力欄への再フォーカスだけで、バーを二重に出さない。

⌘F を押したとき、1 行以内の非空の選択があればそれが、選択が空ならキャレットの語（→ 出現の強調の「語」）が needle に入って即検索される（VS Code の既定と同じ）。

一致はリテラル・大小無視・重ならない。打つたびに一致を取り直し、全一致に地が敷かれ、選択の先頭以降で最初の一致（無ければ先頭へ循環）が選択される。**現在の一致**は状態として持たず、常に選択から導く——選択がちょうど一致のどれかならそれで、そうでなければ無い（本文をクリック・打鍵して選択が一致から外れれば、現在の一致の地は消え、件数の位置は「?」になる。VS Code と同じ）。Enter は、選択が一致そのものならその次へ、そうでなければ選択の先頭以降で最初の一致へ。⇧Enter はその前へ（両端で循環）。選んだ一致の行が縦に見えていなければ、その行を本文の中央に見せる。縦に見えていれば最小限のスクロールで見せる（横に隠れていれば横だけ寄り、見えていれば動かない）。

現在の一致は、選択の地の上に全一致と違う不透明の地で見分けられ（選択の色は見えなくなる）、その行全体にも薄い地が付く。一致は俯瞰にも出る——ミニマップに範囲と行の薄い地、スクロールバーの中央に印。一致を集めるのは上限までで、上限に届けば件数は「上限+」と出す。一致が多いとき（千件を超える）はミニマップには現在の一致だけが出て、スクロールバーは近い行をまとめた印になる（全部を描いて固まらないため）。

バーを開いたまま本文を編集すると、一致と件数は少し遅れて追従し（打鍵のたびに文書全体を探さない）、その間の地は編集に合わせてずれて字から離れない。選択は動かさない（打ち込みを乱さない）。文書を切り替えると同じ needle で新しい文書の一致を敷き直す（ジャンプしない）。文書が無くなればバーは閉じる。Esc で閉じると地は消え、選択はそのまま残り、焦点はテキスト面へ戻る。一致の地は本文と undo に載らない。

端末焦点中の ⌘F はスクロールバック検索（→ [layout](../chrome/layout.md) の「両面のキー」）。

## 出現の強調

同じものが他のどこにあるかを、探さずに見せる。2 種類あり、どちらも本文と undo に載らない地で、規則は VS Code の既定に合わせる。

**選択文字列の出現**——1 行以内・空白だけでない・長すぎない文字列を選択すると、他の出現（大小無視）にうっすら地が付く。選択自身と、選択より前から始まって選択に重なる出現には付かない。本文だけに出て俯瞰には出ない。選択の変化ですぐに取り直す（本文を変える操作は選択の変化を伴うので、そこで取り直される）。検索バーが同じ文字列を探している間と、検索バーの入力欄に打っている間は出さない（検索の一致と二重にしない）。面に焦点が無いときは地が薄くなる。

**語の出現**——キャレットが語の上にあると（または選択がちょうど 1 語か 1 語の内側だと）、少し遅れて同じ語（大小区別・語の境界つき）の全出現に地が付き、スクロールバーの中央とミニマップにも出る。語は英数字などの並びで、記号と空白で切れる（全言語で同じ定義。数の語の「数字」は ASCII だけ）。長い行ではキャレットの前後の範囲だけから探す（VS Code と同じ。範囲の端にかかる語は端で切れる）。打鍵・本文の変更で消え、次にキャレットを動かすと出直す——打鍵に伴うキャレットの移動では出ない（本文の変更と同じ runloop の選択の変化は打鍵と見なす）。キャレットが出ている範囲の中を動く間は取り直さない。焦点が本文と検索バーの外へ出ると消え、本文へ戻るとキャレットを動かさなくても出直す（⌘F で検索バーへ移っても消えない）。

## 見え方

見本「コード本体」の値を持つ（→ [design-system](../../design/design-system.md) §5「Code view」）。行番号のガター（右寄せ）とその右の git ガター（本文はその右端から）・固定の行高・上端の余白・キャレットの色と寸法・役割ごとの色・装備の色と寸法はトークンで、フォントの決め方は 1 か所に閉じる。俯瞰（ミニマップ・スクロールバー・印・影）と強調の地は、寸法を VS Code の既定に、色を VS Code Dark Modern / Light Modern の値に合わせ（見本から外れる）、同じ意味の Orbe のトークンがあるもの（git の印・キャレット・縁）はそれを使う。本体の最低幅の中に俯瞰の幅も入る——極端に狭い列では本文とミニマップが縮む（俯瞰を自動で隠す規則は持たない）。地は chrome と同じ veil で、背景透過の設定に追従する。ガター（行番号と印の列）は面と同じ地を本文の上に持つ——不透明なら本文はその下に隠れ、透過時は veil の濃度ぶんだけ薄く残る。テキスト選択の地はシステムの選択色（テキストエンジンに差し替え口が無い）。

## キー

エディター焦点中の chrome キーは面が先取りする。分類は[レイアウト](../chrome/layout.md)の「chrome キーの分類」——window コマンドはタブ経由で上位へ、⌘S は保存、端末のキー（フォント）は何も起こさず端末にも届かず、両面のキーのうち ⌘F はファイル内検索、⌘↑↓ はテキスト面の文書先頭／末尾へ。それ以外の打鍵はテキスト面へ届く（日本語 IME を含む）。検索バーは面の配下なので、バーに焦点がある間も chrome キーは効く（⌘↑↓ だけはバーの入力欄の中で先頭／末尾へ動く）。⌘Z / ⌘⇧Z / ⌘X / ⌘C / ⌘V / ⌘A は Edit メニューの key equivalent が responder chain でテキスト面へ届く。⌘Z は続けて打った文字をまとめて戻す。

端末焦点の ⌘S は端末へ届く（Orbe は束縛しない）。

## 焦点

焦点の文書があるとき、エディター面の焦点 view はそのテキスト面（無ければ面自身）。タブ切替・パレット閉・⌘R 確定・制御 API でエディター面へ戻るフォーカスはここへ来る。テキスト面をクリックしてフォーカスを取ると、面の記憶がエディターへ移る（→ [faces](faces.md)）。文書を開いた・切り替えた瞬間に焦点が面の中にあれば、新しいテキスト面へ移す。

## テキストエンジンの境界

テキストエンジン（TextKit 2 の自前ビュー）は 1 モジュールに閉じ、公開は「面を作る 1 関数」だけ。面の契約は本文・undo の区切り・色の適用・可視区間・「行の印を置く」1 操作（文書がハンクから作り、他の区間と同じくオフセットで押す）・「URL が ⌘クリックされた」を外へ渡す 1 つの口（行き先はエンジンが知らない）・「面の地を置く」1 操作（載せる側が自分の地と同じ色を渡し、面がその矩形の地を敷く——本文の下と、本文の上に浮くガターの両方。載せる側は面の矩形に自分の地を描かない）に加え「本文を丸ごと置き換える」1 操作を持ち、置き換えは通常の編集と同じく undo に載り、同じ通知で呼び出しから戻るまでに文書へ届く（行索引・構文木・ハンクが打鍵と同じ経路で追従する）。置き換えの前に変換中の IME セッションを畳み、置き換え後の選択は解け、キャレットは同じオフセット（本文が短ければ末尾）に置く。

俯瞰と検索と強調のために「面の中の出来事を外へ出す口」も持つ——見えている範囲を**本文の言葉**で読む（先頭に見えている行のオフセット・その行が隠れている割合・可視行数・本文が右にまだ続くか。実際に置かれた行の矩形から出し、エンジンの推定の文書高に依らない）、その逆の「この行をこの割合だけ隠して先頭に置く」1 操作（ドラッグ用）、「このオフセットの行を中央に見せる」1 操作、「この区間が見えるところまで最小限スクロールする」1 操作（縦に見えていれば縦は動かず横だけ寄る）、選択の読み書き（置くだけで見せない）、「強調の地を種類ごとに置く」1 操作（検索の一致・現在の一致・選択文字列の出現・語の出現。地は選択の地の上・文字の下に出る）、「インデント単位を置く」1 操作（検出するのは文書——開いたときと丸ごと置き換えたとき——で、面はタブの表示幅と装備の段に写す）、「見える範囲が変わった」「選択が変わった」の通知。面の外（俯瞰）で起きたホイールは、面の view へ渡せば面が自分のスクロールへ渡す（載せる側は面の中の view の階層を知らない）。ここでいう行は行索引の行（本文が改行で終わるときの末尾の空行を含む）で、エンジンは見えている範囲の測定とその逆を同じ「行の矩形」で行う。面の pt と行高は契約に出ない——契約を横切る値は本文のオフセットと行だけ。

最終行を最上段まで送れる範囲と、横スクローラーの様式（オーバーレイ）の固定もエンジンが持つ——スクロールできる範囲は文書の高さとは別の値で、文書の高さ（エンジンが layout の事実として読む）には触れない。エンジンは layout していない行の位置を推定で持つので、遠くへ飛ぶ操作（中央へ・先頭へ）は飛んだ先の行が落ち着くまで置き直す（推定が変わって狙いの行がずれたり、描いた本文と装備・強調の地・クリックの当たりが食い違ったりしないため）。強調の地を選択の地の上に出すためにエンジンの部品（STTextView）の内部の層の並びに依存しており、その依存はエンジンのモジュールの中に閉じる。

文書・行索引・言語・色付け・役割は別モジュールで、エンジンも chrome のトークンも知らず、構文解析器の型もその公開面に出ない。装備も俯瞰も検索も強調も同じ境界に従う——「何を描くか」（ハンクからどの行が追加か、行の文字列からどの桁に線か・どの空白に点か・どこが URL か、ミニマップの字の列と配置・スクロールバーのつまみと印の写像、一致の列と次／前、出現の規則）はその別モジュールの純関数。装備と強調の地の「どう描くか」（行の座標に写す・区間の矩形に地を敷く）はエンジンが持つ。俯瞰はエンジンの外——面を組む場所が、契約（見えている範囲・選択・「この行を先頭に」）と純関数だけからミニマップとスクロールバーを描き、動かす。文書は構文の事実（ある区間の役割）を答えるだけで、俯瞰の窓もキャッシュも知らない。エンジンの移行で書き直すのは装備と強調の地の「どう描くか」・スクロールの範囲・横スクローラーの様式の固定だけ。エンジンと構文解析器の型に触れる import は、`Sources` ではそれぞれのモジュールの外で lint が落とす。Orbe 本体がエンジンと合成する場所は 1 か所（見え方をトークンから組む場所）。エンジンの移行はそのモジュールの差し替えで済む。

## 入口

人がファイルを開く入口は[面の骨](shell.md)のエクスプローラー（ツリーのクリック・新規作成）、エージェントの入口は制御 API の `open_file`（→ [control/api](../control/api.md)）。`open_file` は開けたらエディター面が見える配置にして（隠れていれば全面、分割中は焦点だけ）、そのタブを選び、テキスト面へフォーカスする。どちらもツリーがその文書の祖先を開いて選択表示する。
