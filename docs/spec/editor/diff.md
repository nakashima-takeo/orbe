# diff

ファイルの変更を、エディター面のタブとして読み、その場で直す場所。作業ツリーの変更（index と今の本文の差）と、ステージ済みの変更（HEAD と index の差）を、普通のファイルと同じ字と構文色で見比べる——端末で `git diff` を流し読みする代わりに、行番号・構文色・スクロールの手触りをそのまま持った本体で変更を確かめるため。開く口は、ソース管理パネルの行（人が自分の変更を見る）・PR のパネルの変更ファイルの行（人が PR の変更を読む）と制御 API `open_diff`（エージェントが人に変更を見せる）（→ 入口）。作業ツリー diff の新しい側はその場で編集でき、⌘S で保存できる——変更を見ながら直すのに、ファイルタブへ移らなくてよい（ステージ済み diff などは読むだけ。⌘F は持たない → 編集）。

## diff タブと種類

diff タブは識別（根・根からの相対パス・種類）を持ち、ファイルタブと同じ列に並ぶ（→ [shell](shell.md)）。識別は git の座標で、ファイルの実体ではない——作業ツリーのパスがシンボリックリンクでも解かない。同じ識別をもう一度開けばタブは増えず焦点だけ移り、位置は保つ。種類は 3 つで、種類が 2 つの側を決める。

| 種類 | 古い側 | 新しい側 | タブの注記 |
|---|---|---|---|
| 作業ツリー | index の版 | そのファイルの文書（開いていれば未保存を含む今の本文） | （作業ツリー） |
| ステージ済み | HEAD の版（rename なら元のパスの HEAD の版） | index の版 | （ステージ済み） |
| PR | PR のマージベースのコミットの版（rename なら元のパスの版） | PR の先頭のコミットの版 | （PR #番号） |

同じファイルの作業ツリー diff とステージ済み diff は別のタブ。PR の diff の識別は、種類の中に手元のリポジトリと PR の同一性を持ち、コミットは持たない——PR に push があっても同じタブのまま、新しい両端で作り直す（→ PR の diff）。版の本文は作業ツリーに出したときの姿（smudge と eol を通したもの）。作業ツリー diff とステージ済み diff の版の本文は、根のサービスが（パス, 版）ごとに 1 か所で持つ（→ [files](files.md)）——ガターの底と diff の古い側は同じ本文を引く。PR の diff の版の本文は、根のサービスを通らず、両端のコミットを名指しして git から読み、その diff が持つ（→ PR の diff）。

## 文書の共有

作業ツリー diff の新しい側は、そのファイルの文書そのもので、ファイルタブと**同じテキスト面**を見え方を切り替えて使う。だから同じファイルのファイルタブと作業ツリー diff タブは、スクロール位置・選択・undo を共有する——diff を開くと最初の変更へ送るので、ファイルタブへ戻るとその位置にいる。ファイルタブで編集した未保存の本文はそのまま diff の新しい側に出て、diff の中で打った編集はファイルタブの ⌘Z で戻る（逆も同じ）。文書が開いていなければ diff が開いて持つ（タブには出ない）ので、後からファイルタブを開けば同じ文書が出る。

新しい側をどれにするかは、作業ツリーのそのパスの今の姿で決める——ファイルが在って UTF-8 なら文書、無ければ「消した」（全部の行が削除。途中のディレクトリがシンボリックリンクに置き換わったパスも、git と同じく無い——リンク先のファイルを開かない）、サブモジュールなら「Subproject commit」の行（→ [サブモジュール](#サブモジュール)）、シンボリックリンク・サブモジュールとして見せられないディレクトリ・UTF-8 でない・読めないなら表示できない。開いた後もそのファイルが変わるたびに決め直す（消したファイルを戻せば文書に戻り、開いた後で消せば全部削除になり、UTF-8 でなくなれば理由の一文になる）。新しい側の文書が替われば（文書が無くなって版の本文に替わるときを含む）、新しい側で並びを置けるようになるまで本体に何も出さない（開くときと同じ。並びの無い面と、前の両側の並びを載せた面を出さない）。使わなくなった文書はファイルタブの見え方に戻し、ほかに使うタブが無ければ閉じる。替わった文書が未保存なら、仮の diff タブは普通のタブになり、タブ行に未保存の印が出る。ただし文書が未保存の間は、作業ツリーの姿が変わっても手放さず、index の版 ↔ 未保存の本文を出し続ける——未保存の本文を確認なしに失わない（ファイルタブが、消えたファイルの未保存の本文を保つのと同じ）。読み直しは未保存が下りた時点で行う（保存したときも、⌘Z で保存時の本文へ戻して未保存が下りたときも）。

文書は実体ごとに 1 つで、それを使うタブ（ファイルタブと作業ツリー diff タブ）が持ち主になり、最後の持ち主が離れたときに閉じる。**未保存の確認は、その文書を使う最後のタブを閉じるときだけ出す**——未保存の文書のファイルタブを閉じても diff タブが使っていれば確認は出ず、未保存の印は diff タブに出て、その diff タブを閉じるときに確認が出る（VS Code と同じ）。連の最後の端末タブ・workspace を閉じるとき・終了の確認は、連の文書の単位で数える——diff タブだけが使う文書も 1 件で、同じ文書をファイルタブと diff タブが使っていても 1 件（タブの数ではない）。cd で連が畳まれるとき、diff タブは行き先の連の列へ移り、同じファイルの文書は 1 つに揃う（どちらが残るかは → [code](code.md) の連を移るとき）。

ステージ済み diff と PR の diff の両側と、作業ツリーで消したファイルの新しい側、サブモジュールの行の新しい側は、版の本文を読むだけで持つ文書（面も diff が持つ）。文書と面は 1 対 1 なので、版の本文が変われば文書と一緒に面も作り直す——新しい面でも、前の面で先頭に見えていた所（削除行・詰め物の塊の途中を含む）を先頭に置く。古い側が変わらなければ（index だけが変わったステージ済み diff）、古い側の同じ行の同じ段に付けて写すので、`git add` した箇所が読んでいる所より上で行の数が変わっても、読んでいた削除行が上端に残る。読んでいた追加の行が新しい並びに無ければ、同じ区間の頭に置く。両側とも変わったとき（ブランチの切り替えなど）は、前の面の位置（新しい側の行と段）のまま。開いた後の位置を決める前の作り直しは引き継がず、追いついた並びで 1 回だけ決める（→ 下）。

## インラインと並列

見せ方は 2 つで、タブ行の右端（焦点が diff タブのときだけ出る）の「インライン / 並列」で切り替える。選択はアプリ全体で 1 つで、どの diff タブにも効き、再起動でも戻る（→ [persistence](../platform/persistence.md) の app-state）。切り替えても、見えている先頭の新しい側の行は保たれる。

開いたときは、最初の変更区間——上の文脈の行の上端から区間の終わり（区間の削除行・並列の詰め物を含む。削除だけの区間ならその境の削除行の終わり、末尾の区間なら並びの終わり）まで——が見える位置へ送る（収まれば区間の先頭の行を中央に、収まらなければ範囲の先頭を上端に）。区間が先頭の行から始まるなら文書の先頭を見せ、先頭の行の前に差し込まれた削除行は、見えている高さより長くても頭から見える（消したファイルは全部の行がこの形）。インラインでは、見えている削除行の色を先に作る（初めて見せるときの色の上限待ちも、見えている削除行で効く）。

送るのは開いた後の 1 回だけで、開いた時点に追いついた最初の並びで決める。作業ツリー diff は、開くときに新しい側の文書がディスクを読み直す（既に開いている文書でも）。根のサービスは、開いた後に始めた status と版の本文の取り直しを済ませる（根が git 管理下かをまだ判定していなければ、判定の後に始める最初の取り直し）。その後の状態から作った並び——作業ツリーは今の index の本文に対する文書の今の版の行差分、ステージ済みはその status で決まる版（rename なら元のパスの HEAD）の本文の行差分——が載った時点で送る。だから監視の知らせより先に開いても（エージェントがファイルを書いた直後・`git add` した直後の open_diff）、その変更へ送る。それより後に現れた変化では送らない——変更の無い状態で開いた diff は、後から変更が現れても位置が動かない（ファイルタブと共有する面も動かない）。追いつくまでの間（普通は数十〜数百 ms）は、並びは出るが送らない。送る位置は見えている高さで決まるので、本体に置いた面が大きさを持ってから送る。

diff の色の待ち（→ [code](code.md) の「開いた直後の色」）は diff のタブ 1 つにつき 1 回で、古い側と新しい側を合わせて最大 50ms。待つのは、開いた時点に追いつき、最初の変更へ送った画面（変更が無ければ、追いついた画面）を出す直前だけで、送った先の見えている範囲の色を待つ。それより前に出る追いつく途中の画面では待たず、色は届き次第付く。開いた後に版の本文が変わり、文書と面を作り直したとき（`git add`・ブランチの切り替え）も待たない。

- **インライン**: 新しい側の面 1 枚に、古い側にしか無い行（削除行）を差し込む。左から 旧番号｜新番号｜＋ / −｜本文。追加の行は青の地と ＋、削除行はオレンジの地と −、文脈の行は地なし。
- **並列**: 左が古い側・右が新しい側の 2 面を 1px の境で並べ、各側 1 列の番号。両面はスクロールを共にし、どちらの面で指を動かしても 1 枚の紙として縦横に動く。焦点は最後に焦点のあった側（既定は右）。

どちらも**全部の行を普通のファイルと同じ構文色**で描く（削除行は古い版の本文全体を解いた色）。追加・削除は行の地と記号で見分け、字に diff 専用の色は持たない。空白の点も普通のファイルと同じ規則で出る。行の地は行番号の列の左端から面の右端（縦スクロールバーの列の下）まで届く。差し込んだ削除行は選べず、当たらない。diff の面はミニマップと git の印の列を持たず、スクロールバーに git の印も出さない。

## 並びの規則

並びは行差分の区間の列と両側の行の数だけから作る（純関数）。行は両側ともエディターに見える行と同じ数え方（→ [code](code.md) のハンク）なので、区間の外の行は両側で 1 対 1 に揃う。

- **インライン**: 区間の削除行は、区間の新しい側の始まりの境に、古い側の行を指す差し込みとして並べる。追加の区間には型「追加」を付け、旧番号を持たない。文脈の区間は旧番号の始まりを渡す（区間の中の行は番号が 1 ずつ進む）。改行で終わる本文の末尾の空の行も 1 行として比べるので、末尾に改行を足せば空の行の追加、消せば空の行の削除として出る（「\ No newline at end of file」の印は出さない——エディターの行に無いものを差し込むことになる。VS Code と同じ）。改行で終わる本文どうしなら、末尾の空の行は両側で揃う——末尾に空の行で始まる塊を足すと、足した塊が追加になる（git と同じ位置）。
- **並列**: 文脈は両側とも型なし。変更区間は両側の同じ行から並べ、左は型「削除」、右は型「追加」。区間の削除と追加の数の差だけ、短い側の区間の後ろに詰め物（何も指さない差し込み。淡い地）を置く——続く文脈が左右で同じ高さに揃う。片側 0 件の区間は相手側に区間の件数ぶんの詰め物。

## 行差分

作業ツリー diff の差分は「文書の底（index の版）↔ 本文」の行差分そのもので、ガターと同じく文書が裏で取り、編集でずらして持つ（→ [code](code.md) のハンク）。diff を出している間だけ、文書の行差分の上限を**編集の数（削除と追加の行数の和）10,000** に上げる——共通の先頭・末尾を落とした残りが大きくても、編集の数が上限以下なら行ごとに取る（1MB のファイルの先頭と末尾を 1 行ずつ変えても、その 2 か所だけが変更になる）。編集の数は線形の記憶で上限まで数え、越えた時点で打ち切って残り全体を 1 つの変更区間（全部を削除して全部を追加）にする——時間は 1MB 級の最悪でも裏で 1 秒未満。diff の中で打つ間も上限は同じで、打鍵ごとの行差分は最新の版の 1 回に畳まれる。裏の 1 回が打鍵の間隔より長くても、打ち続けている間に届いた前の版の結果は今の本文へずらして置くので、打つのを止める前から変更が出る。diff を閉じれば（ファイルタブへ戻れば）ガターの上限（残りの行数 1000）に戻る。上限の結果が届くまでは前の上限の結果で並びを出し、届けば置き直す（見えている行は動かない）。

古い側は文書のハンクが比べた底から作り、並びは置くたびに文書の今の本文と今のハンクから作る——index の版が変わったとき、ハンクが新しい底に対する結果になるまでは前の底とそのハンクで出し続け、その間に外の書き換えで本文が変わってもハンクは今の本文へずらしてあるので、差し込みは古い側の本文とも今の本文ともずれない。底が今の古い側と違う間は並びを置き直さない。ステージ済み diff は両側とも変わらない版の本文なので、どちらかが変わったときに 1 回、両側の本文と行差分を裏で揃えてから入れ替える。ただし、片側が無いなら、行差分は区間 1 つで手間が本文の大きさに依らないので、その場で入れ替える。ファイルとサブモジュールの置き換え（→ サブモジュール）は行差分を取らず、その場で丸ごとの置き換えにする。作業ツリー diff の新しい側が版の本文のとき（消したファイル・サブモジュールの行）も、この 2 つの規則に従う。

## 追従

diff タブを開いたまま、端末で `git add` / `git restore --staged` / ファイルの保存 / 外のツールの書き換え / コミットをすると、見えている diff が追従する（index と HEAD の変化は監視の到着から数百 ms 以内）。並びを置き直しても、見えている先頭の行は画面の同じ位置に残る。本体に出していない diff（焦点でない diff タブ）は追従せず、本体に出したときに今の版で作り直す——打鍵中に隠れた diff が裏の仕事を起こさない。ステージ済み diff で走っている裏の行差分は、古い側か新しい側の本文が変わったときと、表示できないと決まったときに捨てる。rename の元パスが変わり、新しい元パスの HEAD の版の本文がまだ届いていない間も、走っている行差分を捨て、届いた後に頼み直す。両側の本文が変わらなければ、status が変わっても走っている行差分の結果を待つ——ほかのファイルが次々に変わっても、diff の中身は届く。表示できないと決まった後に、前の本文の結果が届いて表示に戻ることは無い。ファイルタブで編集してから diff タブへ戻ると、編集はそのまま diff に出ている。ステージ済みの rename の元パスは status から引き、status が変われば引き直す。

diff の中で編集したときも、並びは編集のたびに置き直す。行の数を変える編集（改行・行の削除・複数行の貼り付け）は、文書がハンクを編集でずらすので、その場で区間に出る。足した行は追加の行に、消した行は削除行になり、並列では反対の側に詰め物が入る——続く文脈の行が左右で同じ高さに揃い続ける。行の中身だけを変える編集は、裏の行差分が届いた時点で変更に出る（普通は数 ms、変更の多い大きなファイルで最大 1 秒ほど）。元の内容に戻せば、同じく変更の表示が消える。

## PR の diff

PR の diff は、GitHub 上の PR の差分（GitHub の Files changed と同じ両端）を、手元の git の版の本文で見せる。両側とも読むだけ。両端と変更ファイルの一覧は PR の状態が持つ（→ [pull-request](pull-request.md)）——古い側は、PR が比べる基準のベース側のコミットと PR の先頭のコミットとのマージベース、新しい側は PR の先頭のコミットで、その間に rename があれば古い側は元のパスの版。両端が揃うまで（手元に無いコミットを取りに行っている間を含む）は本体に何も出さない。両端が揃ったら両側の版の本文を読み、ほかの diff と同じ規則で並べる。

PR の中のサブモジュールは、作業ツリー diff・ステージ済み diff と同じく「Subproject commit」の 1 行で見せる（→ [サブモジュール](#サブモジュール)）。

PR の diff タブは、開いたときの PR の状態を見続ける。ブランチを切り替えても、そのタブは開いたときの PR の diff を出す。PR に push があったか、PR のベースブランチが付け替えられて両端が変わったら、新しい両端の版の本文を読み直して作り直す（読んでいた位置の引き継ぎはステージ済み diff と同じ）。両端が変わらない間（PR の中身を読み直したとき・確認済みを付け外ししたとき）は、読んだ本文のまま。版の本文を読めなかったときは、PR の中身の読み直しを始めるたびに 1 回読み直す（LFS の取得のような一時的な失敗から、再読込で戻れる。読み直す間は前の理由の一文を出したまま）。PR の diff タブは、開いている間その PR の状態を見ている者になる（GitHub への問い合わせは見ている者がいる間だけ → [pull-request](pull-request.md)）。

PR の diff だけが GitHub のレビューのスレッドを持つ——付いた行の下にスレッドを置き、コメントできる行の右端に新しいコメントの印を出す（並びの決まり・操作・書き込みは → [pull-request-comments](pull-request-comments.md)）。並列では、スレッドの反対側に同じ高さの空きを置いて左右の行を揃える。スレッドのある行は、追加・削除・文脈のどれでも地をスレッドのある行の地に替える。作業ツリー diff とステージ済み diff には印もスレッドも無い。

## 変化が無いとき・片側だけのとき・表示できないとき

- 両側に版があって変更が無ければ、全文が地なしで出る。中身が空の追跡中のファイルも、版がある側は空の本文（空の行 1 つ）として数える。
- 片側だけ（未追跡・index への追加・作業ツリーやステージでの削除）なら、その版に無い側は 0 行で、有る側の全部の行が追加か削除になる——改行で終わる本文の末尾の空の行も含め、エディターに見える行のとおりに出す（新しいファイル `aaa`＋改行は「+ aaa / + 空の行」、`aaa` だけなら「+ aaa」。空のファイルを足せば「+ 空の行」の 1 行）。版が無いことは本文の中身ではなく版の有無の事実なので、空の本文とは分けて持つ——存在しない「空の行」を対応や変更に入れないため。並列なら無い側は詰め物だけ。版が無い側の面もエディターの都合で空の行を 1 つ持つが、その行に番号を描かない（存在しない行を番号付きで出さない。インラインの消したファイルの差し込んだ削除行には、古い側の番号を描く）。片側だけの行差分は本文を割らず、本文の大きさに依らない手間で出る。
- 次のときは、タブは開き、本体の中央に理由の一文が出る（空状態の一文と同じ字と色）。
  - 作業ツリーのパスの姿: シンボリックリンク／サブモジュールとして見せられないディレクトリ／ファイルを読めない
  - 本文: バイナリか UTF-8 でない
  - git: 競合中／版を取れない
  - PR: PR のコミットを取得できない（手元に無く、取りに行っても揃わない。浅いクローンで、取ってある範囲より古い所で分かれた PR と、ベースブランチと共通のコミットが無い PR を含む）／ベースブランチと共通のコミットがない

  両側とも無いパス——作業ツリー diff なら作業ツリーにも index にも無い（「index にも作業ツリーにもない」）、ステージ済み diff なら HEAD にも index にも無い（「HEAD にも index にもない」）、PR の diff ならマージベースにも PR の先頭にも無い（「PR のどちらの側にもありません」）——も同じで、開いた後で両側とも無くなったときも同じ一文に変わる。版の本文が届くまでの間は本体に何も出さない。

## サブモジュール

サブモジュールの行は、git の diff と同じく 1 行の差で見せる（VS Code と同じ）。サブモジュールの側の本文は「`Subproject commit <コミット>`」の 1 行（末尾の改行は無い）で、普通の diff と同じ地・記号・番号で並べ、読むだけ。版の事実はコミットで、字に起こすのは diff の層（ガターの底にはしない）。

- **作業ツリー diff**: 古い側は index のコミット、新しい側は作業ツリーで取り出しているコミット。中が変わっている・未追跡がある（status が言う。`--ignore-submodules=none` で読むので、中の未追跡だけでも）なら末尾に `-dirty` が付く——中身だけ変わったなら同じコミットに `-dirty` が付いた差になる。取り出しているコミットは、見せている間、作り直すたびに根のサービスを通して中の HEAD を引き直す（status の変化と、入れ子の git dir が変わった知らせで → [files](files.md)）。中のリポジトリの最上位がそのパスでなければ（初期化していない）、取り出していないとみなし index のコミットと同じ。
- **ステージ済み diff**: 古い側は HEAD のコミット、新しい側は index のコミット。
- **PR の diff**: 古い側はマージベースの版のコミット、新しい側は PR の先頭の版のコミット（gitlink が指すコミット。サブモジュールの中を読まないので `-dirty` は付かない）。
- **ファイルとサブモジュールを置き換えた行**（どちらの向きも、作業ツリー・ステージ済み・PR とも）: ファイルの本文と「Subproject commit」の行の丸ごとの置き換え（git が削除と追加に割るのと同じ）。サブモジュールからファイルへ置き換えた作業ツリー diff の新しい側は、普通どおりファイルの文書。
- **新しく足した・消したサブモジュール**: 片側だけの 1 行。

サブモジュールとして見せられないディレクトリ（index の版がサブモジュールでなく、中に取り出したコミットも無い）は、作業ツリー diff では「ディレクトリのため、差分を表示できません」の一文が出る。追跡中のファイルを同じ名前のディレクトリに置き換えたときも、`open_diff` にディレクトリのパスを渡したときも同じ。ステージ済み diff は作業ツリーを見ず、HEAD と index の版どうしを比べる——ファイルをディレクトリに置き換えても、ステージしていなければ変わらない本文が出る。HEAD にも index にもファイルとして無いパス（`open_diff` に渡したディレクトリなど）は「HEAD にも index にもない」になる。

## 編集

作業ツリー diff の新しい側——インラインの本文と、並列の右——はファイルタブと同じ面なので、そのまま編集できる。打鍵・削除・改行・IME の変換・貼り付け・カット・字のドロップ・複数カーソルの編集・⌘Z / ⌘⇧Z はファイルタブと同じに効き、編集のメニューの項目も有効になる。編集できるかは見せ方ではなく文書の種類が決める——ファイルの文書の面は編集でき、git の版の本文の面は読むだけ。だから次は読むだけで、打鍵・貼り付け・ドロップ・⌘Z が本文を変えない（選択・コピー・スクロールは効く）。

- ステージ済み diff の両側
- PR の diff の両側
- 並列の左（index の版は編集の相手ではない。VS Code と同じ）
- 作業ツリーで消したファイルの新しい側（未保存の文書を保っていないとき）と、サブモジュールの行

インラインで、変えていない行で打ち始めると、裏の行差分が届いた時点でその行が追加の行になり、上に元の行が削除行として差し込まれるので、打っている行が 1 行下がる。並びが変わっても見えている先頭の行を画面の同じ位置に保つためで、VS Code のインライン diff と同じ動き方になる。元に戻せば削除行が消えて 1 行上がる。打っている行が見えている最後の行なら、差し込まれた瞬間は画面の下へ出て、次の打鍵で見える位置へ戻る。並列では打っている行は動かず、左に元の行が出る。

⌘S は焦点のタブが使う文書を保存する——作業ツリー diff のタブでは、新しい側に使っている文書（並列で左に焦点があっても同じ）。本体に理由の一文だけが出ている間（競合中・index の版を表示できない・読み込み中など）も、新しい側に文書を使っていれば、その文書を保存する。保存の直前の照合と上書きの確認はファイルタブと同じ（→ [shell](shell.md)）。新しい側に文書を使っていない diff（ステージ済み diff、PR の diff、未保存の文書を保っていない消したファイル、サブモジュール、作業ツリーのパスの姿が表示できないもの——シンボリックリンク・読めないファイルなど）では何もしない。編集して未保存になると、仮の diff タブは普通のタブになり（→ [shell](shell.md) の仮のタブ）、未保存の印は diff タブにも、同じファイルのファイルタブ（開いていれば）にも出る。

diff を出している間に外でファイルが書き換わったときも、ファイルタブと同じ規則に従う（→ [files](files.md)）——未保存でなければ本文が差し替わり、差し替えも undo に載るので、⌘Z で差し替え前の本文へ戻れる（それより前の取り消しの履歴も残る）。未保存なら本文は保たれ、タブに衝突の印が出る。

インライン ⇄ 並列を切り替えても新しい側の面は同じなので、変換中の字は確定されず、そのまま変換を続けられる。

diff の中では ⌘F と出現の強調を持たない。どちらも 1 つの文書の本文を探し、その本文の範囲に地を敷く仕組みなので、diff では新しい側の文書の本文にしか届かない——インラインの削除行（古い側の版の行を差し込んだもの）も並列の左（古い側の面）も、探すことも強調することもできない。diff の中で探したいときはファイルタブへ移る。プロジェクト検索の一致の地も diff の面には出さないが、diff の中の編集は、結果に出ているそのファイルの一致をずらし、少し後に探し直す（→ [search](search.md)）。

## 入口

- **制御 API `open_diff {tabId, path, kind}`**（→ [api](../control/api.md)）。`path` は `open_file` と同じ解き方で根と根からの相対パスにし、普通のタブで開く。エディターを見える配置にし、タブを選んで本体へ焦点を移す（版の本文が届く前は面の器が焦点を預かり、面ができたときに面へ移す）。git 管理外は断る。
- **ソース管理パネルの行**（→ [source-control](source-control.md)）。「変更」の行は作業ツリー diff、「ステージされている変更」の行はステージ済み diff を、シングルクリック・↑↓・→ で仮のタブ（焦点は列のまま）、ダブルクリック・Enter で普通のタブ（本文へ焦点）で開く。

- **PR のパネルの変更ファイルの行**（→ [pull-request-panel](pull-request-panel.md)）。その PR の diff を、シングルクリック・↑↓・→ で仮のタブ（焦点は列のまま）、ダブルクリック・Enter で普通のタブ（本文へ焦点）で開く。

制御 API の `open_diff` は PR の diff を受けない。

## 永続しない

diff タブは再起動で戻らない。連の永続は文書のタブだけを書き、焦点が diff タブなら、diff タブを除いた列でその位置にある文書のタブ——右隣、無ければ左隣（焦点のタブを閉じたときに焦点が移る規則と同じ）を焦点として書き、仮のタブが diff タブなら仮は書かない。インライン / 並列の選択だけは app-state に残る。

## VS Code との差

- **ファイルタブと作業ツリー diff で位置・選択・undo を共有する**（VS Code の diff エディターはファイルのエディターと位置が独立）。Orbe は undo とカーソルを面が持ち、1 文書に編集できる面は 1 枚なので、同じ文書は同じ面で見せる。
- **削除行も構文色で描き、空白の点も出す**。
- **⌘F・変更から変更への移動キー・スクロールバーの git の印を持たない**。
