# diff

ファイルの変更を、エディター面のタブとして読む場所。作業ツリーの変更（index と今の本文の差）と、ステージ済みの変更（HEAD と index の差）を、普通のファイルと同じ字と構文色で見比べる——端末で `git diff` を流し読みする代わりに、行番号・構文色・スクロールの手触りをそのまま持った本体で変更を確かめるため。開く口は制御 API `open_diff`（エージェントが人に変更を見せる）。diff タブは読むだけで、編集・⌘F・⌘S は持たない。

## diff タブと種類

diff タブは識別（根・根からの相対パス・種類）を持ち、ファイルタブと同じ列に並ぶ（→ [shell](shell.md)）。識別は git の座標で、ファイルの実体ではない——作業ツリーのパスがシンボリックリンクでも解かない。同じ識別をもう一度開けばタブは増えず焦点だけ移り、位置は保つ。種類は 2 つで、種類が 2 つの側を決める。

| 種類 | 古い側 | 新しい側 | タブの注記 |
|---|---|---|---|
| 作業ツリー | index の版 | そのファイルの文書（開いていれば未保存を含む今の本文） | （作業ツリー） |
| ステージ済み | HEAD の版（rename なら元のパスの HEAD の版） | index の版 | （ステージ済み） |

同じファイルの作業ツリー diff とステージ済み diff は別のタブ。版の本文は作業ツリーに出したときの姿（smudge と eol を通したもの）で、根のサービスが（パス, 版）ごとに 1 か所で持つ（→ [files](files.md)）——ガターの底と diff の古い側は同じ本文を引く。

## 文書の共有

作業ツリー diff の新しい側は、そのファイルの文書そのもので、ファイルタブと**同じテキスト面**を見え方を切り替えて使う。だから同じファイルのファイルタブと作業ツリー diff タブは、スクロール位置・選択・undo を共有する——diff を開くと最初の変更へ送るので、ファイルタブへ戻るとその位置にいる。ファイルタブで編集した未保存の本文はそのまま diff の新しい側に出る。文書が開いていなければ diff が開いて持つ（タブには出ない）ので、後からファイルタブを開けば同じ文書が出る。

新しい側をどれにするかは、作業ツリーのそのパスの今の姿で決める——ファイルが在って UTF-8 なら文書、無ければ「消した」（全部の行が削除）、シンボリックリンク・UTF-8 でない・読めないなら表示できない。開いた後もそのファイルが変わるたびに決め直す（消したファイルを戻せば文書に戻り、開いた後で消せば全部削除になり、UTF-8 でなくなれば理由の一文になる）。使わなくなった文書はファイルタブの見え方に戻し、ほかに使うタブが無ければ閉じる。

文書は実体ごとに 1 つで、それを使うタブ（ファイルタブと作業ツリー diff タブ）が持ち主になり、最後の持ち主が離れたときに閉じる。**未保存の確認は、その文書を使う最後のタブを閉じるときだけ出す**——未保存の文書のファイルタブを閉じても diff タブが使っていれば確認は出ず、未保存の印は diff タブに出て、その diff タブを閉じるときに確認が出る（VS Code と同じ）。終了・端末のタブを閉じるときの確認は文書の単位で数え、diff タブは数えない。

ステージ済み diff の両側と、作業ツリーで消したファイルの新しい側は、版の本文を読むだけで持つ文書（面も diff が持つ）。文書と面は 1 対 1 なので、版の本文が変われば文書と一緒に面も作り直す——新しい面でも、前の面で先頭に見えていた行を先頭に見せる。

## インラインと並列

見せ方は 2 つで、タブ行の右端（焦点が diff タブのときだけ出る）の「インライン / 並列」で切り替える。選択はアプリ全体で 1 つで、どの diff タブにも効き、再起動でも戻る（→ [persistence](../platform/persistence.md) の app-state）。切り替えても、見えている先頭の新しい側の行は保たれる。

- **インライン**: 新しい側の面 1 枚に、古い側にしか無い行（削除行）を差し込む。左から 旧番号｜新番号｜＋ / −｜本文。追加の行は青の地と ＋、削除行はオレンジの地と −、文脈の行は地なし。
- **並列**: 左が古い側・右が新しい側の 2 面を 1px の境で並べ、各側 1 列の番号。両面はスクロールを共にし、どちらの面で指を動かしても 1 枚の紙として縦横に動く。焦点は最後に焦点のあった側（既定は右）。

どちらも**全部の行を普通のファイルと同じ構文色**で描く（削除行は古い版の本文全体を解いた色）。追加・削除は行の地と記号で見分け、字に diff 専用の色は持たない。空白の点も普通のファイルと同じ規則で出る。行の地は行番号の列の左端から面の右端（縦スクロールバーの列の下）まで届く。差し込んだ削除行は選べず、当たらない。diff の面はミニマップと git の印の列を持たず、スクロールバーに git の印も出さない。

## 並びの規則

並びは行差分の区間の列と両側の行の数だけから作る（純関数）。

- **インライン**: 区間の削除行は、区間の新しい側の始まりの境に、古い側の行を指す差し込みとして並べる。追加の区間には型「追加」を付け、旧番号を持たない。文脈の区間は旧番号の始まりを渡す（区間の中の行は番号が 1 ずつ進む）。最後の空の行（改行で終わる本文の末尾）は両側にあれば揃い、新しい側にだけあれば旧番号を持たない。
- **並列**: 文脈は両側とも型なし。変更区間は両側の同じ行から並べ、左は型「削除」、右は型「追加」。区間の削除と追加の数の差だけ、短い側の区間の後ろに詰め物（何も指さない差し込み。淡い地）を置く——続く文脈が左右で同じ高さに揃う。片側 0 件の区間は相手側に区間の件数ぶんの詰め物。

## 行差分

作業ツリー diff の差分は「文書の底（index の版）↔ 本文」の行差分そのもので、ガターと同じく文書が裏で取り、編集でずらして持つ（→ [code](code.md) のハンク）。diff を出している間だけ、文書の行差分の上限を**編集の数（削除と追加の行数の和）10,000** に上げる——共通の先頭・末尾を落とした残りが大きくても、編集の数が上限以下なら行ごとに取る（1MB のファイルの先頭と末尾を 1 行ずつ変えても、その 2 か所だけが変更になる）。編集の数は線形の記憶で上限まで数え、越えた時点で打ち切って残り全体を 1 つの変更区間（全部を削除して全部を追加）にする——時間は 1MB 級の最悪でも裏で 1 秒未満。diff を閉じれば（ファイルタブへ戻れば）ガターの上限（残りの行数 1000）に戻る。上限の結果が届くまでは前の上限の結果で並びを出し、届けば置き直す（見えている行は動かない）。

古い側は文書のハンクが比べた底から作り、並びは置くたびに文書の今の本文と今のハンクから作る——index の版が変わったとき、ハンクが新しい底に対する結果になるまでは前の底とそのハンクで出し続け、その間に外の書き換えで本文が変わってもハンクは今の本文へずらしてあるので、差し込みは古い側の本文とも今の本文ともずれない。底が今の古い側と違う間は並びを置き直さない。ステージ済み diff は両側とも変わらない版の本文なので、どちらかが変わったときに 1 回、両側の本文と行差分を裏で揃えてから入れ替える。

## 追従

diff タブを開いたまま、端末で `git add` / `git restore --staged` / ファイルの保存 / 外のツールの書き換え / コミットをすると、見えている diff が追従する（index と HEAD の変化は監視の到着から数百 ms 以内）。並びを置き直しても、見えている先頭の行は画面の同じ位置に残る。本体に出していない diff（焦点でない diff タブ）は追従せず、本体に出したときに今の版で作り直す——打鍵中に隠れた diff が裏の仕事を起こさない。ステージ済み diff は、版の状態が変わるたびに走っている裏の行差分を捨てる——表示できないに決まった後に、前の本文の結果が届いて表示に戻ることは無い。ファイルタブで編集してから diff タブへ戻ると、編集はそのまま diff に出ている。ステージ済みの rename の元パスは status から引き、status が変われば引き直す。

## 変化が無いとき・片側だけのとき・表示できないとき

- 変更が無ければ全文が地なしで出る。
- 片側だけ（未追跡・index への追加・作業ツリーやステージでの削除）なら、全部の行が追加か削除になる。その版に無い側は 0 行として数える。
- バイナリ・UTF-8 でない・作業ツリーのパスがシンボリックリンク・競合中・git から版を取れないときは、タブは開き、本体の中央に理由の一文が出る（空状態の一文と同じ字と色）。版の本文が届くまでの間は本体に何も出さない。

## 読むだけ

diff タブの本体では、打鍵・貼り付け・落とすが本文を変えない（選択・コピー・スクロールは効く）。⌘F と ⌘S も持たない（検索は文書の本文にしか効かず、削除行を探せない）。ファイルタブへ戻れば同じ面がコードの見え方（編集できる）に戻る。

## 入口

- **制御 API `open_diff {tabId, path, kind}`**（→ [api](../control/api.md)）。`path` は `open_file` と同じ解き方で根と根からの相対パスにし、普通のタブで開く。エディターを見える配置にし、タブを選んで本体へ焦点を移す（版の本文が届く前は面の器が焦点を預かり、面ができたときに面へ移す）。git 管理外は断る。
- セッションは diff を仮のタブで開く口も持つ（文書と diff で仮の枠は 1 つ → [shell](shell.md)）。

## 永続しない

diff タブは再起動で戻らない。タブの永続は文書のタブだけを書き、焦点が diff タブなら、diff タブを除いた列でその位置にある文書のタブ——右隣、無ければ左隣（焦点のタブを閉じたときに焦点が移る規則と同じ）を焦点として書く。インライン / 並列の選択だけは app-state に残る。

## VS Code との差

- **ファイルタブと作業ツリー diff で位置・選択・undo を共有する**（VS Code の diff エディターはファイルのエディターと位置が独立）。Orbe は undo とカーソルを面が持ち、1 文書に編集できる面は 1 枚なので、同じ文書は同じ面で見せる。
- **削除行も構文色で描き、空白の点も出す**。
- **⌘F・変更から変更への移動キー・スクロールバーの git の印を持たない**。
