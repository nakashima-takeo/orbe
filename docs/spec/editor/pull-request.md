# PR の状態

エディター面が GitHub の PR を読むための状態。PR の diff（→ [diff](diff.md#pr-の-diff)）が見るものを 1 か所に置くことで、同じ PR を見る面やタブのあいだで、確認済みや両端が食い違わないようにする。GitHub の読み書きの規則（ブランチの PR の引き方・PR の中身の読み方・確認済みの書き込み）は [GitHub の読み書き](../platform/github.md) が持つ。

見せるのは GitHub 上の PR の中身で、手元の作業ツリーではない——手元に未 push のコミットがあっても、PR の diff に出るのは GitHub が持つ PR の先頭まで（GitHub の Files changed と同じ差分）。確認済みは GitHub 上のコミットに付くので、PR の diff も GitHub 上のコミットを基準にする。

## 2 つの状態

- **worktree の今の PR**は、worktree の根ごとに 1 つ。今のブランチから出ている open の PR はどれか（最新の 1 件）、無ければ作成の入口の材料（ブランチ名・既定のブランチ名・既定のブランチの追跡 ref に対する先行の数・作成ページの URL・ブランチが GitHub に在るか）、出せなければその理由を持つ。PR があるときは、手元とのずれも持つ。
- **PR ごとの状態**は、手元のリポジトリ（`git-common-dir`）と PR の同一性ごとに 1 つ。最後に読めた中身、確認済み（GitHub が返した値と、書いている途中の値）、diff の両端、最後の失敗を持つ。

worktree の今の PR はブランチと一緒に変わる worktree の事実、PR ごとの状態は PR の事実で、寿命が違う。どちらもアプリが動いている間持ち続け（再起動では消える）、ブランチを切り替えても PR ごとの状態は消さない——同じ PR に戻れば、前の中身がすぐ出る。

## 出せない理由

worktree の今の PR は、次のときは GitHub に問い合わせずに理由だけを持つ: git 管理外・ブランチに居ない（detached）・既定のブランチ。既定のブランチは PR の head にならないとみなすので、fork の既定のブランチから親へ出した PR は読めず、「既定のブランチ」の理由になる（限界）。問い合わせた結果の理由は、gh が無い・gh で未ログイン・GitHub のリポジトリでない・GitHub のどのリポジトリか確かめられない・問い合わせの失敗（失敗の種類つき）。読むのは open の PR だけで、マージ済み・閉じた PR しか無いブランチは「open の PR が無い」になる。

## 見ている者と読み直すきっかけ

GitHub に問い合わせるのは、見ている者がいる間だけ。GitHub への問い合わせは 1 回ごとに秒単位の時間と回数制限の枠を使うので、見ている者がいなければ呼ばない。見ている者が去っても最後の答えは持ち続け、誰も見ていない状態から見ている者が現れたら、前の答えを出したまま裏で読み直す。ほかの者が見ている間に見ている者が増えただけでは読み直さない（PR の diff タブを開くたびに GitHub へ問い合わせない）——見ている者がいる間は、下のきっかけで読み直している。PR の diff タブは、開いている間その PR の状態を見ている者になる（誰も見ていなかった PR なら、開いたときにその中身を読み直す）。

worktree の今の PR を読み直すきっかけ:

- 誰も見ていない状態から見ている者が現れたとき、読み直しを頼まれたとき
- 今のブランチ名が変わったとき（前のブランチの答えは出さず、読んでいる状態から引き直す）。ブランチに居ない状態（rebase の途中を含む）から前と同じブランチに戻ったときも、ブランチ名が変わったとみなす
- Orbe の中のネット操作（プッシュ・プル・フェッチ・同期・公開・コミットしてプッシュ）が終わったとき
- リモート追跡の ref が動いたと根のサービスが知らせ、**かつ**このブランチの push 先の追跡 ref か、PR のベースブランチの追跡 ref の値が、前に見た値から変わっていたとき（前に見た値は、問い合わせを出す直前に読んだ値）

リモート追跡の ref が動いたという根のサービスの知らせは、どの ref が動いたかを名前で区別できないので、手元で 2 つの ref の値を読み、変わったときだけ GitHub に問い合わせる——無関係なブランチが fetch で動くたびに問い合わせない。ブランチを 1 本だけ取ったクローン（single-branch）は、ほかのブランチの追跡 ref を作らないので、追跡 ref の値の変化で読み直すことはない。GitHub への問い合わせの最中に次のきっかけが来たら、その問い合わせが終わった後に 1 回だけ読み直す（最初の問い合わせの最中も同じ）。worktree の今の PR を読み直すと、その PR の中身も読み直す。読み直しに失敗しても、前に読めた中身は残し、失敗だけを持つ（失敗は次の読み直し・確認済みの書き込みで消える）。

手元の HEAD が動いただけ（コミット・pull）なら、GitHub に問い合わせずに手元とのずれを数え直す。

## 確認済み

確認済みを付け外しすると、書いている途中の値をすぐ重ねて見せ、GitHub への書き込みは 1 つずつ順に送る（前の書き込みが終わってから次を送る）。変更ファイルに無いパスと、既にその値のパスは書かない。通ったパスは GitHub の値として確定し、通らなかったパスは重ねた値を外して元に戻し、失敗を持つ。

読み直しには出した順の通し番号を付け、通った書き込みには、GitHub が書き込みを受けたと分かった時点（書き込みの答えが届いた時点）の番号を付ける。パスごとに、最後に確定した書き込みの番号を覚え、それより前に出した読み直しの答えでは、そのパスの確認済みを上書きしない——書き込みの答えより前に出した読み直しは、GitHub が書き込みを受ける前の値を返しうるので、通ったチェックを外させない。書き込みの答えより後に出した読み直しは、GitHub の今の値で上書きする（ブラウザで外したチェックは、そこで出る）。書いている途中のパスも上書きしない。書き込みが通らなかったパスは番号を付けず、重ねた値を外すので、その後に届く読み直しの答えで GitHub の値が出る。走っている書き込みは、見ている者がいなくなっても最後まで走り、結果は状態に入る。

この規則で、読み直しと書き込みが重なっても、利用者が最後に押した値が残る。同じパスを続けて押したときは、後の書き込みが終わるまで後の値を重ねて見せる。見せている値は、前の書き込みの答えでも、後の書き込みが終わるまでに届いた読み直しの答えでも変わらない。

## diff の両端

diff の両端は、PR の中身の両端のコミット（PR が比べる基準のベース側のコミットと PR の先頭のコミット）の組ごとに 1 回だけ求める。手順は、マージベースを求める → どちらかのコミットが手元に無いと返ったときだけ、両端のコミットを fetch してもう一度求める → その間の rename の対応を読む。fetch は、PR が置かれたリポジトリを指す remote から、コミットを名指しして行う（ref・FETCH_HEAD・タグを書かない → [git](../platform/git.md)）。利用者が頼んでいない通信で、自動の fetch をオフにしていても起きる。2 回目も求まらなければ再度の fetch はせず、取得できなかったとして理由を持つ。共通の祖先が無い・git が読めないと返ったときは、fetch せずに理由を持つ。浅いクローンで、取ってある範囲より古い所で分かれた PR は、git が浅い境界より先をたどれず、本当に共通の祖先が無い場合と区別できないので、fetch せずに取得できなかったとして理由を持つ（両端のコミットを取ってきても求まらない）。

PR が置かれたリポジトリ（ベース側）を指す remote が手元に無いとき（push 先の fork だけを remote に持つクローンなど）は、コミットを取りに行けないので、手元に無いコミットがあれば取得できなかったとして理由を持つ。

求めるのは、見ている者がいて中身が読めたとき。中身の両端のどちらかが変わったら（PR への push・ベースブランチの付け替え）求め直す。求まらなかった両端は、読み直しを頼まれたときに求め直す。

## 手元とのずれ

PR があるときの手元とのずれは、PR の中身が読めた後に、手元の HEAD と PR の先頭の間で数える——一致・手元にしか無いコミットの数（未 push）と PR にしか無いコミットの数（未取得）。ずれは diff の両端のうちベース側には依らない——PR のベースブランチだけが動いて両端を求め直す間も、前に数えたずれのまま。PR の先頭のコミットが手元に無いとき（両端を求めるために取りに行っている間・取れなかったとき）は数えず、手元の HEAD が PR の先頭と違うことだけを持ち、取れた後に数える。
