# PR の状態

エディター面が GitHub の PR を読むための状態。PR のパネル（→ [pull-request-panel](pull-request-panel.md)）と PR の diff（→ [diff](diff.md#pr-の-diff)）が見るものを 1 か所に置くことで、同じ PR を見る面や diff のあいだで、確認済みや両端が食い違わないようにする。GitHub の読み書きの規則（ブランチの PR の引き方・PR の中身の読み方・確認済みの書き込み・レビューのやりとりの読み方と書き込み）は [GitHub の読み書き](../platform/github.md) が持つ。

見せるのは GitHub 上の PR の中身で、手元の作業ツリーではない——手元に未 push のコミットがあっても、PR の diff に出るのは GitHub が持つ PR の先頭まで（GitHub の Files changed と同じ差分）。確認済みは GitHub 上のコミットに付くので、PR の diff も GitHub 上のコミットを基準にする。

## 2 つの状態

- **worktree の今の PR**は、worktree の根ごとに 1 つ。今のブランチから出ている open の PR はどれか（最新の 1 件）、無ければ作成の入口の材料（ブランチ名・GitHub のどのブランチか・作成ページの URL・ブランチが GitHub に在るか → 作成の入口の材料）、出せなければその理由を持つ。PR があるときは、手元とのずれも持つ。
- **PR ごとの状態**は、手元のリポジトリ（`git-common-dir`）と PR の同一性ごとに 1 つ。最後に読めた中身、確認済み（GitHub が返した値と、書いている途中の値）、最後に読めたレビューのやりとりとその読みの失敗、レビューへの書き込みが走っている対象、PR の diff のコメントの書きかけ（スレッドへの返信と新しいコメントの、本文と、書きかけを作ったときの欄の位置 → [pull-request-comments](pull-request-comments.md#書きかけの残り方)）、レビューの送信の、全体へのコメントの書きかけ・選んだ種類・最後の送信の失敗、diff の両端、中身の読みの失敗、確認済みの書き込みの失敗を持つ。レビューの送信の規則（選べる種類・送れるか・送れない理由）と、未送信のコメントの一覧・今の diff に置けない未解決のスレッドの数も、PR ごとの状態が答える（→ レビューの送信）。

worktree の今の PR はブランチと一緒に変わる worktree の事実、PR ごとの状態は PR の事実で、寿命が違う。どちらもアプリが動いている間持ち続け（再起動では消える）、ブランチを切り替えても PR ごとの状態は消さない——同じ PR に戻れば、前の中身がすぐ出る。

## 出せない理由

worktree の今の PR は、次のときは GitHub に問い合わせずに理由だけを持つ: git 管理外・ブランチに居ない（detached）・既定のブランチ。既定のブランチは PR の head にならないとみなすので、既定のブランチを head とする PR（fork の既定のブランチから親へ出した PR、同じリポジトリの既定のブランチから別のブランチへ出した PR）は読めず、「既定のブランチ」の理由になる（限界）。問い合わせた結果の理由は、gh が無い・gh で未ログイン・GitHub のリポジトリでない・GitHub のどのリポジトリか確かめられない・問い合わせの失敗（失敗の種類つき）。ただし PR を引けている間の同じブランチの引き直しでは、確かめられない・問い合わせの失敗を理由にせず、PR を保つ（→ 見ている者と読み直すきっかけ）。読むのは open の PR だけで、マージ済み・閉じた PR しか無いブランチは「open の PR が無い」になる。

## 見ている者と読み直すきっかけ

GitHub に問い合わせるのは、見ている者がいる間だけ。GitHub への問い合わせは 1 回ごとに秒単位の時間と回数制限の枠を使うので、見ている者がいなければ呼ばない。問い合わせの前に手元で読むもの（追跡 ref の値・既定のブランチ）を読む間に見ている者が去ったら、問い合わせずに読むのをやめ、積んだ読み直しも捨てる（次に見ている者が現れたときに読み直す）。問い合わせの最中に去ったときは、届いた答えのうち、worktree の今の PR は答えを出さず、PR ごとの状態は中身を入れる（どちらも、その答えを受けて次の問い合わせはしない）。見ている者が去っても最後の答えは持ち続け、誰も見ていない状態から見ている者が現れたら、前の答えを出したまま裏で読み直す。ほかの者が見ている間に見ている者が増えただけでは読み直さない（PR の diff を開くたびに GitHub へ問い合わせない）——見ている者がいる間は、下のきっかけで読み直している。worktree の今の PR を見ている者は 2 段に分かれる。**どの PR かだけを追う者**がいる間は、今のブランチの PR を引く問い合わせだけをする。**中身も読む者**がいる間は、加えて PR があればその PR ごとの状態を見て（中身・スレッド・両端を読む）、PR が無ければ作成の入口の材料を読む。PR のパネルは、エディターの面が見えている間は追う者で（上のバーの番号のため。どの画面でも → [shell](shell.md) の上のバー）、PR の画面を出している間は中身も読む者になる（→ [pull-request-panel](pull-request-panel.md)）。エディターを閉じると見ている者がいなくなるので、開き直すたびに PR を引く問い合わせが 1 回走る（fork なら 2 回 → [GitHub の読み書き](../platform/github.md)）。PR の diff は、本体に出ていて面が見えている間だけ、その PR の状態を見ている者になる（誰も見ていなかった PR なら、見始めたときにその中身を読み直す）。PR の画面からほかの画面へ移る・エディターを閉じると PR の中身を見るのをやめ、PR の画面を出し直すと見始める——見ていない間に PR へ push があっても追わず、見始めたときの読み直しで追いつく。PR の diff のコメントの層は worktree の今の PR の答えを読むだけで、見ている者にはならない——diff の PR がその worktree の今の PR かで、未送信のレビューに積む書き込みを受けるかを決める（→ [pull-request-comments](pull-request-comments.md#書き込みの最中と結果)）。

worktree の今の PR が、今のブランチの PR を引き直すきっかけ:

- 誰も見ていない状態から見ている者が現れたとき、読み直しを頼まれたとき
- 今のブランチ名が変わったとき（前のブランチの答えは出さず、読んでいる状態から引き直す）。ブランチに居ない状態（rebase の途中を含む）から前と同じブランチに戻ったときも、ブランチ名が変わったとみなす
- Orbe の中のネット操作（プッシュ・プル・フェッチ・同期・公開・コミットしてプッシュ）が終わったとき
- リモート追跡の ref が動いたと根のサービスが知らせ、**かつ**このブランチの push 先の追跡 ref か、PR のベースブランチの追跡 ref の値が、前に見た値から変わっていたとき（前に見た値は、問い合わせを出す直前に読んだ値）
- Orbe が前面に戻ったとき（アプリが前面に戻った通知を受ける。見ている者がいるときだけで、エディターを閉じていれば問い合わせない）

引き直した PR が今の答えと同じなら、何も替えない——PR ごとの状態に触れず、PR の中身も読み直さない。PR が出来た・別の PR になった・無くなったなら答えを替え、中身も読む者がいれば新しい PR の中身を読み始める。open の PR が無いままなら答えを替えない。ブラウザで PR を作って Orbe に戻ると、前面に戻ったときの引き直しで答えが替わり、PR のパネルと上のバーが追いつく（→ [pull-request-panel](pull-request-panel.md#作成の入口)）。

リモート追跡の ref が動いたという根のサービスの知らせは、どの ref が動いたかを名前で区別できないので、手元で 2 つの ref の値を読み、変わったときだけ GitHub に問い合わせる——無関係なブランチが fetch で動くたびに問い合わせない。ブランチを 1 本だけ取ったクローン（single-branch）は、ほかのブランチの追跡 ref を作らないので、追跡 ref の値の変化で読み直すことはない。GitHub への問い合わせの最中に次のきっかけが来たら、その問い合わせが終わった後に 1 回だけ読み直す（最初の問い合わせの最中も同じ）。PR を引けている間に同じブランチの引き直しが失敗した（問い合わせの失敗・GitHub のどのリポジトリか確かめられない）ときは、答えを替えずに PR を保ち（PR ごとの状態を見続ける）、読みの失敗として持つ（→ 失敗）——一時的な失敗のたびに PR が消えて、中身の追従が止まらないように。gh が無い・未ログイン・GitHub のリポジトリでないと分かったときと、成功の答えで open の PR が無かったときは、答えを替える。PR ごとの状態の中身とレビューのやりとりの読み直しに失敗しても、前に読めたものは残し、失敗だけを持つ（中身とレビューのやりとりの失敗は別々に持つ → 失敗）。

手元の HEAD が動いただけ（コミット・pull）なら、GitHub に問い合わせずに、手元とのずれを数え直す。

PR ごとの状態の中身とレビューのやりとりを読み直すきっかけ（見ている者がいる間だけ。2 つは別の問い合わせで、どちらも読んでいる間に来た読み直しは終わった後に 1 回だけ読む）:

- 誰も見ていない状態から見ている者が現れたとき、読み直しを頼まれたとき
- その PR のリポジトリで、Orbe の中のネット操作が終わったとき
- リモート追跡の ref が動いたと根のサービスが知らせ、**かつ**その PR の先頭のブランチの追跡 ref（PR の先頭のブランチが置かれたリポジトリを指す remote の下）か、ベースブランチの追跡 ref（PR が置かれたリポジトリを指す remote の下）の値が、前に見た値から変わっていたとき（前に見た値は、問い合わせを出す直前に読んだ値。中身が読めて追跡 ref が分かった時点でも覚える）

worktree の今の PR はどの PR かを引く役で、引き直しても PR の中身は読み直さない——同じきっかけ（ネット操作の終わり・同じ追跡 ref の動き）では、worktree の今の PR がブランチの PR を 1 回、PR ごとの状態が中身とレビューのやりとりを 1 回ずつ問い合わせる。ほかの人の新しいコメントは、これらのきっかけか自分の書き込みの後の読み直しまで出ない（定期的には問い合わせない）。worktree の今の PR が別の PR を見始めたときは、その PR を誰も見ていなかったなら、PR ごとの状態が中身を読み直す。

## 作成の入口の材料

open の PR が無い答えには、作成の入口（→ [pull-request-panel](pull-request-panel.md#作成の入口)）の材料——ブランチが GitHub に在るか——が付く。材料を読むのは中身も読む者がいる間だけで、材料が古いか、まだ読んでいないときに読む（→ [GitHub の読み書き](../platform/github.md#ブランチが-github-に在るか)）。材料を古くするきっかけは、PR を引き直すきっかけとは別の並びで、ブランチが GitHub に在るかが変わりうるものだけ:

- 誰も見ていない状態から見ている者が現れたとき、読み直しを頼まれたとき
- 今のブランチ名が変わったとき
- Orbe の中のネット操作が終わったとき
- 追跡 ref の値が変わったとき——根のサービスの知らせで比べたとき（上の、PR を引き直すきっかけと同じ）と、PR を引き直す前に追跡 ref の値を覚え直して、前に覚えた値と違っていたとき

Orbe が前面に戻ったことは材料を古くしない。前面に戻っても PR が無いままなら、GitHub への問い合わせは PR を引く 1 回だけで、作成のボタンの姿は動かない。覚え直した値を比べるのは、Orbe の操作でない push（裏のタブのエージェントなど）がブランチを公開し、根のサービスの知らせが届く前に前面へ戻ったときも、作成のボタンを押せる姿にするため。読み直している間は前の値を出したまま。問い合わせは 1 本ずつで、その間に材料が古くなったり答えが替わったりしたら、結果を入れずに読み直す。

## 確認済み

確認済みを付け外しすると、書いている途中の値をすぐ重ねて見せ、GitHub への書き込みは 1 つずつ順に送る（前の書き込みが終わってから次を送る）。変更ファイルに無いパスと、既にその値のパスは書かない。通ったパスは GitHub の値として確定し、通らなかったパスは重ねた値を外して元に戻し、失敗を持つ。

読み直しには出した順の通し番号を付け、通った書き込みには、GitHub が書き込みを受けたと分かった時点（書き込みの答えが届いた時点）の番号を付ける。パスごとに、最後に確定した書き込みの番号を覚え、それより前に出した読み直しの答えでは、そのパスの確認済みを上書きしない——書き込みの答えより前に出した読み直しは、GitHub が書き込みを受ける前の値を返しうるので、通ったチェックを外させない。書き込みの答えより後に出した読み直しは、GitHub の今の値で上書きする（ブラウザで外したチェックは、そこで出る）。書いている途中のパスも上書きしない。書き込みが通らなかったパスは番号を付けず、重ねた値を外すので、その後に届く読み直しの答えで GitHub の値が出る。走っている書き込みは、見ている者がいなくなっても最後まで走り、結果は状態に入る。

この規則で、読み直しと書き込みが重なっても、利用者が最後に押した値が残る。同じパスを続けて押したときは、後の書き込みが終わるまで後の値を重ねて見せる。見せている値は、前の書き込みの答えでも、後の書き込みが終わるまでに届いた読み直しの答えでも変わらない。

## レビューのやりとり

レビューのやりとり（スレッドと自分の未送信のレビュー → [GitHub の読み書き](../platform/github.md#レビューのやりとり)）は、中身とは別の値で持つ——スレッドが変わるたびに、中身から組んだパネルの列を組み直させない。スレッドを diff に置けるのは、読んだ時点の PR の先頭のコミットが、diff が見せている先頭のコミットと同じときだけ。違う間（PR に push があった後、読み直しが届くまで）は、スレッドはまだ無いものとして扱い、古い版の行のスレッドを新しい版の行に置かない。

中身とレビューのやりとりを読んだ時点の PR の先頭のコミットが食い違ったら、両方を読み直して揃える——書き込みの後に読み直すのはレビューのやりとりだけなので、書いている間に push があるとレビューのやりとりだけが新しい先頭を読む。中身とレビューのやりとりを並べて読む間に push があっても食い違う。そのままではスレッドを置けず、新しいスレッドも受け付けない。どちらの答えが古いかは、出した順からも届いた順からも決まらないので、当てにいかない。両方の答えが届いて食い違っていたら、それより後に出す読みで両方を読み直す——GitHub の答えが一貫していれば、その 2 本の間に push が無い限り揃う。なお食い違っていて、揃え始めてから見ていない先頭のコミットが現れたら（間に push があった）、もう一度両方を読み直す。現れなければ（GitHub の答えが一貫していない）、次のきっかけまで読まない。揃える読みが失敗したら、その失敗（中身の失敗か、レビューのやりとりの失敗）を持ったまま揃えるのをやめ、次のきっかけでまた揃えにいく。どちらかを読んでいる間は待ち、両方の答えが届いた後に見比べる。誰も見ていない間は読まない。先頭が揃っていれば読みは増えない。1 つのきっかけから出る読みは、その間の push が k 回なら、読み直し（中身とレビューのやりとり）のきっかけで 2 + 2k 本まで、書き込みの後の読み直しで 1 + 2k 本まで（GitHub の答えが一貫していないときは、揃える読みの 2 本がさらに足される）——揃える読みを重ねるたびに、まだ見ていない先頭のコミットが要り、push 1 回で現れる先頭は 1 つだから。

レビューへの書き込み（新しいスレッド・返信・解決と、その取り消し・送信）は PR ごとに 1 つずつ順に送り（確認済みの書き込みとは別の列で、互いを待たない）、次のように扱う。

- **受け付け**: 中身とレビューのやりとりがまだ読めていなければ受け付けない。新しいスレッドは、頼んだ diff が行を決めた両端が PR の今の diff の両端と違うときと、行を数えた diff の先頭のコミットが、レビューのやりとりを読んだ時点の先頭のコミットと違うときは受け付けない（スレッドを置かないのと同じ間。古い版の行番号で書かせない）。レビューの送信は、diff の両端を求め終え、その先頭のコミットで中身とレビューのやりとりも読んでいる間だけ受け付ける（ファイルの列・diff・スレッドと、送るレビューの版を揃える）。同じスレッドへの書き込み・同じ新しいコメントの書きかけからの新しいスレッド・レビューの送信は、走っている間と順番を待っている間は、同じ対象への次の書き込みを受け付けない——2 回押しても 2 回は送らない。この「走っている対象」は PR ごとの状態が持つ事実で、同じ PR を見るどの画面からも同じに見える。
- **1 つの書き込みの終わり**: mutation のレスポンスが届いたら、レビューのやりとりを読み直し、その読み直しが届いて初めて終わる。結果（通ったか、失敗の種類）は、書き込みを頼んだ者へ 1 回だけ返す。返信と新しいスレッドは、PR ごとの状態が持つ書きかけの本文を送り（新しいスレッドの行は、頼んだ diff が決めた行）、通ったら（返信は、「解決して返信」で解決だけが通らなかったときも）結果を返す前にその書きかけを消す——頼んだ者が先に消えていても消えるので、送った本文が書きかけに残って二度送られることはない。通らなければ書きかけは残る。mutation がタイムアウトで失敗したときも読み直す（GitHub に届いていれば、読み直しに出る。二重に書くかは利用者が決める）。mutation が通って読み直しが失敗したら、書き込みは通ったとして返り、状態はレビューのやりとりの読みの失敗を持つ。
- **古い読みを取り込まない**: 書き込みのレスポンスより前に出した読みのレスポンス（読めた値も、読みの失敗も）は、GitHub が書き込みを受ける前の姿を返しうるので取り込まず、その後に出した読み直しのレスポンスを取り込む。
- **未送信のレビューの名指し**: 書き込みが名指しする未送信のレビューは、最後に取り込んだ読みのものか、その後の書き込みのレスポンスで分かったもの（作った・送信で無くなった）。
- **見ている者が去った後**: 受け付けた書き込みは最後まで順に送り、結果を頼んだ者へ返す。読み直しはしない（誰も見ていない間は問い合わせない）。次に見ている者が現れたときの読み直しで、GitHub の今の姿が出る。

## レビューの送信

レビューの送信の規則は PR ごとの状態が持ち、バーのボタンとポップアップ（→ [pull-request-review](pull-request-review.md)）は読むだけ——同じ PR を出すどの面でも同じ答えになる。選べる種類は、レビューのやりとりが読めていなければ無し、自分の PR は「コメント」だけ、ほかは「コメント・承認・変更を依頼」。送れるかは、版が揃っていて、選んだ種類を選べ、承認であるか、全体へのコメント（書きかけに、問う側の欄に見えている変換中の字を足したもの）が空白だけでないか、未送信のコメントがあるとき。変換中の字は面ごとの欄が持つ事実なので、状態へは写さず、問う側が渡す——同じ PR のポップアップを 2 つの面で開いても、片方の変換中の字がもう片方の可否を変えない。送るときは、面が先に変換を確定してから頼むので、送る本文は状態の書きかけだけで決まる。送信は、受け付けたら前の送信の失敗を消し、終わったときに通ったかを頼んだ側へ 1 回返す。通れば書きかけを空にして種類をコメントに戻し、通らなければ書きかけを残して送信の失敗を持つ。

未送信のコメントの一覧は、最後に読めたレビューのやりとりから、未送信のコメントを 1 件ずつ取り出したもの（コメント・スレッド・パス・側・行・本文・今の diff に置けるか）。組み直すのは、レビューのやりとり・変更ファイルの列・diff の両端のどれかが変わったときだけ。

## 失敗

失敗は、続く状態か 1 回の出来事かで持ち方を分ける——札（→ [pull-request-panel](pull-request-panel.md#出せない理由と失敗)）を × で閉じたときの働きが違うため。

- **読みの失敗**（続く状態）: 中身の読み・レビューのやりとりの読み（PR ごとの状態）と、PR を保ったままの今のブランチの PR の引き直し（worktree の今の PR）。最後の読みが失敗した理由を持ち、次に読めたら（引き直しは、次に答えを出したら）消える。3 つは人には「GitHub から読めていない」1 つの知らせで見せ、その知らせを閉じた印は、知らせの単位で 1 つ、worktree の今の PR が持つ。知らせを閉じると印を付け、失敗の値は残す。印が外れるのは、読めていない状態が終わった（3 つの読みのどれも失敗していない）とき・人が読み直しを頼んだ（上のバーの再読込と、本体の「再読込」）とき・worktree の今の PR が替わったときだけ——自動の読み直し（前面に戻った・追跡 ref の変化・ネット操作の終わり・見始め）で、一部の読みだけが通っても、別の読みが初めて失敗しても、閉じた知らせを出し直さない。理由を読む所（PR の中身がまだ読めていない間の本体の表示と左の列の一言、「レビュー」のボタンのツールチップ）は印に依らない。
- **書き込みの失敗**（1 回の出来事）: 確認済みの書き込みと、レビューの送信。理由だけを持ち、知らせを閉じると消える。次の同じ書き込みを始めたときにも消える。中身の読みの成功では消えない。

印も値も持ち主（PR ごとの状態と worktree の今の PR）にあるので、同じ PR を出すどの面でも同じに見え、閉じれば、ほかの面でも閉じる（PR の head のブランチを取り出せる worktree は 1 つなので、同じ PR を出す面は同じ worktree の今の PR を読む）。読みの失敗の値は表示のほかには使わず、読み直し・版を揃える読みの判定は失敗の値を読まない。

## diff の両端

diff の両端は、PR の中身の両端のコミット（PR が比べる基準のベース側のコミットと PR の先頭のコミット）の組ごとに 1 回だけ求める。手順は、マージベースを求める → どちらかのコミットが手元に無いと返ったときだけ、両端のコミットを fetch してもう一度求める → その間の rename の対応を読む。fetch は、PR が置かれたリポジトリを指す remote から、コミットを名指しして行う（ref・FETCH_HEAD・タグを書かない → [git](../platform/git.md)）。利用者が頼んでいない通信で、自動の fetch をオフにしていても起きる。2 回目も求まらなければ再度の fetch はせず、取得できなかったとして理由を持つ。共通の祖先が無い・git が読めないと返ったときは、fetch せずに理由を持つ。浅いクローンで、取ってある範囲より古い所で分かれた PR は、git が浅い境界より先をたどれず、本当に共通の祖先が無い場合と区別できないので、fetch せずに取得できなかったとして理由を持つ（両端のコミットを取ってきても求まらない）。

PR が置かれたリポジトリ（ベース側）を指す remote が手元に無いとき（push 先の fork だけを remote に持つクローンなど）は、コミットを取りに行けないので、手元に無いコミットがあれば取得できなかったとして理由を持つ。

求めるのは、見ている者がいて中身が読めたとき。中身の両端のどちらかが変わったら（PR への push・ベースブランチの付け替え）求め直す。求まらなかった両端は、中身を読み直すきっかけ（→ 見ている者と読み直すきっかけ）のたびに、上の手順で求め直す（コミットが手元に無いと返れば、そのたびにもう一度 fetch する）。

## 手元とのずれ

PR があるときの手元とのずれは、PR の中身が読めた後に、手元の HEAD と PR の先頭の間で数える——一致・手元にしか無いコミットの数（未 push）と PR にしか無いコミットの数（未取得）。ずれは diff の両端のうちベース側には依らない——ベースの付け替えで両端のベース側だけが変わり、両端を求め直す間も、前に数えたずれのまま（基準のベース側のコミットは、ベースブランチへの push では変わらないとしている。GitHub の振る舞いとして確かめていない → [GitHub の読み書き](../platform/github.md#pr-の中身)）。PR の先頭のコミットが手元に無いとき（両端を求めるために取りに行っている間・取れなかったとき）は数えず、手元の HEAD が PR の先頭と違うことだけを持ち、取れた後に数える。浅いクローンでは数えず、手元の HEAD が PR の先頭と同じなら一致、違えば違うことだけを持つ——マージベースが求まっても、git は浅い境界の先をたどれず、数が誤りうる。浅くなくなった後（`--unshallow` など）は、次に PR の中身を読み直したときか手元の HEAD が動いたときに数える。浅くないリポジトリでは、共通の祖先が無い PR でも、手元の HEAD と PR の先頭のそれぞれにしか無いコミットの数を数える。
