# プロジェクト検索

タブのエディターの根（→ [files](files.md)）の全体を探し、一致をファイルごとに並べ、押せばその一致を開く。端末で作業している途中でもキー 1 つで入力欄まで届き、打つだけで結果が流れ込む。振る舞いは VS Code の検索ビューの既定に揃え、揃えない所は末尾に挙げる。見た目は [design-system](../../design/design-system.md) §5 の Search panel。

## 入口

- **⌘⇧F** は端末に焦点があっても効く window コマンド（→ [layout](../chrome/layout.md)）。エディターが隠れていれば全面にし、見えていれば焦点だけを移す（`open_file` と同じ規則）。サイドバーを検索パネルで開き、入力欄に焦点を入れて前の検索語を全選択する。0 タブでは何も起きない。
- **種**: 押した時点の焦点が本文で、1 行以内の非空の選択があればそれを検索語に入れて即時に検索する（正規表現が有効なら字どおりになるようエスケープする）。⌘F のバーの入力欄に焦点があればその検索語。それ以外は種を入れない——キャレットの語は使わない（VS Code の既定）。焦点が既に検索パネルにあれば種は入れない。
- **レール**の「検索」を押すと検索パネルへ切り替わり（閉じていれば開き）、入力欄に焦点が入る。検索パネルを出している間にもう一度押すと閉じる（→ [shell](shell.md) のレール）。

## 入力しながら検索

入力欄に打つと、打つのが止まって少し後に根の全体を検索する。Enter・切替・ヘッダーの更新は即時に検索し直す。打ち続けても前の結果は消えずに残り、新しい検索の結果が最初に届いたとき（または終わったとき）に置き換わる——打つたびに結果がちらつかない。空にすると検索を止めて結果を消す。結果はファイルごとにまとまって流れ込み、途中でも見える。

検索中はヘッダーの下端に細い線が流れる（打鍵の検索では少し遅れて出る——速く終わる検索で線がちらつかない）。2 秒を超えた検索ではヘッダーの更新が停止に替わり、押すと止まる。入力欄か結果の列で Esc を押しても検索中なら止まる（検索語は消えない）。止めても、それまでに届いた結果は残る。

## 問いの規則

問いは検索語と 3 つの切替——大文字と小文字を区別（Aa・⌥⌘C）・単語単位（ab・⌥⌘W）・正規表現（.*・⌥⌘R）——で、切替は入力欄の右のボタンか、パネルに焦点があるときのキーで変わる。問いを式に組み立てる規則は 1 か所にある。

- 正規表現でなければ検索語は字どおりに探す。
- 大小を区別しないときは Unicode の大小無視。
- 単語単位は、検索語の先頭の字が単語の字ならそこに単語の境界を足し、末尾の字が単語の字ならそこにも足す（VS Code の検索ビューのディスク側と同じ規則）。単語の字は Unicode の `\w`——日本語も単語の字で、`日本` の単語単位は前後が単語の字に接する出現に当たらない。この規則は開いている文書にも同じに当てる。
- 正規表現の文法は ICU（macOS の正規表現）。ICU で組めない式は入力欄の下に「正規表現が正しくありません。」を出し、検索しない。ICU は通すがディスク側（git grep の PCRE2）が断る書き方は、git の断った理由を同じ場所に出す。1 行の中で探し、複数行にまたがる一致は探さない。

### ディスクと開いている文書の差

ディスクのファイルは git grep が一致した行を送り、その行の中の一致の位置は ICU が同じ式で取る（ICU で 1 つも取れない行は結果にしない）。開いている文書は ICU だけで探す。したがってディスクのファイルで拾えるのは「PCRE2 でも ICU でも一致する行」で、ASCII の検索では差が出ないが、次の 3 種では開いている文書より拾う行が少ないことがある。

- **大小無視の畳み込み**: ICU は `straße` と `STRASSE`、合字 `ﬁ` と `fi` を同じと見るが、PCRE2 は見ない。
- **単語の字の範囲**: 結合文字などで、2 つのエンジンの `\w` の範囲が細部で違う（単語単位の境界もそれに従う）。
- **両エンジンで意味の違う正規表現の書き方**: 利用者が書いた式のうち、2 つの文法で解釈の違うもの。

## 対象

根の下を、根が git 管理下でも管理外でも同じ 1 つの形で探す。

- `.gitignore`（入れ子のものも）・`.git/info/exclude`・git の全体の除外ファイル（`core.excludesFile`。VS Code の既定は効かせない）に書かれたものは出ない。
- 既定の除外——`node_modules`・`bower_components`・`.git`・`.svn`・`.hg`・`.jj` の配下と、`.DS_Store`・`Thumbs.db`・`*.code-search`——は出ない（VS Code の `search.exclude` と `files.exclude` の既定）。含める／除外するファイルの欄は持たない。
- バイナリ（NUL を含むファイル）は出ない。
- サブモジュールと入れ子のリポジトリの中も探す（VS Code と同じ）。
- UTF-8 でないバイトは置換文字として見せる（押して開けば、UTF-8 でないファイルは今の開き方のとおり音で断る）。
- 根がホームのような巨大なディレクトリでも探し、上限・止める・打ち換えで打ち切る。macOS の保護されたフォルダへの許可を求める表示が出うる。

## 開いている文書

根の下で既定の除外に当たらない開いている文書は、ディスクではなく**保存前の中身**を探し、ディスクの同じファイルの行は捨てる（同じファイルが二重に出ない）。開いている文書の結果は、どの版の本文を探したかを持つ。

- 結果に出ている文書を編集すると、その一致の位置は編集に合わせてずれ（字から離れない）、少し後にその文書だけを探し直す。行・プレビューは探し直すまで前のまま。
- 開いているが焦点に無い文書が外（エージェント等）で書き換えられて差し替わっても、少し後にその文書だけを探し直す。
- 探し直した結果が一致 0 ならそのまとまりは消える。検索の最中に文書を編集しても、その文書の結果は消えない（古い版の結果は捨てて、今の本文で探し直す）。
- 面が隠れている間に文書が変わっていれば、面が見えたときと文書が焦点に来たときに探し直す。
- 探し直すのは結果に出ている文書だけで、結果に無いファイルに新しく一致が生じても足さない。ディスクのファイルの外部変更も結果に反映しない（更新で探し直す）——どちらも VS Code と同じ。

## 結果

- ファイルごとのまとまりを**パスの順**に並べる。パスは区切りごとに名前で比べ、名前は大小無視で数を数として比べ（`file2` が `file10` より前）、同じ階層ではファイルが先。名前の比べ方はエクスプローラーと同じ 1 つ（→ [shell](shell.md)）。
- まとまりの見出しは種別チップ・ファイル名・ディレクトリ・一致の件数。見出しは既定で全部開いている。
- 一致の行は、一致の前（先頭の空白を削り、長ければ単語の境で切って `…` を前に付ける）・一致・後ろを出し、列の幅に収まらなければ後ろ、前の頭、一致の順に省略する。
- 一致の総数は **20000 件で打ち切り**、「結果は一部だけです。検索を絞り込んでください。」を出す。
- パネルの下に件数（「N ファイル内に M 件の結果」）を固定で出す。0 件なら「結果がありません。除外の設定と .gitignore を確認してください。」。
- ヘッダーのクリアは検索語と結果を消して入力欄に焦点を戻す。すべて折りたたむ／すべて展開は、開いたまとまりが 1 つでもあれば折りたたむ側になる。

## キーとマウス

入力欄:

- Enter で即時に検索、⌘↓ で結果の列へ（未選択なら先頭の行を選ぶ）。↓ は何もしない（入力の履歴は持たない）。

結果の列:

- ↑↓ は選択だけを動かし、**開かない**。
- ← は一致なら親の見出しへ、見出しなら畳む。→ は畳んだ見出しなら開き、開いた見出しなら最初の一致へ。
- Enter は見出しなら開閉、一致なら開いて本文へ焦点を移す。
- ⌘↑ は先頭の行（か未選択）で入力欄へ戻る。
- Esc は検索中なら止め、そうでなければ選択を外す。

マウス: 一致のシングルクリックは選んで開き、焦点は結果の列に残る（続けて ↑↓ で渡れる）。ダブルクリックは開いて本文へ焦点を移す。見出しのクリックは開閉。

**F4 / ⇧F4** はエディター面（焦点が面の中）にあるとき、選択の次・前の一致を選んで開き、本文へ焦点を移す。畳まれたまとまりは開き、端では先頭・末尾へ回る。検索パネルが隠れていれば出す。結果が無ければ本文へ素通しする。

## 開き方と焦点

一致を開くと、そのファイルが開き（既に開いていれば焦点を移すだけ）、一致が選択され、一致の行が本文の中央に来る——見えていても中央へ送る（VS Code と同じ）。横に隠れていれば横にも寄る。エクスプローラーもそのファイルを選択表示する。ディスクの結果から開いたまとまりは、その時点から開いている文書のまとまりとして扱う。

検索パネルの入力欄と結果の列は面の配下なので、焦点がそこにある間も chrome キーは効く。焦点がパネルに入ると、分割中の面の記憶もエディターへ移る。面の中で文書が切り替わっても、パネル（サイドバー）にある焦点は動かない。

## 一致の地

検索パネルが見えている間、焦点の文書の一致がファイル内検索（→ [code](code.md)）と同じ地で本文・ミニマップ・スクロールバーに出る。選んだ一致は「現在の一致」の地になる。検索パネルを隠す（レールで閉じる・エクスプローラーへ切り替える）と地は消える。⌘F と同時に使えば両方の一致が出る——面の「一致の地」は 1 つで、2 つの出どころの和を押す。

## 状態と永続

- 検索語と 3 つの切替は**タブごと**に持ち、再起動でも戻す（→ [persistence](../platform/persistence.md)）。結果は戻さない——再起動後は入力欄に前の検索語が入った状態で、Enter か更新で検索する。
- サイドバーにどのパネル（ファイル／検索）を出すかは**アプリ全体で 1 つ**で、再起動でも戻す（サイドバーの幅・開閉と同じ → [shell](shell.md)）。
- 根が変わる（cd）と検索を止めて結果を捨て、検索パネルが見えていれば今の問いで検索し直す。

## VS Code との差

- **仮のタブ（プレビューのタブ）を持たない**: 結果は普通のタブで開き、↑↓ では開かない（結果を渡り歩くにはクリックか Enter）。
- **F4 / ⇧F4 はエディター面に焦点があるときだけ**: 端末では F4 が端末アプリ（TUI）に届く。
- **種にキャレットの語を使わない**: VS Code の `seedWithNearestWord` の既定と同じ。
- **単語単位の規則を開いている文書にも同じに当てる**: VS Code は開いているエディターだけ区切り文字の設定で判定する。
- **全体の除外ファイル（`core.excludesFile`）が効く**。
- 置換・「エディターで開く」・入力の履歴・含める／除外するファイルの欄・ツリー表示との切替は持たない。
