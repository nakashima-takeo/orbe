# PR のパネル

今の worktree のブランチから出ている open の PR を、エディター面のサイドバーで読む場所。ブラウザの GitHub へ移らずに、PR の題・説明・コミット・変更ファイルを見て、変更ファイルを PR の diff（→ [diff](diff.md#pr-の-diff)）で開き、確認済み（GitHub の Files changed の Viewed）を付け外しする。パネルが見せるのは 2 つの状態（→ [pull-request](pull-request.md)）——worktree の今の PR と PR ごとの状態——で、パネル自身は見せ方（区分とフォルダの開閉・選択・説明の開閉）だけを持つ。同じ PR を見る PR の diff タブ・タブ行の「確認済みにする」・TopBar と、確認済みや中身が食い違わない。

レールの 4 つ目の項目「プルリクエスト」で開く（→ [shell](shell.md)）。パネルを出している間だけ worktree の今の PR を見る——GitHub に問い合わせるのは、パネルを出している間か PR の diff タブを開いている間だけ。パネルを別のパネルへ切り替えて戻すと、前の中身がすぐ出て裏で読み直す。寸法と色は [design-system](../../design/design-system.md) §5 の PR panel。

## 構成

上からパネルヘッダー（題「プルリクエスト」・再読込・GitHub で開く）と、worktree の今の PR の答えに応じた中身。

- **PR がある**: 頭（PR の印・題と番号・作者 · `head → base`・手元とのずれの帯）、失敗の文（あれば）、列（説明・コミット・変更ファイル）、下端のレビューの送信の区画（レビューのやりとりが読めてから）。中身がまだ読めていない間は何も出さず、最初の読み込みが失敗すれば失敗の文だけを出す。
- **open の PR が無い**: 作成の入口。
- **出せない**: 理由の一文だけ。
- **読んでいる**: 何も出さない。

再読込は、worktree の今の PR を引き直し、PR があればその中身も読み直す。GitHub で開くは、中身が読めている間だけ出て、PR のページをブラウザで開く。

## 頭

PR の印は、open の PR を success、ドラフトを弱い色で描く。題は折り返し、番号は弱い色で題に続ける。2 段目に作者（消えたアカウントなら出さない）と `head → base`（先頭のブランチ名 → ベースブランチ名。収まらなければ末尾を省く）。

その下の帯は、手元とのずれ（→ [pull-request](pull-request.md#手元とのずれ)）を 3 通りで知らせる。

| ずれ | 帯 |
|---|---|
| 手元の HEAD が PR の先頭と同じ | レ点と「この worktree でチェックアウト済み」（success） |
| 数えられた | 「未 push のコミットが N 件あります」「PR に未取得のコミットが N 件あります」（注意の黄。両方あれば「・」でつなぐ） |
| 数えないが違う（PR の先頭が手元に無い・浅いクローン） | 「この worktree の HEAD は PR の先頭と違います」（注意の黄。手元が先か PR が先かは言わない——浅いクローンでは未 push のずれもここに入る） |

ずれを数え終わるまでは帯を出さない。帯の文は省かず、幅に収まらなければ折り返して全文を出し、帯は行数に従って伸びる（題と同じ扱い。意味の要の語が末尾に来るので、省くと読めない）。帯より下は、帯の高さに従って下がる。

## 列

説明・コミット・変更ファイルを 1 本の列で流す。列は見えている行だけを描く——変更ファイルは GitHub の上限まで（数千件）ありうる。

- **説明**は列の頭で、行と一緒にスクロールする。見出しと、本文の先頭 3 行（書かれた Markdown の字のまま。越える分は末尾を省く）。見出しを押すと畳む。説明が空なら見出しごと出さない。説明の見出しは行ではなく、キーでは選べない（ソース管理の親の見出しと同じ扱い）。
- **コミット**は区分の見出し（総数のバッジ）と、PR のコミットの行（題の 1 行目と短い sha）。並びは GitHub の PR と同じく古い順。GitHub は新しい側の 250 件までしか返さないので、総数が読めた件数より多ければ、先頭に「古いコミット N 件は表示していません」の行を置く。コミットの行は押せず選べない（ソース管理のグラフと同じ）。
- **変更ファイル**は区分の見出し（「N/M 確認済み」とツリー表示・リスト表示の切り替え）と、変更ファイルの行。ツリーはエクスプローラーと同じ並び（フォルダが先・名前順。1 つしか子の無いフォルダも畳まない）で、フォルダの行は右に配下の「確認済みの数/ファイルの数」を出す。リストはソース管理の行と同じパス順で、名前の後にディレクトリを出す。ファイルの行の印は、追加が A（青）、それ以外が M（黄）。印の左に、そのファイルの今の diff に置けるスレッドのコメントの総数を出す（0 なら出さない。→ [pull-request-comments](pull-request-comments.md)）。コメントの数が変わっても行は組み直さず、見えている行を描き直す。

ツリーかリストかはアプリ全体で 1 つで、再起動でも戻る（→ [persistence](../platform/persistence.md) の app-state）。区分とフォルダの開閉・説明の開閉・選択は面ごとで、永続しない。

## 確認済み

ファイルとフォルダの行頭にチェックがある。ファイルのチェックは、そのファイルの確認済みを切り替える。フォルダのチェックは配下をまとめて切り替える——配下が全部確認済みなら全部外し、そうでなければ全部付ける。フォルダのチェックは、配下が全部確認済みなら付いた姿、一部なら横線、無ければ空。確認済みのファイルの行と、配下が全部確認済みのフォルダの行は、全体を薄く描く。

付け外しは押した瞬間に出て、GitHub への書き込みは裏で順に送る。通らなければ元に戻り、失敗の文が出る（→ [pull-request](pull-request.md#確認済み)）。確認済みを付け外ししても行は組み直さず、見えている行を描き直す。

## PR の diff を開く

変更ファイルの行は、その PR の diff（→ [diff](diff.md#pr-の-diff)）を開く。シングルクリック・↑↓・→ でファイルの行へ動くと仮のタブで開き、焦点は列に残る（押し続けた ↑↓ は離してから開く。ソース管理の列と同じ間引き）。ダブルクリック・Enter は普通のタブで開き、本文へ焦点を移す。

## キーと焦点

選べるのは区分の見出し・フォルダ・ファイルの行。キーはソース管理の変更の列と同じ型。

| キー | 働き |
|---|---|
| ↑↓ | 選べる行を順に渡る。未選択なら先頭。ファイルの行なら仮のタブで開く |
| ← | 開いた見出し・フォルダなら畳み、そうでなければ親（フォルダか変更ファイルの見出し）へ |
| → | 畳んだ見出し・フォルダなら開き、開いていれば最初の子の行へ（ファイルの行なら仮のタブで開く） |
| Enter | ファイルの行は普通のタブで開いて本文へ、見出し・フォルダは開閉 |
| Esc | 選択を外す |

全体へのコメント欄の ⌘↵ はレビューの送信（→ レビューの送信）。

見出し・フォルダのクリックは開閉。確認済みのキーは持たない（チェックを押す）。

選択は常に見えている行にある。行の組は、PR の中身・ツリーかリストか・開閉のどれかが変わったときに組み直し、そのとき選んでいた行が無くなっていれば選び直す（開かない）。

- **畳んで隠れた**: フォルダを畳めば、その下の選択（ファイルでもフォルダでも）はそのフォルダへ、区分を畳めば、その下の選択は区分の見出しへ移る。開き直しても元の行へは戻らない。
- **ツリーからリストへ切り替えてフォルダの行が無くなった**: 配下の最初のファイルへ移る（見ていた場所の近くに残す）。
- **読み直しで消えた**（PR の変更ファイルから外れた）: 変更ファイルの区分の同じ位置の行（無ければ最後の行）へ移る。区分に行が無ければ選択を外す。ソース管理の変更の列と同じ扱い。
- PR が無くなった・替わって中身がまだ無いときは、行が無いので選択を外す。

レールでパネルを出したとき、今の答えで行を組んだうえで、列に行があれば列に焦点を入れる（行が無ければ求めない——当たらない要求を残すと、行が現れた瞬間に焦点を奪う）。パネルが隠れたとき、焦点がパネルの列か全体へのコメント欄にあれば面の焦点 view へ移す（→ [shell](shell.md#焦点)）。パネルを出したまま列が消えるとき（答えが替わって行が無くなった——ブランチの切り替え・PR のマージ）も、焦点が列にあれば、列が消える前に面の焦点 view へ移し、当てていない焦点の要求は捨てる（ソース管理の親を畳むときと同じ）。根が変わると、パネルは新しい根の worktree の今の PR を見る。

## レビューの送信

列の下に固定した区画で、保留中のコメント（PR の diff で書いた返信・新しいスレッド → [pull-request-comments](pull-request-comments.md)）と全体へのコメントを、1 つのレビューとして送る。上から次を並べる。

- 今の diff に置けない未解決のスレッド（古い版の行に付いた・ファイル単位・rename の判定が GitHub と手元で食い違うファイルの古い側の行に付いた）があれば「現在の diff に表示できない未解決のスレッド N 件」。押すと GitHub の PR を開く——未解決の議論に気づかないまま承認しないため。解決済みは数えない。
- 「レビュー」と、保留中のコメントがあれば「保留中のコメント N」（GitHub の数。書き込みのレスポンスの後の読み直しで変わる）。
- 全体へのコメント欄（任意）。↵ は改行で、10 行まで伸び、その先はスクロールする。
- 承認 / コメント / 変更を依頼 の 3 択（既定はコメント）。自分の PR では「承認」と「変更を依頼」を選べない（GitHub がエラーを返す）。
- 「レビューを送信」と ⌘↵。

全体へのコメントの書きかけと選んだ種類と送信の失敗は PR ごとの状態が持つ（→ [pull-request](pull-request.md)）——パネルを隠しても、別の PR へ移って戻っても残り、アプリを終えると消える。区画は PR ごとに作り直す（変換中に PR が替わっても、前の PR の字を次の PR の書きかけに入れない）。

送れるのは、「承認」か、全体へのコメントか保留中のコメントがあるときだけ（どちらも無ければ「コメント」と「変更を依頼」は送れない）。全体へのコメントは欄に見えている字（変換中の字を含む）で数え、空白と改行だけなら空とみなす（送るときも本文を付けない）。中身とレビューのやりとりを読んだ時点の PR の先頭のコミットが違う間は送れず、ボタンの下に「PR の最新の内容を読み込むまで送信できません」を出す——承認を、diff で見ていないコミットに付けないため。ボタンでも ⌘↵ でも、変換中なら確定してから送る。⌘↵ が送信になるのは全体へのコメント欄に焦点があるときだけで、送れなければエラー音を鳴らし、押し続けたキーリピートは何もしない。diff の返信欄の ⌘↵ は「レビューに追加」で、送信にはならない。送信の最中は欄・3 択・ボタンが押せない姿になり、欄は打てない。2 回押しても送信は 1 回。通れば書きかけを空にし、種類をコメントに戻す（保留中は 0 になる）。通らなければ書きかけと種類を残し、ボタンの下に失敗の文を出す（次に送るときに消える。時間切れは、GitHub で反映されたかを確かめるよう告げる）。

レビューのやりとりの読みが失敗したら、区画の位置に失敗の 1 行（「レビューのコメントを読み込めません（理由）」）を出す。前に読めた内容で区画を出している間も、その下に同じ 1 行を出し、次に読めたら消える——「コメントが無い」と「読めなかった」を見分けられるようにするため。diff の側には出さない。

## 作成の入口

open の PR が無ければ、「プルリクエストを作成」のボタンと、その下に `<ブランチ> → <既定のブランチ> · ↑N`（既定のブランチの追跡 ref に対する先行の数。0 か分からなければ `· ↑N` を出さない）。押すとブラウザで GitHub の作成ページが開く。ブランチが GitHub に無いと確かめられた間は、ボタンを押せない姿にし、「先にブランチを公開してください」を出す。在るか確かめている間・確かめられなかったときは押せる。

## 出せない理由と失敗

出せない理由（→ [pull-request](pull-request.md#出せない理由)）は、git 管理外・ブランチに居ない・既定のブランチ（そのブランチの PR は表示も作成もしないと告げる）・GitHub のリポジトリでない・GitHub のリポジトリか確かめられない・gh が無い・gh が認証されていない、の文で出す。問い合わせの失敗と、中身の読み直し・確認済みの書き込みの失敗は、未ログイン・回数制限・ネット不通・時間切れなら決まった文、それ以外は gh のエラー文の要点。要点が空なら、読み取りは「GitHub から取得できませんでした」、書き込みは「GitHub に反映できませんでした」。PR を保ったまま今のブランチの PR を引き直せなかったときも、その理由を頭の下の失敗の文で出す（中身の読み直し・書き込みの失敗があれば、そちらを出す）。

## タブ行の「確認済みにする」

焦点のタブが PR の diff のタブで、そのパスが PR の変更ファイルにあれば、タブ行のインライン / 並列の左にチェックと「確認済みにする」を出す。押すと、パネルの行頭のチェックと同じく PR ごとの状態の確認済みを切り替える——パネルとタブ行は同じ状態を見せる。PR の diff タブは開いたときの PR を見続けるので（→ [diff](diff.md#pr-の-diff)）、ブランチを切り替えた後も、そのタブの「確認済みにする」は開いたときの PR に書く。

## TopBar の現在地

PR の diff のタブに焦点があるとき、TopBar の現在地は `PR #N · ディレクトリ/ファイル名`（`PR #N` を accent、区切りとディレクトリを弱く、ファイル名を強く）になる（→ [chrome](../chrome/chrome.md)）。窓が main でない間は、`PR #N` もファイル名と同じ段へ沈める。
