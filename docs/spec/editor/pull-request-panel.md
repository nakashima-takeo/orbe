# PR のパネル

今の worktree のブランチから出ている open の PR を、エディター面の PR の画面の左の列で読む場所。ブラウザの GitHub へ移らずに、PR の題・説明・コミット・変更ファイルを見て、変更ファイルを PR の diff（→ [diff](diff.md#pr-の-diff)）で開き、確認済み（GitHub の Files changed の Viewed）を付け外しする。パネルが見せるのは 2 つの状態（→ [pull-request](pull-request.md)）——worktree の今の PR と PR ごとの状態——で、パネル自身は見せ方（区分とフォルダの開閉・選択・説明の開閉）だけを持つ。同じ PR を見る PR の diff・上のバーの番号・TopBar と、確認済みや中身が食い違わない。

上のバーの `PR` で PR の画面にすると出る（→ [shell](shell.md)）。パネルは、面が見えている間は worktree の今の PR がどの PR かを追い（上のバーの番号のため。どの画面でも）、PR の画面を出している間は（左の列を閉じていても）PR の中身も読む（→ [pull-request](pull-request.md#見ている者と読み直すきっかけ)）——GitHub に問い合わせるのは、この間と、PR の diff が本体に出ていて面が見えている間だけ。ほかの画面へ切り替えて戻すと、前の中身がすぐ出て裏で読み直す。寸法と色は [design-system](../../design/design-system.md) §5 の PR panel。

## 構成

上からパネルヘッダー（題「プルリクエスト」・再読込・GitHub で開く）と、worktree の今の PR の答えに応じた中身。

- **PR がある**: 頭（PR の印・題と番号・作者 · `head → base`・手元とのずれの帯）、失敗の文（あれば）、列（説明・コミット・変更ファイル）、下端のレビューの送信の区画（レビューのやりとりが読めてから。読めないままなら、その位置に失敗の 1 行）。中身がまだ読めていない間は何も出さず、最初の読み込みが失敗すれば「表示できません」の一言を出す（見出しと失敗の文と「再読込」は本体に出る → 出せない理由と失敗）。
- **open の PR が無い**: 「プルリクエストなし」の一言（作成の入口は本体に出る → 作成の入口）。
- **出せない**: 「表示できません」の一言（見出しと理由の一文は本体に出る → 出せない理由と失敗）。
- **読んでいる**: 何も出さない。

一言はパネルヘッダーの下に出し、パネルヘッダーはどの答えでも出す。

再読込は、worktree の今の PR を引き直し、PR があればその中身も読み直す。GitHub で開くは、中身が読めている間だけ出て、PR のページをブラウザで開く。

## 頭

PR の印は、open の PR を success、ドラフトを弱い色で描く。題は折り返し、番号は弱い色で題に続ける。2 段目に作者（消えたアカウントなら出さない）と `head → base`（先頭のブランチ名 → ベースブランチ名。収まらなければ末尾を省く）。

その下の帯は、手元とのずれ（→ [pull-request](pull-request.md#手元とのずれ)）を 3 通りで知らせる。

| ずれ | 帯 |
|---|---|
| 手元の HEAD が PR の先頭と同じ | レ点と「この worktree でチェックアウト済み」（success） |
| 数えられた | 「未 push のコミットが N 件あります」「PR に未取得のコミットが N 件あります」（注意の黄。両方あれば「・」でつなぐ） |
| 数えないが違う（PR の先頭が手元に無い・浅いクローン） | 「この worktree の HEAD は PR の先頭と違います」（注意の黄。手元が先か PR が先かは言わない——浅いクローンでは未 push のずれもここに入る） |

ずれを数え終わるまでは帯を出さない。帯の文は省かず、幅に収まらなければ折り返して全文を出し、帯は行数に従って伸びる（題と同じ扱い。意味の要の語が末尾に来るので、省くと読めない）。帯より下は、帯の高さに従って下がる。

## 列

説明・コミット・変更ファイルを 1 本の列で流す。列は見えている行だけを描く——変更ファイルは GitHub の上限まで（数千件）ありうる。

- **説明**は列の頭で、行と一緒にスクロールする。見出しと、本文の先頭 3 行（書かれた Markdown の字のまま。越える分は末尾を省く）。見出しを押すと畳む。説明が空なら見出しごと出さない。説明の見出しは行ではなく、キーでは選べない（ソース管理の親の見出しと同じ扱い）。
- **コミット**は区分の見出し（総数のバッジ）と、PR のコミットの行（題の 1 行目と短い sha）。並びは GitHub の PR と同じく古い順。GitHub は新しい側の 250 件までしか返さないので、総数が読めた件数より多ければ、先頭に「古いコミット N 件は表示していません」の行を置く。コミットの行は押せず選べない（ソース管理のグラフと同じ）。
- **変更ファイル**は区分の見出し（「N/M 確認済み」とツリー表示・リスト表示の切り替え）と、変更ファイルの行。ツリーはエクスプローラーと同じ並び（フォルダが先・名前順。1 つしか子の無いフォルダも畳まない）で、フォルダの行は右に配下の「確認済みの数/ファイルの数」を出す。リストはソース管理の行と同じパス順で、名前の後にディレクトリを出す。ファイルの行の印は、追加が A（青）、それ以外が M（黄）。印の左に、そのファイルの今の diff に置けるスレッドのコメントの総数を出す（0 なら出さない。→ [pull-request-comments](pull-request-comments.md)）。コメントの数が変わっても行は組み直さず、見えている行を描き直す。

ツリーかリストかはアプリ全体で 1 つで、再起動でも戻る（→ [persistence](../platform/persistence.md) の app-state）。区分とフォルダの開閉・説明の開閉・選択は面ごとで、永続しない。

## 確認済み

ファイルとフォルダの行頭にチェックがある。ファイルのチェックは、そのファイルの確認済みを切り替える。フォルダのチェックは配下をまとめて切り替える——配下が全部確認済みなら全部外し、そうでなければ全部付ける。フォルダのチェックは、配下が全部確認済みなら付いた姿、一部なら横線、無ければ空。確認済みのファイルの行と、配下が全部確認済みのフォルダの行は、全体を薄く描く。

PR の diff の見出し（→ [diff](diff.md#見出し)）のチェックと「確認済みにする」「確認済みを外す」、PR の画面のキー v も、本体に出ているファイルの確認済みを同じように切り替える。どれも、diff が見せている PR の状態へ書くので、行のチェックと「N/M 確認済み」と見出しは必ず揃う。

付け外しは押した瞬間に出て、GitHub への書き込みは裏で順に送る。通らなければ元に戻り、失敗の文が出る（→ [pull-request](pull-request.md#確認済み)）。確認済みを付け外ししても行は組み直さず、見えている行を描き直す。

## PR の diff を開く

変更ファイルの行は、その PR の diff（→ [diff](diff.md#pr-の-diff)）を PR の画面の本体に開く（前の PR の diff と入れ替わる）。シングルクリック・↑↓・→ でファイルの行へ動くと開き、焦点は列に残る（押し続けた ↑↓ は離してから開く。ソース管理の列と同じ間引き）。ダブルクリック・Enter は開いて本文へ焦点を移す。

左の列を閉じている間は、上のバーの今のファイルのボタンか ⌘P で出る変更ファイルの一覧（左の列の今の表示と同じ順）から、別のファイルの diff へ切り替えられる（→ [shell](shell.md#変更ファイルの一覧)）。

PR の画面を出していて、面が見えていて、PR の diff が無く、変更ファイルの行が読めたら、選んでいる行（ファイルの行でなければ先頭のファイルの行）の diff を自動で開き、その行を選ぶ（焦点は動かさない → [diff](diff.md)）。変更ファイルが無ければ何も開かず、本体には出すものが無いときの表示が出る（→ [faces](faces.md#面の中身と空状態)）。worktree の今の PR が替わると（ブランチの切り替え・マージ・クローズ）、前の PR の diff は閉じる。

## キーと焦点

選べるのは区分の見出し・フォルダ・ファイルの行。キーはソース管理の変更の列と同じ型。

| キー | 働き |
|---|---|
| ↑↓ | 選べる行を順に渡る。未選択なら先頭。ファイルの行なら開く |
| ← | 開いた見出し・フォルダなら畳み、そうでなければ親（フォルダか変更ファイルの見出し）へ |
| → | 畳んだ見出し・フォルダなら開き、開いていれば最初の子の行へ（ファイルの行なら開く） |
| Enter | ファイルの行は開いて本文へ、見出し・フォルダは開閉 |
| Esc | 選択を外す |

全体へのコメント欄の ⌘↵ はレビューの送信（→ レビューの送信）。

見出し・フォルダのクリックは開閉。

確認済みのキーは v で、列のキーではなく PR の画面のキーとして効く。働くのは、本体に PR の diff が出ていて、そのファイルが変更ファイルに在り（見出しに確認済みの部品が出ている）、焦点が diff の面（コメントの欄ではない所）・面の器（列のために焦点を預かっている間を除く）・この列のどれかにあるとき。返信・新しいコメント・全体へのコメントの欄で打っている間は、v は字として入る。付け外しするのは本体に出ているファイル（見出しのボタンと同じ）で、焦点が列にあり、列で選んでいるファイルが本体のファイルと違えば（↑↓ の直後で diff がまだ替わっていない・その行の diff を開けなかった）、その diff を待たずに開いてから付け外しする。開けなければ音で断る。列でフォルダか見出しを選んでいれば、対象は本体のファイルのまま。押し続けても付け外しは 1 回だけで、次のファイルへは進まない。

選択は常に見えている行にある。行の組は、PR の中身・ツリーかリストか・開閉のどれかが変わったときに組み直し、そのとき選んでいた行が無くなっていれば選び直す（開かない）。

- **畳んで隠れた**: フォルダを畳めば、その下の選択（ファイルでもフォルダでも）はそのフォルダへ、区分を畳めば、その下の選択は区分の見出しへ移る。開き直しても元の行へは戻らない。
- **ツリーからリストへ切り替えてフォルダの行が無くなった**: 配下の最初のファイルへ移る（見ていた場所の近くに残す）。
- **読み直しで消えた**（PR の変更ファイルから外れた）: 変更ファイルの区分の同じ位置の行（無ければ最後の行）へ移る。区分に行が無ければ選択を外す。ソース管理の変更の列と同じ扱い。
- PR が無くなった・替わって中身がまだ無いときは、行が無いので選択を外す。

上のバーで PR の画面へ切り替えたとき、今の答えで行を組んだうえで、左の列を開いていて、列に行がある・これから来る（worktree の今の PR の答えを読んでいる・PR の中身を読んでいる）なら、面が焦点を預かり、行があり次第、列に焦点を入れる（中身の読みに失敗した後で PR の画面を出し直したときも、読み直しが終わるまで待つ）。それ以外（PR が無い・表示できない・中身を読めなかった）は本体の焦点の行き先へ移す（→ [shell](shell.md#焦点)）。行を待つ間に人が焦点を移したら、後で行が現れても焦点は奪わない。パネルが隠れたとき、焦点がパネルの列か全体へのコメント欄にあれば面の焦点 view へ移す（→ [shell](shell.md#焦点)）。パネルを出したまま列が消えるとき（答えが替わって行が無くなった——ブランチの切り替え・PR のマージ）も、焦点が列か全体へのコメント欄にあれば、列が消える前に面の焦点 view へ移し、当てていない焦点の要求は捨てる（ソース管理の親を畳むときと同じ）。根が変わると、パネルは新しい根の worktree の今の PR を見る。

## レビューの送信

列の下に固定した区画で、保留中のコメント（PR の diff で書いた返信・新しいスレッド → [pull-request-comments](pull-request-comments.md)）と全体へのコメントを、1 つのレビューとして送る。上から次を並べる。

- 今の diff に置けない未解決のスレッド（古い版の行に付いた・ファイル単位・rename の判定が GitHub と手元で食い違うファイルの古い側の行に付いた）があれば「現在の diff に表示できない未解決のスレッド N 件」。押すと GitHub の PR を開く——未解決の議論に気づかないまま承認しないため。解決済みは数えない。
- 「レビュー」と、保留中のコメントがあれば「保留中のコメント N」（GitHub の数。書き込みのレスポンスの後の読み直しで変わる）。
- 全体へのコメント欄（任意）。↵ は改行で、10 行まで伸び、その先はスクロールする。
- 承認 / コメント / 変更を依頼 の 3 択（既定はコメント）。自分の PR では「承認」と「変更を依頼」を選べない（GitHub がエラーを返す）。
- 「レビューを送信」と ⌘↵。

全体へのコメントの書きかけと選んだ種類と送信の失敗は PR ごとの状態が持つ（→ [pull-request](pull-request.md)）——パネルを隠しても、別の PR へ移って戻っても残り、アプリを終えると消える。区画は PR ごとに作り直す——作り直す前に、前の PR の欄の変換中の字を前の PR の書きかけへ確定し、焦点が欄にあれば面の焦点 view へ移す（変換中に PR が替わっても、前の PR の字を次の PR の書きかけに入れず、外れた欄に焦点を残さない）。

送れるのは、「承認」か、全体へのコメントか保留中のコメントがあるときだけ（どちらも無ければ「コメント」と「変更を依頼」は送れない）。全体へのコメントは欄に見えている字（変換中の字を含む）で数え、空白と改行だけなら空とみなす（送るときも本文を付けない）。送れるのは、PR の diff の両端を求め終え、その先頭のコミットで中身とレビューのやりとりも読んでいる間だけ——ファイルの列・diff・スレッドと、送るレビューの版を揃えるため（両方が新しい先頭へ一緒に読み直された直後の承認は、利用者がその版の diff を見たかに依らず通る）。揃っていない間は押せない姿にし、ボタンの下に理由を出す: 読み込んでいる・両端を求めている間は「PR の最新の内容を読み込むまで送信できません」、中身とレビューのやりとりの先頭が食い違ったまま揃える読みをやめた間は「PR の最新の内容を揃えて読めませんでした。再読込してください」、diff の両端を求められない間は「PR の diff を表示できないため、送信できません。再読込するか、GitHub で送信してください」（diff で確かめられない版へのレビューを Orbe から送らない。再読込で両端を求め直す → [pull-request](pull-request.md#diff-の両端)）。保留中のレビューが前の先頭に結ばれているときの承認の付き先は確かめていない（→ [pull-request-comments](pull-request-comments.md#限界)）。判定は PR ごとで、開いている diff の有無と数に依らない。ボタンでも ⌘↵ でも、変換中なら確定してから送る。⌘↵ が送信になるのは全体へのコメント欄に焦点があるときだけで、送れなければエラー音を鳴らし、押し続けたキーリピートは何もしない。diff の返信欄の ⌘↵ は「レビューに追加」で、送信にはならない。送信の最中は欄・3 択・ボタンが押せない姿になり、欄は打てない。2 回押しても送信は 1 回。通れば書きかけを空にし、種類をコメントに戻す（保留中は 0 になる）。通らなければ書きかけと種類を残し、ボタンの下に失敗の文を出す（次に送るときに消える。時間切れは、GitHub で反映されたかを確かめるよう告げる）。

レビューのやりとりの読みが失敗したら、区画の位置に失敗の 1 行（「レビューのコメントを読み込めません（理由）」）を出す。前に読めた内容で区画を出している間も、その下に同じ 1 行を出し、次に読めたら消える——「コメントが無い」と「読めなかった」を見分けられるようにするため。diff の側には出さない。

## 作成の入口

open の PR が無ければ、本体に見出し「プルリクエストなし」と一文「このブランチのプルリクエストは、まだありません。」と「プルリクエストを作成」のボタンを出す（左の列は「プルリクエストなし」の一言）。押すとブラウザで GitHub の作成ページが開く。ブランチが GitHub に無いと確かめられた間は、一文を「先にブランチを公開してください」にして、ボタンを押せない姿にする。在るか確かめている間・確かめられなかったときは押せる。在るかを確かめ直している間は前の姿のまま（→ [pull-request](pull-request.md#作成の入口の材料)）。

ブラウザで PR を作って Orbe に戻ると、何も押さなくても、上のバーに番号が出て、PR の画面が PR の中身（左の列の一覧と、自動で開く diff）に替わる——Orbe が前面に戻ったとき、今のブランチの PR を引き直すため（→ [pull-request](pull-request.md#見ている者と読み直すきっかけ)）。Changes・Files の画面に居ても、戻ればバーに番号が出る。ブラウザで PR をマージ・クローズして戻れば、番号が消え、PR の画面は「プルリクエストなし」になる。GitHub の答えが追いついていなければ「プルリクエストなし」のままで、次に前面へ戻ったとき・再読込で替わる。

## 出せない理由と失敗

出せない理由（→ [pull-request](pull-request.md#出せない理由)）は、本体に見出し「プルリクエストを表示できません」と理由の一文で出す（左の列は「表示できません」の一言）。理由の一文は、git 管理外・ブランチに居ない・既定のブランチ（そのブランチの PR は表示も作成もしないと告げる）・GitHub のリポジトリでない・GitHub のリポジトリか確かめられない・gh が無い・gh が認証されていない、の文。今のブランチの PR の問い合わせの失敗と、PR の中身の最初の読みの失敗も同じ見出しで出し、失敗の文に「再読込」のボタンを添える（押すとパネルヘッダーの再読込と同じ）。失敗の文は、未ログイン・回数制限・ネット不通・時間切れなら決まった文、それ以外は gh のエラー文の要点。要点が空なら、読み取りは「GitHub から取得できませんでした」、書き込みは「GitHub に反映できませんでした」。PR の中身が読めている間の失敗——PR を保ったまま今のブランチの PR を引き直せなかった・中身の読み直しや確認済みの書き込みが失敗した——は、左の列の頭の下の失敗の文で出す（中身の読み直し・書き込みの失敗があれば、そちらを出す）。

## TopBar の現在地

PR の画面を出しているとき、TopBar の現在地は `PR #N · 根`（`PR #N` を accent、区切りと根を弱く）になる（→ [chrome](../chrome/chrome.md)）。番号は worktree の今の PR のもので、答えが替われば描き直す。PR が分からない間（読んでいる・PR が無い・出せない）は根だけ。窓が main でない間は、`PR #N` も根と同じ段へ沈める。
