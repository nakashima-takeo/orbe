# chrome

ターミナルの外側に常駐する Orbe 自身の顔。最上段の `StatusRow` 1 つ（タブ 1 枚でも常時表示）が 2 段からなり、上段が「今どこにいるか」、下段がタブ行を受け持つ。エージェントの状態をターミナルの基本情報として常時見せる、という Orbe の中心思想がここに乗る。

## 構成と地

タイトルバーは非表示（信号機ボタンのみコンテンツ上に残る）。上段は標準タイトルバー高に一致させ、信号機を帯の縦中央に置いて上下余白を対称化する。罫線は持たず、下段の地の濃度差が境界を成す。最背面には accent と working のラジアルグローが敷かれ、上段は透明でこれが透ける。

背景透過時（非フルスクリーン）は StatusRow 全体に端末面と同濃度の veil を敷き、その上に既存のタブ行の地を重ねる——ステータス行の背景もデスクトップまで透ける（→ [layout](layout.md)・[config](../platform/config.md)）。不透明時は上段透明・下段はタブ行の地。chrome の全ユーザー向け文言は現在言語に追従する（[localization](../platform/localization.md)）。

## 上段（TopBar）

左から、信号機ぶんの余白・workspace 名・アクティブタブの実効 cwd（`currentPwd ?? initialCwd`・`~` 短縮・先頭側省略）——現在地を粗→細の順に読ませる並び。右端に全 workspace 横断のエージェント状態件数ストリップ（後述）、中央は空けて窓ドラッグ面にする。幅が足りないときは cwd から縮む（workspace 名・ストリップは保護）。テキストの縦位置は信号機 close ボタン中央へ寄せる。

環境変数 `ORBE_STATE_DIR` 設定時のみ、workspace 名の右隣に build-id（ビルド時の git 短縮 SHA）を dim 表示する。検証用の隔離インスタンスでビルドの鮮度を見分けるための表示で、未設定の常用 Orbe では出ない（[persistence](../platform/persistence.md)）。

## 下段（タブ行）

全幅のタブ行。**同じ git worktree のタブは 1 本の連（セグメント）に連なる**——連は淡いブロック 1 枚で、その中にタブのセルが区切り線で仕切られて並ぶ。2 枚以上の連は左端に worktree の識別色バー（3pt・縦いっぱい）が立ち、1 枚の連はバーも区切り線も持たず単独タブの見た目になる。セルはタイトル末尾省略・クリックで切替、選択セルは前景色反転、非選択セルは地を持たない（連の地が透ける）。タブ背景を状態色で塗らない。行の末尾に `+` で新規タブ。

**連のキー**は cwd が属する git worktree ルート（`.git` を親方向へ探して得る正準形パス）。リポジトリ内のどのサブディレクトリにいても同じ worktree なら同じ連に入る。git 管理外は cwd 自身をキーにする（実質グループ化されない）。**識別色**は worktree ルートの basename をハッシュして 48 色（24 色相 × 2 トーン）から決める——同じリポジトリはどのマシン・どの起動でも同じ色。衝突は許容し、名前で区別する。

タブ配列は「同じキーのタブは必ず隣接する」という不変条件を保つ。新規タブは同じキーの連の右端へ入る。`cd` で所属が変わったタブは、同じキーのタブが他所にあればその連の右端へ、他の連を割る位置に取り残されたならその連の直右へ出る（タイトル更新と同じ契機）。連の中が 1 枚になれば普通のタブに戻り、識別バーも消える。タブを閉じたあとのフォーカスは連の中で決める——閉じたタブが 2 枚以上の連の右端なら同じ連の左隣へ、それ以外は従来どおり右隣（位置据え置き・末尾なら左）へ。

**中クリックで閉じる**: タブは中クリック（マウス中ボタン）でそのタブを閉じる。非選択タブも切替を挟まずその場で消え、確認は挟まない（→ [layout](layout.md)・[workspace](../platform/workspace.md)）。サイドボタンでは閉じない。ウィンドウが非アクティブなときの初回クリックはアクティブ化に消費されて閉じない——確認も取り消しも持たない破壊操作なので、誤爆をここで止める。

**右クリックでコンテキストメニュー**: タブを右クリック（副ボタン・ctrl+クリック）すると macOS 標準のコンテキストメニューが開く。項目は「エージェント状態をリセット」の 1 つで、選ぶとそのタブのエージェント状態を `idle` へ遷移させる（→ 後述「idle への遷移」）。右クリックはタブを選択しない。状態グリフの出ていないタブ（idle か状態なし）では項目は無効で押せない——グリフが出ているタブだけリセットでき、押すとグリフが消える、という見え方に揃える。メニューは開いたまま時間が経ちうるので、項目は右クリックした時点のタブ（位置ではなく同一性）に効く——開いている間に他のタブが閉じて位置が詰まっても別のタブをリセットしない。改名中（インライン編集中）のタブは編集欄が右クリックを取るので対象外。

**並び替え**: ドラッグ&ドロップで左右に並び替えできる（同一 workspace 内のみ・実データのタブ配列そのものを入れ替え・順序は永続）。セルの掴みは自分の連の中だけで動く——所属は worktree が決めるので、連をまたいで動かす意味がない。連ごと動かすときは左端の識別バーを掴む。1 枚の連は識別バーを持たないので、そのセル自体を掴むと連の移動になる。掴みは小さな移動量の閾値でクリック切替と区別し、掴んだものを指に追従させ、挿入先に accent 色の縦キャレットを出す（セル掴みは連内のセル境界、連の掴みは連と連の隙間）。指を離した瞬間に 1 回だけ並べ替える（commit-on-drop。ドラッグ中はデータを変異させない）。掴んでいる間にタブ集合や連の構造が変わったら（shell 終了・`cd` の再判定など）掴みを破棄する——凍結した幾何が実体とずれるため。

**overflow（比例縮小 ＋ 水平スクロール）**: タブ群は水平スクロール領域（スクローラー非表示）に載る。各セルの幅は自然幅（タイトル＋状態グリフ＋左右余白）を床 40pt・上限 140pt に収めた値で、2〜3 文字の短い名前でも床の幅を持ち、上限を超える名前は末尾省略になる。合計が利用可能幅に収まる間はそのまま。収まらないときは行内の全セルをその幅に比例して縮め、床に達したセルは凍結して残りの不足を残りのセルへ再配分する。**再配分の単位は行であって連ではない**——同じ長さのタブは、どの連にいても、単独でも同じ幅になる。全セルが床でも収まらないときだけ水平スクロールする。タブ切替時はアクティブタブを可視位置へ自動スクロールする。描画クリップでタブを隠さない——到達不能なタブを作らないため。

## タブタイトルの解決

タイトルは次の優先順位で決まる。

1. **明示タイトル**（`Cmd+R` で付与・tab 単位・sticky・空入力確定で解除）
2. **アプリ報告タイトル**（OSC 0/2）。ただし `currentPwd` と同値のときは採用しない——libghostty が明示タイトル未受信の間に立てる pwd フォールバックを除外するため。
3. **cwd 派生**。所属 workspace の `rootPath` 基準で整形する: 圧縮アンカーを root の親に置く＝root 以下なら root 名を先頭要素とする相対、root 外は `~` 基準、root ちょうどは basename。いずれも fish `prompt_pwd` 流に末尾要素以外を頭 1 字へ圧縮する（深さ上限なし）。

`Cmd+R` はフォーカス中タブをタブ行内でその場編集する（中央パレットは出さない）。現在の表示名をプリフィルし全選択して開き（打てば置換）、空確定で解除・Esc で取消・他所クリックで取消。編集中は window レベルの chrome コマンドを不活性化する。シェル統合の自動タイトル送出は既定 conf で止めてあり、タブ名はこの precedence だけが決める（[config](../platform/config.md)）。

**描画とフォント**: タイトルの描画は基底フォント（既定は等幅システム・設定 `tab-title-font-family` で差し替え可・未設定/解決不能名は既定へ退避・[settings](../palette/settings.md)）に、Nerd アイコン・点字・絵文字の各領域を run 単位で同梱フォントへ明示割り当てる（絵文字は設定 `emoji-font` の実効値。apple 選択時は割り当てず OS フォールバック）——ghostty 側と違い chrome は自前でフォント解決するため。text 既定の emoji 可能記号（Claude Code の ✳ 等）は VS16 を足してカラー表示へ昇格する。タブ自然幅の計測も同じ変換・同じ基底フォントで測る（フォント未解決のバンドル無し起動では割り当てなし＝素の chrome 描画）。この run 割り当てはタブ以外の chrome テキスト——TopBar の workspace 名/cwd・パレット行——にも適用される。

## タブのエージェント状態インジケータ

各materialize済みタブはタイトルの前に、`agentState` の状態グリフを出す（working=円弧スピナー・waiting=吹き出し浮遊・done=チェック・静止）。通常のworkspace切替で隠れタブを順次起こしている途中は、まだ未materializeのタブにグリフを出さない。Reduce Motion 環境ではアニメーションを止め静的な形で残す。`idle`・無し（nil）は出さない。状態の詳細（種別グリフ＋件数）は上段右端の横断ストリップが持つ。

各状態のグリフは既定で自前字形だが、設定パレットの「エージェントアイコン」で状態ごとに SF Symbol へ差し替えられる（[settings](../palette/settings.md)）。差し替えても状態のモーション・Reduce Motion 時の静止・選択タブの対テーマ色は維持する。装飾用途の固定グリフ（dispatch の作成中スピナー等）は差し替え対象外。

## idle への遷移（done のフォーカス消費とタブのリセット）

見ているタブ（アクティブ表示タブ かつ ウィンドウがキー＝前面）には `done` を残さない——結果が目の前に出ている場所で通知を光らせ続けない、という原則。開いて見ている最中に `done` が届いたとき・別タブから `done` のタブへ切り替えたとき・前面復帰したときのいずれでも、そのタブの `done` を `idle`（休止）へ遷移させる。idle はタブにインジケータを持たないため `done` バッジは消えるが、横断ストリップには休止中エージェントとして残る。

背面（非キー）で届いた `done` はバッジが残り、前面復帰・切替で消える。フォーカス消費は `waiting`・`working` を消費せず残す。コマンド名・セッション ID は保持する（resume を壊さない）。

同じ遷移をユーザーの意思で起こすのがタブのコンテキストメニューの「エージェント状態をリセット」（前述）。こちらは `waiting` / `working` / `done` のいずれからでも、そのタブを `idle` へ遷移させる——背面タブで立ちっぱなしのグリフを、そのタブへ切り替えずに黙らせるための手段。フォーカス消費と同じく、コマンド名・セッション ID・文言・状態変化時刻は保ち、state だけを書き換える。横断ストリップには休止中として残り、Attention 一覧からは消える。

リセットは一回限りの書き換えで、次の報告が来るまで `idle` のまま残る。稼働中の `working` を落としても次の報告で必ず `working` に戻るわけではない（`working` の報告契機は CLI のフック粒度に依り粗い → [agent/notify](../agent/notify.md)）。次に届く報告が `done` なら done として立つ。それまで横断ストリップの休止件数は実稼働中のエージェントを含みうる。また、リセット後に届く報告は `idle` からの遷移として扱われる——直前と同じ state の再報告でも実変化になり、文言の上書き・状態変化時刻の更新・通知音とピルがその規則どおりに起きる。

## 全 workspace 横断エージェント件数（ストリップ）

全 workspace の**activatedタブ**を走査し、`agentState` を `working / waiting / done / idle` ごとに件数集計する（タブ単位。idle は数えるが `error`・nil は数えない）。未materializeタブの復元agentはlive件数へ混ぜない。この状態順で状態色グリフ＋件数を出す（グリフは CLI 非依存。タブと同じく設定で SF Symbol へ差し替え可 → [settings](../palette/settings.md)）。項目は区切り線を持たず間隔で分け、休止（idle）項目は減光する。ラベル文字は持たない。件数 0 の種別・全体 0 は出さない。

上段右端に裸のグリフ列（囲みなし）で固定表示し、**クリックで Attention パレットを開く**（→ [attention](../palette/attention.md)）。⌘⌘ は画面に書けないジェスチャなので、可視の入口をここに対で持つ。同じlive集計を同じ更新契機でWorkspaceパレットにも出し、そこだけは未消費の復元チケット（休眠agent）を持つタブ数を独立したdormant（zzz）チップとして後置する（→ [workspace パレット](../palette/workspace.md)）。

## アップデートのトースト（右下・非モーダル）

アプリ内アップデートが「再起動待ち」になった瞬間に一度だけ、ウィンドウ右下にトーストを重ねる（モーダル overlay とは独立の層。パレット類が開いていればそちらが前）。文言・挙動・出現条件は [update](../platform/update.md) が持つ。常駐 chrome にアップデート表示は無く、この一過性のトーストと設定パレットのアップデートセクションだけが面を持つ。

## ウィンドウ操作と更新駆動

行の余白ドラッグでウィンドウ移動、余白ダブルクリックでシステム設定準拠の zoom/minimize（機構は [layout](layout.md)）。

更新はイベント駆動: タブのタイトル変更・タブ/workspace 切替・cwd 到着・いずれかのタブのエージェント状態変化・タブ集合の変化（開く・閉じる）・背景 workspace でのタブの materialize（休眠の解除）。重い StatusRow snapshot（全 workspace×全タブ走査）は runloop tick 単位に coalesce され、同一 tick 内の複数要求は tick 末尾の 1 回へ畳まれる（trailing-edge。中間状態は落ちるが最終状態は必ず反映＝取りこぼしゼロ）。`window.title`（アクティブ workspace 名。Mission Control 等の外部観測用で画面には出ない）は O(1) なので coalesce せず即時反映する。
