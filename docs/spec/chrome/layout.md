# レイアウト

1 つのウィンドウの中に何がどう積まれ、誰が誰を参照するかの構造。ここが窓・chrome・端末・オーバーレイの土台になる。

## SwiftUI ホスト構成

host 所有。`window.contentView` は SwiftUI ルート `ChromeHostingView`。ルートビュー `AppShell` は最背面に装飾層 `BackgroundGlow`（accent＋working のラジアル・非対話）を敷き、その上に上段 chrome ＋下段 content を置く。

- `BackgroundGlow` の地は透過状態で変わる: **不透明時（100%・フルスクリーン）は不透明な地を敷き**、**透過時は地を敷かず clear** にする——端末の透明ピクセルをデスクトップまで抜くため。glow ラジアル自体は透過時も残る。窓が main でない間は glow を描かない（地の扱いは同じ）（→ [chrome](chrome.md)）。
- content の不透明な地は通常は各端末 surface（ボードを選んでいればボードの面）が描くため、**選択が空（タブが 0 でボードも無い）のときだけ** content を薄めた地で埋める。透過ウィンドウ越しにデスクトップが透けるのを防ぐ backstop で、背景不透明度の設定変更にライブ追従する。タブかボードが出ているときは出さず二重 veil を避ける。
- 上段 chrome はネイティブ SwiftUI。下段は単一の AppKit ステージを passthrough representable で内包し、その中に content（Z=0 端末・ボード / Z=1 エディター。`reconcileContent()` 専有）とウィンドウ単一のブラウザ層（Z=2 → [browser/core](../browser/core.md)）を兄弟配置する。ブラウザ層は content の照合から構造的に切り離されているため、開閉・幅変更で端末の矩形は一切変わらない。
- content に載る表示単位は**面の器**——端末面の上にエディター面を重ねた 1 枚（→ [editor/faces](../editor/faces.md)）。器は連（同じ worktree のタブ → [chrome](chrome.md)）ごとにあり、端末面には選んでいるタブの端末が出る。エディターを開いているかは窓が 1 つだけ持ち（エディターで見せているタブ）、器はそれを照合から受け取って写す。エディター面の地は chrome と同じ veil で塗り、端末面の地は端末 surface が描く。開いている間は下の端末面を見せず（描画は続ける）、二重 veil を避ける。
- ボードを持つ workspace が前面の間は、ボードの面（窓に 1 枚。前面の workspace のボードを映す）も連の器と並べて content に載り、ボードを選んでいる間だけ見える（→ [board](board.md)）。
- 配置状態（content とその空判定）と上段 chrome の状態は薄い `@Observable` モデル経由で `WindowController` が所有・駆動する（状態の正は WindowController）。
- 窓が main window かも同じモデルが持つ。`WindowController` が窓の main の得失を受けて書き写し（生成時は main でない）、`AppShell` が根で Environment として注入して、上段・タブ行・`BackgroundGlow` が読む。未注入の根（見本系・メニューバー）は main 扱いで前面の姿に描く。DS 部品（タブのセル・件数ストリップ）は窓を知らず、退いた姿で描くかを引数で受ける。
- 背景透過／ブラーは `WindowController` が所有する `ChromeTranslucency` を各 SwiftUI root へ Environment 注入して chrome 各面へ配り、各面が自分の地を同じ実効不透明度で薄める——端末面と veil 濃度を揃えるため。端末領域には塗らず二重 veil を避ける（値更新は窓の不透明度同期と同一 tick）。
- 窓ドラッグは chrome 背景の透明 NSView が `mouseDown` で処理する。1 クリックは `window.performDrag(with:)` で Window Server へ委譲し（Space 切替等に参加させるため）、ダブルクリックはシステム設定 `AppleActionOnDoubleClick` を読んで zoom / miniaturize / 無効を明示実行する。タブ／＋ は前面で tap を持つため空き領域だけを拾う。
- 信号機ボタンが chrome の上にあるか・あるならその縦位置は、殻（`AppShell`）が付けた極小 representable が実窓から読み、上段の左余白と縦中心へ反映する（→ [chrome](chrome.md)）。実窓を読むのはここだけで、見本系（preview・gallery）は probe を持たず「信号機が上段の縦中央にある（寄せ量 0）」既定で決定的に描く。読み直す契機は窓への配置・レイアウト・**フルスクリーン遷移の完了**——遷移の最中はレイアウトと macOS によるボタンの移動の前後関係が定まらないため、幾何が確定した時点で決め直す。
- パレット・オンボーディング等のフルウィンドウ overlay は `AppShell` の `.overlay` でネイティブ SwiftUI compose する（提示状態と各 overlay のモデルを提示元が立て下げる。addSubview／入れ子 NSHostingView は持たない）。窓全面（タイトルバー帯を含む）を占めるため safe-area を無視する。

## 構造と参照方向

1 ウィンドウは複数の workspace（→ [workspace](../platform/workspace.md)）を束ね、各 workspace が複数タブ（とボードを持つ workspace ならボード → [board](board.md)）、各タブが端末 surface を 1 枚持つ。workspace の選択は「何も無い／ボード／どのタブか」の 1 つの値で、タブは位置でなくタブそのものを指す。workspace の中の連（同じ worktree のタブの並び）ごとに 1 つのタブグループがあり、連のタブはそのエディター面を共有する。ドメイン状態は Foundation 純粋型 `SessionStore` が持ち、`WindowController` が窓・ビュー・chrome を束ねる薄いコーディネータ、その下に `Workspace`（root path ＋タブ群）・`TerminalTab`（タブの同一性・エージェント状態・明示タイトル・所属の連・復元単位・制御イベントの発火）・`TabGroup`（連のキー・エディターのセッション・器・開いていた文書の復元待ち）・`SurfaceView`（surface 1 = NSView 1。libghostty 埋め込みと、シェルが報告するタイトル / cwd）と続く。連の表示単位は面の器（→ [editor/faces](../editor/faces.md)）で、端末面の中身は `SurfaceView` をネイティブスクロールバー層で包んだ view（→ [terminal/core](../terminal/core.md)）。クローズと同一性はタブを単位に、エディターは連を単位に、エディターを開いているかは窓を単位に扱う。

所属の正はタブが指す連の 1 か所で、連のキーはそこから読む。キー K の連は「同じ workspace のキー K のタブの所属」で引き、表は持たない——連の隣接は `SessionStore` が保証している。連を作る・付け替える・畳むのは `WindowController` だけで、連の寿命はそれを所属に持つタブが居る間だけ。新しいタブ（新規・spawn・閉じたセッションの復元・起動時の復元）は、cwd の根で同じ workspace の連を引き、無ければ新しい連に入る。cd で根が変わったときの付け替えは [editor/code](../editor/code.md) の連を移るとき。

mount の単位は連の器と、その中の起きた（materialize 済みの）タブの端末。content の中身は 1 つの照合が揃え、タブを足す・閉じる・選ぶ・cd・workspace の切替・隠れたタブを起こす・背景で起こすのどの経路も、状態を変えたあとこれを呼ぶだけにする——経路ごとに器を足し外しすると、新しくできた連の器を載せ忘れるなどの抜けが出るため。

状態を書くのは命令で、画面へ写すのは描く関数 1 つ。命令は 3 つ——**選ぶ**（選択を書き、エディターを閉じる。タブ行のクリック・巡回・新しいタブ・`focus_tab`・閉じたエージェントを戻す・ボード）、**エディターで見せる**（選択とエディターで見せるタブを対象のタブへ。⌘⇧F・`open_file`・`open_diff`）、**⌘E**（エディターで見せるタブを今のタブと無しの間で反転）で、どれも書いた後に 1 回だけ描く。選択を動かさない経路（タブの閉鎖の後・workspace のアクティブ化・選ばずに足したタブが空の workspace の選択になった後）は描くだけを呼び、選び直さない——選んでいないタブが閉じただけでエディターが閉じないため。描く関数は最初に、エディターで見せるタブが今選んでいるタブでなければ無しにし（見せるタブが替われば閉じる）、続けて選んでいるタブを起こし、照合し、焦点を当て、done を消し、chrome を更新する。見せているものは、選択・エディターで見せるタブ・⌥ だけの長押しが成立しているかの 3 つから導く——何も無い・ボード・タブの端末・タブのエディター・タブの透かし（エディターで見せているタブを、⌥ を押している間だけ端末で見せる → [editor/faces](../editor/faces.md)）。長押しが成立しているかは入力の事実で、窓は複製して持たない。透かしの出入りは描く関数を通らず、選んでいるタブの連の器へ見せ方を動きつきで写すことと、done を消すことだけを行う——描く関数は焦点を当て直すので、通すと左の列の入力欄などにあった焦点がエディターの本体へ移るため。別の workspace のタブへ移る命令は、workspace・選択・エディターで見せるかを全部書いてから 1 回だけ描く——途中の workspace を描くと、移り先ではないタブが一瞬「見ているタブ」になるため。照合が保つのは 3 つ。

- 器の端末面に入るのは、その連の起きたタブの端末だけ。surface は端末が窓に付いたときに生まれるので、器が画面に出ても同じ連の休眠タブ（agent の resume を待つタブ）は素のシェルとして起きない。休眠タブは後続 tick に 1 枚ずつ起き、起きてから器へ差さる。
- content に載るのは、前面の workspace の器のうち端末を 1 枚以上持つものと、前面の workspace がボードを持てばボードの面だけ。器は窓に付く前に大きさと可視を確定させる——窓に付いた瞬間の可視性でエクスプローラーが根のサービスを握るか決まり、差した端末はその寸法で pty を起こすため。器が初めて content に載るとき、連の開いていた文書が戻る（→ [editor/shell](../editor/shell.md)）。
- 見えるのは選択が指すもの 1 つ。タブならその連の器、ボードならボードの面で、他は隠す。器の見せ方は 3 つで、エディターで見せているならエディター、透かしているなら透かし、そうでなければそのタブの端末。何も無ければ何も見せず、0 タブの地を出す。前面の workspace のほかの器は端末の見せ方で、content に載っていない器も同じ——載せる前に見せ方を写し、外す器は端末にしてから外す。見せ方は即時に写し、同じ値なら器は何もしない（進行中の切り替わりの動きを切らない）。

照合は焦点を当てない（器を外す・隠すと焦点は落ちうる）。焦点を戻すのは照合を呼んだ側で、その契機は後述のフォーカス。

背景 workspace に生えたタブは、端末をその連の器へ差し、器ごと一瞬窓に付けて外すことで surface を起こす（前面化しない）。

参照は**一方向**。タブ → 上位への通知（タブ閉鎖・タイトル・ウィンドウレベル chrome キー・cwd 報告・エージェント状態変化）は `TerminalTab` のクロージャ、連 → 上位への通知（エディターの変化・エディター面からのウィンドウレベル chrome キー）は `TabGroup` のクロージャで行い、どちらも `WindowController` が配線する。surface は所属タブへ、エディター pane は所属の連へ事実（タイトル・cwd・閉鎖要求）を通知するだけで、どれも上位を型として参照しない。見せ方の正は窓が持ち、照合が器へ写す。

## chrome キーの分類

変換中の ⌘ 付きのキーは、この分類より先に窓の根でまず IME へ渡る。受け手は「変換中の ⌘ キーを IME へ先に渡す口」を持つ入力の受け手（端末とエディターのテキスト面）で、根は受け手が何かを知らない。「IME が使ったか」は受け手が、渡している間にキー割り当てのコマンドが届いたかで判定し、使わなければ以下の分類どおりの順（window レベル → 面 → メニュー → keyDown）で流れる。口を持たない受け手（パレット等の入力欄）では、変換中でも IME へ先に渡さず、以下の分類どおりの順で流れる。

主窓の入力欄（パレット・ヘルプ・タブ名の変更・検索バー・エディターの入力欄）が変換中のとき、窓全体のコマンド・メニュー・⌘ キーを IME へ先に渡す口を経てなお受け手の無いキーは、⌘ の有無を問わず、欄のキー（↑↓・esc・⇥・⌫ など）として扱われずに入力欄（IME）へ渡る。未確定の文字は欄から見えないので、そこで欄がキーを取ると変換が壊れ、打った内容が消えるため。↑↓ は変換候補を動かし、esc は変換だけを取り消す。IME が使わなかったキーは、テキスト欄の既定動作になる（⇥ なら次の欄へ移り、打ちかけの文字は確定される）。端末とエディターのテキスト面（本文と、絵の差し込みの入力欄）はこの扱いを受けず、それぞれの IME 経路のまま。

修飾キーだけのジェスチャ（⌘⌘・⌥ だけの長押し）はキー割り当てではなく、この分類の外にある。どちらも local monitor でイベントを観測して判定し、イベントは消費しない。

chrome キーは「どの面が所有するか」（window / 端末 / エディター / 両面）と、window コマンドは「タブが無くても効くか」の網羅分類を持つ。default 節なしの switch なので、将来コマンドを追加するとこの分類はコンパイルで強制される。

- **タブ不要のコマンド**（ブラウザ開閉 ⌘B・新タブ・閉じたエージェント パレット・新規 workspace・workspace 切替・デフォルトエージェント起動・各パレット表示・設定・ヘルプ）は window レベルが面より先に配信するため、面が 1 つも無い 0 タブやボード上でも効く（overlay 表示中・タブ改名中は不活性。ブラウザが開いて焦点がブラウザ層内にある間は、window レベルで横取りせずブラウザ層へ単一降下させて一括裁定する → [browser/chrome](../browser/chrome.md)。面があるときも同じハンドラへ集約されるので挙動差はない）。
- **タブ依存のコマンド**（タブ切替・リネーム・⌘W・⌘E・⌘⇧F）は焦点の面（端末 surface・エディター pane・ブラウザ層）起点で届く。端末・エディターでは同じに効き、0 タブでは受け手が無く no-op。ブラウザ焦点中は網羅分類で一括裁定し、ブラウザ操作 5 キー（`⌘T` 新タブ・`⌘W` `TODAY` タブ閉鎖・`⌘R` ページ再読込・`⌘⇧T` 閉じたタブ復元・`⌘S` サイドバー開閉）と `⌘B` / `Esc` をブラウザ層が直接処理、安全な下層遷移とパレット類は上位へ転送、端末・エディター専用キーと `⌘F` は背後誤爆を防ぐため無動作で消費する（URL 入力中・ポップオーバー表示中・IME 変換中の保護規則は [browser/chrome](../browser/chrome.md)）。ボードの面も、焦点が自分の中にあるときだけ同じ window コマンドを受け（タブ切替は巡回し、選んでいるタブが無いので他は no-op）、端末・エディター・両面のキーは何も起こさず飲む（→ [board](board.md)）。
- **端末のキー**（フォント ⌘+/-/0）は端末面だけが扱う。エディター・ブラウザ焦点中は消費して何も起こさず、端末へも届かない。
- **エディターのキー**（⌘S 保存・⌘⇧B 左の列の開閉・⌘P 上のバーの今の項目の一覧の開閉）はエディター面だけが扱う（ただしブラウザ焦点中の `⌘S` はサイドバー開閉としてブラウザ層が扱う）。端末焦点中は Orbe が束縛せず端末へ届く。
- **両面のキー**（⌘F・⌘↑↓）は焦点の面がそれぞれの意味で扱う——⌘F は端末がスクロールバック検索、エディターがファイル内検索（→ [editor/code](../editor/code.md)。本体が diff のときと、本体が空のときは何も起きず、端末にも届かない）。⌘↑↓ は端末がスクロールバックの先頭／末尾、エディターが文書の先頭／末尾、ブラウザではページまたは入力欄の既定動作へ通す。
- エディター面ではその他の通常キーは、本体に面があればテキスト面へ届き、面の無い本体（空・使えないときの表示・diff の理由の一文）では面が飲む（→ [editor/code](../editor/code.md)・[editor/diff](../editor/diff.md)）。ブラウザの新しいタブ画面の背景も通常打鍵を飲む。

## フォーカス

フォーカスは排他管理。描く関数の最後（タブ切替・workspace 切替・⌘E・⌘⇧F）・パレット／ヘルプを閉じたとき・⌘R の確定・選んでいるタブが cd で別の連へ移ったとき・制御 API `focus_tab` / `open_file` / `open_diff` のいずれでも、見せているものへフォーカスが戻る——全面ブラウザ表示中またはブラウザへ焦点があった右シート表示中（下層へ明示的に移る操作を除く）はブラウザへ、それ以外はボードならボードの焦点の宛先（→ [board](board.md#焦点)）、何も無ければどこにも置かない、タブの端末ならその端末 surface、タブのエディターならエディター面の焦点 view（本体が文書ならそのテキスト面、diff なら見せている面（並列なら最後に焦点のあった側。既定は右）、面が無ければ面自身）へ。`select`・`showInEditor`・`⌘E` は下層へ明示的に移るためブラウザの焦点記憶を譲り（全面表示中なら閉じる）、workspace 切替や背景タブ閉鎖はブラウザの状態と焦点記憶をそのまま保つ。`focus_tab` はエディターを閉じてそのタブの端末へ、`open_file` / `open_diff` はそのタブのエディターへ着く。エディター面の骨の操作（ファイルを開く・切り替える・新規作成）は焦点をテキスト面へ運び、上のバーで画面を切り替えると、一覧に行があればその一覧へ、無ければ本体へ焦点が移る（→ [editor/shell](../editor/shell.md) の焦点）。⌥ だけの長押しの透かしは焦点を動かさない（→ [editor/faces](../editor/faces.md)・[browser/core](../browser/core.md)）。

## ショートカット

- Cmd+B 内蔵ブラウザを開く・閉じる（→ [browser/core](../browser/core.md)）/ Cmd+E エディターを開く・閉じる（→ [editor/faces](../editor/faces.md)）/ Cmd+S エディターの文書を保存（→ [editor/code](../editor/code.md)。ブラウザ焦点中はサイドバー開閉 → [browser/chrome](../browser/chrome.md)）/ Cmd+Shift+B エディターの左の列を開く・閉じる（→ [editor/shell](../editor/shell.md)）/ Cmd+T 新タブ（[worktree パレット](../palette/worktree.md)を開く。タブ行の `+` も同じ。ブラウザ焦点中は新しいタブを作成 → [browser/chrome](../browser/chrome.md)）/ Cmd+Shift+T 閉じたエージェント パレット（後述。ブラウザ焦点中は閉じたタブを復元 → [browser/chrome](../browser/chrome.md)）/ Cmd+Shift+[ ] および Cmd+Shift+←→ タブ切替（ボードを持つ workspace ではボードも含めて巡回 → [board](board.md)）/ Cmd+W タブを閉じる（連の最後のタブで、エディターに未保存の文書があれば確認 → [editor/shell](../editor/shell.md)。アクティブ workspace の最後のタブを閉じても、ボードを持てばボード、持たなければ 0 タブの空状態でアクティブに残る。ウィンドウは閉じない → [workspace](../platform/workspace.md)。ブラウザ焦点中は `TODAY` タブのみ閉鎖 → [browser/chrome](../browser/chrome.md)）/ Cmd+Shift+A エージェント起動パレット・Cmd+Shift+C デフォルトエージェント起動（→ [agent/launch](../agent/launch.md)）/ Cmd+Shift+S workspace パレット（→ [workspace パレット](../palette/workspace.md)）/ Cmd+Shift+X タスク画面（→ [tasks](../palette/tasks.md)）/ Cmd+, 設定パレット（→ [settings](../palette/settings.md)）/ Cmd+F 検索（端末はスクロールバック → [search](../terminal/search.md)、エディターはファイル内 → [editor/code](../editor/code.md)）/ Cmd+R タブリネーム（ブラウザ焦点中はページ再読込 → [chrome](chrome.md)・[browser/chrome](../browser/chrome.md)）/ Cmd+↑↓ 先頭/末尾ジャンプ（端末はスクロールバック → [terminal/core](../terminal/core.md)、エディターは文書 → [editor/code](../editor/code.md)）/ Cmd+Shift+E アクティブタブの cwd を GUI エディタで開く / ⌘⌘（Cmd 素タップ×2）Attention パレット（→ [attention](../palette/attention.md)。前面時。背面時はメニューバーのドロップダウン → [menubar](menubar.md)）。
- フォント動的ズーム Cmd +/-/0（ghostty binding action）。

**Cmd+Shift+T は「閉じたエージェント」パレットを開く**（→ [closed-agents](../palette/closed-agents.md)）。この workspace で閉じたまま戻っていないエージェントセッションを[寿命ログ](../platform/session-log.md)から一覧し、Enter で 1 件を休眠チケットとして戻して起こす。閉じ方（人のジェスチャ・プロセス終了・制御 API・エージェント自身の終了）を問わず、アプリの再起動をまたいで戻せる。素のシェルタブは対象外——戻してもプロセスもスクロールバックも戻らず、resume を持つ CLI だけが中身ごと戻るため。戻るのは cwd と同一性だけで、明示タイトルは付かず、位置は新規タブと同じ規則——同じ worktree の連が残っていればその右端、無ければ末尾（→ [persistence](../platform/persistence.md)・[chrome](chrome.md) の連）。0 タブの workspace でも開く。

## cwd の確定

cwd を指定せずに起こすタブ（エージェント起動・制御 API の `spawn`・初回起動のシェル）の初期 cwd は、アクティブタブの実効 cwd（0 タブ・ボード選択中なら workspace の root path）を**明示指定**して起こす——cwd 未指定の surface は ghostty がホームへ解決してしまうため、ここで必ず確定させる。[worktree パレット](../palette/worktree.md)がリポジトリを探す基点も同じ値を使う。workspace 新規作成時の初期シェルは rootPath 指定（→ [workspace](../platform/workspace.md)）。

## GUI エディタ起動（Cmd+Shift+E）

アクティブタブの cwd（OSC 7 報告値、無ければ初期 cwd）を GUI エディタでフォルダとして開く。エディタは `$VISUAL` → `$EDITOR`（GUI エディタのときのみ採用）→ PATH 検索（`code`/`cursor`/`windsurf`/`zed`/`subl` の先頭ヒット）で決定し、解決・起動は子プロセス PATH（[shell-path](../platform/shell-path.md)）で行う——GUI アプリの限定 PATH を回避するため。解決できたときだけプロセス内に覚える。未検出は `NSAlert`、cwd 不明はビープ。同じ解決を OSC 8 リンク（→ [terminal/links](../terminal/links.md)）のテキストファイルにも使い、そこではフォルダの代わりにファイルパスを渡す。
