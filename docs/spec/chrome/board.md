# ボード

ボードは、workspace がタブの並びとは別に持つ 1 枚の面。端末の代わりに content を占めるが、タブではない——端末 surface を持たず、閉じられず、並びの中で動かない。今ボードを持つのは [Home](../platform/workspace.md#home) だけ。中身は部品の並びで、今ある部品は[タスクの自動追加](../platform/automation.md)の部品だけ。何も決めていない Home のボードはこの部品 1 つを出す。

タブの並びの外に置くのは、タブの並びが「端末 surface 1 枚」を前提に、制御 API・Attention・保存・秘書の判定から広く読まれているため。ボードを混ぜると、それらすべてに例外が要る。どの workspace がボードを持つかは store の 1 つの判定が決め、workspace 自身は知らない。

## タブ行での位置と見え方

ボードを持つ workspace では、タブ行（[chrome](chrome.md)）の左端、横スクロール領域の外にボードのセルが固定される。セルは単独タブの器（無彩色の地・小さな角丸）に家のグリフと workspace 名を載せ、右に細い区切り線を置く。選択中はタブと同じく前景色を反転する。ラベルは workspace 名なので、Home を改名すれば追随する。

スクロール領域の外にあるので、タブが多くて横スクロールしてもセルは左端に残り、タブの幅の配分・並び替えのドラッグの幾何にも入らない。セルの幅は、タブに配る利用可能幅から先に引く。

## 選び方と巡回

セルのクリックでボードを選ぶ。⌘⇧] / ⌘⇧[（⌘⇧→ / ⌘⇧← も同じ）は「ボード → タブ 1 … タブ n → ボード」を 1 つの環として回る。ボードを選んでいる間もこのキーで巡回できる。タブが 0 枚なら、巡回してもボードのまま。

workspace の選択は「何も無い／ボード／どのタブか」の 1 つの値で、タブは位置ではなくタブそのものを指す。並び替え・連の再編・タブの追加で並びが変わっても、同じタブを指し続ける。

## 消えない・動かない

ボードは閉じる操作を受けない。セルには中クリック・右クリックのメニュー・ドラッグを付けていない。タブをボードの左へ落とすこともできない（並び替えはスクロール領域の中だけの話）。⌘W はボードを選んでいる間は何も起こさない。制御 API の `close_tab` もボードを指せない（ボードには tabId が無く、`list_tabs` にも出ない）。

ボードを持つ workspace の最後のタブを閉じると（⌘W・中クリック・`close_tab`・シェル終了のいずれでも）ボードが選ばれ、空表示にはならない。ボードを選んでいる間に他のタブが閉じても（秘書の会話が終わったときを含む）、ボードは出たままで、閉じたタブの画面は残らない。

## 選んでいる間は「選んでいるタブが無い」

ボードには場所も面も無いので、選んでいる間は 0 タブと同じ規則に乗る。例外を作らないため。

- ⌘W・⌘R・⌘E・⌘⇧F・⌘F・⌘↑↓・⌘S・フォントの拡大縮小は何も起こさず、端末にも届かない。⌘⇧E はビープする。
- ⌘T・⌘⇧A・⌘⇧C・⌘⇧S・⌘⇧X・⌘⇧T・⌘,・⌘H・⌘⌘ はいつもどおり効く。新しいタブは workspace の root で起き、選ばれる。
- 上段の現在地と位置ドットは出ない。done のフォーカス消費・通知の抑制は効かない（見ているタブが無い）。
- 制御 API の `list_tabs` では、その workspace のどのタブも `active: false`。`focus_tab` でタブを指すと、そのタブが選ばれてボードから外れる。
- [秘書](../agent/secretary.md)・`start_task`・`select: false` の `spawn` が裏でタブを起こしても、ボードは出したままにしてそのタブを選ばない——裏で起こすタブを選んで見せるのは、何も出していなかった（空の）workspace だけで、ボードを持つ workspace は空にならない。

## 部品の並び

ボードの中身は、上から並べた部品と、その下のフッター。部品は種類で指し、1 つのボードに同じ種類は 1 つまで。今ある種類は `automation`（下の自動追加の部品）だけ。

- 部品を置く・外すのは[制御 API](../control/api.md)（`list_board_parts`・`add_board_part`・`remove_board_part`）と、それにそのまま乗る MCP のツールと [`orb board`](../control/cli.md)。人の手で置く・外す画面は無い——何を出すかは AI に頼んで変える。置くは末尾へ、既にあれば何もしない。外すも無ければ何もしない。
- 宛先はボードを持つ workspace だけで、ほかは断られる。どの workspace がボードを持つかは `list_workspaces` の `hasBoard` で外から見える。
- 置く・外すは人の選択・焦点・前面の workspace を動かさない。前面の workspace のボードならすぐ描き直り（ボードを選んでいなくても、戻れば変えた並びで出る）、背景の workspace なら前面に出たときに変えた並びで出る。
- 自動追加の部品を外しても、タスクの自動追加そのもの（走っている回・予定・候補）は消えず、⌘⇧X の提案タブからもいつもどおり扱える。置けばすぐ戻る。打ちかけの欄の文字はメモリに残っていれば戻る。
- 自動追加の部品を外すと、フッターの右の断りも消える——部品が無いのに残ると、何の断りか読めないため。

## 自動追加の部品

Home のボードは、タスクを生む仕組み（タスクの自動追加。画面では「自動化」と呼ぶ）を頼み、見て、手で動かす場所。1 件ずつのタスクをさばく ⌘⇧X とは階層で分ける。部品は、上の全幅の依頼の欄・左の一覧・右の欄（選んだ自動化の詳細か、欄を選んでいる間の案内）で 1 つ。下にボードのフッターを出す。自動化を作る・書き換えるのは AI の仕事なので、ボードでは定義を書き換えず、人は依頼の欄から頼む。

画面は自動化のストアと走らせ役を毎回読み、値を写さない。持つのは選択（同一性。欄か一覧の行のどれか 1 つ）と欄の中身だけ。だから裏の回の確定・AI による変更や削除・⌘⇧X での操作はすぐ映り、選択は同じ自動化に付いていく（消えたら同じ位置の行、末尾で頭打ち。一覧に居る間に行がすべて消えれば欄）。並びが変わっても選んだ自動化は替わらない。

画面に出す値（流れの段の並び・各段の件数・出力先の累計・回の結果の文・回の区分）は、自動化の定義・出力先ごとに溜める状態・回の記録を 1 か所で読み替えて作る。それらの形に依るのはそこだけで、一覧・詳細はその値と立ち位置（名前・止めているか・走っているか・次回・最新の回の区分）だけを読む。

### 依頼の欄

部品の上の全幅の欄（「❯ 自動化したいことを入力（例：自分宛ての Slack DM を10分ごとに確認して、依頼だけをタスク候補にする）」、右に「↵ 依頼する」）に打って ↵ を押すと、その文がタスクの自動追加の依頼として[秘書](../agent/secretary.md)の頼みの列に入り、欄が空になる。欄に打った文はどれも自動追加の依頼として届く——欄は自動追加を頼む口で、だから自動追加の部品の中にある。

- 空か空白だけの欄の ↵ は何もせず、何も出さない。日本語入力の変換を確定する ↵ では送らず、↵ を押し続けても送るのは 1 回だけ。
- 受けたときは文字で知らせない。秘書が作業中・入力待ちで頼みが溜めに積まれたときも何も出さない（手が空いたら届く）。claude が無ければフッターの右に赤で「claude が見つからないので依頼できない」と出し、欄はそのまま。
- ボードに出る文言（欄・フッター・断り）には「秘書」の語を出さない。人にとっての口は自動化を頼む欄で、誰が受けるかは中の話のため。
- 打ちかけの文字は保存しない（Orbe を終了すると消える。⌘⇧X の入力欄と同じ）。
- 欄の例と、欄を選んでいる間に出す入力例は 1 か所の並びから引く。今ある出力先で言える例だけを置く。並びは Slack の DM・GitHub の PR（どちらもタスク候補）・「毎晩23時に ~/bin/daily-note.sh を実行する」（コマンド）で、先頭を欄の例にも使う。

### 修正を依頼

一覧で自動化を選んで ⌘↵ を押すと、その場でその自動化の直しを頼む（「自動化 3「Backlog: 担当課題」を直す。」の 1 行）。焦点は一覧に残り、受けたときは文字で知らせない（溜めに積まれたときも）。直し方を細かく伝えたいときは、欄にふつうに書けば自動追加の依頼として届く。

- 頼む相手は押した時点のストアから引く。もう消えていれば頼まず、フッターの右に赤で「その自動化はもうありません」を出す。claude が無ければ赤で「claude が見つからないので依頼できない」。

### 一覧

左の欄の頭に「自動化 4」（件数）。行は 2 段で、上に点・名前・右端の文、下に出力先の種類（「タスク候補」「コマンド」「報告」）といつ（「30分ごと」「毎日 9:00 / 13:00」）。

- **並び**: 前回が失敗したもの（止めていない）→ それ以外（止めていない）→ 止めているもの。群の中は ID 順。走っているかは並びに効かない——走り出すたびに行が跳ねないため。
- **右端**: 走っていれば「実行中…」（強調色）、止めていれば「停止中」、まだ回っていなければ「まだ回っていない」、前回が失敗なら「13:00 に失敗」（赤）、ほかは前回の結果（「16:40 に 2件を追加」「16:00 に新着なし」「23:00 に完了」「18:00 に報告」「18:00 に報告なし」）。この順で上が勝つ。失敗の理由は詳細の実行履歴で読む。
- **点と名前**: 前回が失敗（止めていない）なら赤、止めていれば沈んだ色、それ以外は強調色。止めている名前は減光する。色だけに意味を載せず、右端の文字でも言う。

並び・点・右端は立ち位置から読み、前回が失敗かどうかは回の区分の 1 か所の判定から来る。同じ判定が散ると、優先順位が 1 か所だけずれるため。

### 詳細

一覧で自動化を選んでいる間、右の欄に出す。

- **見出し**: 名前と、その下に前回（「前回 今日 16:40　2件をタスク候補に追加」、コマンドが走った回なら「前回 今日 23:00　完了」、報告のある回なら「前回 今日 18:00　<報告の 1 行目>」、失敗なら「前回 今日 13:00　失敗」。まだなら「まだ回っていない」）。右に「次回 16:50」（今日でなければ日付付き）、止めていれば「停止中」。
- **流れ**: 段を縦の線でつなぐ。「トリガー（いつ）→ 取得元 → Orbe 既に見たものを除く → 処理 1..n → 出力先」。取得元の無い自動化は、既に見たものを除く段も無い（段が無ければトリガー → 出力先だけ）。
  - 取得元は役割と手段の札（agent はモデル名、コマンドは「コマンド」）だけを出し、名前は空。箱に依頼文かコマンドの全文、agent なら下に使えるツールを札で並べ、作業ディレクトリは指定があるときだけ短い注記で出す。承認なしで裏で走るものを、いつも確かめられるため。
  - 処理の段は名前と手段の札（agent はモデル名、コマンドは「コマンド」）、箱に指示文かコマンドの全文、コマンドなら作業ディレクトリの注記。モデルを省略した段は、走るときと同じ解いた既定（最後の段は sonnet、ほかは haiku）を出す。
  - 出力先の段は名前に出力先の種類を出す。コマンドなら取得元・処理の段のコマンドと同じく、箱にコマンドの全文・作業ディレクトリの注記を出す（上限は出さない）。手段の札は出さない——名前「コマンド」と同じ語で、何も言い足さないため。
  - 出力先が報告なら、出力先の段は名前「報告」だけ（報告は定義に何も持たない）。
  - 出力先がタスク候補なら、出力先の段の下に[採用・見送りの累計](../platform/automation.md#採用見送りの累計)を作業ディレクトリと同じ注記で「これまでに採用 9件 / 見送り 3件」と出す。0 件でも出す——候補を出し続けているのに一度もさばかれていないことも、読む値だから。
  - [通知](../platform/automation.md#回の知らせ)があれば、どの出力先でも、出力先の段の注記のいちばん下に通知先を「通知：メニューバー」「通知：通知センター」と出す。注記は出どころ（作業ディレクトリ・累計・通知）ごとに 1 行。通知を切り替えるキーは置かない——定義を書くのは AI の口だけで、人は依頼の欄から頼む。
  - 右の「前回の件数」の列に、最新の回で各段を出た件数を棒と数で出す（棒の長さはその回の最大が基準）。件数の列は取得元を持つ並びだけに出す。取得元は取れた数、既に見たものを除くは新しい項目の数、処理の各段は出した行の数、出力先はタスク候補なら受けた候補の数、コマンドなら標準入力に渡した行の数（走らなかった回は 0）、報告なら報告があれば 1。
  - 届かなかった段は数を出さない。取得元で落ちた回は何も出さず、段で落ちた回はその段の手前まで（落ちた段は回の記録の最後の段）。出力先で落ちた回（出力先の記録を持つ失敗。出力先のコマンドが 0 以外で終わった回など）は最後の段まで出し、出力先は出さない。新しい項目が無かった回・途中の段が 0 件を出した回は、その先の段と出力先を出さない。
- **実行履歴**: 見出しの右に直近の回の帯（最大 20 回。古い回が左、出した回は強調色・何も出さなかった回は沈んだ色・失敗は赤）。出した回は、タスク候補なら候補を 1 つ以上受けた回、コマンドなら走った回、報告なら報告のある回。下に新しい順で時刻と結果の 1 行ずつ。時刻は今日なら「16:40」、ほかの日は「10/3 13:00」、「今すぐ」で回った回は時刻の後に「今すぐ」を添える。
  - 結果は「2件を追加」「完了」（コマンドが走った）「新着なし」「処理 2 ですべて除外」（最初に 0 件を出した段）「追加なし」（候補を出さず対応済みだけ）「報告の全文」「報告なし」（最後の段が何も出さなかった。「すべて除外」とは読まない）「失敗：理由」。
  - 失敗の行は理由の全文を赤で、報告の行は報告の全文を折り返す。ボードで失敗の理由と報告を読めるのはここだけで、失敗の理由は直すかどうかを決める材料になるため。ほかの行は 1 行で末尾を省く。

長ければ右の欄が縦にスクロールし、選択が替わると先頭へ戻る。窓が狭く流れと実行履歴を並べると流れの原文が読めない幅になるときは、実行履歴を流れの下へ回す。

### 欄を選んでいる間

右の欄には詳細の代わりに、案内の一文（「いつ、何をしてほしいかを一文で送ると、左の一覧に加わります。」）と「入力例」の 3 つを出す。一覧は左に残る。自動化が 0 件のときも、選べるのは欄だけなので案内が出る。

### キー

キーは焦点のある場所（欄か一覧）で意味が替わる。欄の「↵ 依頼する」と一覧の「↵ 今すぐ実行」は別の場所のキーで、欄では space・↵ が文字の入力・送信になり、一覧の操作にならない。

欄は一覧の上の 1 段で、欄と一覧の行は 1 つの選択を分け合う——⌘⇧X で入力の行き先と一覧の行が 1 つの選択の同一性なのと同じ作法。選ばれて見えるのは常に 1 か所で、焦点の場所は選択から決まる。

- 欄を選んでいる間は、どの行も選ばれた見た目にならず、右の欄は案内になる（詳しく見る自動化が選ばれていない）。欄の枠は強調色になる。
- 一覧の行を選んでいる間は、欄は控えめな枠になる。
- ↑↓ は欄と一覧の行を 1 つの並びとして端で巡回する。欄の ↓ は一覧の先頭、先頭の行の ↑ は欄、欄の ↑ は一覧の末尾、末尾の行の ↓ は欄へ移る。欄から一覧へは、並びの次（先頭の行）か巡回した先（末尾の行）へ移る。

一覧に焦点がある間:

| キー | 動き |
|---|---|
| ↑↓ | 選択。先頭の ↑・末尾の ↓ は欄へ（押し続ければ流れる） |
| space | 停止 ⇄ 再開 |
| ↵（修飾なし） | 今すぐ実行 |
| ⌘↵ | 修正を依頼（その場で頼む） |
| ⌘⌫ | 確認なしで削除。同じ位置の行が選ばれる |

欄に焦点がある間:

| キー | 動き |
|---|---|
| ↵ | 依頼する |
| ↓ | 一覧の先頭へ |
| ↑ | 一覧の末尾へ |
| esc | 一覧の先頭へ（↓ と同じ） |

自動追加が 0 件なら、欄の ↑↓ は何もしない。

- space・↵・⌘↵・⌘⌫ は押した瞬間だけを操作にし、押し続けたキーリピートでは何も起きない。取り消せない操作を繰り返さないため。削除に確認を挟まないのはタスクの ⌘⌫ に揃えたため。
- 日本語入力の変換中の ↵・↑↓・esc は変換へ渡る。
- 走っている間の ↵ は断り、フッターの右に赤で「実行中のため今すぐ実行できません」を出す。
- space・↵・⌘⌫ の 3 つの操作は、キー・キーの表示・名前・断りまで ⌘⇧X の[提案タブ](../palette/automation.md)の中身と 1 つの定義を共有する。画面ごとにキーと表示が食い違わないため。⌘↵ はこの定義に入れない（⌘⇧X の中身では何もしないキーで、共有の定義はボードの都合を持たない）。
- 一覧のほかのキー（⇥・⌘↑↓・文字キーなど）と欄の ⇥ は何も起こさず、焦点もボードの外へ出ない。

フッターの右の断り（赤）は 1 枠で、次の操作（↑↓・space・↵・⌘↵・⌘⌫・esc・行のクリック・欄に打つ）で消える。フッターの左は焦点のある場所で効くキーで、ボタンは置かない。

- 一覧: 「↑↓ 移動　space 停止（止めていれば 再開）　↵ 今すぐ実行　⌘↵ 修正を依頼　⌘⌫ 削除」。自動化が 0 件なら出さない。
- 欄: 「↵ 依頼する　↓ 一覧へ」。自動化が 0 件なら「↓ 一覧へ」は出さない。

行のクリックで選ぶ。ポインタが乗っただけでは選択を動かさない——ボードは常に出ている画面で、ポインタが横切るたびに詳細が替わるのを避けるため。

### 時刻

「今日」「次回 17:00」などの時刻の文言は分の境で描き直す。開きっぱなしの画面に、日をまたいだ「今日」や過ぎた「次回」が残らないため（⌘⇧X は開いた時点で固定）。

### 0 件

自動化が無ければ一覧の頭は「自動化 0」、その下に「自動化はまだありません」を出し、一覧のキーは出さない。依頼の欄はいつもどおり出て、選ばれるのは欄だけ（右の欄は案内）。

## 焦点

ボードの面は、エディター面と同じく、焦点（first responder）が自分の中にあるときだけ chrome キーを受ける。焦点が欄にあっても同じ。端末タブを選んでいる間ボードは隠れて窓に残るが、焦点が無いので欄にも一覧にもキーが届かない。

焦点の宛先は部品の中（自動追加の部品の欄と一覧の 2 か所）にあり、部品がある間はボードの面そのものは焦点を受けない。面が焦点を受けられると、中身に焦点が無いままキーが黙って飲まれる状態が生まれうるため。部品が 1 つも無い間は、飲まれて困る中身が無いので面が焦点を持つ——⌘⇧] / ⌘⇧[・⌘T・⌘⇧X などの窓のキーはいつもどおり効き、ほかの打鍵は何も起こさない。

- 焦点が外から部品へ入る（ボードを選ぶ・パレットを閉じる・workspace を切り替えて戻る）と、欄が選ばれて欄に焦点がある。⌘⇧X が開くと入力欄に焦点があり ↓ で一覧へ下りるのと同じ形。一覧で選んでいた行は保たない——⌘⇧X も開き直すたびに選択を初めからにし、ボードへ入るのは開き直しにあたるため。
- 焦点がボードの中にある間の当て直し（裏のタブが閉じた・地のクリック）では、選んでいる場所（欄か一覧の行）のまま。
- 欄に焦点が来ると、打ってあった文は全文が選ばれる（AppKit の入力欄の既定。⌘⇧X の入力欄と同じ）。打てば置き換わり、→ で末尾から続けられる。
- クリックは中身へ届く。欄を押せば欄、行を押せばその行、一覧の地を押せば一覧（欄から来たなら先頭の行）、それ以外の地を押せば選んでいる場所へ焦点が移り、続けてキーが効く。
- メニューバーの[自動化の知らせ](menubar.md)を押すと、外から入る規則の後にその自動化の行が選ばれ、焦点は一覧にある（行き先の指定が入り方の既定に勝つ）。自動化が消えていれば欄が選ばれ、自動化の部品が無ければボードが開くだけ。
- ボードを通り過ぎるだけの移動（Home をボードのまま離れたあと、別の workspace から Home のタブへ `focus_tab` で移ると、Home へ戻る途中でボードが選ばれる）では、焦点は移った先のタブに残り、欄へは入らない。

部品の並びが変わったとき、焦点は**ボードの中にあるときだけ**追う。外（端末タブ・⌘⇧X などのパレット・別の workspace）にある焦点は、部品が置かれても外されても動かない。

- 焦点がボードの中にあるところで部品が外されると、焦点は窓へ落ちずボードの面に残る。
- 空のボードを見ていたところへ部品が置かれると、外から入ったときと同じく欄に焦点が入り、そのまま打てる。

## 空の状態

部品を 1 つも持たないボード（自動追加の部品を外したとき）は、中央に沈んだ一文（「まだ何も置かれていません」）だけを出し、フッターも出さない。字種と色はエディター面の空状態と同じ。地は端末・エディター面と同じ veil で、背景不透明度の設定にライブで追従する。

## 保存

ボードを選んでいたかと、部品の並び（決めた workspace だけ。空にした並びも空のまま戻る）は workspace ごとに保存し、再起動後も戻る（→ [persistence](../platform/persistence.md)）。保存の部品の並びが読めなければ、その欄だけ何も決めていない既定（自動追加の部品 1 つ）に戻る。どの workspace がボードを持つかは保存しない（Home であることから決まる）。
