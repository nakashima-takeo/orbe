# ボード

ボードは、workspace がタブの並びとは別に持つ 1 枚の面。端末の代わりに content を占めるが、タブではない——端末 surface を持たず、閉じられず、並びの中で動かない。今ボードを持つのは [Home](../platform/workspace.md#home) だけ。中身は部品の並びで、今ある部品は[自動化](../platform/automation.md)の部品だけ。何も決めていない Home のボードはこの部品 1 つを出す。

タブの並びの外に置くのは、タブの並びが「端末 surface 1 枚」を前提に、制御 API・Attention・保存の判定から広く読まれているため。ボードを混ぜると、それらすべてに例外が要る。どの workspace がボードを持つかは store の 1 つの判定が決め、workspace 自身は知らない。

## タブ行での位置と見え方

ボードを持つ workspace では、タブ行（[chrome](chrome.md)）の左端、横スクロール領域の外にボードのセルが固定される。セルは単独タブの器（無彩色の地・小さな角丸）に家のグリフと workspace 名を載せ、右に細い区切り線を置く。選択中はタブと同じく前景色を反転する。ラベルは workspace 名なので、Home を改名すれば追随する。

スクロール領域の外にあるので、タブが多くて横スクロールしてもセルは左端に残り、タブの幅の配分・並び替えのドラッグの幾何にも入らない。セルの幅は、タブに配る利用可能幅から先に引く。

## 選び方と巡回

セルのクリックでボードを選ぶ。⌘⇧] / ⌘⇧[（⌘⇧→ / ⌘⇧← も同じ）は「ボード → タブ 1 … タブ n → ボード」を 1 つの環として回る。ボードを選んでいる間もこのキーで巡回できる。タブが 0 枚なら、巡回してもボードのまま。

workspace の選択は「何も無い／ボード／どのタブか」の 1 つの値で、タブは位置ではなくタブそのものを指す。並び替え・連の再編・タブの追加で並びが変わっても、同じタブを指し続ける。

## 消えない・動かない

ボードは閉じる操作を受けない。セルには中クリック・右クリックのメニュー・ドラッグを付けていない。タブをボードの左へ落とすこともできない（並び替えはスクロール領域の中だけの話）。⌘W はボードを選んでいる間は何も起こさない。制御 API の `close_tab` もボードを指せない（ボードには tabId が無く、`list_tabs` にも出ない）。

ボードを持つ workspace の最後のタブを閉じると（⌘W・中クリック・`close_tab`・シェル終了のいずれでも）ボードが選ばれ、空表示にはならない。ボードを選んでいる間に他のタブが閉じても（agent が終わったときを含む）、ボードは出たままで、閉じたタブの画面は残らない。

## 選んでいる間は「選んでいるタブが無い」

ボードには場所も面も無いので、選んでいる間は 0 タブと同じ規則に乗る。例外を作らないため。

- ⌘W・⌘R・⌘E・⌘⇧F・⌘F・⌘↑↓・⌘S・フォントの拡大縮小は何も起こさず、端末にも届かない。⌘⇧E はビープする。
- ⌘T・⌘⇧A・⌘⇧C・⌘⇧S・⌘⇧X・⌘⇧T・⌘,・⌘H・⌘⌘ はいつもどおり効く。新しいタブは workspace の root で起き、選ばれる。
- 上段の現在地と位置ドットは出ない。done のフォーカス消費・通知の抑制は効かない（見ているタブが無い）。
- 制御 API の `list_tabs` では、その workspace のどのタブも `active: false`。`focus_tab` でタブを指すと、そのタブが選ばれてボードから外れる。
- `start_task`・`select: false` の `spawn` が裏でタブを起こしても、ボードは出したままにしてそのタブを選ばない——裏で起こすタブを選んで見せるのは、何も出していなかった（空の）workspace だけで、ボードを持つ workspace は空にならない。

## 部品の並び

ボードの中身は、上から並べた部品と、その下のフッター。部品は種類で指し、1 つのボードに同じ種類は 1 つまで。今ある種類は `automation`（下の自動化の部品）だけ。

- 部品を置く・外すのは[制御 API](../control/api.md)（`list_board_parts`・`add_board_part`・`remove_board_part`）と、それにそのまま乗る MCP のツールと [`orb board`](../control/cli.md)。人の手で置く・外す画面は無い——何を出すかは AI に頼んで変える。置くは末尾へ、既にあれば何もしない。外すも無ければ何もしない。
- 宛先はボードを持つ workspace だけで、ほかは断られる。どの workspace がボードを持つかは `list_workspaces` の `hasBoard` で外から見える。
- 置く・外すは人の選択・焦点・前面の workspace を動かさない。前面の workspace のボードならすぐ描き直り（ボードを選んでいなくても、戻れば変えた並びで出る）、背景の workspace なら前面に出たときに変えた並びで出る。
- 自動化の部品を外しても、自動化そのもの（走っている回・予定・候補）は消えず、タスクの自動追加は ⌘⇧X の提案タブからもいつもどおり扱える。置けばすぐ戻る。打ちかけの欄の文字はメモリに残っていれば戻る。
- 自動化の部品を外すと、フッターの右の断りも消える——部品が無いのに残ると、何の断りか読めないため。

## 自動化の部品

Home のボードは、自動化を頼み、見て、手で動かす場所。1 件ずつのタスクをさばく ⌘⇧X とは階層で分ける。部品は、上の全幅の依頼の欄・左の一覧・右の欄（選んだ自動化の詳細——見出し・地図・選んだ部品のカード——か、欄を選んでいる間の案内）で 1 つ。下にボードのフッターを出す。自動化を作る・書き換えるのは AI の仕事なので、ボードで書き換えるのは定義のうち[通知](#通知)だけで、ほかは依頼の欄から頼む。

画面は自動化のストアと走らせ役を毎回読み、値を写さない。持つのは選択（同一性。欄か一覧の行のどれか 1 つと、地図の段）・地図に居るかと欄の中身だけ。だから裏の回の確定・AI による変更や削除・⌘⇧X での操作はすぐ映り、選択は同じ自動化に付いていく（消えたら同じ位置の行、末尾で頭打ち。一覧に居る間に行がすべて消えれば欄）。並びが変わっても選んだ自動化は替わらない。

画面に出す値（一覧の行・見出しと帯・地図の行と線・カードの中身・回の結果の文・回の区分・畳み）は、自動化の定義・部品の状態・回の記録を 1 か所で読み替えて作る。値は読む側ごとに分かれ（一覧の行・詳細・カード）、結果の文・回の区分・畳みは共有する。定義と記録の形に依るのはそこだけで、一覧・詳細・カードはその値と立ち位置（名前・止めているか・走っているか・最後の回が失敗した部品があるか・次回）だけを読む。地図の線の割り当ても読み替えが行ごとの値に解き、ビューは描くだけ。

画面では部品を名前だけで言う（「返事が要る連絡を選ぶ」）。役割（取得・処理・判定・報告・作業・外部操作）は地図の役割の列とカードの頭でだけ見せる。行き先・出力先を言う言葉には役割の名前を使わない。成否・状態の印（成功のチェック・失敗の斜めの十字・停止の 2 本線・実行中の回る輪・帯の棒）と流れの向きの矢印は自前の図形で描き（[デザインの原則](../../design/design-system.md#1-原則) 8）、色だけでなく形でも見分ける。

### 依頼の欄

部品の上の全幅の欄（「❯ 自動化したいことを入力（例：自分宛ての Slack DM を10分ごとに確認して、依頼だけをタスク候補にする）」、右に「↵ 依頼する」）に打って ↵ を押すと、「依頼: 」に続けたその文を最初の入力にして Home に claude が 1 つ起き（[秘書](../agent/secretary.md)）、そのタブへ移って、欄が空になる。起きた claude の役目は自動化の定義を書く・直すことなので、欄に打った文はどれも自動化の依頼として扱われる——欄は自動化を頼む口で、だから自動化の部品の中にある。

- 空か空白だけの欄の ↵ は何もせず、何も出さない。日本語入力の変換を確定する ↵ では送らず、↵ を押し続けても送るのは 1 回だけ。
- 受けたときは文字で知らせない（claude のタブへ移る）。claude が無ければフッターの右に赤で「claude が見つからないので依頼できない」、Home にタブを起こせなければ「依頼できなかった」と出し、欄はそのまま。
- ボードに出る文言（欄・フッター・断り）には「秘書」の語を出さない。人にとっての口は自動化を頼む欄で、誰が受けるかは中の話のため。
- 打ちかけの文字は保存しない（Orbe を終了すると消える。⌘⇧X の入力欄と同じ）。
- 欄の例と、欄を選んでいる間に出す入力例は 1 か所の並びから引く。今ある部品の行き先で言える例だけを置く。並びは Slack の DM（タスク候補）・「平日 9:00 に、レビュー待ちの PR をまとめて Slack の #dev-me に投稿する」（作業）・「毎晩23時に ~/bin/daily-note.sh を実行する」（外部操作）で、先頭を欄の例にも使う。

### 修正を依頼

選んだ部品のカードの「修正を依頼」を押すと、依頼の欄に「自動化「<自動化の名前>」の部品「<部品の名前>」の修正：」が入り（書きかけがあれば置き換える）、焦点が欄に移って末尾から続けて打てる。続きを書いて ↵ で、欄からふつうに頼む。押しただけでは頼まない。キーは当てない——↵ は自然でよく使う操作にだけ当てるため。キーだけで頼むときは、欄に自分で書く。

### 一覧

左の欄の頭に「自動化 4」（件数）。行は 2 段で、上に名前と状態、下に前回の結果と次回。

- **状態**（名前の右）: 走っていれば回る輪と「実行中」（強調色。どれかの部品が走っているか、流している途中。流しの部品と部品の間も含む）、止めていれば停止の 2 本線と「停止中」、ほかは何も出さない。止めている名前は減光する。
- **前回**（下段の左）: 最後の回が失敗した部品があれば失敗の印、無ければ成功の印と「前回 16:41」。時刻はどの部品かを問わず最後に動いた時刻で、今日なら時刻だけ、昨日なら「前回 昨日 23:00」、ほかは「前回 10/12 10:00」。まだ一度も動いていなければ印なしで「まだ動いていない」。状態（実行中・停止中）と前回の結果は混ぜない——走っていることと前回失敗したことは別の事実で、片方がもう片方を隠さないため。
- **次回**（下段の右）: 部品のうち次に予定で回る時刻「次回 16:50」。予定のある部品が無ければ「手動」、止めていれば出さない。
- **並び**: 最後の回が失敗した部品があるもの（止めていない）→ それ以外（止めていない）→ 止めているもの。群の中は ID 順。部品ごとの最新の回で見るので、失敗の後に別の部品が成功しても上の群に残る。走っているかは並びに効かない——走り出すたびに行が跳ねないため。
- **選択の地**: 焦点が一覧にある間、選んでいる行は濃い地。地図にある間は薄い地。
- **定義を読めない自動化**（[automation](../platform/automation.md#保存)）: 名前（読めなければ「自動化 #3」）と、下段に赤の失敗の印と「定義エラー（invalid parts[1].instruction）」（理由の原文を添える。英語の画面は「説明: 原文」）。前回・次回・状態は出さず、並びは最後の回が失敗した群に入る——人が気づいて直すべきものなので。

並びと状態は立ち位置から読み、失敗した部品があるかは 1 か所の判定から来る。同じ判定が散ると、優先順位が 1 か所だけずれるため。

### 詳細

一覧で自動化を選んでいる間、右の欄に出す。上に見出し、その下の左に地図、右に選んだ部品のカードの欄。

定義を読めない自動化を選んでいる間は、名前・理由の行（一覧と同じ）・「修正を依頼」のボタンだけを出し、地図もカードも出さない（↵ / → で地図へ入らない）。「修正を依頼」は依頼の欄に「自動化「<名前>」の修正：<理由の原文>」を入れ（読むのは AI なので説明の語は付けない）、焦点を欄へ移す（[修正を依頼](#修正を依頼)と同じ流儀）。一覧のキーは ↑↓ と ⌘⌫（削除）だけが効き、⌘↵・space は何もしない。

- **見出し**: 名前と、その下に「通知：メニューバー」（通知しなければ「通知：なし」）。この行は地図の先頭の段で、地図に居てこの段を選んでいる間は濃い選択の地になり、[通知](#通知)の 3 択がこの行の右に開く。右に、部品のうち次に予定で回る時刻（「次回 16:50」。今日でなければ日付付き。予定のある部品が無ければ「手動」）、止めていれば停止の 2 本線と「停止中」。その下に「直近の実行」と帯（全部品を混ぜた新しい 20 回。古い回が左。出した回は高い棒、何もしなかった回は低い棒、失敗は赤の斜めの十字）。出した回は[回の区分](../platform/automation.md#回の知らせ)の「出した」（判定が候補を 1 つ以上受けた・報告が文を書いた・外部操作が走った・作業が何もしなかった以外）。

#### 地図

見出し「流れ」の右に部品の数（「12 部品」）と列の見出し「未処理」「前回」。部品を入力の深さ順（入力の無い部品が先、同じ深さは定義の順）に 1 行ずつ縦に並べ、続けて行き先の行を並べる。行の高さは決まっていて、12 部品でも一画面に収まる。

- **行**: 左から溝・役割（「取得」「処理」「判定」「報告」「作業」「外部操作」）・名前・予定の札（「30分ごと」「毎日 9:00」「手動」。前の部品に連動する部品には付けない）・走っていれば「実行中」・出力の形式エラーの札・入力の部品の名前（左向きの矢印と「GitHub・CI」）・未処理・前回。幅に収まらなければ、入力の部品の名前（矢印ごと）、次に予定の札の末尾を省き、名前と出力の形式エラーの札は省かない。
- **未処理**: 入力のある部品だけ、読めば取る行の数だけで（「6」。古さの上限を過ぎた行を除く。1 以上は強調色、0 は沈んだ色）。
- **前回**: その部品の最新の回の成否の印・時刻（一覧と同じ言い方）・量。量は取得「新着 2 件」・「新着なし」、処理「1 件を次へ」、判定「候補 2 件」・「候補なし」、失敗「失敗」（赤）。報告・作業・外部操作は量を言わない。何も起きなかった量（新着なし・0 件を次へ・候補なし）は沈んだ色。まだ動いていなければ印なしで「まだ」。最新の回が不明な記録なら、成否の印と時刻だけで量を言わない。
- **失敗の理由**: 最新の回が失敗した部品は、行の下に理由の行を足す（「制限時間内に終わらなかった（the part "contact" ended: stopped at the time limit）」。赤。言い方は[回の記録の失敗の種類](../platform/automation.md#回の記録)の日本語に原文を添える。英語の画面は原文を重ねず、原文にだけある抜粋を「説明: 抜粋」で添える）。理由の行でも、溝の下へ続く線は途切れずに描く。
- **出力の形式エラーの札**: 部品に[外した印](../platform/automation.md#決まりを外した出力)があれば、赤の札「出力の形式エラー」。
- **行き先の行**: 役割の欄は「行き先」。判定の部品があれば「タスク候補」（右に「判断待ち 6 件」——この自動化の棚に出ている判断待ちの候補の数。⌘⇧X の棚と同じ数え方）、報告か作業の部品があれば、その文の出し先（通知がメニューバーなら「メニューバーに出す」、通知センターなら「通知センターに出す」、通知しなければ「ボードに残す」）。部品ではないので選べない。
- **溝の線**: 部品どうしのつながりを `git log --graph` の流儀で描く。行を上から見て、その行で最後の受け手を迎える入力の線のうち最も左の線に点を置き、無ければ空いている最も左の線に置く。ほかの入力の線は点へ曲がり込み、下にまだ受け手が居れば曲がり込みつつ下へも続く。その行で終わった線は空き、次の行から使える。点の出力を受ける行が下にあれば、点から下へ線が続く。行き先の行の入力は、タスク候補なら判定の部品すべて、文の出し先なら報告と作業の部品すべて。線の本数（溝の幅）は自動化ごとに要る分だけ取る（入力の多い自動化で線が溢れない）。
- **点**: 普段は強調色の輪、最新の回が失敗なら赤の輪に斜めの十字、走っている間は点の代わりに回る輪（働いている色）。行き先の行は塗りつぶした点。
- **選択の地**: 地図に居る間、選ばれている部品の行に濃い地。一覧に居る間は地図に地は無い。
- 行のクリックはその部品を選んで地図に居る（下の[キー](#キー)）。

#### 選んだ部品のカード

地図の右の欄。部品が選ばれている間（地図の部品の段に居る間）だけ中身を出し、一覧に居る間・「通知」の段の間は空のまま幅を保つ——段を移るたびに地図の幅が変わらないため。地図に出さない部品の中身（手段・モデル・ツール・指示文・出力の性質・取り方・上限・制限時間・場所・回の記録）を出すのはここだけ。

- **頭**: 前回の成否の印（走っていれば回る輪、まだ動いていなければ無し）・役割・名前。
- **項目**（部品に無い項目は出さない。この順）:
  - 「実行」agent なら「claude（sonnet）」（モデルを省いていれば役割の既定）、コマンドなら「コマンド」。
  - 「ツール」agent のツール。MCP は「Gmail（MCP）」（`mcp__` から次の `__` までをサーバー名とし、claude.ai のコネクタの頭 `claude_ai_` とプラグインの頭 `plugin_<プラグイン名>_` は落とし、頭を大文字に）、`Bash(git log:*)` は「git log コマンド」（末尾の `:*` の手前まで）。同じ表示になるもの（同じサーバーのツール・同じコマンド）は最初の 1 つにまとめる。
  - 「予定」「30分ごと」「平日 13:00」「手動」「前の部品に連動」。
  - 「出力の性質」（取得・処理だけ）出す行が何を表すか——「今の集合」か「出来事の流れ」。出来事の流れの取得は、前回成功の目印から取ることを添える（「出来事の流れ（前回 16:00 以降を取る）」。一度も成功していなければ添えない）。出す側の性質で、受け手の取り方とは別の語で言う。
  - 「入力元」左向きの矢印と「重複をまとめる」。受け手の取り方（毎回すべての入力・古さの上限のある入力）は、名前に「（毎回すべて・24 時間まで）」を添える。
  - 「出力先」次の部品なら右向きの矢印と「開発の依頼を選ぶ」、判定は「タスク候補（判断待ち 6 件）」、報告と作業は行き先の行と同じ文の出し先（「メニューバーに出す」など）、外部操作は「なし（コマンドを動かすだけ）」。
  - 「未処理」（入力のある部品だけ）「8 件」（1 以上は強調色、0 は沈んだ色）に件数の上限を添える（「上限なし」「100 件を超えた古い分は捨てる」）。
  - 「制限時間」「10 分」（省いていれば手段の既定）。
  - 「場所」（作業ディレクトリのあるコマンドだけ）。
  - 「次回」（予定のある部品だけ）「10/19 13:00」、止めていれば「停止中」。
- **指示文かコマンド**: 箱に全文。
- **出力の形式エラーの枠**: 部品に[外した印](../platform/automation.md#決まりを外した出力)があれば、赤の地に「出力の形式エラー · 16:30 · 2 件」、外れた件の理由（「3 件目：link が無い」。最初の 5 件）、結果の一言（「その場で修正済み」／「修正されず失敗」）。
- **前回の報告・前回の応答**: 報告の部品は「前回の報告」、作業の部品は「前回の応答」と時刻、下に文を残した最新の回の全文。
- **この部品の実行履歴**: その部品の回を新しい順に、時刻と結果の 1 行ずつ。時刻の列は中身の最も広い時刻に合わせる（狭くても見本の幅）。手で実行した回は時刻の後に「手動」。結果は取得「新着 2 件」・「新着なし」、処理「3 件のうち 1 件を次へ」、判定「5 件を判定して候補 1 件」・「6 件を判定、候補なし」、報告「2 件を要約」（入力の無い報告は「報告した」）・「報告なし」、作業「完了」・「何もしなかった（<理由>）」、外部操作「実行した」、失敗「失敗：<日本語の説明>（<原文>）」（赤。英語の画面は原文を重ねず、原文にだけある抜粋を「説明: 抜粋」で添える）。何も起きなかった結果は沈んだ色。行の末尾に、形式エラーをその場で直して通った回は「（形式エラーを修正済み）」、上限で捨てた回は「（古い 2 件を捨てた）」「（多すぎた 3 件を捨てた）」、読む前に残す期間を過ぎた出来事があった回は「（読む前に期限で消えた 2 件）」、判定の確定で捨てた案は「（既に候補にあるので 1 件を捨てた）」「（対応済みにする候補が無いので 1 件を捨てた）」を添える。[不明な記録](../platform/automation.md#回の記録)は時刻と「成功（記録を読めない）」「失敗（記録を読めない）」だけ（失敗は赤）。失敗の理由と何もしなかった理由は全文を折り返し、ほかは 1 行で末尾を省く。取得の新着なし（失敗でも手動でもない回で新しい項目が 0、行末に添え書きが付かない回）が 3 回以上続く区間は、期間の 1 行「13:05〜16:30 は新着なし」（日をまたげば「10/18 9:00〜16:30 は新着なし」）に畳む——短い間隔の取得の「新着なし」が、他の回を押し出さないため。
- **ボタン**: 「⌘↵ ここまで今すぐ実行」（地図の ⌘↵ と同じ操作で、その部品まで流す。キーと名前と断りも同じ定義から読む）と「修正を依頼」（[修正を依頼](#修正を依頼)）。

長ければ右の欄全体が縦にスクロールし、選択が替わると先頭へ戻る。窓が狭く、地図とカードを並べると地図に残る幅が決まった下限に満たないときは、カードを地図の下へ回す（一覧とカードの幅は固定なので、狭い窓では地図の幅だけが削られるため）。このとき部品が選ばれていなければカードは出さない。選んだ段が見える範囲の外へ出ても、↑↓ でスクロールを引き寄せない（12 部品で一画面に収まる前提）。サブメニュー「通知」を開くときだけは「通知」の行を見える範囲へ引き寄せる（→ [通知](#通知)）。

### 通知

地図の「通知」の段（見出しの「通知：…」の行）で ↵ か → を押すと（行のクリックでも）、行が詳細の見える範囲の外にあれば引き寄せてから、行の右に、行の上端に揃えてサブメニュー「通知」が開く。中身は「通知しない／メニューバー／通知センター」の 3 行で、今の設定の行に印が付き、↑↓ の選びもその行から始まる。

- ↑↓ で選び（端で巡回）、↵ で決める。行のクリックでも決まる。← か esc は何も変えずに閉じて「通知」の段へ戻る。メニューの外のクリックは閉じるだけで、下の行や欄へは届かない。ポインタが乗っても選びは動かない。
- 決めた値は自動化の定義の `notify` に書かれ（[自動化](../platform/automation.md#回の知らせ)）、`list_automations`・`orb automation list` に出て、再起動後も残る。見ていた版を添えて書き、今と同じ値を選んだら何も書かない。決めている間に自動化が消えていた・AI が書き換えて版が変わっていたら、書かずに何も出さない（印は今の値を指す）。
- 書き換わるのは通知だけで、走っている回は止まらない。見出しの行・行き先の行・カードの出力先はすぐ替わり、知らせは決めた後に記録される回から（走っている回も含む）新しい設定に従う。
- 通知センターを選んだとき、Orbe の通知の許可がまだ決まっていなければ、その場で macOS が許可を問う（AI の口で書いたときと同じ）。
- サブメニューは「通知」の段の付属で、焦点の場所を増やさない。段が変わる・地図を出ると閉じる——外から入る（欄が選ばれる）・知らせを押して行を指す・その自動化がほかの口で消えて選択が移る、のどれでも。端末タブへ移る・パレットを開くだけでは閉じない。開いている間に AI が通知を書き換えれば印は今の値へ移る。開いた後に行が詳細の見える範囲から外れれば閉じる——見えないメニューがキーを奪わないため。部品の上下の端を越えるなら、収まるまで内側へずれる。
- 置くのはボードだけで、⌘⇧X の提案タブには置かない。提案タブは候補をさばく場所で、通知の状態も出していないため。

開いている間のキー:

| キー | 動き |
|---|---|
| ↑↓ | 3 行を選ぶ（端で巡回。押し続ければ流れる） |
| ↵（修飾なし） | 選んでいる行に決めて閉じる（押した瞬間だけ） |
| ← / esc | 何もせず閉じる |

ほかのキー（space・⌘↵・⌘⌫・→・文字・⇥ など）は何も起こさず、下の地図や一覧の操作にもならない。

### 欄を選んでいる間

右の欄には詳細の代わりに、案内の一文（「いつ、何をしてほしいかを一文で送ると、左の一覧に加わります。」）と「入力例」の 3 つを出す。一覧は左に残る。自動化が 0 件のときも、選べるのは欄だけなので案内が出る。

### キー

キーは焦点のある場所（欄・一覧・地図）で意味が替わる。⌘⇧X の棚と候補の一覧と同じ流儀で、一覧の ↵ / → で地図へ入り、地図の ← で戻り、⌘↵ で実行する。欄では space・↵ が文字の入力・送信になり、一覧の操作にならない。

地図は一覧の子の場所で、一覧で選んだ自動化の段（見出しの「通知」と部品）を選ぶ。地図に居る間も一覧の行は選んだまま（薄い地）。段が「選ばれている」のは地図に居る間だけで、地図の選択の地・カードの中身・地図の ⌘↵ はそれを読む——焦点のある列だけが選ばれているに揃え、見えない部品に ⌘↵ が効かないため。地図へ入ると前に居た段が選ばれ、初めて入るときと、一覧で別の自動化を選んだ後は先頭の部品。地図に居る間に選んでいた自動化がほかの口で消えると一覧へ戻る（移った先の自動化の段を勝手に選ばない）。部品が消えれば同じ位置の段へ。

欄は一覧の上の 1 段で、欄と一覧の行は 1 つの選択を分け合う——⌘⇧X で入力の行き先と一覧の行が 1 つの選択の同一性なのと同じ作法。選ばれて見えるのは常に 1 か所で、焦点の場所は選択から決まる。

- 欄を選んでいる間は、どの行も選ばれた見た目にならず、右の欄は案内になる（詳しく見る自動化が選ばれていない）。欄の枠は強調色になる。
- 一覧の行を選んでいる間は、欄は控えめな枠になる。
- ↑↓ は欄と一覧の行を 1 つの並びとして端で巡回する。欄の ↓ は一覧の先頭、先頭の行の ↑ は欄、欄の ↑ は一覧の末尾、末尾の行の ↓ は欄へ移る。欄から一覧へは、並びの次（先頭の行）か巡回した先（末尾の行）へ移る。

一覧に焦点がある間:

| キー | 動き |
|---|---|
| ↑↓ | 選択。先頭の ↑・末尾の ↓ は欄へ（押し続ければ流れる） |
| ↵ / →（修飾なし） | 地図へ |
| ⌘↵ | 今すぐ実行（終わりの部品すべてまで流す） |
| space | 停止 ⇄ 再開 |
| ⌘⌫ | 確認なしで削除。同じ位置の行が選ばれる |

地図に焦点がある間:

| キー | 動き |
|---|---|
| ↑↓ | 段を選ぶ（端で止まり巡回しない。先頭の部品の ↑ は「通知」の段。行き先の行には止まらない。押し続ければ流れる） |
| ⌘↵（部品の段） | 選んでいる部品まで流す |
| ↵ / →（「通知」の段） | [通知](#通知)のサブメニューを開く |
| ← / esc | 一覧へ（一覧の行はそのまま） |

欄に焦点がある間:

| キー | 動き |
|---|---|
| ↵ | 依頼する |
| ↓ | 一覧の先頭へ |
| ↑ | 一覧の末尾へ |
| esc | 一覧の先頭へ（↓ と同じ） |

自動化が 0 件なら、欄の ↑↓ は何もしない。

- ↵・→・⌘↵・space・⌘⌫ は押した瞬間だけを操作にし、押し続けたキーリピートでは何も起きない。取り消せない操作を繰り返さないため。削除に確認を挟まないのはタスクの ⌘⌫ に揃えたため。
- 日本語入力の変換中の ↵・↑↓・esc は変換へ渡る。
- 一覧の ⌘↵（今すぐ実行）は終わりの部品すべてまで、地図の ⌘↵（ここまで今すぐ実行）は選んでいる部品まで[流す](../platform/automation.md#止める流す)。流している途中の ⌘↵ は断り、フッターの右に赤で「実行中のため、今は実行できません」を出す。
- 流す・停止 ⇄ 再開・削除の操作は、場所ごとのキーとの対応・キーの表示・名前・断りを 1 つの定義が決め、キーの処理・フッターの左・カードのボタンがそれを読む。キーを変えたときに表示だけが嘘にならないため。
- 一覧のほかのキー（← / esc・⇥・⇧⇥・⌘↑↓・文字キーなど）、地図のほかのキー（部品の段の ↵ / →・⇥・⇧⇥・space・⌘⌫・文字キーなど）と欄の ⇥ は何も起こさず、焦点もボードの外へ出ない。

フッターの右の断り（赤）は 1 枠で、次の操作（↑↓・↵・→・←・⌘↵・space・⌘⌫・esc・行や地図のクリック・欄に打つ）で消える。フッターの左は焦点のある場所で効くキーで、フッターにボタンは置かない（押せるのはカードのボタンだけ）。

- 一覧: 「↑↓ 移動　↵ 部品を見る　⌘↵ 今すぐ実行　space 停止（止めていれば 再開）　⌘⌫ 削除」。自動化が 0 件なら出さない。
- 地図の部品の段: 「↑↓ 部品　⌘↵ ここまで今すぐ実行　← 一覧へ」。
- 地図の「通知」の段: 「↑↓ 部品　↵ 通知を変える　← 一覧へ」。
- サブメニューを開いている間: 「↑↓ 移動　↵ 決定　← 戻る」。
- 欄: 「↵ 依頼する　↓ 一覧へ」。自動化が 0 件なら「↓ 一覧へ」は出さない。

行のクリックで選ぶ。一覧の行のクリックは一覧に居る（部品は選ばれていない）。地図の部品の行のクリックはその部品を選んで地図に居る。見出しの「通知」の行のクリックはその段を選んでサブメニューを開く。地図・カードの地のクリックは地図に居る（前に居た段。初めてなら先頭の部品）。ポインタが乗っただけでは選択を動かさない——ボードは常に出ている画面で、ポインタが横切るたびに詳細が替わるのを避けるため。

### 時刻

「次回 17:00」「昨日」などの時刻の文言は分の境で描き直す。開きっぱなしの画面に、日をまたいだ時刻や過ぎた「次回」が残らないため（⌘⇧X は開いた時点で固定）。

### 0 件

自動化が無ければ一覧の頭は「自動化 0」、その下に「自動化はまだありません」を出し、一覧のキーは出さない。依頼の欄はいつもどおり出て、選ばれるのは欄だけ（右の欄は案内）。

## 焦点

ボードの面は、エディター面と同じく、焦点（first responder）が自分の中にあるときだけ chrome キーを受ける。焦点が欄にあっても同じ。端末タブを選んでいる間ボードは隠れて窓に残るが、焦点が無いので欄にも一覧にもキーが届かない。

焦点の宛先は部品の中（自動化の部品の欄・一覧・地図の 3 か所）にあり、部品がある間はボードの面そのものは焦点を受けない。面が焦点を受けられると、中身に焦点が無いままキーが黙って飲まれる状態が生まれうるため。部品が 1 つも無い間は、飲まれて困る中身が無いので面が焦点を持つ——⌘⇧] / ⌘⇧[・⌘T・⌘⇧X などの窓のキーはいつもどおり効き、ほかの打鍵は何も起こさない。

- 焦点が外から部品へ入る（ボードを選ぶ・パレットを閉じる・workspace を切り替えて戻る）と、欄が選ばれて欄に焦点がある（地図には居ない）。⌘⇧X が開くと入力欄に焦点があり ↓ で一覧へ下りるのと同じ形。一覧で選んでいた行は保たない——⌘⇧X も開き直すたびに選択を初めからにし、ボードへ入るのは開き直しにあたるため。
- 焦点がボードの中にある間の当て直し（裏のタブが閉じた・地のクリック）では、選んでいる場所（欄・一覧の行・地図の段）のまま。
- [通知](#通知)のサブメニューは地図の「通知」の段の中の状態で、焦点の場所ではない。外から入ると欄が選ばれるので閉じる。地図を出ても閉じる。
- 欄に焦点が来ると、打ってあった文は全文が選ばれる（AppKit の入力欄の既定。⌘⇧X の入力欄と同じ）。打てば置き換わり、→ で末尾から続けられる。カードの「修正を依頼」が書き出した直後だけは、キャレットが末尾にあり、そのまま続きを打てる。
- クリックは中身へ届く。欄を押せば欄、行を押せばその行、一覧の地を押せば一覧（欄から来たなら先頭の行、地図から来たなら選んでいる行）、地図の部品の行を押せばその部品、見出しの「通知」の行を押せばその段、地図・カードの地を押せば地図、それ以外の地を押せば選んでいる場所へ焦点が移り、続けてキーが効く。
- メニューバーの[自動化の知らせ](menubar.md)を押すと、外から入る規則の後にその自動化の行が選ばれ、焦点は一覧にある（地図には居ない）（行き先の指定が入り方の既定に勝つ）。自動化が消えていれば欄が選ばれ、自動化の部品が無ければボードが開くだけ。
- ボードを通り過ぎるだけの移動（Home をボードのまま離れたあと、別の workspace から Home のタブへ `focus_tab` で移ると、Home へ戻る途中でボードが選ばれる）では、焦点は移った先のタブに残り、欄へは入らない。

部品の並びが変わったとき、焦点は**ボードの中にあるときだけ**追う。外（端末タブ・⌘⇧X などのパレット・別の workspace）にある焦点は、部品が置かれても外されても動かない。

- 焦点がボードの中にあるところで部品が外されると、焦点は窓へ落ちずボードの面に残る。
- 空のボードを見ていたところへ部品が置かれると、外から入ったときと同じく欄に焦点が入り、そのまま打てる。

## 空の状態

部品を 1 つも持たないボード（自動化の部品を外したとき）は、中央に沈んだ一文（「まだ何も置かれていません」）だけを出し、フッターも出さない。字種と色はエディター面の空状態と同じ。地は端末・エディター面と同じ veil で、背景不透明度の設定にライブで追従する。

## 保存

ボードを選んでいたかと、部品の並び（決めた workspace だけ。空にした並びも空のまま戻る）は workspace ごとに保存し、再起動後も戻る（→ [persistence](../platform/persistence.md)）。保存の部品の並びが読めなければ、その欄だけ何も決めていない既定（自動化の部品 1 つ）に戻る。どの workspace がボードを持つかは保存しない（Home であることから決まる）。
