# 子プロセス PATH

Orbe が起こす子プロセスに渡す `PATH` を決める。git・gh・GUI エディタ・補完の generator・エージェント CLI——外部コマンドを起こす面はすべて、ここが解決した**同じ 1 つの値**を読む。

GUI から起動したアプリのプロセス PATH には、ユーザーが導入したツールが載っていない。ターミナルから叩けば動く `git` や `gh` が、Orbe からは「未導入」に見える。これを避けるため、ユーザーのデフォルトシェルを起こして本人の PATH を取り出す。

値を 1 つに保つこと自体が要件になっている。同じ問い（このマシンで子プロセスに与える PATH は何か）に複数の実装が別々に答えると、取り方の差がそのまま機能ごとの差になる——ある面ではコマンドが見つかり、別の面では見つからない、という食い違いが生まれる。解決は 1 箇所が持ち、他は読むだけにする。

## 取り方

デフォルトシェルを **login かつ interactive** で起こし、`/usr/bin/env` の出力から PATH を読む。

- **interactive で起こす**のは、`.zshrc` が対話シェルでしか読まれないため。PATH をそこに書いている環境（mise・asdf・nvm などの shim を足す構成が該当する）では、`-i` を落とすと shim を丸ごと取りこぼす。しかもシェル自体は成功で終わるので、**失敗として検出できない欠落**になる。
- **`/usr/bin/env` から読む**のは、シェルの文法に依存しないため。子プロセスの環境を出させるので、シェルが PATH をどんな形（fish のリスト型など）で持っていても、渡る時点では区切り文字列になっている。
- 取れた文字列は PATH として読めるかを検査し、読めない値は捨てる。絶対パスでない要素・空の要素は落とす。実在するディレクトリかは見ない——後から作られる先を落とさないため、また検査を環境に依存させないため。

rc は対話シェルで任意のコードを走らせるので、標準入力は塞ぎ、標準エラーは捨て、上限つきで打ち切る。

**終わったことを決めるのはシェルの終了であって、出力の読み切りではない。** rc が背景にプロセスを残すと、そのプロセスが出力の書き込み端を握ったままになり読み切りは永遠に来ない。読み切りを待つ形にすると、正しく取れた PATH を捨てて上限まで張り付くことになる。シェルの終了後に残るのはバッファの汲み出しだけなので、そこは短い猶予で区切る。

## 既知パスの union

取れた PATH には、コマンドが置かれている既知の場所を必ず足す。取得に失敗したときだけでなく、**成功したときも常に**足す——「起動には成功したが中身が足りない」が、この機構が救うべき主なケースだから。

足すのは末尾で、シェル由来の並びは先頭にそのまま残す。PATH は前にあるものが勝つので、既知パスを先頭へ差し込むと、ユーザーがバージョン管理ツールの shim を先頭に置いて選んだはずのコマンドを、別の場所にある同名コマンドが踏み潰す。既知パスは「無いものを補う」役であって、ユーザーが決めた優先順を「奪う」役ではない。

重複は初出だけを残す。シェルから何も得られなかった場合は既知パスだけになるが、値が空になることはない。

## 解決は 1 回、結果は次回起動へ持ち越す

シェルを起こすのはプロセスにつき 1 回だけ。並行して要求されても 1 回に畳む。得た値は `app-state.json` に温存し、次の起動はシェルを起こさずに答えられる（[persistence](persistence.md)）。温存するのは既知パスを足す**前**の値で、読み出すときに足し直す——既知パスの集合は Orbe の版で変わりうるので、合成後を焼くと古い集合がディスクに固定される。

温存された値があっても、起動ごとに 1 回は解決し直してキャッシュを更新する。ユーザーの PATH が変わったとき、いつまでも古い値を配り続けないため。

**待ちの上限は、呼び出す側がレイテンシ要求として選ぶ。** メインスレッドから呼ばれうる面（エディタ起動・起動復元・エージェント起動）は、プロセス全体で使い切る予算の範囲でだけ待ち、尽きたら待たずに既知パスだけで答える。予算は呼び出しごとに配り直さない——起動復元はペインの数だけ PATH を要求するので、1 回ぶんの上限では全体の停止時間を抑えられない。背景で走っていて誰も待たされない面は、解決の着地まで待つ。

上限に達して既知パスだけで答えた場合でも、その値をプロセスに焼き付けることはしない。解決は裏で走り続け、着地すれば以降の呼び出しが正しい値を得る。起動直後のたまたま早い 1 回が、痩せた PATH をセッション全体に固定してしまうのを防ぐ。

同じ理由で、この PATH を使ってコマンドの実体を探す面（[エージェント検出](../agent/launch.md)・[エディタ](../chrome/layout.md)・gh）は、**見つかったときだけ**結果を覚える。「見つからなかった」を覚えると、PATH が整う前の 1 回の失敗がセッション全体を縛り、この機構が解こうとしている問題がそのまま残る。

PATH の再解決は起動時の 1 回きりなので、Orbe の起動中にユーザーが PATH を変えても、再起動するまで反映されない。

なお、ターミナルのペインに渡す環境はここでは扱わない。ペインはユーザーのシェルをそのまま起こすので、PATH は自前で組み立てる（[cli](../control/cli.md)）。
