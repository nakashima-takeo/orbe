# 裏で回す仕組み

登録された予定を、タブを開かずに画面の裏で回す基盤。予定は「何を走らせるか（シェルのコマンドか軽い agent）」「いつ」「期限」で決まる。この基盤は画面も登録の口も持たず、使い手（待ちの条件・[自動化](automation.md)など）が自分の保存先から予定を登録し、結果を受けて自分で記録する。

部品は 3 つ。

- **番人**: 次の時刻を数え、時刻が来た予定の 1 回を始める。
- **実行の係**: アプリに 1 つ。同時に走る数・止める手・終了時の回収を受け持つ。予定ではない単発の実行も、番人を通らずにここへ直接渡す。
- **裏の 1 回**: 子プロセスを 1 つ起こし、上限で打ち切り、片付けてから返る。

## 予定と次の時刻

「いつ」は「○分ごと」（間隔）か cron 式（5 欄: 分・時・日・月・曜日）。間隔は最後に走ってからの長さで時計に揃わず、cron 式は暦の時刻で時計に揃う——意味が違うので書き方も 2 つに分ける。間隔は 1 分より短くできない——AI が誤って秒単位で登録しても、外部のサービスを叩き続けないため。7 日より長くもできない——極端な間隔は予定を組む時点で時計の値があふれるため。

cron 式は受け取った時点で解析し、正しくない式は予定にならない。各欄は `*`・数・範囲 `a-b`・刻み（`*/n`・`a-b/n`・`a/n`〔a から欄の最大まで〕）とそれらの `,` 区切りで、月と曜日は英名（`JAN`・`MON` など、大文字小文字を問わない）も書ける。曜日の 0 と 7 は日曜。断るのは、欄の数が 5 でない・範囲外・逆順の範囲・刻み 0・解釈できない字（`@daily` などの略記と `L W # ?` もここに入る）・日と曜日のどちらも `*` でない・一度も来ない（絞った日が、絞ったどの月にも無い。2 月は 29 日まであるとみなす）式。

- 日と曜日は、少なくとも一方の欄がちょうど `*` でなければならない。標準 cron は両方を絞った式を「どちらか一致」で回し、絞ったかどうかを値ではなく書き方で決める（`1-31` も絞ったことになる）。この形を断ると、受けた式はすべて日・曜日・月・時・分の「かつ」で数えられ、AI が知っている cron の意味と Orbe の意味が割れない。

番人も実行の係も保存を持たない。保存は使い手が持つので、登録には「数え始め」を添える。数え始めは最後に走った時刻で、まだ走っていなければ予定を作った時刻。

次の回は **「数え始めより後の最初の回」** という 1 つの規則で決まる。走らせたら、数え始めをその回の開始時刻に進める。過ぎた回の扱いは「いつ」の種類が持つ。

| いつ | 次の回 | 過ぎていたら |
|---|---|---|
| 間隔 | 数え始め＋間隔 | 過ぎた回数にかかわらず 1 回だけ走らせる |
| cron 式 | 数え始めより後で、かつ今の分の始まり以降の最初の該当時刻 | 今の分より前に過ぎた該当時刻は回さず、次の該当時刻を待つ |

- cron 式は cron と同じく「その時刻にだけ回る」。Mac が眠っていた・Orbe が動いていなかった間に過ぎた時刻は回さない。今の分に入っている該当時刻は今の回として走らせる——予約は該当時刻ちょうどに発火し、数え直す時点の今はわずかに過ぎているので、「今より後」で数えると回るべき回まで飛ばすため。分の粒度は cron の意味（その分に一致したら回る）と同じ。前の回が長引いて次の該当時刻の分を越えて終わったら、その回も飛ぶ。
- cron 式の該当時刻はその時点のタイムゾーンの暦で、月・日・曜日・時・分のすべてが一致する時刻（秒 0）。夏時間で存在しない時刻は次に存在する時刻へずらし、繰り返す時刻は最初の方を取る。
- 新しく登録した予定はすぐには走らない。すぐ確かめたいときは使い手が「今すぐ」を呼ぶ。
- スリープ明け・再起動・時計の変更をすべてこの規則で扱う。
- 時計が大きく戻って数え始めが今より未来になったら、今から数える。そのままでは次の回が戻った分だけ遠のき、予定が止まってしまうため。この規則も次の時刻の関数の中にあり、番人はそろえた数え始めを覚え続ける（覚えないと、時計が戻っている間は次の回が今に連れて遠のき続ける）。
- 期限がその回以前、または期限が今以前なら、次の出来事は「期限が来た」になる。過ぎていた回も、期限まで過ぎていれば走らせない——走らせてから期限を判定すると、結果の記録が 2 通りに割れるため。

この規則は純関数 1 つで、使い手の画面（[待ちの条件](tasks.md)の「次は 7 分後」など）も同じ関数を読む。

## 番人

壁時計で待つ。待ちは最も早い出来事に合わせた予約 1 本で、その発火には頼らず、スリープ明け・時計の変更・タイムゾーンの変更で全予定を数え直す。cron 式はタイムゾーンで意味が変わるので、タイムゾーンの変更も契機に入る。

登録の形は 2 つ。

- **仕事＋いつ＋期限**: 時刻が来たら仕事を実行の係へ渡し、1 回の結果を使い手へ返す。
- **始め方＋いつ**: 時刻が来たら使い手の「1 回の始め方」を呼び、止める手を受け取り、使い手からの「終わった（数え始めはこの時刻）」の知らせで数え直す。1 回が複数の段から成る使い手（自動化の部品の契機は、1 回の上限で切った行を取り切るまで部品の回を続けて回し、回によっては出し直しも挟む）が、段の間も含めて 1 回として番人に重ねない保証・「今すぐ」・走っているかを任せるための形。前者はこの形で仕事を 1 つ渡すものとして働く。いつを持たない登録もでき、その予定は「今すぐ」でだけ走る。

- 同じ予定は重ねて走らせない。走っている間に次の回が来ても積まず、終わった時点で数え直す。「今すぐ」も走っている間は何もしない。使い手は予定が走っているかを問える。走っているかは画面から観測でき（ボードの自動化の一覧の「実行中…」）、始まり・終わり・止めのどれでもすぐ届く。観測に乗るのは予定の有無と走っているかだけで、数え直しや予約の張り直しでは画面を描き直さない。
- 同じ ID での再登録は「外す＋登録」。走っている回は止め、その結果は返さない。使い手の保存は結果を受けたときにしか進まないので、止めた回は保存上「まだ走っていない」になり、番人の記憶と食い違わない。
- いつだけを差し替える口があり（いつを持たないものへ、またはその逆も）、走っている回は止めない。何を走らせるかが変わらない書き換え（自動化の部品の名前・予定・止める／再開）で、走っている回を殺さないため。
- 期限が来たら、走っている回を止め（結果は返さない）、「期限が来た」を 1 度だけ返して予定を外す。
- 予定 ID には使い手が名前空間を付ける（例「wait:12」「automation:3/judge」）。保存を持たないので、使い手ごとに番人を持ってよい。共有の資源は実行の係が持つ。

## 実行の係

同時に走る数は agent が 2 本、コマンドが 4 本まで。枠は種類ごとに別々で、溢れた分は来た順に待つ。再起動の直後に過ぎていた予定がまとめて走っても claude が何本も立ち上がらず、枠が別なので軽い確認のコマンドが重い agent の後ろで待たされない。

実行を受け取ると止める手を返し、結果は main で 1 度だけ届く。止めた回は「止められた」で返る。

Orbe を普通に終了すると、走っている全グループを止め、回収してから終わる（短い猶予の後は SIGKILL）。順番待ちの分は走らせずに捨てる。クラッシュや強制終了で落ちたときに子が残るのは範囲外。

## 裏の 1 回

### 起こし方

- コマンドは `/bin/sh -c <文字列>` で走らせる。rc は読まない。作業ディレクトリは予定ごとに持ち、既定はホーム。走る時点で無ければ「始められなかった」。
- コマンドの仕事は、保存する定義（コマンドと作業ディレクトリ）とは別に、1 回分の入力（標準入力に渡すデータと、子の環境に足す変数）を持てる。足す変数は子の環境だけに置き、Orbe のプロセスの環境は変えない。
- 子の環境は「Orbe のプロセスの環境＋子プロセス PATH（[shell-path](shell-path.md)）」で、他の起こし口と同じ形。コマンドは 1 回分の入力の変数をそこへ足す。PATH の確定を待ってから起こす。
- 子は専用のプロセスグループで起こし、Orbe が持つソケット・pty・他の実行の pipe を一切渡さない。標準入力は渡すデータか空。Orbe が無視している SIGPIPE は子では既定に戻し、シグナルマスクは空にする——起こすスレッドが塞いでいるシグナルを継ぐと、止めるときの SIGTERM が届かず子の後始末が走らないため。

### 上限

1 回の実行は 3 つの上限で打ち切る。既定は種類ごとに置き、仕事ごとに変えられる。

- **経過時間**: スリープ中を数えない時計で測る（スリープ中は子も止まっている）。
- **無出力**: 標準出力か標準エラーに 1 バイトでも出力があれば延びる。仕事ごとに外せる。外した実行は経過時間の上限だけで止まる——上限を経過時間の一本にしたい使い手のため（自動化の部品は、利用者が決める上限時間だけで止める）。
- **出力量**: 成果として貯めるものだけに掛ける。コマンドでは標準出力と標準エラーのそれぞれ、agent では最終応答の大きさ。超えたら打ち切る——黙って捨てて走らせ続けると、切れた出力を完全なものとして読ませてしまうため。agent の標準エラーは成果ではないので、貯める量を抑えるだけで走らせ続ける。

結果には、どの上限で打ち切ったかと、経過時間の上限と同じ時計で測った走った長さが残る——使い手が上限の残りを見積もるとき、スリープを含む実時刻の差では少なく見積もるため。

### 止め方と片付け

止めるのは常にグループ単位。打ち切り・停止・終了時は SIGTERM → 猶予 → SIGKILL。

**実行の寿命＝グループの寿命**。リーダーが自分で終わった場合も、背景に残った孫をグループごと止めてから返る。リーダーは最後に回収する——先に回収すると、空いたプロセスグループ番号が再利用されたときに無関係なグループ（タブのシェルなど）へシグナルが届くため。

出力の終わり（EOF）は無期限には待たない。グループから逃げた孫が出力の書き込み端を握っていても、リーダーの終了から短い猶予で返る。ツールの実行で別のプロセスグループやセッションへ逃がした孫は、グループの停止では拾えない。

### 1 回の結果

表示用のコマンド行（実際に走らせたもの）、始まりと終わりの時刻、終わり方（終了コード・シグナル・上限で打ち切り・止められた・始められなかった〔理由〕・指定したツールが使えなかった〔ツールの名前〕）を持つ。コマンドなら標準出力と標準エラー（それぞれ切り詰めたかどうか）、agent なら最終応答の本文（失敗で終わった回は CLI が返した失敗の理由）と CLI が失敗を報告したかどうか。結果の保存は使い手の領分。

## 非対話の agent

裏で回せる agent は claude だけ（[launch](../agent/launch.md) の検出結果を、実行のたびに PATH の確定を待って解き直す。起動直後の「検出中」を「無い」と取り違えないため）。指定するのはモデル・許可の規則・依頼文で、依頼文は標準入力で渡す（引数の長さの上限と、プロセス一覧に出ることを避ける）。会話は残さない。

作業ディレクトリは回ごとに一時ディレクトリの下へ作る空のディレクトリで、回の後に中身ごと消す。作れなければ「始められなかった」。claude は作業ディレクトリの中の読み取り専用のコマンド（`cat`・`ls`・`grep` など）を許可の規則と関係なく走らせるので、その範囲を空にするため。ディレクトリに結び付く claude の登録（local・project スコープの MCP サーバーと設定）は読まれない。

許可の規則は、組み込みのツール名・`Bash(<コマンドの接頭>:*)`・MCP のツールの完全名（`mcp__` で始まる名前）。組み込みの規則は、ツール名を「持たせるツール」に、規則そのものを「許すもの」に分けて渡す——`Bash(gh search prs:*)` なら Bash を持たせ、その接頭のコマンドを許す。作業ディレクトリの中の読み取り専用のコマンドは規則と関係なく通る（中は空）。MCP のツールを指定しない形では、作業ディレクトリの外のファイルを引数に取って読むコマンドは、規則に一致していても拒否される（`id` のようにファイルを読まない読み取り専用のコマンドは通る）。外のファイルを読ませるには、それを読むコマンド（スクリプトなど）を許す。この解釈（規則の `,` 区切りと `Bash(<接頭>:*)` の一致）は claude の CLI の版に依る。崩れた場合は、名指ししたコマンドが agent に拒否される形で現れる。

使えるツールの絞り方は、MCP のツールを指定するかどうかで変わる。

- **MCP のツールを指定しない**: 利用者の Claude Code の設定・プラグイン・hook・MCP サーバーを一切読まず、指定した組み込みの規則だけで走る。外部の文面を読む判定役は、この閉じた形で走る。
- **MCP のツールを指定する**: 利用者が登録した MCP サーバーを名前で使うので、利用者の設定を読む。そのうえで指定したもの以外は問わずに拒否する。利用者が自分で「常に許可」にしたツール（MCP も、Bash を持たせた実行では Bash のコマンドも）は、この絞り込みの外で使える。利用者が設定で足した作業ディレクトリ（`additionalDirectories`）の下も、指定なしで読める。利用者のプラグインの hook も実行のたびに走るので、通知音などの副作用が出うる。
- どちらでも、利用者の「許可を問わない」既定（bypassPermissions など）は効かせない。
- どちらでも、利用者の CLAUDE.md と auto memory は読まない。判定が利用者の個人的な指示や記憶で揺れないため。
- MCP のツールを指定した実行は、claude の MCP サーバーの接続を最大 60 秒待たせてから始める（無出力の上限より短い）。待たないと、起動に数秒かかるサーバーのツールが無いまま始まり、取得役が何も取れない。
- MCP のツールを指定した実行は、始まりの出来事（その回で使えるツールの一覧）に指定したツールが 1 つでも無ければ、モデルを呼ぶ前にその場で止め、終わり方を「ツールが使えなかった」（揃わなかった名前）にする。最後まで走らせて「無かった」を添える形にしないのは、モデルを 1 回無駄に呼び、ツール無しで別の答えを作らせうるため。
- Orbe 自身の MCP（[エージェントプラグイン](../agent/plugin-package.md)のサーバー）は使えない。裏の子はタブの印を持たない（[notify](../agent/notify.md)）ので、プラグインの MCP シムは空サーバーになる。指定すると「ツールが使えなかった」で終わる。

claude の出力は出来事の流れとして 1 行ずつ読み、生きていることの測りに使う。保持するのは最後の `result`（最終応答と失敗の印）だけ。1 行の長さにも上限を置き、超えた行は捨てる——大きなツールの結果だけで応答を失わないため。捨てた行が最終応答だった（応答が届かずに終わった）場合は、出力量の上限で打ち切ったものとして返す。

codex と agy は「裏で回せない」を理由付きで返す。codex は組み込みツールを「これだけ許可」と指定する手段が無く、禁止を列挙するしかない（版が上がって増えたツールが漏れる）。agy は使えるツールの指定も、会話を残さない指定も持たない。claude が見つからないときも走らせずに「始められなかった」を返す。

## 1 行 1 件の JSON の読み取り

コマンドの出力にも agent の最終応答にも、同じ読み方を当てる（自動化の部品の手段はどちらでもよいため）。実行とは切り離した純関数で、形の検証は使い手が型で決める。

- 行の区切りは LF と CRLF のどちらでもよい。
- 各行は JSON オブジェクト 1 つ。使い手の型として読めた行だけを受ける。
- 読めない行には、行番号と理由（JSON でない・オブジェクトでない・キーが無い・null・型が違う など）を残す。
- 空行は項目にも捨てた行にもならない。
