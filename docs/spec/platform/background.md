# 裏で回す仕組み

登録された予定を、タブを開かずに画面の裏で回す基盤。予定は「何を走らせるか（シェルのコマンドか軽い agent）」「いつ」「期限」で決まる。この基盤は画面も登録の口も持たず、使い手（待ちの条件・[タスクの自動追加](intake.md)など）が自分の保存先から予定を登録し、結果を受けて自分で記録する。

部品は 3 つ。

- **番人**: 次の時刻を数え、時刻が来た予定の 1 回を始める。
- **実行の係**: アプリに 1 つ。同時に走る数・止める手・終了時の回収を受け持つ。予定ではない単発の実行も、番人を通らずにここへ直接渡す。
- **裏の 1 回**: 子プロセスを 1 つ起こし、上限で打ち切り、片付けてから返る。

## 予定と次の時刻

「いつ」は「○分ごと」か「毎日の時刻の集まり（9:00・13:00 など）」。間隔は 1 分より短くできない——AI が誤って秒単位で登録しても、外部のサービスを叩き続けないため。7 日より長くもできない——極端な間隔は予定を組む時点で時計の値があふれるため。毎日の時刻は時 0〜23・分 0〜59 で 1 つ以上、重複は 1 つにまとまる。

番人も実行の係も保存を持たない。保存は使い手が持つので、登録には「数え始め」を添える。数え始めは最後に走った時刻で、まだ走っていなければ予定を作った時刻。

次の回は **「数え始めより後の最初の回」** という 1 つの規則で決まる。間隔なら「数え始め＋間隔」、毎日の時刻なら「数え始めより後の最初の該当時刻」（その時点のタイムゾーンで数え、夏時間で存在しない時刻は次に存在する時刻へずらす）。走らせたら、数え始めをその回の開始時刻に進める。

- 新しく登録した予定はすぐには走らない。すぐ確かめたいときは使い手が「今すぐ」を呼ぶ。
- 次の回が今以前なら「過ぎている」とみなし、過ぎた回数にかかわらず 1 回だけ走らせる。スリープ明け・再起動・時計の変更をすべてこの規則で扱う。
- 時計が大きく戻って数え始めが今より未来になったら、今から数える。そのままでは次の回が戻った分だけ遠のき、予定が止まってしまうため。この規則も次の時刻の関数の中にあり、番人はそろえた数え始めを覚え続ける（覚えないと、時計が戻っている間は次の回が今に連れて遠のき続ける）。
- 期限がその回以前、または期限が今以前なら、次の出来事は「期限が来た」になる。過ぎていた回も、期限まで過ぎていれば走らせない——走らせてから期限を判定すると、結果の記録が 2 通りに割れるため。

この規則は純関数 1 つで、使い手の画面（[待ちの条件](tasks.md)の「次は 7 分後」など）も同じ関数を読む。

## 番人

壁時計で待つ。待ちは最も早い出来事に合わせた予約 1 本で、その発火には頼らず、スリープ明け・時計の変更・タイムゾーンの変更で全予定を数え直す。毎日の時刻はタイムゾーンで意味が変わるので、タイムゾーンの変更も契機に入る。

登録の形は 2 つ。

- **仕事＋いつ＋期限**: 時刻が来たら仕事を実行の係へ渡し、1 回の結果を使い手へ返す。
- **始め方＋いつ**: 時刻が来たら使い手の「1 回の始め方」を呼び、止める手を受け取り、使い手からの「終わった（数え始めはこの時刻）」の知らせで数え直す。1 回が取得と判定のように複数の段から成る使い手（タスクの自動追加）が、段の間も含めて 1 回として番人に重ねない保証・「今すぐ」・走っているかを任せるための形。前者はこの形で仕事を 1 つ渡すものとして働く。いつを持たない登録もでき、その予定は「今すぐ」でだけ走る。

- 同じ予定は重ねて走らせない。走っている間に次の回が来ても積まず、終わった時点で数え直す。「今すぐ」も走っている間は何もしない。使い手は予定が走っているかを問える。走っているかは画面から観測でき（⌘⇧X の自動追加タブの「実行中…」）、始まり・終わり・止めのどれでもすぐ届く。観測に乗るのは予定の有無と走っているかだけで、数え直しや予約の張り直しでは画面を描き直さない。
- 同じ ID での再登録は「外す＋登録」。走っている回は止め、その結果は返さない。使い手の保存は結果を受けたときにしか進まないので、止めた回は保存上「まだ走っていない」になり、番人の記憶と食い違わない。
- いつだけを差し替える口があり（いつを持たないものへ、またはその逆も）、走っている回は止めない。何を走らせるかが変わらない書き換え（タスクの自動追加の名前・いつ・止める／再開）で、走っている回を殺さないため。
- 期限が来たら、走っている回を止め（結果は返さない）、「期限が来た」を 1 度だけ返して予定を外す。
- 予定 ID には使い手が名前空間を付ける（例「wait:12」「intake:3」）。保存を持たないので、使い手ごとに番人を持ってよい。共有の資源は実行の係が持つ。

## 実行の係

同時に走る数は agent が 2 本、コマンドが 4 本まで。枠は種類ごとに別々で、溢れた分は来た順に待つ。再起動の直後に過ぎていた予定がまとめて走っても claude が何本も立ち上がらず、枠が別なので軽い確認のコマンドが重い agent の後ろで待たされない。

実行を受け取ると止める手を返し、結果は main で 1 度だけ届く。止めた回は「止められた」で返る。

Orbe を普通に終了すると、走っている全グループを止め、回収してから終わる（短い猶予の後は SIGKILL）。順番待ちの分は走らせずに捨てる。クラッシュや強制終了で落ちたときに子が残るのは範囲外。

## 裏の 1 回

### 起こし方

- コマンドは `/bin/sh -c <文字列>` で走らせる。rc は読まない。作業ディレクトリは予定ごとに持ち、既定はホーム。走る時点で無ければ「始められなかった」。
- 子の環境は「Orbe のプロセスの環境＋子プロセス PATH（[shell-path](shell-path.md)）」で、他の起こし口と同じ形。PATH の確定を待ってから起こす。
- 子は専用のプロセスグループで起こし、Orbe が持つソケット・pty・他の実行の pipe を一切渡さない。標準入力は渡すデータか空。Orbe が無視している SIGPIPE は子では既定に戻し、シグナルマスクは空にする——起こすスレッドが塞いでいるシグナルを継ぐと、止めるときの SIGTERM が届かず子の後始末が走らないため。

### 上限

1 回の実行は 3 つの上限で打ち切る。既定は種類ごとに置き、仕事ごとに変えられる。

- **経過時間**: スリープ中を数えない時計で測る（スリープ中は子も止まっている）。
- **無出力**: 標準出力か標準エラーに 1 バイトでも出力があれば延びる。
- **出力量**: 成果として貯めるものだけに掛ける。コマンドでは標準出力と標準エラーのそれぞれ、agent では最終応答の大きさ。超えたら打ち切る——黙って捨てて走らせ続けると、切れた出力を完全なものとして読ませてしまうため。agent の標準エラーは成果ではないので、貯める量を抑えるだけで走らせ続ける。

結果には、どの上限で打ち切ったかが残る。

### 止め方と片付け

止めるのは常にグループ単位。打ち切り・停止・終了時は SIGTERM → 猶予 → SIGKILL。

**実行の寿命＝グループの寿命**。リーダーが自分で終わった場合も、背景に残った孫をグループごと止めてから返る。リーダーは最後に回収する——先に回収すると、空いたプロセスグループ番号が再利用されたときに無関係なグループ（タブのシェルなど）へシグナルが届くため。

出力の終わり（EOF）は無期限には待たない。グループから逃げた孫が出力の書き込み端を握っていても、リーダーの終了から短い猶予で返る。ツールの実行で別のプロセスグループやセッションへ逃がした孫は、グループの停止では拾えない。

### 1 回の結果

表示用のコマンド行（実際に走らせたもの）、始まりと終わりの時刻、終わり方（終了コード・シグナル・上限で打ち切り・止められた・始められなかった〔理由〕・指定したツールが使えなかった〔ツールの名前〕）を持つ。コマンドなら標準出力と標準エラー（それぞれ切り詰めたかどうか）、agent なら最終応答の本文（失敗で終わった回は CLI が返した失敗の理由）と CLI が失敗を報告したかどうか。結果の保存は使い手の領分。

## 非対話の agent

裏で回せる agent は claude だけ（[launch](../agent/launch.md) の検出結果を、実行のたびに PATH の確定を待って解き直す。起動直後の「検出中」を「無い」と取り違えないため）。指定するのはモデル・使えるツールの名前・依頼文で、依頼文は標準入力で渡す（引数の長さの上限と、プロセス一覧に出ることを避ける）。会話は残さない。

使えるツールの絞り方は、MCP のツール（`mcp__` で始まる名前）を指定するかどうかで変わる。

- **MCP のツールを指定しない**: 利用者の Claude Code の設定・プラグイン・hook・MCP サーバーを一切読まず、指定した組み込みツールだけで走る。外部の文面を読む判定役は、この閉じた形で走る。
- **MCP のツールを指定する**: 利用者が登録した MCP サーバーを名前で使うので、利用者の設定を読む。そのうえで指定したもの以外は問わずに拒否する。利用者が自分で「常に許可」にしたツールは、この絞り込みの外で使える。利用者のプラグインの hook も実行のたびに走るので、通知音などの副作用が出うる。
- どちらでも、利用者の「許可を問わない」既定（bypassPermissions など）は効かせない。
- どちらでも、利用者の CLAUDE.md と auto memory は読まない。判定が利用者の個人的な指示や記憶で揺れないため。
- MCP のツールを指定した実行は、claude の MCP サーバーの接続を最大 60 秒待たせてから始める（無出力の上限より短い）。待たないと、起動に数秒かかるサーバーのツールが無いまま始まり、取得役が何も取れない。
- MCP のツールを指定した実行は、始まりの出来事（その回で使えるツールの一覧）に指定したツールが 1 つでも無ければ、モデルを呼ぶ前にその場で止め、終わり方を「ツールが使えなかった」（揃わなかった名前）にする。最後まで走らせて「無かった」を添える形にしないのは、モデルを 1 回無駄に呼び、ツール無しで別の答えを作らせうるため。
- Orbe 自身の MCP（[エージェントプラグイン](../agent/plugin-package.md)のサーバー）は使えない。裏の子はタブの印を持たない（[notify](../agent/notify.md)）ので、プラグインの MCP シムは空サーバーになる。指定すると「ツールが使えなかった」で終わる。

claude の出力は出来事の流れとして 1 行ずつ読み、生きていることの測りに使う。保持するのは最後の `result`（最終応答と失敗の印）だけ。1 行の長さにも上限を置き、超えた行は捨てる——大きなツールの結果だけで応答を失わないため。捨てた行が最終応答だった（応答が届かずに終わった）場合は、出力量の上限で打ち切ったものとして返す。

codex と agy は「裏で回せない」を理由付きで返す。codex は組み込みツールを「これだけ許可」と指定する手段が無く、禁止を列挙するしかない（版が上がって増えたツールが漏れる）。agy は使えるツールの指定も、会話を残さない指定も持たない。claude が見つからないときも走らせずに「始められなかった」を返す。

## 1 行 1 件の JSON の読み取り

コマンドの出力にも agent の最終応答にも、同じ読み方を当てる（タスクの自動追加の取得はどちらでもよいため）。実行とは切り離した純関数で、形の検証は使い手が型で決める。

- 行の区切りは LF と CRLF のどちらでもよい。
- 各行は JSON オブジェクト 1 つ。使い手の型として読めた行だけを受ける。
- 読めない行には、行番号と理由（JSON でない・オブジェクトでない・キーが無い・null・型が違う など）を残す。
- 空行は項目にも捨てた行にもならない。
