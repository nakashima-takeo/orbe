# タスク

人と agent が同じ一覧を読み書きするための、Orbe が持つタスク一覧。agent は会話をまたいで「やること」を残し、人はそれを workspace をまたいで眺めて並べ替える。入口は人向けの[タスク画面](../palette/tasks.md)（⌘⇧X）と、[制御 API](../control/api.md)（MCP にも出す）と [`orb task`](../control/cli.md)。タスクから作業を始めるのは、人ならタスク画面の ⌘T、agent なら [`start_task`](../control/api.md)（MCP だけ）で、どちらもタスクを進行中にして作業の場所（下記「worktree」）を付ける。

## 一覧は 1 本の列

一覧はユーザーが決める 1 本の列で、workspace をまたぐ。並べ替えは「別のタスクの前／後ろ」で指す——番号で指すと、読んだ後に他から挿入されたときにずれるため。

新しいタスクが入る位置は 2 通り。

- **列の末尾**（既定）: 制御 API・CLI・MCP の `add_task`。
- **見ている欄で、その優先度の未着手の先頭**: タスク画面で人が足したタスク（入力欄から足す・GitHub タブで「タスクにする」・受信タブで提案をタスクにする）。人が今見ている欄（タスクのタブの範囲で絞った一覧。範囲が「すべて」なら全部）の未着手のタスクのうち、足すタスクと同じか低い優先度の最初のタスクの直前に入る（無ければ列の末尾）。人がその場で足したタスクを、見ている欄の未着手の中で同じ優先度のものより上に置き、見えている高い優先度のタスクは越えない。見ていない workspace のタスクは基準にしない。

どちらも 1 回の変更・1 回の保存で入る。ステータス別の欄や workspace での絞り込みは、この列から抜き出して見せる表示側の仕事で、列そのものは組み替えない。

一覧の唯一の正はアプリ内のストア 1 つで、どの入口も同じ変異を呼ぶ。値の検証と不変条件はそのストアだけが持つ——入口ごとに別の検証を作らないため。

## タスクの値

- **ID** … 1 から振る短い整数。削除しても使い回さない（次に振る番号を永続する）。agent が会話をまたいで覚えて使い、`orb task set 12` と打てる短さが要るので、起動ごとに振り直す tab / workspace の ID とは別物。
- **タイトル** … 前後の空白を除いて空でない 1 行。制御文字と改行類（行区切り・段落区切りの文字を含む）は不可。行を壊さない書式文字（ZWJ でつないだ絵文字など）は使える。
- **ステータス** … 未着手（`todo`）・進行中（`in_progress`）・完了（`done`）。完了したタスクは削除するまで一覧に残り、完了日時は持たない。
- **待ち** … ステータスとは別の属性で、理由（空でない）と待ち始めた日時を持つ。理由だけを変えても待ち始めた日時は動かない。完了にすると待ちは外れ、完了のタスクには待ちを入れられない（同じ変更でステータスを戻せば入れられる）。待ちは解ける条件を持てる（下記「待ちの条件」）。待ちの席は「待っている」か「解けた（起きたこと）」のどちらか 1 つで、両方を同時には持たない。
- **優先度** … 高・中・低。既定は中。
- **期限** … 暦日だけ（時刻とタイムゾーンを持たない）。暦に存在しない日付は受けない。
- **workspace** … 任意（下記）。
- **結び付き** … GitHub の Issue・PR の順序付きの列（下記）。空なら結び付きなし。
- **worktree** … 任意。このタスクの作業の場所（下記）。
- **詳細** … 複数行の自由記述。人も agent も読む前提の欄。
- **追加日時** と **追加者** … 追加者は、追加の時点で呼び出し元タブの agent が作業中（`working`）を報告していたときの、その agent の名前（claude など）。agent が自分のターンの中で足したときだけがこれに当たる。人が GUI やシェルから足したとき、終了を報告しない agent（codex / agy）が去った後のタブから足したとき、作業中を報告しない agent から足したときは何も残らない——取り違えた名前が残ると後から直せないので、確かなときだけ残す。

不正な値・組み合わせは拒否し、そのとき一覧は変わらない。

## 待ちの条件

AI は待ちに「解ける条件」を付けられる——「PR #214 にレビューが付いたら」のような説明と、それを確かめるシェルのコマンド・確認の間隔（1 分以上）・期限。Orbe は出来事の種類（GitHub・Slack など）を知らず、渡されたコマンドを[裏で回す仕組み](background.md)で回すだけ。条件を付けるのも変えるのも AI で、人ができるのは待ちごと外すこと（[タスク画面](../palette/tasks.md)の「解除」）だけ。

- **期限は必須で、過ぎた期限は付けられない。** 付けたまま忘れられた条件が裏でコマンドを叩き続けないため。満たされなくても期限で必ず解ける。
- **確かめるのは付けた直後に 1 回、以後は間隔ごと。** 書き間違いがすぐ実行の記録に出て、すでに満たしていれば即座に解ける。数え始めは保存せず、最後の確認の始まり（まだなら付けた日時）から導く。再起動の後もこの規則で続き、終了している間に期限を過ぎた条件は、次の起動で「期限が来た」で解ける。
- **コマンドは人の承認なしに走る。** 走る場所は条件を付けたタブの作業ディレクトリ（タブが分からなければホームディレクトリ）。代わりに、実際のコマンドと「いつ・何が起きたか」の記録を画面にいつも出す。
- **成功は「終了コード 0 で終わった」だけ。** 失敗・シグナル・上限での打ち切り・始められなかった、はすべて記録して待ち続ける。
- **解けると、待ちは「起きたこと」に置き換わる。** 起きたことは、解けた待ち（理由・待ち始め・条件と経過）・解け方（満たした＋確認の標準出力の先頭／期限が来た）・解けた日時を持つ。「起きたこと」として行に出すのは標準出力の 1 行目で、空なら「条件を満たした」、期限なら「期限が来た」。ステータスは変えない。解けたら知らせるだけで、agent を勝手に起こさない——知らせは agent の通知と同じメニューバーのピル（[menubar](../chrome/menubar.md)）と完了の通知音（[sound](../agent/sound.md)）。
- **起きたことが消えるのは、[⌘T](../palette/tasks.md) で会話へ届けたとき・新しい待ちを付けたとき・完了にしたとき。** 待ちを外す変更（理由を空にする）では消えない。
- **付ける値の規則**: 説明は空でない 1 行（タイトルと同じ文字の規則）、コマンドは空でない、作業ディレクトリは絶対パス、間隔は 1 分以上、期限は今より後。条件は待っている間だけ持てる——待っていないタスクには理由と同じ変更で付ける。完了のタスクには付けられない。
- **理由だけを変えても、条件と経過は変わらない。** 条件を付け直すと、新しい同一性で確認の回数と記録は空から始まる——記録はその条件の確認の記録で、付け直した条件は別の条件なので。条件だけを外すと待ちは残る。理由を外すと待ちごと外れる。
- **確認の経過**: 確認の回数と、直近の一定件数の実行の記録（始まり・終わり・結果・標準出力と標準エラーの先頭）。記録は件数で切るので一覧は際限なく育たない。回数は別に数えるので「確認 N 回目」は正しい。

### 会話

条件には、条件を付けた agent の会話（CLI 名とセッション ID、付けたタブの workspace）が付くことがある。付くのは、呼び出し元タブの agent が作業中（`working`）を報告しているとき——agent が自分のターンの中で付けたとき——だけ（追加者と同じ「確かなときだけ残す」規則）。シェルから `orb` で付けた条件や、終了を報告しない agent が去った後のタブから付けた条件には付かない。付けたのが[秘書](../agent/secretary.md)（付けた時点の秘書のタブ）なら、そのことも記録する。会話は、解けた後の [⌘T](../palette/tasks.md) がその会話を続きから始める（秘書なら秘書の係へ渡す）のに使う。作業ディレクトリと会話は Orbe が呼び出し元タブから入れ、agent が自分で書いた値は使わない。

### 待ちの条件の係

アプリに 1 つの係がストアを観測し、条件を持って待っているタスクを番人に登録する。登録し直すのは条件の同一性が変わったときだけ。番人の結果は、タスクと条件の同一性を添えてストアへ書き戻す。付け直し・解除と結果の到着が競っても、ストアは同一性の合わない結果を捨てる——古い条件の結果が新しい条件の記録に混ざったり、新しい条件を解いたりしない。解ける瞬間は「記録を足して、待っているを解けたに置き換える」を 1 回の変異・1 回の保存で行う（間に読んだ agent に「待ちも起きたことも無い」状態を見せない）。解けたら、係は解けたタスクと起きたことを窓へ知らせ、窓がピルと音の知らせを組む。待ちが解ける処理はすべて係のこの 1 か所を通るので、起動直後に期限で解けるものも同じく知らせる。

## workspace の参照

タスクは workspace を、workspace が持つ内部専用の永続 ID で指す。改名しても root path を変えても結び付きは切れず、同じ root の workspace が 2 つあっても取り違えない。外（API・CLI）には今までどおり起動ごとの workspace ID と名前で見せ、永続 ID は出さない。

**解決できない参照は「workspace なし」として扱う**——「なし」の判定はこの 1 規則だけ。workspace を削除してもタスクの側は書き換えないので、削除済みの workspace を指すタスクは、表示・API・絞り込みのどれでも「なし」と区別がつかない（永続 ID は使い回さない）。書き換えないのは、workspace 機能からタスクへの書き込み経路を作らないため、保存の時機がずれた状態（workspace は戻るのにタスクの結び付けだけ外れる）を作らないため、そして workspace 構成の退避物を戻せば結び付きも戻るようにするため。

agent がタブの中から workspace を指定せずに足したタスクは、**呼び出し元タブの workspace** に付く（[Home](workspace.md#home) のタブからなら Home）。タブの外から足したとき、および呼び出し元タブが分からないとき（タブの環境 `ORBE_TAB` を受け継がない MCP クライアント経由など → [api](../control/api.md)）は「なし」。明示的に「なし」を指定することもできる。CLI の `--workspace current` は前面の workspace を指し、呼び出し元タブの workspace とは限らない（[cli](../control/cli.md)）。

## GitHub の Issue・PR との結び付き

タスクは GitHub の Issue・PR を複数持てる。1 つの結び付きは「リポジトリ（`owner/name`）・種別（Issue / PR）・番号」で、列の**先頭が主**——画面の行の頭や右の欄の見出しに出るのは主である。

- **項目の同一性はリポジトリと番号だけ**で決まり、種別を含めない。GitHub では Issue と PR が 1 つのリポジトリの中で同じ番号の空間を使うので、番号が同じなら同じ項目である。リポジトリ名は大小文字を区別せず、小文字で持つ。
- **1 つの項目は 1 つのタスクにだけ結び付く。** すでにほかのタスクに付いている項目を付けようとすると拒否し、拒否の理由に相手のタスクの ID を入れる（agent が外す相手を知れるように）。agent（制御 API・CLI・MCP）の付け替えは「相手から外す → こちらに付ける」の 2 回の変更で行う。[タスク画面](../palette/tasks.md)の付け替え（GitHub タブの ⌘L・右の欄の「＋ 結び付ける」）は 1 回の変更で、前のタスクから外し、選んだタスクの結び付きの末尾に足し、1 回だけ保存する——間に読んだ agent に「どこにも付いていない」状態を見せないため。同じタスクの中で同じ項目を 2 回持つことも拒否する。GitHub 側から「この項目のタスク」を引くとき、答えがいつも高々 1 つになるようにするため。
- **種別は指定どおりに保存し、保存時に GitHub へ照合しない**（オフラインでも足せるように）。食い違っていても同一性には種別を含めないので「1 項目 1 タスク」は狂わず、画面では番号だけが出て気づける。
- リポジトリは `owner/name`（各段は英数字・`-`・`_`・`.` で空でない）、番号は 1 以上だけを受ける。
- **保存するのは結び付きだけ**で、タイトルや状態などの GitHub の値は保存しない。古い値が正のように残らないよう、値は画面が開いたときに GitHub へ問い合わせる（[タスク画面](../palette/tasks.md)）。リポジトリが改名されても保存した名前は書き換えない（GitHub は古い名前からも引ける）。

### 外した項目と、PR の自動の結び付け

[タスク画面](../palette/tasks.md)（⌘⇧X）を開くと、完了していないタスクの worktree（ディレクトリが在るもの）のブランチに PR があれば、その PR をそのタスクの結び付きの末尾に足す。agent が worktree で PR を作れば、人が手で結ばなくてもタスクに付く。突き合わせは [worktree パレット](../palette/worktree.md)の clean と同じ規則——ブランチの同一性は remote の台帳（push 先の remote の正式名＋ブランチ名）で決め、PR は head がそれと等しいものだけを数える——で、規則を二重にしない。選ぶのは open の最新、無ければ最新。結び付きのリポジトリは PR が置かれたリポジトリ（head のリポジトリとは限らない）。worktree が作業のブランチ（下記「worktree」）と別のブランチにいる間・既定ブランチ・detached の worktree、GitHub に届かない（GitHub でない・gh が無い・未認証・オフライン）リポジトリでは何もせず、失敗を画面に出さない。完了したタスク・既にどこかのタスクに付いている PR には足さない。開いている間・閉じている間に出来た PR は、次に開いたときに付く。

**人が外した項目は、自動では付け直さない。** タスクは「外した項目」を持ち、結び付きの変更のたびに、外れた項目をそこへ足し、足された項目をそこから消す。外した経路（画面の ⌫・画面の付け替え・CLI・MCP）は区別しない——経路で分けると、agent が誤って付いた PR を外しても次に開いたとき付き直る。手で結び付け直すと記録から消え、以後は普通に扱われる。自動の結び付けは記録を見て避けるだけで、記録を変えない。外した項目は `tasks.json` にだけ出し、API には出さない（agent が読み書きする必要の無い内部の記録で、付け直せば消える）。

## worktree

タスクは worktree（作業の場所）を 1 つ持てる。値は「そのパスを含む git の worktree のルート（git の外ならそのディレクトリ）」に揃えたパスで、タブの連の色分けと同じ規則（場所のキー）で揃える。だから「そのタスクの worktree で動いている agent」は、タブの場所のキーとの等値だけで決まり、タブごとに git に問い合わせない。worktree の中のサブディレクトリを渡しても、ルートに揃って保存される。

- **1 つの worktree は高々 1 つのタスクにだけ付く。** 制御 API・CLI・MCP から、ほかのタスクが持つ worktree を付けようとすると拒否し、拒否の理由に相手のタスクの ID を入れる（結び付きと同じ形。agent は外してから付ける）。人が [⌘T](../palette/worktree.md) で場所を選んで ↵ したときだけは付け替わる（前の持ち主から外れる。フッターが先にそれを言う）。
- **制御の入口で付ける worktree は、実在するディレクトリの絶対パスでなければ拒否する。** 実在しない値を受けると、一覧には出ないのに他のタスクへの付与を拒む、見えない衝突になるため。制御文字・改行類を含むパスも、タイトルと同じく拒否する——書き込みと読み込みは同じ形の規則を当て、受けた値が次の起動の読み込みで拒まれて一覧ごと退避される、ということが起きない。
- **ディレクトリが消えた worktree は「なし」として扱う**（workspace の参照と同じ規則）。値は書き換えずに残るので、同じパスに worktree を作り直せば元のタスクの worktree として戻る。消えた値もほかのタスクへの付与を拒む（⌘T の ↵ なら付け替わるので、人の操作は詰まらない）。
- **付くのは作業を始めたとき**——[⌘T](../palette/worktree.md) の ↵ と [`start_task`](../control/api.md) は、タスクを進行中にして用意した場所を付ける変更を 1 回で行う。制御 API・CLI・MCP で直接付けることもできる。
- **[Home](workspace.md#home) のタスクの作業場**は、worktree の代わりに Home の中のタスクごとのフォルダ（[Home のタスクの作業場](workspace.md#home-のタスクの作業場)）で、同じこの席に記録する。git の外のフォルダでも値は同じ規則で揃うので、agent の表示はそのまま効く。
- 完了したタスクも worktree を持ち続ける。外れるのは、付け替え・明示的に外したとき・タスクの削除のときだけ。
- **作業のブランチを覚える。** worktree を付けるたび（⌘T の ↵・制御 API・CLI・MCP のどれでも）、その時点でそこが checkout しているブランチを記録する（detached・git の外・HEAD をファイルから読めない〔reftable のリポジトリ〕なら「ブランチなし」）。記録が「ブランチなし」か既定ブランチの間は**未確定**で、ブランチで絞らない（PR の自動の結び付けも agent の表示も、worktree のパスで引く）——既定ブランチの main worktree を付けてから、そのタスクの作業ブランチを切る、というよくある手順で、作業ブランチの PR と agent が付くように。未確定の worktree が既定ブランチ以外にいるのを [タスク画面](../palette/tasks.md)を開いたときの PR の自動の結び付けが見たら、そのブランチで確定する（PR が無くても確定する）。確定した後は、worktree の今のブランチが記録と同じ間だけ、そこをこのタスクの作業とみなす——PR の自動の結び付けと、agent の表示（行の札・タスク画面の右の欄の agent の場所）はこの間だけ効く。main worktree のようにブランチを切り替えて別の作業に使い回す場所でも、確定した後に別のブランチで作った PR や、別の作業をしている agent がこのタスクに付かない。元のブランチに戻れば、また効く。今のブランチが無い・分からない（detached・HEAD をファイルから読めない）ときも絞らない。記録は API には出さない（`tasks.json` にだけ出す）。
- タスクの worktree で作業中か入力待ちの agent は、[タスク画面](../palette/tasks.md)の行と右の欄に出る（完了したタスクと、worktree が確定した作業のブランチと別のブランチにいる間は出さない）。

## 保存

一覧は state ディレクトリの `tasks.json` に、変更のたびに即座に書く（[persistence](persistence.md)）。終了時の flush は要らず、強制終了でも失わない。再起動すると列の順・各値・ID の採番位置が同じに戻る。

結び付き・worktree・作業のブランチ・外した項目の欄の無い `tasks.json` は、それぞれ無いものとして読む。待ちの条件は付けるときと同じ値の規則で読む（期限が過ぎていることだけは問わない——読んだ後に解ける）。worktree は形（空でない絶対パスで、制御文字・改行類を含まない）だけを確かめ、ディレクトリの在否は読み込みで問わない。`tasks.json` が在るのに使えない（読めない・構造破損・非互換バージョン・ID の重複や採番位置との矛盾・結び付きや worktree の値が不正・同じ項目か同じ worktree が 2 つのタスクに付いている・待っているのと解けたのを両方持つ・待ちの条件が値の規則に反する）ときは、原本を `tasks-broken-<日時>.json` へ退避してから空の一覧で始める。人が書き溜めた内容は失うと戻らないので、workspaces.json と同じ退避の規律を共有する。

タスクの変化は制御 API のイベント（`wait_for_event`）にならない。確認の記録も変更なので、条件の数だけ最短 1 分ごとに保存が走る。
